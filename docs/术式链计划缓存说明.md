# 术式链计划缓存

这份说明对应结构计划与当次释放数据分开的实现。缓存只保存已经解析过的链结构。费用、伤害、冷却数字、武器、视线和随机结果仍在原来的时刻读取。

2026-10-30 修复后的最终源码已通过 `.\gradlew.bat compileJava --offline --no-daemon`。缓存计数已接入原来的性能记录，打开采样后可以在 `/shuperf` 导出里查看。尚未打包，也没有进游戏实测，不能据此声称服务端 TPS 提升。

## 什么会被记住

一次查找的键是：技能类型、按原顺序的术式 id、每个位置的原胚、以及进程内的结构代际。技能名字、玩家、槽位、手持物品、游标、法杖冷却缩减和属性加成都不进键。

只缓存长度不超过 64 的链，缓存里最多留 64 条整链。一条记录里是「没有步进时的整链」，或者「全部步进切片」，二者取其一。每个切片保存分段、角色标志、修饰模板、成员下标、份数、锁定/垂落和链聚能输入。复制次数只存数字，不把每一份展开成节点。

结构结果如果超过每条 16384 个下标、标志或模板单元，这条不放入缓存，这一次释放改走原来的动态路径，不会因此放不出来。

未知或未声明支持结构缓存的释放定义会使整条链不进缓存。没有登记的定义可以记住「这里没有定义」；之后登记会改变代际，旧记录作废。

## 缓存什么时候还在

- 服务端启动时绑定这一台服务器和它的线程，并清空缓存。
- 只有这条服务器线程能读写缓存。没绑定、服务器不对或线程不对时，直接走旧路径。
- 代际变化后，下一次查找先清空再处理。代际本身不会因为重进服归零。
- 停服时清空并丢掉缓存引用。重开的世界从空缓存开始，不沿用上一局的计划。
- 正在进行的一次释放如果中途代际变了，继续用已经拿在手里的那份分段图。已经冻结的冷却、费用份额和修饰计划保持原样。原先要在接触、延迟或段执行时重读的角色、份数、锁定和垂落，改回原来的动态读取，并且仍用这一份分段，不换成新图。

装配、换法杖或改原胚只要让键变了，下一次自然对不上旧记录，不需要单独的失效回调。只改原胚不会改变进度签名；签名仍然只有术式 id，游标规则和以前一样。

## 计数怎么读

`/shuperf` 仍是原来的导出。新增四个计数，一次查找只会落下其中一种终态：

| 计数 | 含义 |
| --- | --- |
| `CAST_PLAN_HITS` | 资格够、缓存里已有，直接取到计划 |
| `CAST_PLAN_MISSES` | 资格够、可以放入缓存，但这次还没有条目 |
| `CAST_PLAN_COMPILES` | 同一次查找里，结构编译完整成功并且已经放入缓存。它跟在 miss 后面，不是第四种互斥终态 |
| `CAST_PLAN_BYPASSES` | 没绑定、线程或服务器不符、定义不够格、链长超过 64，或编译时超出单元预算。预算超限只记这个，不先记 miss |

命中不会去冒充切开链条或角色扫描。`CHAIN_SPLIT` 只在真的调用切开时累加，命中路径不再切。`CHAIN_ROLE_SCAN` 的口径从「执行时那一次回扫」扩大为「实际发生的角色扫描」：编译计划时扫一次，代际对不上或没有上下文而回退时再扫。命中后直接读标志，不计这一项。`CAST_PLAN_COMPILE` 只包真正的结构编译。这些耗时项仍然可以嵌套，不能相加当成总耗时。

采样关掉、或不在绑定的服务器线程上时，计数和耗时都不会增加。这和原来的性能记录一样。

## 仍然每次现算的东西

魔力、水势、费用和退款，领域是否已学，当前刻和纪元，普通攻击力，法杖属性伤害，接触时再次拿到的主手，双重会话里已经冻结的载体和武器加成，附魔反应与快照，锁定、落点和场地查询，动量，几何、种子和随机数。5 刻双重间隔和 6 刻伤害汇总的排程没有改。

旧的无上下文调用保持原来的算法，不会用线程局部变量去猜「当前这次计划」。
