# 垂丝瀑布定向审查

2026-10-26。仅阅读最终Renderer、Layout及实施结果，未修改游戏代码、未运行重复编译或图像接口。

最终静态结论：正常0.5/1/2格宽主路径符合裁决，thin异常窄回退P2已关闭。当前定向审查没有其他待修复缺陷；最新修正后的编译尚未确认成功。

## 修复复核：thin P2关闭

已读取最终WaterCurtainLayout：新增固定内容包络常量25/64与39/64，两处异常回退均调用thinFallback，统一将该包络映射到[-W/2,W/2]。不再把64px透明留白压入水宽，也没有按帧重裁导致横向跳动。12px水体在14px包络中保留原始摆动余量，符合此前最小修复建议。以下初审问题保留供追溯，不再开放。

## [P2] thin回退把64px透明画布当成实际水宽

WaterCurtainLayout.horizontalSpans两处THIN分支当前把整张U=0..1映射到[-W/2,W/2]。实施结果已确认thin每行只有12px不透明，全部位于x=25..38的14列包络，其余为透明留白。因此W=0.2回退时，可见水宽仅约0.0375格（12/64×0.2），并非约0.2格；W从1/3略下降进入回退时会突然缩成细线。超过TILE_GUARD的另一回退也同样丢掉大部分可见宽度。

最小修复：保持原PNG不改，只给THIN设置覆盖所有帧的固定内容包络U，例如经像素核实的[25/64,39/64]；或新增无透明侧边的thin运行时裁切资源并使用整幅UV。不要按每帧重新裁包络，避免水体横向跳动。若要求严格铺满W，可另规定12px基准及1px摆动余量，但不能继续把64px留白等同W。两处fallback共用同一规则。补充略低于1/3、0.2以及超tile上限时的可见宽度核对。

## 正常路径已核对

- Renderer只读entity.width/height，布局没有聚能或术式id参数。时间只用于flowFrame，不用于宽度；聚能后从首次绘制就是最终同步宽度。
- 24px/格；边缘各1/6格。W=0.5中段1块，W=1中段4块，W=2中段10块，外沿始终±W/2。固定边缘不随W拉宽；不足整块同时裁几何与U。
- 左右中共用同一frame，按每2tick推进、16帧取模。顶点顶部使用较小V、底部较大V，配合已验证的向下8px素材，没有旧UV滚动叠加。
- 纵向每128px为16/3格，超长分成同帧多段，余段裁到帧内；上下半纹素保护不越入下一帧。极短尾段采样保护会稍改变亚像素纹理覆盖，但不构成跨帧问题。
- 顶点仅为实体局部偏移，未在世界坐标float上相减，避免远坐标精度与重复相机平移问题。
- 白色普通顶点、轻微冷色重水、NO_OVERLAY、FULL_BRIGHT、LEQUAL、COLOR_WRITE与NO_CULL均已实现。每个分件一张四边形，静态RenderType，未发现双份正反绘制。
- 正式视觉只读原实体尺寸，不新增实体/伤害，不改WeepingCurtain起流、供水、排空或地面截断。去掉交叉侧片导致近侧视更薄，报告已明确，碰撞厚度保留。
