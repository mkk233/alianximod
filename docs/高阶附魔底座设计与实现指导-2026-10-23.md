## 2. 分类与三层职责

玩法名称为高阶附魔；逻辑仍是MAGIC、baseDamage=0、isEnchantment=false、ATTACK宿主。
不新增第九个ChainRole，不新增TechniqueType来绕开既有等级与装配系统。
UI通过领域能力显示“高阶附魔”，不能把isEnchantment改真。
高阶领域独立成一个CD步骤，不被吞进后续攻击；前置E归紧邻领域，与它同一步计CD。
复杂度是MAGIC解锁等级，不是装配容量；首版保持既有assemblyCost算法。

每个领域有三条独立通道：

| 层 | 来源与作用 | 禁止混用 |
| --- | --- | --- |
| 原生脉冲native | 领域自带特殊效果，如敌潮湿、友水势 | 不执行整份外接E，不伪造hurt赚水势 |
| 友方攻击供给aura | owner/盟友命中时区内获得附加伤害 | 不写主手NBT，不送本体伤害、状态、范围、速度或CD |
| 外接E接触contact | E快照绑定零伤领域，敌人真实相交持续尝试 | 不自动把这份E供应给友方，不变成原生脉冲 |

三层共享实例生命周期和几何，但使用不同关系策略、取样时点与限流键。
新领域不进入旧FieldInfluence.occupied，不兼得旧场地数量倍伤。

雾雨作为底座示例：完整5×5×8范围已获用户确认；锚点、寿命、费用等其余数值为试调建议，细节见配套文：

| 项目 | 示例值 |
| --- | --- |
| 固定几何 | 完整宽5×深5×高8的axisbox，施法水平位置为中心，脚底为底面 |
| 寿命/CD | 200tick / 80tick |
| 生成/维护 | 每真实域40魔力 / 每20tick8魔力 |

| 本人/盟友原生水势 | 每20tick+2，首次在生成20tick后，100封顶 |
| 友方供给 | 基础潮印中性反应magicDamage，当前预计2，以公共解析实值为准 |

## 4. Domain v1拟新增类型

以下文件拟放在`shu/technique/release/domain/`，均非当前已存在能力。

### 4.1 DomainDefinition

声明几何工厂、固定生成策略、生命周期、初始/维护费用、原生效果、供给定义及边界策略。
参数可为不同长宽高和未来不同形状；首版axisbox不把雾雨5×5×8写死在公共代码。
建议方法：geometryAt(cast)、initialCost、upkeepCost/period、nativePolicy、auraSpec、boundaryPolicy。
通过ReleaseDefinition可选domain能力读取，未声明的攻击/场地保持原行为。
公开内容注册口须能登记该定义，不能只有内置术式可调用。

### 4.2 DomainInstance与DomainService

实例字段：instanceId、ownerId、dimension、固定geometry、revision、startedAt、expiresAt、nextUpkeepAt、active。
同时持有ContactEnchantState句柄和原生脉冲计时；供给不复制成玩家永久状态。
Service负责同波计划预检/提交、维护、实例查询、完整快照、幂等关闭。
重放创建新实例，不免费刷新旧域；每个实际域均独立收费及维护。
关闭一次性停止contact、native、boundary、aura资格并同步移除。

### 4.3 DomainGeometry

至少提供bounds、fullyContains(AABB)、intersects(AABB)、完整进入区间与出口裁切。
native、aura、封界资格统一使用完整身体AABB包含。
外接E接触仍用真实体积相交，不把intersects也叫“已入域”。
固定世界几何由生成时保存，不随owner移动；客户端只消费同一几何快照。
未来球、柱或其它形状通过能力实现，不令所有领域都用单一radius猜范围。

### 4.4 DomainBoundaryPolicy

声明普通运动的外入内允许、内出外限制，owner/盟友豁免。
按当前身体AABB与位移求完全位于域内的参数区间，不只比较运动首末中心点。
超大身体或载具组无法完整装入时，首版不困、不参与native，明确为支持边界。
是否允许接触E仍由接触策略与体积相交判定，不受上述native豁免误伤。

### 4.5 AuraContribution与DomainAuraResolver

贡献包含领域实例/修订、解析后附加伤害和类型，不包含武器基础攻击力。
Resolver在实际命中时livequery当前合法攻击者与领域，不读取发射时缓存结果。
本人或Relations确认盟友，且完整身体AABB在域内才产生候选。
所有领域/类型总共取一个最大附加值，平局按稳定instanceId排序。
不是每元素各取一份，也不是每个owner叠一份。

### 4.6 AttackEnchantmentContext

包含唯一根攻击/归账ID、revision、攻击种类、原攻击者、是否已解析aura和贡献快照。
明确ROOT_MELEE、ROOT_ARROW、ROOT_TECHNIQUE与CONTACT、NATIVE_DOT、STATUS_DERIVED等派生种类。
contact/nativeDOT/状态派生伤害不再拿aura；不能只凭DamageType猜根攻击。
上下文从实际入口传递，避免同一攻击跨多个hook重复添加或另发hurt递归。
即使最终贡献为0也标记已解析，不能后续阶段重新抽域。

## 5. 链路、复杂度与注册

领域MAGIC/baseDamage0/isEnchantment=false/ATTACK，独立步骤与公共CD不变。
E+领域+A：第一按只生成带接触快照的域，CD加E/规则；下一次有效按键才A。
友方供给来自领域自身auraSpec，不能从该外接E自动复制。
UI标识取domain能力，复杂度10示例不等于装配占10格。

[PlayerShuData.isUnlocked](../src/main/java/com/bslx/XueXiMod/player/PlayerShuData.java)
约156行对MAGIC比较magicLevel与complexity，UNIVERSAL/MOVEMENT始终解锁。
法术等级默认0、上限20；不能用UNIVERSAL实现高复杂度门槛。
当前内置术式多为复杂度0，没有现成高阶等级先例。

规则复制的N来自实际计划展开；每个域实例有独立ID和维护任务。
同一未执行波次内的复制域共同预检，双重延迟波次各执行时重新核验和付费。
不把未来波次费用提前全部扣走，也不在当前步骤预占未释放的后续独立步骤CD。
失败后波不撤销已成功前波，也不倒退此前链游标。

## 6. 费用事务与维护

[MagicPool.trySpend](../src/main/java/com/bslx/XueXiMod/player/MagicPool.java)
约28—60行先扣当前法杖储魔，再扣玩家池。
restore约64行只还玩家池，不恢复原法杖来源；不能直接作为本次事务回滚。
拟新增ManaPaymentReceipt记录实际来源、实际金额及提交/回滚状态。
来源应记录具体法杖身份或可验证引用，不能把退款给后来换到手上的另一法杖。
预检与提交在同一服务端步骤执行，失败退款到原来源并幂等，不能越过池上限吞掉差额。

本次尚未执行的同一波次：先预检全部copy能力、固定几何、可绑定E与总魔力。
创建和E绑定全部成功才提交费用与发布。未接受首波失败无半生成、不收费、不CD、不推进。
已接受计划的延迟后波失败，整后波不生成、不收费或按收据准确退款；不撤既有CD、游标或成功前波。
部分创建异常必须清理本波临时状态，再按收据回滚，不能反复重试无限造前几域。
裸领域费为40×N，三份示例120；默认100池且无额外储魔明确拒绝，不缩水成两份或一份。
外接E及规则若定义有魔力费，沿既有统一计划口径计入一次；不得再叠fieldSpawnExtra重复收领域生成费。
精确定义：本波总预检额＝统一计划算出的本波E/规则等非领域生成成本（按现定义和既有次数规则计一次）＋40×本波真实领域数。
领域生成费替换原该宿主生成项，禁止叠fieldSpawnExtra或重复generic host cost。
40×3=120仅为裸领域示例；外接项若有费用，总额更高，不假定所有E/规则当前都收费。
ManaPaymentReceipt覆盖整波实际扣款；每域每20tick维护8独立于首付，不包含在生成费中。
实例开始后按自己的nextUpkeepAt扣维护，失败立即关闭。
到期或维护失败不按未消费时间退款；不消耗水势维持，不扣术式石。
到期优先于维护与脉冲：200tick到期当拍直接终结，不扣末次维护费、不再发native脉冲。
费用显示、计划预检、真实扣取统一resolver，不允许UI显示旧6而实际扣40。

默认魔力100，普通回复每20tick5，法杖效率可修改；维护8是有净支出的试调例。
高复杂度不自动增加魔力池，不保证所有玩家默认能无限维持多个域。

## 7. 普通运动六面封界

native、aura和“已入域”统一完整身体AABB，不以中心或部分接触判断。
partial进入者允许退回；生成时身体已完整位于内部的敌人立即具有封界资格。
运行中关系改变实时查询，获得许可后不继续困住，失去许可后按当前完整包含判定。
六面含顶部和底部；普通跳跃、击退、跌落亦经同一运动约束。

```text
约束普通运动(bodyAABB, displacement)：
  取rootVehicle与全部乘客union AABB及许可集合
  全组许可 → 不加领域约束
  对每个候选域求完全包含的运动参数区间
  从外到部分接触后退 → 不困
  外→完整进入→同tick外出 → 截至内部出口前
  已完整在内部 → 不能越过任意六面
  联合所有领域与方块约束，求共同合法候选位置
  原版踏步/方块碰撞之后最终候选再校验，不逐域setPos推拉
```

载具组只有root及所有乘客均获许可才豁免，几何使用union AABB。
各乘客不能单独拉回导致脱乘或抖动；无法完整容纳的组首版不困、不native。
传送清除旧运动约束历史，不跨传送路径扫入域，也不把人强行拉回。
死亡、跨维度不封锁，noPhysics/旁观/第三方自定义位移需列明确支持边界。
AI不另改视线或寻路，可能持续尝试走向边界，需测试性能而非擅加AI系统。

双端移动shape/候选裁切接点必须核验当前Forge1.20.1版本。
已有水幕证明墙自身canCollideWith不能控制移动者选择性碰撞，不可照抄方法名。
如需Mixin或最小补丁，先锁定实际方法与依赖，不捏造Forge万能运动事件。

## 8. 命中时友方供给与三个接点

首版供给只有附加伤害，无基础E状态、范围、速度、冷却或武器本体倍率。
雾雨可用基础潮印中性反应的公共magicDamage作为自身供给，当前预计2，以解析实值为准。
不写主手NBT、不建立永久属性；离开领域后下一次命中不再获得贡献。
箭以命中时当前合法owner在域内判断，发射时在域内不足以保留加成。
伤害归原攻击者，不转给领域owner；水势继续走既有真实伤害事件，不再手动奖励一次。

必须有三个明确接点：

1. 普通玩家近战：原版根hurt调用前合并base+contribution。
2. 原版箭实际onHit：确定当前攻击者和真实目标后、hurt前合并。
3. 模组攻击术式：直接命中hurt或ReleaseBatch最终归账hurt前合并。

仅LivingHurtEvent再加金额可能太晚，原版无敌帧已按此前输入比较。
需要原版注入时列为版本验证任务，不声称已有万能事件能保证普通近战与箭入口。
所有接点使用同一AttackEnchantmentContext和resolver，禁止双入口各加一次。

```text
根归账前(baseAmount, attacker, target, context)：
  派生contact/nativeDOT/status → 不取aura
  context已解析 → 复用本次结果，禁止再次livequery
  livequery攻击者当前完整身体所在有效领域，关系动态查询
  所有候选贡献取一个最大值，平局稳定instanceId
  amount = baseAmount + contribution
  同一次正常hurt(amount)，不另发额外hurt
```

三份汇总一本账一次hurt，只加一次贡献，不是每份都加再汇总。
若三份本体归账合计S、供给B，本次根输入是S+B，不能变成三份各加B。
晚到copy另开独立归账窗口时重新查询攻击者当前领域，再加一次该窗贡献。
攻击上下文不能跨不同归账窗口永久复用；同窗又不能重复解析。
第三方箭/攻击术式/间接爆炸需逐类适配；未适配者不承诺有供给。

跨系统例：箭原伤D与领域供给B在根hurt前一次合算为D+B。
该箭已穿水幕且目标仅有水环这一项后续防御时，按既有阶段先0.5再0.8，事件金额为0.4×(D+B)。
不能另发一笔供给伤绕过水幕或水环；这也不是所有护甲/吸收/模组组合的最终掉血保证。
若现有专用DamageSource会改变防御识别或伤害阶段，列为集成验证，不默认为已兼容。

## 9. 原生脉冲、重叠与接触

每域独立安排原生脉冲，但收益和施湿采用跨实例的目标级统一门控。
雾雨示例：同种wet效果同目标10tick最多+2，跨owner、域、刷新、新建或离开重入不重置。
同玩家水势20tick最多+2，100封顶；不是每域各发2，不做离开再进立即领奖。
水势原生收益只给拥有现有玩家水势池的玩家，不为生物或宠物新增资源池。
首次生成后10/20tick才到对应首拍，不能在创建时额外赠送一拍。
多个域仍各自收费维护；限流不能以省费为由合并实例。
周期水势直接credit，不伪造受伤或攻击，也不拿新水势替代魔力维护。

外接E沿每host自己的ContactEnchantState和正常无敌帧尝试。
不把native湿度/水势限流表用于清掉E，也不合并不同host为一笔绕过无敌帧。
领域特殊效果、友方伤害供给和外接E效果互不重复施加。
纯效果contact首版按既有文档明确拒绝；不得静默接受收费后丢效果。

先保留旧攻击默认行为，再逐能力启用新域；不顺手重做全部等级或附魔系统。
