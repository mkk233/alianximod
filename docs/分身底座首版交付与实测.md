## 已接入的基础能力

幻影与普通分身共用实体、主人索引、请求、响应事务和生命周期。幻影最多成功提交一次响应；普通分身冷却后可继续响应。提交前被拒绝不消耗次数、不收费；提交后即便伤害被免疫或取消，也消费本次响应及费用。

当前动作是从分身眼睛发出的单目标基础脉冲。可由命令主动触发，也可在敌人非致死伤害被接受后于下一 tick 尝试反击。致死伤害直接结束，不做临终反击。分身响应不会继续触发其他分身响应。

诱敌仅覆盖受限的原版僵尸、骷髅类目标，对方没有目标或正在追主人时才可引向分身。不会强抢正在追其他玩家的目标。扫描节拍、候选数量和目标租约都有上限。

资源由主人支付。出生和响应使用现有魔力收据，保留原池或原法杖的退款来源。伤害遵守既有权限检查和原版无敌帧，不接入旧一分为三汇总、火种、潮印或主手附魔消耗。

## 开发入口

需要命令权限等级 2、在线玩家身份以及足够魔力。只操作本人分身。使用 UUID 以 `/shu clone list` 的实际回执为准。

```text
/shu clone spawn phantom
/shu clone spawn normal
/shu clone list
/shu clone respond <UUID>
/shu clone dismiss <UUID>
/shu clone dismiss all
```

生成时留在当前地点。主动响应采用请求时冻结的主人视线方向，但射线原点是分身眼睛。响应回执不等同于保证造成伤害。

三个真实术式 ID 为 `clone_phantom`、`clone_body`、`clone_response_pulse`。它们带开发入口限制，不加入普通玩家学习、刻印、获取或装配；旧术式默认保持玩家可用。整链误塞开发术式应在费用与释放状态变化之前拒绝。

## 默认参数与配置

生成费用 10，生成冷却 20 tick；响应费用 2、响应冷却 20 tick、基础伤害 2、射程 8 格。分身默认生命 20、诱敌半径 8 格、自然寿命 0。

寿命 0 的含义是本次已加载会话内无自然到期。登出、死亡、换维、实体区块卸载、世界卸载或停服都会清理。首版不跨存档恢复，不强制加载区块。

两个生成术式的专项字段为 `lifetimeTicks`、`maxHealth`、`decoyRadius`；脉冲专项字段为 `fixedDamage`、`range`。费用、冷却、伤害倍率沿用现有标准配置声明和服务端读取链，配置修改按现行机制在下次开世界生效。数值边界和最小声明示例以详细设计第 10 节及项目配置平衡指南为准。

结构上限固定为每人 4 具、全服 128 具、每具 1 条待执行请求、全服每 tick 最多提交 32 次响应。硬上限不冒充术式平衡参数。

## 用户实测顺序

1. 分别生成两种分身，移开主人；确认原地驻留及类型显示。使用 `list` 取得 UUID。
2. 令目标位于分身视线内，主动响应。确认射线从分身位置判定，墙体能阻挡，提交前无合法目标时不扣费。
3. 幻影一次有效提交后结束；普通分身在冷却后再次有效响应。随后故意制造一次无目标或魔力不足，再恢复条件，确认普通分身仍能继续使用。这一步覆盖本轮修复。
4. 敌人非致死攻击应触发一次下一 tick 的反击尝试，普通分身不会因此自动消失；致死伤害不反击。主人、友方和其他分身响应不形成反击循环。
5. 测试有限诱敌、撤回、每人数量上限、登出、死亡、换维、区块卸载和同 JVM 重开世界。
6. 修改配置后重开世界，分别验证费用、生命、寿命、范围、伤害和倍率。单改伤害不应改变费用。伤害为 0 仍消费已提交的响应。
7. 回归普通旧术式的学习、装配和释放，以及旧幻剑。完整清单见详细设计第 15 节。

以上均未在游戏中执行。静态复核或编译不能替代原版 AI 目标保持、实体跟踪、区块事件及实际画面验证。
