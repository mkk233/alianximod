# 双重释放调整意见与实现指导

日期：2026-10-23。状态：设计已收束，待实施。
本次只新增本文；未修改源码，未编译，未操作游戏，验收均未执行。
本文为后续实现指南，不是功能完成记录。
此前测试组合中关于双重带三个宿主、间隔10tick、从按键时开始CD的说明，由本文新规则覆盖。

## 1. 用户确认的行为

### 1.1 普通双重

- 双重释放只取紧跟的两个终结成员A、B，不吞第三个C。
- A、B之间间隔5tick，不等待A或B各自的基础冷却。
- B实际放出后，才启动双重+A+B的总冷却。
- 持续攻击的完成口径建议为攻击体创建成功，不等整段攻击寿命结束。
- A默认在接受计划时立即执行，是本版实施建议。

### 1.2 动作触发双重

示例：冲刺 → 双重释放 → 横劈 → 竖劈。
冲刺沿实际运动路径碰到目标时，在该次实际接触位置开一组：横劈即时，竖劈在5tick后。
同次冲刺可以撞到多个目标，每个目标分别产生自己的A/B组。
整次动作的总CD只加冲刺、双重、横劈、竖劈四项一次，不按碰撞次数重复加。
全程没有任何碰撞，只算冲刺自己的CD。

用户没有在本轮逐条确认费用、游标、关系许可、目标去重及失败处置；以下相应条款是本版建议。
不要把“只算冲刺CD”推导为免费释放整套组合。

## 2. 本版推荐的统一口径

### 2.1 成员与附属项

A/B是终结成员，可以是攻击、合法零伤宿主或独立附魔。
索敌、弹道、复制、聚能等附属规则不额外占一个终结成员名额。
前置基础附魔绑定其紧邻的合法宿主，不额外占A/B名额；尾部独立附魔作为终结成员。
只取A/B时，C及其前置附属项留给下一次步骤，不预执行、不预付其费用、不预占其CD。
同一份编译计划必须同时供选段、释放、费用、CD和游标使用。
禁止一套代码选两段、另一套代码仍按旧规则算三段。

### 2.2 动作窗口与目标

建议每次父施法对同一个合法LivingEntity只开一组，按UUID去重。
同目标贴身停留、离开后重新进入本次冲刺路径，都不再开组。
排除本人、术式实体及关系规则不允许触发的对象；不要仅以“不是本人”代替关系判定。
关系查询复用现有Relations能力，默认owner-only契约不能被顺手扩成完整盟友系统。
无合法敌向目标时不得伪造碰撞组；关系变化在接收组时确认并保存结果。
碰撞后的A/B各自命中其他对象，仍遵守各攻击体已有目标过滤。

### 2.3 释放完成与冷却

父会话经过ACTIVE_ACTION → DRAINING → COOLDOWN。
动作窗口结束后停止接收新组，但已接收的B仍继续排程。
以“动作窗口已结束”和“所有接收组已终结”两者较晚时刻启动一次CD。
组终结包括成功提交、明确失败或取消，不能让失败的B永久卡锁。
普通双重同样等待B的实际执行结果，不能以scheduler入队或runner返回当成放出。
持续攻击体创建成功即提交；不等待其40tick等存续时间结束。
若攻击体无法生成、魔力预留失败或执行失效，应返回明确拒绝结果。
首版兼容建议：横劈、竖劈等无需额外蓄力的宿主，保证A实际提交后5tick提交B。
有独立蓄力或异步前摇、尚无准备—提交协议的宿主，必须在开始动作和扣费前明确拒绝组合，不扣费、不推进。
不能静默延迟B，也不能arm跳蓄力；这属于本版兼容前提，不是用户要求限制术式种类。
零伤领域、水环、水墙若可即时创建，正常作为A/B，不得因baseDamage=0拒绝。
未来可扩展预先准备后按5tick提交，但须另定义准备成本、有效期与多碰撞复用，现runner不具备该协议。

### 2.4 游标与失败建议

父会话接受时锁住当前载体/槽的链，不立即推进游标。
父会话只终结一次；在最终结算处只推进一次、启动CD一次、发送终结同步一次。
建议空挥仍消费整个动作步骤，推进到后续C，不留下下次裸放的悬空双重。
这个空挥游标策略是实施建议，不是用户已确认规则。
合法碰撞但魔力不足记为triggerFailure，不记成miss。
建议只要发生合法碰撞，就结算完整组合CD一次，即使该组因缺魔未放出。
不要用资金不足恢复为“无碰撞”，借此获得只有冲刺CD的结果。
死亡、离线、跨维及显式取消的游标/CD处置须集中在父会话终结分支，保持一次性。
取消后不执行pending成员，不通过重新登录或旧任务回调复活会话。

## 4. 拟新增/扩展接口职责

以下是建议接口，尚不存在，不得当成已实现API引用。

- 拟新增network/CompiledReleaseStep：统一持有动作、规则、A/B、附属E、后续游标和CD项目。
- 拟新增network/CastExecutionSession：父会话ID、owner、载体身份/槽、epoch、维度、状态、pending组及终结标记。
- 拟新增network/ActionContact：targetUUID、contactTick、actualContactPoint、direction、groupId不可变快照。
- 拟新增network/ReleaseOutcome：COMMITTED、REJECTED、CANCELLED及实际提交tick、失败原因。
- 拟扩展runner执行契约：接收显式上下文与单次终结回调，不再只返回Runnable。
- 拟扩展动作能力契约：报告合法接触及窗口结束，不由调用者猜固定结束tick。
- 拟扩展预算接口：整组原子预留、分成员提交、未消费余额按来源退款。

建议位置可调整，但职责和一次性约束必须保留。
动作与规则通过ChainRole及能力注册组合，不能按movement_dash或rule_dual_release的ID接特例。
至少覆盖DUAL、TRIPLE、当前聚能的既有语义；现8个ChainRole不新增。
未跟规则的普通动作、普通A+B仍沿合法原路径，不强制变成动作触发计划。
本次碰撞模式明确针对ACTION→规则块；RULE→ACTION→其他宿主须保留与此前缀不同的既有含义，通过统一编译能力处理，不能把所有含ACTION的链改成碰撞模式。

## 5. 接触几何与子组快照

每tick保存旧身体AABB与实际位移，先做包围盒粗筛，再执行扫掠窄阶段。
窄阶段求身体沿实际位移首次接触目标的时间参数，不用输入速度代替已发生位移。
按接触时间排序，平局使用稳定实体身份，保证多人同帧触发可复现。
不要用宽大的斜线包围盒把路径两侧没碰到的目标算入。
瞬移、换维等不属于本次冲刺的连续扫掠段，取消或重置采样，不能横跨全图扫人。
接触锚点和方向在接收子组时冻结，A/B均从该快照生成。
B不随玩家继续冲刺、转头、目标走动而漂移。
A杀死了触发目标也不取消B；B仍在原快照处放出，并按正常攻击体规则寻找可命中对象。
owner死亡、离线、跨维、显式取消才使pending组失效。

每目标group创建独立batch；A/B各开自己的Tally。
一分为三的份数只在本成员内汇总，不能把十字斩A+B当成同一攻击的copies。
不同目标组也不能共享同一Tally，避免互相吞伤或扩大命中份数。
异步回调显式传递batch，不依赖已解绑的ReleaseBatch.current。
不为5tick节奏额外清无敌帧；保留各术式现有策略。
当前普通TechniqueHits可能绕帧，不应写成“所有攻击均原版无敌帧”。
零伤宿主Contact附魔继续RESPECT策略，不借此任务改变其规则。

## 6. 费用与失败：本版实施建议

动作起手费用只付一次。
每组在A执行前，按公共子规则计划原子预留整组费用，预留时可用余额真实减少。
包含规则、E、A/B及实际复制份成本；规则当前可能为0，但不能硬编码永远免费。
生成屏障/领域时继续使用其真实实例费用，禁止又叠一次generic宿主生成费。
同组A/B共享一份预算，不同组不能抢用同一笔已经预留的余额。
A实际成功后提交A对应份额；B成功后提交B份额。
B拒绝、取消或父会话终止，只退还未消费份额，不能撤销已经发生的A。
退款必须按ManaPaymentReceipt记录的法杖/玩家来源处理，不能统一restore到玩家池。
预留失败不生成半组、不免费放A、不把合法碰撞改成miss。
预约与提交要有幂等身份，重复回调不得重复扣费、退款或推进。
如普通双重首波接受失败，保持原“未接受不推进”的规则；接受后的异步失败由父会话收束。
本次不扩展魔力经济、复杂度或领域收费玩法。

## 7. 状态与伪代码

```text
acceptCompiledStep(plan):
  validate carrier, slot, eligibility, epoch, dimension
  acquire execution lock for this carrier/slot
  create parent session; do not advance cursor
  pay/reserve action cost once
  if payment/start fails before acceptance: refund unused receipt, release lock, reject without CD/advance
  start action(contact callback, actionEnded callback)

onLegalContact(contact):
  if parent not ACTIVE_ACTION or targetUUID in session.processedTargets: return
  add targetUUID to session.processedTargets BEFORE reserve or any synchronous callback
  freeze contact snapshot; mark legalCollision=true
  allocate groupId; add group to pending BEFORE invoking any runner
  reserve entire group budget atomically
  if reserve fails: finish group as triggerFailure; return
  run A with frozen geometry and terminal callback
  on A REJECTED/CANCELLED: do not schedule B; refund all unused group reserve; once onGroupTerminal(group)
  after A commits: schedule B at A.actualCommitTick+5 with same snapshot
  before B: validate parent epoch/dimension/lifecycle
  B terminal callback commits successful share or refunds unused share; once onGroupTerminal(group)

onActionEnded():
  parent.actionEnded=true; parent.state=DRAINING
  tryFinishParent()

onParentCancel():
  unregister/stop contact source FIRST; actionEnded=true; state=DRAINING
  cancel each pending group once, refund unused shares, call once onGroupTerminal
  tryFinishParent() even if no action-ended callback will ever arrive

onGroupTerminal(group):
  once-only guard; settle unused source receipt; decrement pending
  tryFinishParent()

tryFinishParent():
  if !actionEnded or pending != 0 or terminalAlready: return
  claim once-only terminal identity; terminalAlready=true BEFORE mark/advance/sync
  now=actual terminal tick
  cd = legalCollision ? fullActionRuleABCooldown : actionOnlyCooldown
  mark official cooldown at now+scaled(cd)
  advance compiled step once; release execution lock; sync once
```

同步执行回调也可能在run调用栈中触发，必须先加pending再调用，防止父会话提前终结。
普通双重可复用相同结果与终结机制，但无动作接收窗口，只有一组A/B。
父取消先停止接触来源并将actionEnded置true、状态置DRAINING，再逐组幂等终结和退未消费预算，统一调用tryFinishParent，不依赖后续动作结束回调。
该已接受会话无合法碰撞时用动作CD、有合法碰撞时用完整CD，按本版建议只结算一次；旧回调只能无操作返回。
缺费目标仍记合法碰撞且已加入处理集，本版不启用同一动作内对该目标重试。
正式CD计算与执行锁是两个状态；不要靠塞一个巨大readyTick再不断修补代替会话。

## 8. 明确时间线

无缩减：冲刺30+双重20+横劈20+竖劈25=95tick。
动作窗口约10tick，仅作为例子，真实结束以动作完成通知为准，不硬编码inclusive边界。

| 情形 | A/B执行 | 正式CD |
| --- | --- | --- |
| t2、t8各撞一个目标 | A2/B7，A8/B13 | 窗口已结束且B13提交，t13→108 |
| t2、t4各撞一个目标 | A2/A4/B7/B9 | 等动作窗口实际结束后启动95tick |
| 全程无碰撞，窗口t10结束 | 不产生A/B | t10→40，只有冲刺30tick |
| 合法接触但缺魔 | 记录triggerFailure，不生成该组 | 建议窗口结束后完整95tick一次 |

多个组可以交错，不能排成全局单队列，把第二组A或第一组B挪到其他组之后。
法杖普通双重例：双重20+飞弹20+金针20，缩减10%后总54tick。
A默认t0，B若t5成功提交，则正式CD为t5→59；C留给下一次。
首版若A/B有不兼容的真实蓄力，开始动作/扣费前拒绝；不允许把B拖后而仍称满足5tick。

## 9. 分阶段实施顺序

1. 统一CompiledReleaseStep与成员选择；普通双重只A/B、间隔5tick，费用/CD同计划。
2. 改造runner结果回调，覆盖独立E、攻击体、零伤宿主和蓄力异步成功/失败。
3. 接入父会话与执行锁，移走入口提前mark/advance；保留普通A+B独立步骤。
4. 改动作步骤编译和碰撞窄阶段，加入冻结快照及动作结束通知。
5. 接入每组预算预留、分份提交和来源退款。
6. 统一取消、死亡、离线、跨维、停服清理及陈旧回调处理。
