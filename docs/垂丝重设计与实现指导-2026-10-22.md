## 一、这一版垂丝是什么

一发是一条连续垂落的水丝，多发在空间中自然铺成瀑布。
保留法术攻击身份，不把它做成长驻场地、水墙或新的资源系统。
主轮廓由固定上沿、持续流动的帘身、落水点构成。
水流看起来在经过固定空间，不能只画一个移动弹头的历史拖尾。

玩家前方生成出水上沿，水丝向下逐渐展开。
展开到哪里的水体，就在哪里具有攻击几何；未展开处没有隐形伤害柱。
地形挡住水流时就地截短，底部在真实接触点出水花。
没有地面时，到最大长度末端散开，不向下无限延伸。
本稿不把水花或散开的装饰水滴变成额外攻击份。

同批多发优先横向排布，共享大致帘面，允许轻微高差和起流错峰。
相邻条带可以在视觉上衔接，但各自的寿命、攻击份和命中账独立。
后来补放的水丝不能给旧水丝续命，也不能让已结束的旧攻击重新生效。
独立释放可以形成层次；不要自动把不同时刻、不同玩家的释放并成一个玩法组。

## 三、通用模块划分：以下名称均为拟新增建议

不要在公共入口写 `if (id == water_weeping_arc)` 来接每项规则。
在释放定义中声明能力，由统一生成、几何与命中流程消费。
先接垂丝这一种载体，并给现有点/体积攻击提供默认兼容行为。
不用一次把所有攻击、光束和场地都迁到新结构。

### AttackGeometry：攻击形状

拟新增概念：声明线段、带、面等几何，不负责资源扣除和伤害。
建议最小字段：
- shapeKind：SEGMENT / STRIP / SURFACE等明确类型。
- anchor、forward、right：生成时固定的局部坐标系。
- maxFallLength、baseWidth、baseThickness：长度与横截面分别声明。
- geometrySampler：按年龄与生命周期返回当前实际水体区间。
- collisionPolicy：地形裁切、粗筛与窄判的策略引用。
- scalePolicy：例如现有全维缩放与本次横截面缩放。

一个有效攻击份只有一个逻辑实体。
几何采样的多个小段、渲染细纹和底部水花不增加有效份数。
必须设置采样上限；采样精度随曲率和长度选择，不随粒子数量选择。

### GeometryLifecycle：时间与占用区间

拟新增概念：描述随时间实际存在的几何范围。
推荐约40tick：0—8起流，8—32供水，32—40排空。
这些是试调阶段边界，允许配置，但服务器只有一个权威年龄。

- 起流：水头由上向下推进，水尾仍接上沿。
- 供水：从上沿至当前裁切末端保持连续水体。
- 排空：上沿停止供水，尾界向下推进，底部最后散开。
- 结束：活跃区间为空，不再参与命中，只允许待付账完成。

不能只降低alpha却保留整柱碰撞。
无水的上端、尚未到达的下端和已排空的区间都不能伤害。

### GeometrySample：碰撞与画面共用的结果

拟新增建议字段：
- ageTick / geometryVersion：识别此拍几何状态。
- activeSegments或activeStrips：当前存在的有限线段/带片。
- broadPhaseBounds：覆盖活跃几何的紧致AABB。
- width / thickness：已按唯一缩放策略处理的横截面。
- clippedEnd、surfaceNormal、hasImpact：落地水花的只读提示。
- visualPhase：起流、供水、排空、结束。

粗筛用AABB找候选，窄判必须针对线段厚度或带片与目标体积。
不能用整个AABB直接作为最终命中，否则弯曲水丝空隙也能伤人。
渲染必须消费同一参数化几何和同一裁切结果，不能自己积累历史点当作命中水体。
服务器裁切为权威；客户端可插值，不能自行决定被墙隔开的伤害区域。
当前ClientTrack只提供位置追踪，不能据此假定形状或阶段年龄已经同步。
形状参数、权威年龄/阶段及必要裁切状态需另建同步协议，并覆盖中途进入视野。

## 四、空间布局与地形

### 单份生成

默认从玩家前上方形成固定上沿，避免在眼睛位置铺一整片高亮水体。
当前CastFrame.origin默认实际为null，WaterCurveEffect未设start时实体兜底眼睛。
新默认水口仅在overrideGeometry=false时由眼睛位置加水平前向偏移计算。
已有override时保留frame.origin/volumePoint，不能再次前移；entityLock不能把水口搬到目标。
生成距离与高度作为定义参数试调，不在本文虚构已经批准的精确数值。
最大垂落长度约5—6格，上沿至落点沿当前形状连续展开。
垂落可有轻微弧度，但不回到“一个小球沿弧线前飞”的表达。

### 同组多份

默认布局固定组锚点和横向基向量，按有效份索引分配条带；已有空间覆盖时保留既定位置。
横排优先，轻微高差和起流错峰仅改善轮廓。
错峰不能重新分配copy身份，不能绕过整组水势快照。
每份有自己的实际生成时刻和约40tick生命周期；组结束时间由最后一份决定。
组内视觉衔接不合并命中集合，也不共享续命计时。

### 地形裁切

- [ ] 生成时对预期下落路径做地形查询，不能从墙后先命中再裁切。
- [ ] 每个服务端tick检查当前活跃几何，新放方块应截断水体。
- [ ] 方块移除后按剩余生命周期重新采样，不重置年龄和已命中集合。
- [ ] 地形裁切不能只检测实体中心的位移射线，整条带都需要覆盖。
- [ ] 阶梯、斜面、低顶、墙边分别验证，底部水花贴真实接触面。
- [ ] 无地面时在长度上限散开，不生成永久落点实体。

## 五、聚能、索敌、规则如何接入

推荐将垂丝登记为trajectoryMutable=false，继续使用既有ATTACK角色。
不新增ChainRole，保留8类角色与索敌→弹道→规则→攻击的公共结算次序。
垂落、三维交错按固定几何攻击的公共规则只处理生成位置，不把水帘改成横飞或追踪弹丸。
同组横排仅为默认布局；已有空间覆盖时保留既定位置，不用横排再次改写落点。

## 六、资源：先确定组，再原子预留

### 有效份的定义

有效份是服务器真正安排生成、具备独立一生一次命中资格的攻击份。
最终数量N应在一分为三、波次、实体生成倍率等实际展开后确定。
一次客户端请求、一个视觉条纹、一个曲线采样点都不等于一个有效份。
同一组必须有唯一组ID、固定份ID列表和不可变普通/重水模式。

若规则展开形成多波，先明确它们是否属于同一预算组，再提交实现。
不能让前一波打出的水势资助已声明属于同组的后一波。
避免在spawn里临时追加实体，却没有纳入20×N预算。

### WaterMomentum原子协议（拟补强）

现有reserve仅登记Hold，commit才扣水势，尚不能阻止重复占用同一余额。
必须先补强，再把它作为重水的可靠基础。
建议句柄字段：owner、amount、state、groupId及所属会话标识。
state明确为RESERVED、COMMITTED、RELEASED，转换幂等。

- [ ] 可用水势=当前余额减尚未提交的排他预留。
- [ ] 同owner并发/同tick多组预留串行验证，不能超卖。
- [ ] commit验证owner、会话与状态，只能RESERVED→COMMITTED一次。
- [ ] release只能释放尚未提交预留，重复调用不增加余额。
- [ ] 死亡、下线、换维度及取消负责关闭未提交句柄。
- [ ] 账本清理不把已提交支出退回。

这里的“原子”指服务端状态变更的一致性，不承诺磁盘崩溃事务。
即使当前没有可见蓄力取消阶段，也必须使用原子API，不能假设永远不会重入。

### 整组普通/重水选择

1. 解析链、最终有效份列表、魔力花费与20×N水势预算。
2. 魔力不足，拒绝整组；不扣水势、不生成任何份。
3. 水势不足，整组普通模式，不消费任何水势。
4. 水势足额，整组重水模式，建立排他预留。
5. 固定组模式与预算快照，后续收入不改变本组。
6. 首个有效份成功生成时，提交整组水势支出。
7. 首份生成前取消，释放未提交预留。
8. 首份生成后取消或后续份失败，不退已提交水势。

魔力检查、扣费和水势预留之间需要统一失败回滚策略，避免只扣一种资源。
“首份成功生成”须有生成结果反馈，不能只以调用spawn作为成功。
实现前写清魔力既有预付语义，保留已批准规则，不能借此重复扣费。

## 七、命中与响应边界

### 一生一次，不是持续周期伤害

每有效份的 `hitInterval=0`，保持整个生命周期的目标接受集合。
目标后来走进当前水体可以被该份命中。
离开后再进入不能再次受该份伤害。
不同份可以各命中一次；同份多个几何片段同拍重叠目标只接受一次。
几何展开、地形重算、起流错峰和渲染重建都不能清空接受集合。
现有周期光束继续使用自身hitInterval和轮次，不改成垂丝模式。

### 现有顺序不能直接承载新重水条件

[TechniqueHitSettle.java](../src/main/java/com/bslx/XueXiMod/shu/technique/release/entity/TechniqueHitSettle.java) `tryHit`约33行：
当前先写hitOnce/lastHitTick，再 `HitPayloads.apply`，然后settle或回调。
[HitPayloads.java](../src/main/java/com/bslx/XueXiMod/shu/technique/release/payload/HitPayloads.java) `apply`约33—45行会先施加潮湿。
当前settle又会在伤害前处理已有控制，再记录Tally或直接hurt。
不能把“命中前湿度≥26”写成payload之后读取，也不能把Tally.record当伤害成功。

### 推荐新顺序（接口均为拟新增）

1. 验证caster、目标、当前活跃几何与地形，完成窄判。
2. 根据份ID+目标ID检查并登记本份一生一次接受资格。
3. 首次有效接触创建(releaseGroup,target)的preWet快照；后续份读取该共享快照。
4. 创建PreHitResponse，引用组快照、重水模式、份身份及控制描述。
5. 按既有策略施加普通payload，例如本次潮湿+6。
6. 直接伤害或Tally归账；保留响应上下文等待实际伤害结果。
7. 实际伤害成功后，重新检查目标活性、地面/空中、现有效果及ControlGate，再提交控制。
8. 本次实际伤害赚取水势走现有事件，不回写组模式。

本份“接受”与“造成伤害成功”须分开命名。
同份伤害被拒绝时是否仍消耗一生一次机会，沿现有接受语义保持一致并写测试。
不要为重试伤害而每拍重新攻击，绕过无敌帧或产生重复payload。

## 八、重水控制与成功伤害反馈

只有本组为重水，且本组首次有效接触前目标潮湿≥26，才具备控制资格。
本组首份把潮湿从20加到26，不能让本组后续份因此获得资格。
每个(releaseGroup,target)在首次有效接触时锁定一次preWet，组内所有后来份共享。
先通过目标过滤、几何窄判和本份一次命中检查，再在任何潮湿payload前创建组快照。
本组的潮湿+6不能自激跨过26门槛；后续独立释放可以使用已经增加的潮湿。
取舍明确：首份不足26，即使外部后来加湿，本组仍无资格；首份达到26，即使后来去湿，本组资格仍保留。
实际成功伤害仍是控制必要条件；flush使用已锁资格，不重新读取潮湿。
组快照不随6tick窗口清理，保留到全部攻击份结束且待结算处理完。
控制仍需该份归账实际造成约定的成功伤害，不能只碰到目标就控制。

### 成功结果接口

[TechniqueHits.java](../src/main/java/com/bslx/XueXiMod/shu/technique/release/TechniqueHits.java) `hurt`约18行已有boolean返回。
现有调用方并未完整把成功结果传回每份响应描述，Tally也延迟执行伤害。
拟新增HitOutcome需把结算成功、目标、组/份和待控制上下文连接起来。
不要为每份控制额外调用一次hurt，导致三份伤害被拆开。

Tally窗口内多份合并一次伤害时，应明确哪些有效贡献取得成功通知。
同一实际结算成功，可向该窗口有效贡献反馈结果，但目标级ControlGate最多放行一次。
结算失败则不消耗控制间隔，不施加下压或缓步。
如果仅用boolean认定成功，明确它和实际伤害量的差别，不能凭record金额赚水势。

组快照只冻结湿度资格，不冻结最终控制动作。
grounded可用于接触诊断，但不能直接决定延迟结算后的动作；成功后重新判断落地状态。
不得复用现有settleControlTicks的amplifier 4作为本稿amplifier 0缓步。

### 目标级ControlGate（拟新增）

key是“重水垂流这一类控制+目标UUID”，跨施法者和副本共享。
这不是全游戏通用控制免疫，不阻止其它术式自己的控制。
使用服务端绝对tick，同一目标20tick最多一次。
只在确认本次将成功应用控制时更新记录。
临时表需在目标消失、世界卸载、服务器结束或过期维护时清理。

地面目标：
- [ ] MOVEMENT_SLOWDOWN amplifier 0，初始约8tick。
- [ ] 已有同级或更强减速时直接跳过，不刷新、不叠加隐藏效果。
- [ ] 同级即使剩余不足8tick也不延长；只有目标没有减速时才添加约8tick缓步。
- [ ] 跳过不占用20tick控制间隔；无实际应用不能记成成功控制。

空中目标：
- [ ] 向下冲量轻量且有下落速度限幅。
- [ ] 不对已高速下落目标反复无限加速。
- [ ] 设置需要的速度同步标记，客户端不能只看到瞬移。
- [ ] 不把向下速度改成固定传送，不穿过地形。

## 九、三份归账与延迟命中

每份稳定copy身份贯穿生命周期，固定轮次0。
一分为三仍走统一Tally，不分别绕开账本直接攻击。
首个有效贡献开启约6tick汇总窗口。
同窗口其它未记份加入归账；同份重复回调永久忽略。

窗口结束后，40tick水体仍可能遇到后来进入的目标，或出现迟来的新copy。
允许未记过的新copy为同目标开启第二个增量窗口。
不清永久已接受/已归账集合，不让旧copy再进账。
不无限等到40tick结束才第一次扣血。
不把这理解为每6tick伤害一次：只有新copy贡献才开窗。

当前Tally已经具有上述晚来新副本开启增量窗口的行为，不默认新增结算策略。
验证样例：t0 copy0命中→t6结1份；t20 copy1命中→t26再结1份；copy0再次进入拒绝。
interval=0固定round0，flush清pending金额但保留(target,round,copy)历史。
热光束的PERIODIC originTick/hitInterval保持不变。
本次沿用该能力，只补组湿度快照、成功结果回调及上下文生命周期。
当前damages.put保存同窗最后金额，再乘份数；本稿维持每份同额，继续该规则。
若设计允许不同copy金额，必须累计真实贡献金额，不能用最后一份金额×数量。
不借本次更改无敌帧，也不修改普通光束的周期定义。

最后一笔结算可能晚于画面消失。
实体消失后，账本与待成功响应保留到最后窗口完成，再释放上下文。
不得在视觉结束时清掉未付账，也不得因失去实体引用而重复结算。
结算时目标已死亡/失效沿现有安全条件处理，不能复活目标或换目标补伤害。

## 十、视觉与性能实现指导

上沿用短而清晰的出水线，避免在眼睛正前方形成白色遮挡块。
主体是半透明带，边缘可辨，内部有向下流动纹理与少量高光。
轻微宽度变化表达水性，几何轮廓仍连续。
排空阶段尾界下移，不能整帘瞬间消失。
落地水花只负责提示接触位置，不生成额外碰撞或长期粒子云。

多份条带靠共享上沿、接近的帘面和底部连续水花形成瀑布。
条带之间留缝，避免遮住敌人和准星。
重水可加深颜色、增加流量感和落水力度，但不伪造更大伤害范围。
视觉细纹数量与有效份数解耦；增加细纹不能提高伤害或消耗。

- [ ] 一份一个逻辑实体，不能每滴水一个实体。
- [ ] 同组可批处理渲染，共用材质与几何缓存。
- [ ] 距离远时降低细纹和水花，保留上沿/帘身/落点轮廓。
- [ ] 粒子预算按组限制，主要出现在起流、落地、结束。
- [ ] 避免每帧网络同步全部采样点；优先同步有限参数与必要裁切摘要。
- [ ] 客户端插值不能延长服务端已结束的攻击区间。
- [ ] 透明排序、近距离穿帘、背面观察、第三人称均需验收。
- [ ] 缓存随实体/组结束或断连清理，不按不断增长的历史轨迹保存。
