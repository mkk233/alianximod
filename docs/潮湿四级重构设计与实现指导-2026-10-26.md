## 1. 档位

潮湿仍是 0 到 100。`WetnessState.tierOf`（`WetnessState.java` 15–28 行）已经按这个边界分档，超过 100 仍是 4 档，小于等于 0 是 0 档。不要另做第五档，也不要让负数或超上限溢出成别的等级。

| 档 | 潮湿 | 移速 | 额外回势 | 资格 G | 近战费 | 箭价比例 r | 呼吸倍率 |
|---|---|---|---|---|---|---|---|
| 0 | 0，以及没有实体 | 0 | 0 | 20 | 20 | 1 | 1 |
| L1 | 1–25 | 15% | 0 | 20 | 20 | 1 | 1 |
| L2 | 26–50 | 15% | 1 | 15 | 15 | 0.75 | 1 |
| L3 | 51–75 | 30% | 2 | 15 | 15 | 0.75 | 1 |
| L4 | 76–100，以及大于 100 | 30% | 2 | 10 | 10 | 0.5 | 2 |

0 档没有潮湿效果。L1 有减速，但没有额外回势，偏转也不优惠。未潮湿和 L1 的来袭仍是资格 20、近战 20、箭价 100%。

移速是固定比例，不是药水 amplifier 连乘。原版缓慢用 `(amplifier + 1) * -0.15`。潮湿若沿用现在的 amplifier `tier - 1`，L1 到 L4 会变成 15%、30%、45%、60%。实现必须写成精确的 `-0.15` 或 `-0.30`，操作 `MULTIPLY_TOTAL`，UUID 固定，并且只挂在潮湿这个效果上。效果移除时修饰去掉。不要每个 tick 再乘一次。

深海自己的缓慢仍是 amplifier 0、持续 20 tick 的原版缓慢，和潮湿修饰连乘。潮湿减 15% 再遇到深海，是 `基础 × 0.85 × 0.85`，不是合并成减 30 个百分号。不要改 `DomainPulses` 那次 `addEffect`。

L3 的「其他属性」只预留第 2 节这个只读入口。这次不在入口里加攻击、护甲或别的属性。

## 2. 冻结的只读入口

公共类型在 `src/main/java/com/bslx/XueXiMod/status/WetnessTiers.java`。名字和字段如下，不要另起一套快照类。

```java
public final class WetnessTiers {
    public record Profile(
            int tier,
            double movementReduction,
            float attackReward,
            float qualifyingFunds,
            float meleeCost,
            float arrowCostRatio,
            int breathMultiplier) {
    }

    public static Profile ofValue(int wetness) { /* 只读常数 */ }
    public static Profile of(LivingEntity entity) { /* 无副作用 */ }
}
```

`Profile` 不可变。读取不写状态、不注册效果、不改随机数。

- `ofValue` 只查上表。不需要运行期注册。小于等于 0 得到 0 档。大于 100 得到 L4，不抛错。
- `movementReduction` 用正数 0、0.15、0.30，表示减掉的比例。真正写到属性上的修饰是相反数。
- `of(null)` 以及读不到实体时返回 0 档。不要用 `isAlive()` 把已经死亡的目标挡在外面。致命一击仍要能读到死前的潮湿。
- 有实体时按 `WetnessState.read` 的当前值取档。这个读取本身不施湿，也不改持续效果。

经济侧只调用这个入口，不自己复制一张表，也不改 `WetnessState.java`。

## 3. 持续 50 秒沿用

`WetnessState.DURATION_TICKS` 已经是 1000，也就是 50 秒。每次 `grant` 成功仍刷新这一段。没有逐 tick 衰减。这次不改持续时间，不改施湿来源的数量。

已经在用的施湿入口保持原样：缺月 `wetness(6)`，垂丝命中施湿 6，`HitPayloads`，`FieldZones`，`DomainPulses.grantWet`，潮印按条数乘 5。潮印固定贡献仍是每条 +2 伤、+5 湿、施术者 +2 水势，不并进额外回势，也不被额外回势吞掉。

精确值仍在 `ForgeData/xueximod_attribute_states/wetness`。读档仍走现有 `WetnessState.reconcile`。死亡重生不复制这段数据，规则没有要求死亡后保留潮湿。

末影龙和凋灵只有本模组 `WETNESS` 走父类 `addEffect(MobEffectInstance, Entity)`，其他药水仍保持原版直接 false。

## 4. 额外回势：成功一次才计一次

额外回势读的是被打中的那个目标的 `Profile.attackReward`。L1 和 0 档是 0，L2 是 1，L3 和 L4 是 2。攻击者潮湿不决定这笔奖励。

只在实际攻击成功、并且这次伤害数额为正时记一次。普通攻击、箭、攻击术式都算，但必须能认出玩家攻击来源。下面这些不加这笔奖励：

- 事件取消、伤害被完全吸收、数额不大于 0
- 原版无敌帧挡住、因而没有成功的 `hurt`
- 窒息、溺水来源
- L4 怕水生物的环境伤害
- 坠落、燃烧，以及主人不在线时魔法剑那类没有玩家攻击来源的伤害

领域里的原生窒息本来就不产水势，这套抑制保持。不要把抑制扩成「所有溺水都不记公共水势」。额外奖励自己拒绝窒息和水敏感来源即可。

计次跟着真正打出去的那一次成功伤害，不跟着复制份数：

- 目标还活着不是条件。致命一击只要数额为正，仍算一次。不要用 `isAlive()` 滤掉。
- `ReleaseBatch.Tally` 多份收成一次 `hurt` 时，只记这一次。不要写进 `Tally.record` 或 `flush`，否则会按份数另计。
- 现有攻击会清无敌时间再打的语义不改。不改无敌帧长度。
- 潮印仍在这次 `hurt` 返回后按条数给固定 2 点。额外回势与它叠加，不从固定 2 点里扣，也不把固定 2 点再加一遍。

落点不要放进 `WaterMomentum.credit` 本体。那个方法还接着减伤、潮印和领域周期。奖励应在 `ReleaseBaseEvents.onDamage` 里、现有公共记账之后，单独调用经济写入者的辅助方法。部分卸力和其后的基础减伤仍不回势。实际打中的剩余伤害、以及偏转之后的反击，仍按原来的实际伤害记账。

## 5. 偏转门槛和箭价

偏转读攻击者，不读防守者。防守者自己的潮湿不给来弹打折。

- 近战读这次攻击者。水势够不够仍看承接这下水术式的主人，不看攻击者的水势账。
- 箭在每次真正接触时读当前 `owner`。owner 不是生物、或没有 owner，用 0 档：资格 20、近战 20、箭价 100%。这是没有优惠，不是取消偏转。偏转仍要有有效水术式真实接住。
- 同一次宿主报价里，两次 `quote`、预留和提交共用刚读到的那一份 `Profile`。报价期间潮湿再变，不改已经算好的费用。
- 不把潮湿折扣写进箭的永久标签。下一拍接触、反弹换了 owner、或 owner 的潮湿变了，都按当时的 owner 重新读。锁的是这一次事务，不是这支箭的终生价格。
- 剩余直接伤害的冻结仍是另一件事。`DeflectionMarks.REMAINING_DIRECT` 继续记伤害，不记湿度。

令箭上当前剩余直接伤害为 `D`，费用比例为 `r`，可用水势为 `M`，资格为 `G`。`M` 仍是 `WaterMomentum.available`，余额减去尚未提交的预留。

1. `M < G`：不偏转。门槛不够时，即使这笔箭的费用很小，也不卸力。
2. `M >= G` 且 `M >= D * r`：完整偏转。扣 `D * r`。箭上的直接伤害仍写 `D`，不因为打了折就变小。
3. `M >= G` 但 `M < D * r`：耗尽 `M`。余伤是 `max(0, D - M / r)`。把这个余伤永久写回剩余直接伤害。然后再算水幕 50% 和水环 20%。

水势费用不是箭伤害。不能把 `D - cost` 当成 `r` 不等于 1 时的余伤，也不能把 `D * r` 写进伤害标签。

对照：

| 输入 | 结果 | 扣除 | 箭上剩余直接伤害 |
|---|---|---|---|
| D24，M15，L2（G15，r 0.75） | 部分 | 15 | 4 |
| D24，M18，L2 | 完整 | 18 | 24 |
| D24，M14，L2 | 不偏转 | 0 | 仍是 24 |
| D24，M10，L4（G10，r 0.5） | 部分 | 10 | 4 |
| D24，M12，L4 | 完整 | 12 | 24 |

D24、M15、r 0.75 时，`M / r = 20`，余伤 `24 - 20 = 4`。不能把 `direct - cost`（会得到 9）或 `D * r`（会得到 18）写入标签。

部分卸力之后，下一个宿主用标签上的余伤当作新的 `D` 重新报价，不能用水势 `cost` 代替 `D`。这一次的比例不跟箭走。owner 没变、潮湿也没变时，下一次自然还是同一个 `r`，但 `D` 从 4 起算，不能先把 4 再乘 0.75 存回去。

完整捕获之后放出去，伤害仍是捕获时的 `D`。折扣只减少扣掉的水势。

仍要留下的旧行为：

- 只适配原版普通箭、药箭和光灵箭。三叉戟和其他未知弹种不扣偏转水势。
- 友方来弹在收购前放行，不扣款。
- 一支箭完整偏转最多 3 次。第 4 次不再给优惠偏转。部分卸力不计这 3 次。
- 归属、火焰、药水、穿透尽量留下。宿主失效时安全放出，不复制箭。
- 水幕 50%、水环 20% 仍在随后那一次实际 `hurt` 上，不回写剩余直接伤害。
- 部分卸力和这次之后的基础减伤不回势。实际受伤和反击照旧。

现在的生产入口：

- `DeflectionEconomy.quote` 四参数重载固定 `WetnessTiers.ofValue(0)`，也就是资格 20、近战 20、`r` 1。带 `Profile` 的重载只用调用方锁住的那一份。旧断言里「19 拒绝、近战刚好扣 20、比例为 1 时部分余伤等于 `D - M`」仍然成立。
- `Quote.remaining` 仍是扣费后的剩余水势，不是箭伤。`residualDirect` 在完整偏转时是 `D`，部分卸力时是 `max(0, D - M / r)`。拒绝时不拿它改箭。
- `ArrowBook.applyCommit` 的部分分支写 `residualDirect`。完整分支把传入的 `D` 写入 `REMAINING_DIRECT`。
- `DeflectionService.open` 若两次读取的可用水势不同，会再报价一次。两次报价、预留和提交共用同一份 `Profile`，中间不再读 owner。

## 6. 呼吸

需要呼吸的生物在 L4 按原版空气消耗的 2 倍扣氧。唯一入口仍是 `PressureBreath.onBreathe`。不要再订一个 `LivingBreatheEvent`。

`PressureBreath.onBreathe` 仍是唯一入口。它把深海领域倍率与 `WetnessTiers.of` 的 `breathMultiplier` 交给 `combineBreath`：取较大值后再封顶 2，原版消耗为 0 时不放大。`marksSuffocation` 不读潮湿。

接上之后：

- 先走现有 `resists`。旁观、创造无敌、水下呼吸、潮涌核心、以及对水不会溺水的生物，整次不动。原版呼吸豁免保留。
- 领域倍率是深海里现有的最大倍率。L4 的 `breathMultiplier` 是 2，其他档是 1。两边取最大，再用现有上限 2。L4 和深海同时在，仍是 2 倍，不乘成 4 倍。
- 原版这一 tick 消耗已经是 0 时保持 0。呼吸附魔本 tick 免耗，不强制再扣。
- 人在空气里并且是 L4 时，这次要 `canBreathe=false`、`canRefillAir=false`，否则人在空气中不会扣氧。只在领域或 L4 至少有一边成立时才改事件。两边都没有就保持现在的直接返回，不写空气值。
- 离开 L4 只停止加倍。不把空气写成满，也不在离档时调用 `setAirSupply`。
- `marksSuffocation` 仍只认深海领域。不要把 L4 算进这张窒息票据。深海那次溺水继续不产水势。

怕水伤害不放进这个呼吸方法，也不放进 `PressureDrownMixin`。

## 7. 飞行下降

这是初调参数，不是终值。默认只压竖直速度：

- L3：若当前 `y` 大于 `-0.08`，压到 `-0.08`。
- L4：若当前 `y` 大于 `-0.30`，压到 `-0.30`。
- 已经更负的下降保持，不要往上托。
- 0 档、L1、L2 不压。

2026-10-26 初稿按飞行种类纳入，并跳过玩家。2026-10-27 起这条资格改成：服务端、存活、三级或四级、不在黑名单、不在地面、不在骑乘、不在实际流体。玩家的飞行、滑翔和跳跃，以及没有飞行种类的空中生物，走同一套 `-0.08` / `-0.30`。`FlyingMob`、`FlyingAnimal` 和 `Probe` / `WetnessFlyer` 不再当资格门。`register` 仍留着。普通路径仍跳过恼鬼和末影龙，避免和专用钩子重复；这两条专用路径问同一个黑名单。蝙蝠挂顶的 `isResting()` 仍跳过。不改 `fallDistance`，也不改创造飞行能力开关。没接到 `travel` 或 `move` 的私有 AI 不会因此被改掉。

黑名单只免潮湿下降，不免掉湿度、减速、呼吸、怕水或水势。键是 `wetness.flightExemptEntityIds`，写在下次 Forge 加载会生成的 `config/xueximod-common.toml`：

```toml
[wetness]
flightExemptEntityIds = ["minecraft:ender_dragon"]
```

默认只有 `minecraft:ender_dragon`。空列表表示谁都不豁免，不退回默认。名字要和注册名完全一致，加载时不查注册表。合法但游戏里没有的 id 会留下，只匹配它自己。重载同一份 COMMON 规格时整表替换。

跳过仍包括：乘客、已经落地、实际处在流体里的生物。水生生物不要因为潮湿被额外下压。恼鬼和末影龙不走速度夹紧。

入口仍在这一拍 AI 之后、当次移动之前，同时盖住 `LivingEntity.travel` 和 `FlyingMob.travel`。幻翼和恶魂的 `FlyingMob.travel` 不调用父类。悦灵自己的 `travel` 也不调用父类，所以 `WetnessAllayMixin` 在 `Allay.travel` 开头调用同一个 `beforeTravel`。烈焰人、凋灵、非休息蝙蝠没有自己的 `travel`，沿 `LivingEntity.travel`。同一拍不要压两次。不要写在 `LivingTickEvent` 里。速度夹紧之后，原版还会继续加自己的移动输入，不要求这一帧的最终位移正好等于 `-0.08` 或 `-0.30`。

速度夹紧不改碰撞，不替它们调用摔伤结算，也不清空 `fallDistance`。原版摔伤规则保持：谁本来免疫仍免疫，谁本来会累计仍累计。不额外 `hurt`。地面不能被这股速度强行穿进去。

恼鬼在 `beforeTravel` 里直接返回。`WetnessVexMixin` 改的是 `Vex.move` 里那次 `Monster.move(MoverType, Vec3)` 的向量，字节码 owner 是 `Monster`，不是 `Entity`。只处理服务端、`MoverType.SELF`，并跳过黑名单、乘客和实际流体。原位移 `v` 保留。追加量是 `extraDown`：`min(v.y, 本档下限) - v.y`，已经更快时为 0。从当前碰撞箱移过 `v` 之后的终点，只用方块碰撞形状裁这段 `extraY`，结果是 `(v.x, v.y + allowed, v.z)`。不把整个目标 Y 送去碰撞。不关 `noPhysics`，不改 `onGround` 和 `fallDistance`。水平穿墙保留。

末影龙不进 `travel`。`WetnessDragonMixin` 只接 `EnderDragon.aiStep` 里服务端那两次 `EnderDragon.move(SELF, Vec3)`。字节码 owner 是 `EnderDragon` 自己。传入向量已经含贴墙时的 0.8 倍。那里只记录 `extraDown`，把原始向量原样返回。不改这次移动、位置和 `deltaMovement`。部件仍按原版位移更新，原版攻击打在这个位置上。全部部件更新之后，第一次 `checkWalls` 用参数修改钩子，不用 INVOKE 之前的普通注入。第一次 `EnderDragon.checkWalls(Lnet/minecraft/world/phys/AABB;)Z` 的 ordinal 0 参数已经是 `head.getBoundingBox()`。同名同描述符的 ordinal 1、2 才是颈和身体，钩子不改。头、颈、身体用当时的真实碰撞箱直接裁 `extraY`，不再上移造对照箱，也不先下压再往回补。允许的新增负 Y 用 `setPos` 加到龙主体和 `getSubEntities()` 的全部部件。允许量为 0 则不移动。钩子返回更新后的头碰撞箱，后两次原版调用再读已经下移的颈和身体。不改 `xo` / `yo` / `zo`，不改 `positions` 历史，不改碰撞标记。阻挡除真实方块碰撞形状外，还包括非空气、非 `DRAGON_TRANSPARENT` 的整格，没有碰撞形状的也算。当前真实箱已经和阻挡形状体积重叠时，允许量为 0，不把原来的穿墙推出去。透明体积不额外挡。只追加这段允许的下降。不用 16×8 的大箱，也不用上一拍部件箱。栖息这拍没有那两次 `move` 就不额外位移。`tickDeath` 里的 `move` 不接。每次 `aiStep` 进入时和这次消费后清掉暂存的追加量。`beginDragonStep`、`adjustDragonMove`、`correctDragonDescent` 在任何 `DRAGON_EXTRA` 读写之前，龙为 null 或在客户端就返回。空移动向量原样返回，不写 0。客户端不读表，也不 `setPos`。

纯函数：`WetnessFlight.limitedVertical`、`descentEligible`、`extraDown`。`WetnessFlightClip.clipExtra` 调用 `Shapes.collide`。参照箱和阻挡形状已经严格体积重叠时，允许追加量为 0，不把原来的穿墙推出去。只贴着边界则继续向下裁，贴到为止为 0。相交看形状本身，不用外包围盒。多部件用 `strictestExtra`，任一相关部件重叠则共同追加量为 0。原来的两个飞行 Mixin 仍只做速度夹紧。新增 Mixin 只有悦灵、恼鬼、末影龙这三只，注入方法都是 private 实例方法。

## 8. 怕水

L4 且 `isSensitiveToWater()` 为真的生物，按原版水中扣血的同一次调用受伤：`hurt(damageSources().drown(), 1)`。烈焰人、末影人只是例子。判断用原版方法，不写死类名。雪傀儡、炽足兽等原版返回真的生物跟着走。

挂在 `aiStep` 尾部，服务端，生物仍在这次逻辑里。已经 `isInWaterRainOrBubble()` 的，原版 2780 行自己会打，不要再打一遍。

不要把实体标成在水里。那样会带出游泳、灭火和其他无关行为。不要伪造整个人在水中。

原版溺水伤害不绕过无敌帧。`invulnerableTime > 10` 且这次伤害不大于上次时，`hurt` 会自己拒绝。所以这不是每个 tick 都打 1 点。不同阶段的窒息和水伤沿用原版这个政策，不要另设冷却。

## 9. 旧重水：兼容停用

旧重水控制和旧的按份扣费停用。深海重压领域完整保留，不走这套。
