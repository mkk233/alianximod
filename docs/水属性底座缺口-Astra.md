# 水属性底座缺口

裁决：gpt-6-astra。日期：2026-10-21。对照 `docs/水属性术式.md`。方案对照现有释放代码查过重。能量层已接到碰撞体积：`能量 × 附魔半径`，默认能量为 1。潮湿药水、水势、蓄力、场地、命中载荷、凝结障碍和幻影契约已接到同一条释放链，旧术式不填字段时行为不变。缠绕、位移争夺、配方编译、完整几何、飞行中再拆、地上火方块和分身智能仍未做。

## 0. 查重后的补丁边界

五层是现有释放链的补丁，玩家仍用这一条链。旧术式不填五层时，走现在的修饰、弹道和生成。`define()` 的参数表不改。若以后要加字段，只加 `ReleaseDefinition` 上的 `default` 方法，未配置表示沿用原路径。不新增 `ChainRole`，不按术式 id 结算。

形态不另做系统。它就是现在的 `TechniqueHitSpec.spawn` → `TechniqueHitEntity` → `TechniqueHitRenderer`。`visual`、贴图、长宽高、`path`、命中盒已经是外观和判定。斩击贴片、信标光柱、水色带、潜影贝模型是同一渲染器里的分支。剑实体 `SwordEntity` 保持自己的实体和渲染器。没人调用的 `HitVolumes` 不复活成第二套形态。

| 层 | 合并到 |
| --- | --- |
| 能量 | 所有术式通用的来源大小，默认 1。碰撞体积用它和元素反应的半径加成相乘。不是水的介质，也不是某一属性专用 |
| 运动 | 现有 `Trajectory`、各 `Motion`、`FUNCTION` 注册口，以及链上的索敌和弹道修饰 |

| 性质 | `CastFrame` 的附魔字段和 `TechniqueHitSettle` |
| 终结 | 现有撞上、到期和爆燃 listener。还没有统一的末端事件槽 |

第一刀若写代码，只允许把可选五层配置交到上面这些已有入口，并保证同一效果只跑一次。不写第二套实体生成，不写第二套弹道，不重做索敌、一分为三、双重释放和附魔。上表里标成「没有」的能力这次不提前做。

## 1. 一句话结论

现有释放链可以继续承担修饰收集、索敌 → 弹道 → 规则 → 攻击的解析顺序、攻击生成和基础命中结算。完整覆盖文档需要新增数据化复合释放定义、阶段时间轴、组合运动、实例群管理、扩展判定、状态与资源、受伤拦截和末端事件这些底座。

五层统一作为释放定义的五个数据维度，玩家界面继续使用一条释放链。五层是能量、运动、形态、性质、终结。能量层对所有属性生效，表示这次释放的来源有多大。来源越大，碰撞体积越大。火属性来源大，火就更旺，体积跟着变大；水、木、土、金用同一条倍率，不按术式 id 另算。

选择这个关系有两个原因：

- 现有链已有明确的修饰覆盖和结算规则，可以继续使用。
- 文档的终极配方包含多个运动、多个性质以及多个阶段，五个单选槽无法直接表达。

`ChainRole` 保持现有八个。五层字段、阶段字段和效果类别均属于定义数据，不增加 `ChainRole`。配方名称只负责展示、发现和选取通用定义，运行时依据能力字段执行。

## 3. 缺的底座能力

以下按依赖排序。列出的能力共同构成完整目标底座。阶段性交付时，尚未接通的效果应明确标记为未支持。

### 3.1 数据化复合释放定义与确定性编译

服务模块：五层、默认值、自由组装、复合配方、配方发现。

数据层：

- 释放定义：五层描述、阶段描述、兼容条件、默认值、修饰字段键、能力标签。
- 实例：编译后的只读释放计划，以及本次取定的参数。
- 玩家：模块及配方解锁信息。

接法：

- `ReleaseDefinitions` 继续登记既有 `ChainRole`，并承载能力描述。
- 目标选择使用 `SEEK_SPACE`、`SEEK_ENTITY`；垂落、交错使用对应角色；双重、三份使用对应规则角色。
- 能量、形态、性质、终结及其余运动描述，可由 `ACTION` 定义携带声明式修饰数据。必须显式区分“提供修饰数据”和“执行动作”，保证修饰不会独立攻击。能量是数值，不是一种会自己放出去的介质。
- `ATTACK` 是攻击、场地或防御实例的执行边界，可生成零伤害的防御场或控制场。
- “同类覆盖”按语义字段键与阶段范围判定。例如两个主路径修饰互相覆盖；路径、尺度变化和牵引载荷可以共存。同一个字段上的重复性质仍执行近者覆盖。
- 默认值只在存在执行边界时补齐。纯修饰链保留现有行为；已经支持的附魔继续回退到下一次普通攻击。

多运动配方必须能声明“不同运动通道并用”或“不同阶段先后执行”。如聚拢与环绕可形成径向收束加角向运动，追踪、回卷与聚合则需要明确的阶段关系。自由拼装遇到互斥主路径时，仍按近者覆盖。

配方识别必须依据能力描述，匹配结果可以选择声明式复合定义，所有行为仍由通用底座执行。旧成品名作为配方材料时，应展开为公开的能力组合，并保留后续字段覆盖能力。

缺失会阻塞：全部多层配方，尤其沧澜漩涡、万流归海、镜花水月；也会导致“水幕”“水环”作为配方材料时出现隐含特例。

### 3.2 锚点、目标引用与回退策略

服务模块：地面、自身、攻击来源、上空定位；追踪、聚拢、反弹、聚合后的重定位。

数据层：

- 释放定义：锚点类型、偏移、回退顺序、重取时机、目标失效策略。
- 实例：固定世界坐标、初始朝向、独立目标引用。
- 实例或防御记录：受击时的攻击来源位置及来源实体。

接法：索敌阶段先完成现有选择，再按通用回退链得到有效锚点。上空与地面是锚点变换，不占用新增 `ChainRole`。

必须分开保存固定锚点与可变化的追踪目标。追踪可以更新目标位置；水牢、漩涡的场地位置保持释放快照。聚合只在规定的合并事件重取一次锚点。攻击来源锚点在受击事件取定。

斩击仍遵守 `trajectoryMutable == false` 只改变生成位置。

缺失会阻塞：涌泉、水涡、漩涡、水镜反射、万流归海、天河倾落，以及无有效目标时的可靠释放。

### 3.3 阶段时间轴、事件原因与实例生命周期

服务模块：起手—持续—收尾、预告、低频脉冲、回旋、回卷、全部终结。

数据层：

- 释放定义：阶段长度、脉冲周期、阶段切换条件、结束事件及触发资格。
- 实例：当前阶段、阶段时钟、已触发事件、结束原因、取消状态。

接法：攻击解析生成带时间轴的实例。阶段可以驱动运动、判定、载荷和视觉；伤害只能在授权的结算事件发生。

提供撞击、到点、寿命结束、回收完成等通用事件，并区分自然结束、打断、死亡、区块卸载等原因。末端事件保证至多执行一次，异常清理是否允许爆发由定义明确规定。

双重释放仍按原有间隔调度，其生成的每份实例各自运行生命周期。

缺失会阻塞：回旋水刃、激流冲刷、高压水牢，以及所有终极术式和八种终结。

### 3.4 组合运动与动态尺度、密度

服务模块：追踪、扩散、环绕、回旋、聚拢、上涌、推进、回卷、压缩；可组合的坠落。

数据层：

- 释放定义：主路径、局部形状、尺度与密度变化、转向限制、阶段运动策略。
- 实例：速度、方向、尺度、密度、路径进度、追踪状态。

接法：保留现有 `Trajectory` 值作为主路径来源，并增加路径之外的运动通道和阶段策略。`TrajectorySampler` 继续提供可复用的路径采样；开发者函数通过既有注册口接入。

必须明确主路径替换与局部形状的边界：

- 垂落、风暴等覆盖主路径后，原 FUNCTION 路径失效。
- 需要保留的刃形、索形或局部曲线应进入独立局部几何描述，再随主路径运动。
- 追踪每 tick 修正运动方向，目标失效后按最后有效方向直行。
- 尺度收缩与密度增加采用明确预算关系，避免压缩凭空产生无限伤害。

所有接受这些运动改写的攻击必须 `trajectoryMutable == true`。已有不可变斩击保持原约束。

缺失会阻塞：缚流水索、回旋水刃、潮汐浪、高压水牢、沧澜漩涡、深海重压，以及带局部形状的组合弹道。

### 3.5 能量层与碰撞体积

能量层替换原来的水源层。水源按水的介质分类，只有水系用得上，不能当所有术式的底座。能量层只回答来源有多大，火、水、木、土、金和没有属性的攻击都读它。

数据放在数值结算里，不放进 `ChainRole`。现有入口是 `ElementReaction` 和 `EnchantBonus.radiusMultiplier`。同属性反应把伤害乘 1.30、冷却乘 0.70。木生火把半径乘 1.10，这个半径已经折进附魔的 `radiusMultiplier`。`TechniqueHitSpec.spawn` 在这个倍率大于 1 时，把长和宽再乘一次，高目前不乘。剑术里还有几处自己读火焰附魔的半径。

能量和这些加成叠乘，不互相覆盖：

`最终体积倍率 = 能量倍率 × 已经含有元素反应的半径倍率`

能量默认 1，旧术式体积不变。能量 2、木生火半径 1.10 时，体积倍率是 2.20。反应的伤害、冷却、持续时间、距离、搜索、速度仍走 `ElementReaction` 原来的项，能量不把它们再算一遍。碰撞体积变大用这一条倍率，火更旺是体积变大的表现，不按火的术式 id 单独放大。

生成水仍是把一格水放进世界的那个术式，不属于能量层。水滴、水流、水雾、水域、雨幕若要区分，用形态和运动表达，不用能量层分成五种水。

发射器、滞留场地和雨幕的生成节奏仍是缺的。生成一个视觉上的水滴不等于多一次伤害。这项和能量倍率分开，不因为改了能量层就当作已经有了。

缺失会阻塞：水雾、持续水流、漩涡、深海水域、镜花水月、天河倾落。

### 3.6 分裂、聚合与群体回收

服务模块：飞行中分裂、多股追踪、聚合、潮汐回卷。

数据层：

- 释放定义：分裂阈值、份数、继承策略、聚合条件、回收截止时间、预算分配。
- 实例：父子关系、群体标识、成员状态、共享预算与命中记录。

接法：分裂由阶段事件产生子实例，并继承目标策略、来源归属和结算账本。聚合结束旧成员，生成新的聚合实例，按锚点策略重新定位。

一分为三继续创建三份释放，群体系统负责其内部的后续分裂与聚合。两层复制必须共享明确的规模和伤害预算，防止指数膨胀。

“回收全部”必须定义死亡、撞毁、卸载、失联成员如何计入完成，以及超时后的处理。

缺失会阻塞：万流归海、潮汐回卷及带群体回收的天河倾落。

### 3.7 几何判定、连续扫掠与区域成员管理

服务模块：全部形态，进入、驻留、离开区域的行为。

数据层：

- 释放定义：胶囊、链条、扇形、圆环、圆柱、平面等几何参数及扫掠策略。
- 实例：当前与上一位置、当前几何、区域成员。
- 目标：按来源或场地关联的驻留记录。

接法：扩展 `TechniqueHitSpec` 的形状描述，继续经 `TechniqueHitEntity.tryHit` 及共享资格检查进入命中流程。高速移动使用连续扫掠，避免水刃、水索穿过目标却漏判。

水镜需要带法线、有效面和厚度容差的平面交互；场地需要稳定的进入、驻留、离开事件。伤害碰撞、实体阻挡和投射物拦截是不同用途，必须分别声明。

缺失会阻塞：压缩水刃、水幕、水环、缚流水索、浪潮、漩涡、水镜、水龙卷，以及形状准确的雨幕和深海水域。

### 3.8 通用载荷、状态与位移约束

服务模块：潮湿、缓速、牵引、缠绕、净化、治疗、压强、侵蚀；水牢、上涌和击退。

数据层：

- 释放定义：效果类型、强度、周期、对象筛选、叠加与冲突规则。
- 目标：潮湿值、来源、过期时间、控制约束、侵蚀状态。
- 实例—目标关系：驻留时间、压强层数、水牢稳定度。

接法：命中先生成有效接触事件，再分发伤害、状态、控制、治疗等载荷。零伤害命中也可以施加潮湿或控制。

具体需要：

- 潮湿上限、衰减、档位及其对减速、击退抗性、牵引、水牢稳定度、雷伤、冻结和燃烧时间的影响。
- 通用属性标签与状态查询接口，让雷、冰效果读取潮湿。
- 牵引、推退、击飞仍是各自的位移效果。多块场地不另做位移争夺：附着的索敌和弹道只套用一次，伤害按施法者当下所在的场地份数相乘，其他效果站在任意一块里就按单份生效。
- 水牢的稳定度、挣脱和解除条件。
- 治疗与净化的友方筛选、可清除异常列表。
- 净化实体燃烧与清除世界火焰的独立权限。
- 压强按驻留累计，侵蚀按规则破甲或低频流失。

位移更新可以逐 tick 执行；伤害继续受结算周期约束。

缺失会阻塞：水雾铺场、缚流水索、水牢、涌泉、激流冲刷、漩涡、高压水牢、深海重压、净化扩散，以及全部潮湿联动。

### 3.9 通用结算账本与伤害资格

服务模块：单次、低频持续、累计后爆发、命中转控制。

数据层：

- 释放定义：结算模式、周期、次数上限、预算、直接命中与末端伤害的关系。
- 实例及实例群：按目标记录的命中、待结算伤害、已支付额度、末端结算标记。
- 目标：必要的来源级周期资格记录。

接法：扩展现有 Tally 的作用域和结算时机，同时保留现有一分为三约六 tick 汇总语义。持续阶段、群体收尾和末端爆发使用各自明确的账本边界。

所有通用伤害最终通过一致的伤害入口，范围终结也遵循相同规则，避免 listener 独立绕过归属、预算或防重复检查。

压强每五 tick 增层可以成立，伤害按授权事件结算。累计命中后一次结算的模式不能提前支付同一份伤害。

十 tick 只能作为默认脉冲间隔，不能保证所有原版或其他模组环境都接受每次伤害。底座保留原有受击冷却，接受伤害可能被拒绝，并区分有效接触与实际受伤，供水势等系统使用。

缺失会阻塞：安全的持续漩涡、高压水牢、万流归海汇总、镜花水月，以及不会双算的终极爆发。

### 3.10 伤害进入前拦截与反制事务

服务模块：卸力、吸收、回流、反弹；近战、投射物、爆炸击退和火焰缓冲。

数据层：

- 释放定义：防护对象、覆盖形状、适用伤害、系数、容量、优先级、反制方式。
- 实例：防御场有效期、剩余容量。
- 玩家或目标：防护关联、待用回流额度。
- 受击事件：来源、削减前后数值、实际削减量、反制标记。

接法：必须建立受伤进入前的统一拦截口，覆盖外来伤害，限定到该防护所属的受保护实体。`TechniqueHits.hurt` 只是本模组主动伤害入口，无法单独承担该能力。

同一次受击形成一份事务：判断防护资格 → 计算削减 → 记录实际削减量 → 转化资源 → 安排允许的反制。多个防护的叠加、优先级和容量扣除需要统一处理。

伤害反弹与投射物偏转分别定义；投射物偏转需要真实轨迹接触。爆炸击退削弱、燃烧缩短也需要各自的事件接口。

反制必须携带来源及反射深度限制，防止双方水镜无限互弹。延迟反击进入正常攻击结算。

缺失会阻塞：水幕、水环、环流水护、水镜反射、回流爆、镜花水月，以及第六节完整的卸力与回流。

### 3.11 水势与强化消费

服务模块：第五节水势、第六节回流、终极释放门槛。

数据层：

- 释放定义：获得条件、转换系数、强化目标、消费时机、环境条件。
- 玩家：水势、上限、待用回流强化、必要的冷却与持久化数据。
- 实例：本次消费快照与强化结果。

接法：由实际伤害、有效卸力、成功反射及合规的环境施法事件提供资源。命中已潮湿目标的额外收益读取统一状态接口。

攻击实例化时完成资源预留或消费，再通过通用参数强化伤害、半径、寿命、治疗量和回流预算。魔力与水势分别计账。

需要限制自身伤害、友方互刷、反弹递归、重复结算和雨天低成本空放刷资源。

缺失会阻塞：环流水护、回流爆、强化水刃、扩大漩涡、延长水牢、增强治疗，以及完整的终极成长闭环。

### 3.12 通用终结操作与临时障碍

服务模块：八种终结。

数据层：

- 释放定义：终结触发条件、操作顺序、几何、载荷、预算。
- 实例及实例群：终结执行状态、回收结果、临时障碍寿命与归属。

接法：在时间轴末端槽中组合通用操作：

| 终结 | 所需通用操作 |
| --- | --- |
| 爆流 | 范围采样、一次结算 |
| 塌缩 | 几何收缩、中心聚拢、终结伤害 |
| 冲刷 | 定向位移、净化载荷 |
| 凝结 | 临时障碍生成、实体碰撞、到期清理 |
| 潮汐回卷 | 群体回收、完成或超时判定、聚合后爆发 |
| 镜面破碎 | 碎片子实例生成、共享伤害预算 |
| 深海重压 | 广域结算、压强读取、压制状态 |
| 净化扩散 | 传播范围、目标去重、有限次净化传播 |

凝结建议先使用有寿命的实体障碍。真实方块替换、流体改造和跨卸载恢复明确推迟，对应缺口是世界修改权限、变更记录与恢复底座。实体障碍版本必须明确是否阻挡玩家、怪物和投射物；若要求改变寻路，也需另补导航影响能力。

缺失会阻塞：所有带终结配方；尤其凝结、潮汐回卷、镜面破碎无法靠现有爆炸 listener 完整实现。

### 3.13 服务端权威同步、视觉与规模预算

服务模块：全部多人行为、水体积、镜面、雾、场地、随机形态、成长和配方提示。

数据层：

- 释放定义：视觉结构、同步参数、表现降级、实例和判定预算。
- 实例：服务端随机种子、阶段、几何、群体成员和权威状态。
- 玩家：水势、解锁与配方发现状态。
- 目标：需要展示的潮湿、控制与压强状态。

接法：服务器决定命中、随机形态和资源；客户端按同步描述表现水体、雾、镜面、螺旋和滞留区域。视觉碎片与伤害实例数量分开限制。

界面只提供模块排序、可理解的参数和结果预览。配方名、默认值、覆盖冲突以及缺少执行边界均应可见。曲线函数保持开发者接口。

镜面的反弹功能不依赖真实实时反射渲染。完整实时反射可以后置，明确缺口是专门的镜面渲染能力。

缺失会阻塞：镜花水月的雾镜表现、深海水域的场地表现，以及雨幕、分裂聚合在多人和高数量情况下的可靠运行。

### 第七节配方覆盖核对

以下是能力验收范围，避免把缺项留给后续术式特判。

| 配方范围 | 必须具备的新增能力 |
| --- | --- |
| 水弹、水刃 | 定义默认值；水刃另需压缩、胶囊与扫掠 |
| 水幕、水环、水涡、水牢、水雾 | 防御拦截、对应几何、滞留、状态、控制、低频结算 |
| 缚流水索、回旋水刃、环流水护、涌泉、激流冲刷 | 追踪与链条、双阶段折返、卸力水势、地面锚点与击飞、持续推进与净化 |
| 水镜反射、回流爆、漩涡、潮汐浪、高压水牢 | 平面反制、吸收账本与终结、场地牵引、扩散推进、驻留压强 |
| 沧澜漩涡 | 聚拢环绕组合、区域潮湿与牵引、低频压强、塌缩 |
| 万流归海 | 分裂追踪、群体回收聚合、共享账本、大浪终结 |
| 镜花水月 | 雾场、平面防护、卸力反制事务、碎片终结 |
| 深海重压 | 球牢向区域形态的阶段切换、减速、压强累积、坠落与压缩爆流 |
| 天河倾落 | 上空锚点、预告与雨幕发射器、群体回收、冲刷、实体及环境净化 |

其中，配方写出的材料与结果之间存在省略时，应在声明式复合定义中补全阶段和默认能力，并向玩家展示展开结果。

## 4. 明确拒绝的做法

- 新增第九个 `ChainRole`，或另建一套实际承担链路分派的隐性角色枚举。
- 在运行时按术式 id 特判落点、弹道、规则、附魔、结算或终结。
- 同时维护五槽装配与释放链两套执行语义。
- 将配方优先级用于绕过同类近者覆盖、伤害预算和弹道可变性限制。
- 让能量、形态、性质或终结修饰自行触发本次攻击。
- 把能量层做成水源、火源或其他某一属性才读的字段。
- 用能量倍率替换元素反应已经算过的伤害、冷却或半径。反应半径已经在附魔倍率里，能量只再乘一次。
- 用一分为三替代飞行中分裂，用双重释放替代生命周期末端事件。
- 用当前 FUNCTION 预览曲线证明本文档的运动、控制或终结已经实现。
- 让不可变斩击接受轨迹改写，或让固定场地持续跟随镜头。
- 每 tick 直接伤害、修改无敌帧，或承诺十 tick 间隔可以绕过所有受击冷却。
- 让反弹无限递归，或让吸收、伤害、回流资源重复计入同一份受击。
- 用视觉粒子承担权威碰撞，让客户端决定随机命中形态。
- 将真实方块凝结、导航阻挡、镜面实时反射等未实现能力隐藏在成品名下面。
- 向玩家开放函数输入。
- 用超过五百行的大文件集中承载编译、运动、状态、拦截和渲染。

## 5. 建议的底座落地顺序

1. 先确定语义合同。拍板链与五层关系、同类字段键、执行边界、复合配方展开、回流含义、锚点固定规则和伤害预算。
2. 建立定义编译、锚点和生命周期。先验证默认值、覆盖、阶段切换、取消与末端只执行一次。
3. 统一命中事件、账本与基础载荷。打通单次、低频、只加状态、延迟汇总四条路径，再让范围伤害进入同一规则。
4. 扩展几何、滞留场与组合运动。验证扫掠、区域进出、追踪失效、主路径覆盖和局部形状保留。
5. 接入潮湿、位移约束、净化、治疗、压强与侵蚀。明确多来源状态仲裁及解除行为。
6. 接入受伤拦截、水势和反制。重点验证多防护叠加、真实削减量、资源扣除、反弹递归和外部战斗模组兼容。
7. 建立实例群与通用终结。验证分裂预算、丢失成员、聚合、回收超时、碎片共享结算和临时障碍清理。
8. 完成视觉、配方发现和成长展示，再做配方覆盖验收。同步协议和规模上限从实例底座开始设计，视觉精度逐步补齐。

每阶段按职责拆分文件，单文件保持五百行以内。最终验收应同时覆盖单人、多人、目标死亡、施法者死亡、打断、区块卸载及第三方减伤参与等边界。

## 6. 第十一节必须由人拍板的事项

以下默认项均为“默认可改”。涉及语义和接口的项目应先确认；具体数值可以在接口稳定后调整。

| 待决事项 | 为什么需要拍板 | 默认建议 |
| --- | --- | --- |
| 模块与成品同名 | 影响定义展开、配方识别和界面认知 | 能量是通用倍率，默认 1。水滴、水流、水雾不再占第一层。成品名作为可展开的能力预设 |
| 五槽、必填与重复 | 决定整个编译模型 | 使用单链、五层数据维度；要求执行边界，其余补默认；同字段近者覆盖，不同载荷可共存 |
| 多运动、多形态组合 | 影响是否能表达终极配方 | 兼容通道可以并用，互斥主路径近者覆盖；阶段切换和复合几何由开发者定义 |
| 展开、扩张、旋转、包覆等别名 | 防止同义模块形成不同语义 | 展开/扩张归扩散，旋转归环绕，包覆归聚拢；保留可配置参数差异 |
| 上空锚定 | 影响生成位置和坠落方向 | 作为锚点类型及高度参数，不新增 ChainRole |
| 幻影 | 决定是否需要分身行为与战斗归属 | 先提供无独立命中的视觉残像；战斗分身明确推迟 |
| 潮湿 | 影响跨属性、控制与目标状态接口 | 上限一百，按文档四档；连续一秒无有效水系接触后，每秒衰减五点；控制加成另设上限 |
| 水势 | 影响获得事件、溢出和消费事务 | 上限一百，溢出丢弃；实际伤害、实际削减及成功反制按规则获取，环境奖励限频 |
| 回流的即时与延迟含义 | 文档同时写了“返还一击”和“强化下一次术式” | 回流储存强化下一次水系攻击；反弹负责即时反击；需要两者时分别配置并受同一预算约束 |
| 自身锚点是否跟随 | 决定水环移动和场地稳定性 | 按文档固定世界坐标；若要求移动护体，另显式增加实体绑定策略，朝向不随镜头变化 |
| 耗蓝、冷却、硬直 | 现有按伤害计费会使零伤害防御与治疗成本失真 | 增加定义级基础及规模成本，旧攻击保留现有公式；水势独立消费；取消退款规则明确配置 |
| 终极引导与打断 | 影响生命周期、资源及收尾资格 | 终极允许预告和引导；被打断执行清理，默认不触发高伤终结 |
| 与其他战斗模组的顺序 | 决定卸力差值和资源是否被多算 | 以明确拦截阶段收到的伤害值计算本次削减，资源只认本次真实削减量；具体事件顺序需在目标环境验证 |
| 随机形态同步 | 影响多人命中一致性 | 服务端生成种子及权威几何，客户端仅重建表现 |

此外，凝结是否修改世界方块、净化是否清除环境火焰、缠绕是否限制瞬移、友方与 PvP 判定，虽然未在第十一节逐项展开，也必须在相关底座落地前确认。

总体裁决：保留现有链及八角色，以数据化复合定义把五层能力接入实例生命周期；先完成通用判定、结算、状态和反制契约，再让全部配方成为这些能力的可验证组合。
