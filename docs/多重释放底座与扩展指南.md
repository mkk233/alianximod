## 现在有什么

`rule_dual_release` 登记 `MulticastSpec.fixed(2)`，角色仍是 `ChainRole.RULE_DUAL`。它按原始装配格向后读两格。读到的实际成员里，序号 0 立刻出手，后面每个实际成员间隔 `MulticastExpansion.MEMBER_GAP_TICKS`（3 刻）。同一成员上的复制份共用这个序号。修饰、附魔、内层多重和复制声明各占一格，它们本身不是额外的时间节点。

`rule_triple_cast` 仍是 `ReplicationSpec.of(3)`，不是多重。它乘到后面第一个接受复制的宿主上。屏障、领域、护体、场地、条件释放和命中体积攻击都接受复制；动作和多重本身不接受。不按基础伤害是否大于 0 取舍。

面对多重的复制声明仍被标成忽略，不进费用和冷却。内层修饰只挂到该层第一个适用宿主，不广播给后面的兄弟。落点指定和三维交错看 `acceptsPlacementModifier()`：弹道固定的斩击也接受，因为它们只改生成位置和刀面。锁定实体、跟随和垂落仍只给接受瞄准或弹道可变的宿主。增幅只给会吃元素术法链倍率的命中体积，不套到屏障、领域或剑技上。附魔仍看 `canReceiveEnchantment`。

解析只有 `MulticastParser.parse` / `openingIndex`。展开是 `MulticastExpansion`。下标是调用时那份术式列表的原始顺序，不是 `TechniqueChain.split` 之后的段号。

本批在同一套声明上又登记了这些数量。多重仍是 `RULE_DUAL`，复制仍是 `RULE_TRIPLE`。

| 编号 | 名称 | 声明 |
| --- | --- | --- |
| `rule_dual_release` | 双重释放 | `MulticastSpec.fixed(2)`，原有 |
| `rule_triple_release` | 三重释放 | `fixed(3)` |
| `rule_quadruple_release` | 四重释放 | `fixed(4)` |
| `rule_octuple_release` | 八重释放 | `fixed(8)` |
| `rule_sixteen_release` | 十六重释放 | `fixed(16)` |
| `rule_exhaustive_release` | 穷尽释放 | `remaining()`，从自身下一原始格读到当前链尾 |
| `rule_double_cast` | 一分为二 | `ReplicationSpec.of(2)` |
| `rule_triple_cast` | 一分为三 | `of(3)`，原有 |
| `rule_quintuple_cast` | 一分为五 | `of(5)` |
| `rule_octuple_cast` | 一分为八 | `of(8)` |

普通链按复制声明读取因子，未声明复制时不再固定乘 3。批量编译和协同编译在所属编译器已经接管时，凡是声明了 `multicastSpec()` 的术式，包括 `fixed(2)`、其他固定次数和 `remaining()`，都用 `MulticastCompileAdapter` 复用同一次 `MulticastParser` 展开。读取边界、成员顺序、成员延迟和复制积都来自这次展开，不再按固定两段计数，也不再给第二段单独排 3 刻。短链在链尾停下，不补足到声明格数。有实际成员就释放；一个成员都没有时，付款前提示「这次多重没有可释放的成员，没有释放」。展开适用却没有离开当前格时，提示「多重展开没有离开当前格，没有释放」。这两句和接续自己的父段、子段、一层限制分开。双重套双重不再被当成没有排满两段。

## 固定次数怎么加

在新的释放定义上让 `multicastSpec()` 返回 `MulticastSpec.fixed(正整数)`，或返回 `MulticastSpec.remaining()`。不要新增角色，不要在 `ChainSteps`、`CompiledReleaseStep` 或按键里写 id。

登记之后 `ChainStructureEpoch` 会变，计划缓存按代际丢掉旧计划。缓存仍然开着。展开放在 `CompiledReleaseStep.StructureChoice` 里，里面没有玩家、付款、目标或随机结果。

上表里的八重、十六重和穷尽已经是可装配术式。固定次数从自身之后的原始格向后读，短了就停在链尾；有实际成员就释放。一个成员都没有时，普通链、批量编译和协同编译都在付款前拒绝，后两者的提示键是 `gui.xueximod.batch.multicast_empty`。展开已经适用、但下一格没有离开当前格时，这两处编译器改用 `gui.xueximod.batch.multicast_boundary`，不再提示双重没有排满两段。穷尽用 `remaining()`，从下一原始格读到当前链尾，不回绕。

复制另走 `replication()`。宿主是否接下这份复制，看 `ReleaseDefinition.acceptsReplication()`。

## 链怎么分步

`ChainSteps.list` 用同一次解析分步。打开位置到 `nextIndex` 是一步，前导动作和它前面的附魔算在同一步里，动作本身不进展开。普通的一发一个宿主还是原来的路径，`pullAfterA` 不再决定这一步拉几名。

空展开会单独成一步。`CompiledReleaseStep.compile` 给出拒绝文案「这次多重没有可释放的成员，没有释放」，账单为空。按键在付款前失败，这一步不推进。批量编译和协同编译使用同一句中文，英文分别写在 `zh_cn.json` 与 `en_us.json` 的 `gui.xueximod.batch.multicast_empty`。命中接续仍按自己的规则要求父段、一层和子段；结构对不上时用 `gui.xueximod.batch.continuation_structure`，缺父段、缺子段和只能一层仍用原来的三句。这些都不是多重嵌套的拒绝。

## 报价

费用和冷却只认 `chargedIndexes`，每个原始格一次。前导动作和它前面的附魔另计入冷却；动作法力在 `actionShare`，不进 `groupBill()`。被忽略的复制、无用修饰和已移除规则不进费用、不进冷却。

每个成员的份数是它自己的 `replicationIndexes` 上因子连乘，空则是 1。连乘、成员费、规则费和它们的合计一旦超出 int，`CompiledReleaseStep.chargeRefusal` 是「这次多重的份数或费用超出可表示范围，没有释放」。这种拒绝不是把份数截成最大整数，也不是把溢出后的负数当成 0 费。正常范围内的份数和价钱保持原值。`AutomaticRound` 继续读原来的份额字段和这句拒绝。

缓存把这次展开、成员宿主、附魔下标和复制份数放进切片。命中后 `copiesBefore`、`releasedSegments`、锁定、垂落和冻结输入先读这份切片，不再先重解析。登记代际仍会丢掉旧计划。缓存没有关掉。

## 运行接线

手动释放、动作碰撞触发、领域捕获和领域自动轮已接入共享展开。嵌套成员共用一条时间队列，自动轮仍保持领域自己的轮次时钟。实际发布回执保留成功份额，未发布份额退回；规则费在本轮第一笔真实成功发布时保留一次。领域允许绑定哪些攻击仍沿用现有准入规则。

后续增加多重术式时，通过声明读取数量复用这些入口，不再另做按术式名称判断的执行队列。本批新增的固定次数和穷尽，以及批量、协同里的全部多重声明（含原有双重释放），都走这条共享展开。2026-11-16 的统一返修去掉了批量 `dualRemaining` 和协同 `dualPending` 这两段旧门槛；设计 2/2、实现 3/3 当时已经用完，这次没有追加正式复审。

## 载具容量

容量没有扩大。测试用伞仍是 32 格，八重、十六重和穷尽可以按这 32 格使用。剑术是四个入口，每条链各自 8 格，只检查当前这一条，不把四条链拼在一起。

剑术拒绝的是固定多重且 `fixedCount >= 8`。因此八重和十六重不能用于剑术，术式说明里写了「不能用于剑术」。三重、四重和穷尽仍可用于剑术。一分为八是复制因子 8，剑术和伞都可以用，不受这道固定多重限制。双重、一分为二、一分为三和一分为五同样可用。

装配在扣物品之前拒绝，施放在占用冷却和执行之前拒绝。提示键是 `gui.xueximod.sword.multicast_limit`。
