# 术式制作表：资源与状态字段

前四页现为 144 列 `A:EN`。`B` 编号、`N` 功能描述、`O` 特效、`DV` 备注的含义不变。新增内容在 `DW:EN`，第六页是「资源状态明细」。表内标成已配置，只说明这张表有这条记录。现行代码仍读取原来的固定字段，不会因这次改表就改掉游戏行为。

## 怎么选

带下拉的新列只从「数据表」的连续列表里选。

| 主表列 | 列表 |
| --- | --- |
| `DW` 配置启用 | 既有名称「是否」 |
| `DX` 资源 | 资源列表 |
| `DY` 状态 | 状态列表 |
| `DZ` 操作 | 操作列表 |
| `EA` 作用对象 | 作用对象列表 |
| `EB` 触发时机 | 触发时机列表 |
| `EE` 寿命策略 | 寿命策略列表 |
| `EI` 计量单位 | 计量单位列表 |

明细页 `C/D/E/F/G/H/K/O` 用同一套列表。要增加选项，在对应列紧接最后一项往下写，中间不要空行。名称用 `INDEX/COUNTA` 跟着连续区域走，不使用数组公式。隔一个空行再写的项不会进当前下拉。

`DX` 和 `DY` 只填一个。整组 `DW:EN` 都空，表示这条没有通用配置。魔力留在原来的费用列，不进资源列表，不能再用通用资源操作扣一次。

## 额外效果

主表这一行是第 1 条，不抄到明细。还有下一条时，主表 `EN` 填写本行 `B` 的编号。明细从配置序号 2 起，`A` 列用同一个编号关联，不复制制作状态。明细 `T` 固定留空，不再往下套。

## 旧档、0 和仅设计

`AR`、`AW`、`BQ`、`BR`、`DC:DL` 的第 2 行标题加了「旧档·」。原数值、空单元格和 0 都还在，只作迁移证据，不与新配置各执行一遍。`N`、`DV` 仍是需求原文，不据此再生成一份效果。`BQ`、`BR` 继续停用。`DM` 耗氧倍率留在原列。

数字 0 是写下来的 0。寿命不适用、继承、无限或未定时，寿命 tick 留空，不用 0 代替。纯等级状态的数值列可以空，等级写在 amplifier。炉心的默认寿命是无限，tick 留空。

2026-10-28表格迁移时，火种、炉心的本体字典标为「仅设计」，真实存储列留空。这是当次迁移的历史标注。后续火属性底层已登记资源`xueximod:fire_seed`和状态`xueximod:furnace_core`：火种存于实体`xueximod_attribute_states.fire_seed`，炉心运行态存于玩家`xueximod_furnace_core`。当前规则与验证状态见[火属性二级玩法设计](火属性二级玩法设计.md)及其开发记录；不要再从表中历史空值推断代码尚未登记。表内字典键仍不等于可随意拼接的游戏ID。

水势、潮湿、缓慢以及新增火种、炉心的本体存在，只说明代码里已有对应对象，不表示每个术式行都已接到通用字段。通用字段是制作输入；选择这些选项不会自动改变既有术式，具体行为仍需在对应制作任务中接入代码。

2026-10-29起，燎原和焚天的新挂载使用同一份`xueximod:fire_seed`余额并逐段付款。触发时机列表在原有选项后增加「燃烧结算」，名称范围按连续单元格自动变长，四张状态页的触发列和资源状态明细的触发列都引用这个名称。燎原、焚天的资源扣款触发用「燃烧结算」，周期 tick 分别为 20 和 4，数值 10 表示一个完整段请求 10 点，不是启动时预扣全部。首次接触和范围选取只写在详细需求里，作为挂载时机。燎里仍在命中成功时消费当时全部余额。待制作原始数据页保留迁移前档案，不回写这次新需求。空的资源列仍然只表示该行没有通用配置，不表示所有术式都已接入。本版已有统一编译退出码 0，没有追加正式复审，也没有游戏验收。
