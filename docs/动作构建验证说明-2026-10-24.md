## 配置

- 注解处理器是 `org.spongepowered:mixin:0.8.5:processor`。缓存里没有这个分类器时由主控解析下载，不用主 jar 另拼类路径。
- `compileJava` 依赖 `createMcpToSrg`。处理器参数是 `-AmappingTypes=tsrg`、`-AreobfTsrgFile`（该任务的 `output`）、`-AoutTsrgFile`、`-AoutRefMapFile`。没有 `-AmergeBehaviour=merge`。
- 两个处理器输出登记在 `compileJava` 的 `outputs.files`：
  - `build/tmp/compileJava/compileJava-refmap.json`
  - `build/tmp/compileJava/compileJava-mappings.tsrg`
- 编译前只删除这两个文件并保证父目录存在。编译结束后文件缺失、refmap 不是带非空 `mappings` 和 `data.searge` 的 JSON，或成员文件没有 3 段字段行 / 4 段方法行，任务失败。
- `reobfJar` 的类型是 `RenameJarInPlace`。`extraMappings.from(memberMappingProvider)` 在配置阶段接入，并依赖 `compileJava`。原来的 `getMappings()` 不动。refmap 和 `extractSrg` 不送进 SpecialSource。
- `copyMixinRefmap` 把处理器 refmap 复制成 `build/generated/mixin-refmap/xueximod.refmap.json`。这个目录用 `builtBy` 挂到 main output，不经过 `processResources`。`jar` 和客户端 run 任务依赖这次复制。`jar` 打完后如果根上不是恰好一份 `xueximod.refmap.json`，任务失败。
- 各个 run 设置 `mixin.env.remapRefMap=true`，`mixin.env.refMapRemappingFile` 指向 `createSrgToMcp` 的输出（SRG → 官方名，文件名是 `output.srg`）。这些 run 任务依赖该输出生成。没有 `disableRefMap`，没有全表 `remap: false`，没有把 `require` 改成 0，没有关 target validator。

`xueximod.mixins.json` 的 `refmap` 是 `xueximod.refmap.json`。客户端 Mixin 以 `src/main/resources/xueximod.mixins.json` 的 `client` 数组为准。本文不另列一份清单。

IDE 直接编译不会带上这些 `-A` 参数，不能代替这次 Gradle 构建。
