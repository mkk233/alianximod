## 路径

本地包是 `com.bslx.XueXiMod.animation.core`。数学在 `math`，骨架在 `model`。类和方法名保持可追踪。局部变量、参数和字段按项目命名门禁加长，坐标字段是 `coordinateX`、`coordinateY`、`coordinateZ`，四维再加 `coordinateW`。

逐文件来源、原样范围和裁剪见根目录 `THIRD_PARTY_NOTICES.md`。

## 原样保留的计算

- 关键帧时间采样、姿势并集插值、关节局部变换和父矩阵按上游顺序相乘。
- `TransformSheet` 的二分找帧仍是区间收缩。低于首帧取首帧，高于末帧取末帧。负时间不再先加上末帧时间或剪辑时长。
- `JointTransform.toMatrix` 仍是平移、右乘旋转、再缩放。`OpenMatrix4f(JointTransform)` 仍是上游那条先旋转、再平移、再缩放的构造，两条顺序不同，没有合并。
- 骨架姿势先把当前关节矩阵交给子关节，子关节返回后再按需要右乘去原点逆矩阵。
- `Vec3f` 变长参数 `average` 仍乘以数量。`getMostSimilar` 仍使用上游的点积括号。

## 裁剪

- `TransformSheet.getCorrectedModelCoord` 与 `transformToWorldCoordOriginAsDest` 去掉未使用的 `LivingEntityPatch` 参数。`Vec3` 改为 `Vec3f`。坐标公式还在，这不是攻击位移或无敌系统。
- `Armature` 去掉开发环境日志和 `JsonAssetLoader` 的 JSON 导出。找不到关节时 `getOrLogException` 返回 `Joint.EMPTY`。
- `Vec3f` 去掉 Epic Fight 日志和 Minecraft `Vec3` 互转。零长度求旋转直接失败。
- `MathUtils` 没有整文件复制。没有 Camera、PoseStack 或世界射线。
- `Vec2f` 并进 `Vec3f`。`Vec4f` 保留，因为矩阵乘向量需要 `w`。
- `AnimationTransformEntry` 不再依赖 Mojang `Pair`。`Armature` 的 id 映射改为 `HashMap<Integer, Joint>`。
- 共享静态缓冲改为方法内临时对象，避免并发把采样写成脏值。
- 不可逆矩阵不再改写成单位矩阵。结果非有限时抛出 `IllegalArgumentException`。
- `Joint.HierarchicalJointAccessor.equals` 补上了上游丢掉的返回值，按路径签名比较。
- 没有接入 Epic Fight 模组依赖，没有改伤害、费用、冷却或现有术式类。

## 生产边界

- 采样时间、关键帧时间和变换分量必须有限。两帧及以上的时间必须严格递增。单帧轨道恒定，进度为 0，不除以零。
- 空轨道的 `getInterpolatedTransform` 返回空变换。`AnimationClip.getPoseInTime` 在没有关节时返回空姿势。
- `clipTime` 必须有限，允许小于等于 0。`loopedSampleTime` 在时长不大于 0 时返回 0，不做取模。普通 `getPoseInTime` 不循环。
- 关节 id 在 `[0, jointCount)`，层级内唯一，关节数等于 `jointCount`，无环。深度超过 `Joint.HIERARCHY_DEPTH_LIMIT`（1024）时失败。
- 绑定矩阵必须有限且行列式非 0。`initOriginTransform` 与 `getPoseAsTransformMatrix` 不把 NaN 写入姿势矩阵。
- `Keyframe`、`TransformSheet.getInterpolatedTransform`、`AnimationClip.getPoseInTime`、`AnimationClip.loopedSampleTime`、`Armature.getBoundTransformFor` 和 `Armature.getPoseAsTransformMatrix` 可以直接被外部程序调用。没有加入 JUnit。

## 相对上游的采样与所有权

上游普通采样在时间为负时会加上末帧时间或剪辑时长，只加一次。本地改成夹取：低于首帧取首帧，高于末帧取末帧。烘焙和未烘焙同一含义。循环只由 `loopedSampleTime` 取模，时长不大于 0 时返回 0。

`Keyframe` 的时间构造后不变，已去掉 `setTime`。要改时间就新建 `Keyframe`，再放进新的 `TransformSheet`，由整轨严格递增检查接受或拒绝。构造和 `getKeyframes` 不交出内部数组。`transform()`、`getStartTransform`、`getInterpolatedTransform`、`AnimationClip.getJointTransform`、`getJointTransforms` 和 `getPoseInTime` 交回副本。剪辑在 `addJointTransform` 时复制轨道。校正方法改拥有的关键帧，`getCorrectedModelCoord` 和 `extendsZCoord` 仍返回写好的新轨道，`correctAnimationByNewPosition` 仍改调用方自己的那份。外部改副本不会留下旧的烘焙缓存。

`MathUtils.getAngleBetween` 在任一向量长度不超过 `1e-5` 时返回 0，其余余弦夹到 `[-1, 1]`。`correctAnimationByNewPosition` 的水平投影近零时偏航为 0，平移和竖直仍用原公式。

### 加载和采样

加载按固定提交 `9d25f19c` 的主动作入口：轨道按 JSON 顺序，根校正标志开始为真。`IK_left` / `IK_right` 以及其它 `IK*` 只登记后跳过，不消耗标志，也不生成骨。`Coord` 校验后丢掉，不作为骨，不推动实体，但把根校正标志置假。已知骨先转置，只有标志仍为真才左乘绕 X 轴 -90 度，然后消耗标志，再左乘该骨转换后的 localBind 的逆。绑定转换单独做一次。FK 仍用核心的父矩阵 × 绑定 × 增量。

每条轨道用自己的时间采样，不拿 Root 的帧号去套别的骨。缺轨道、哈希不符、未知骨架或未知辅助轨只隔离或拒绝该条，不让整份注册失败。别名 `epicfight:biped/combat/dagger_dual_airslash` 和 `sword_dual_airslash` 共用一份剪辑。

可采样不等于已经还原完成。带 Coord 或 IK 的 35 条是降阶：辅助运动被丢掉，观感可能和上游运行时不一样。生产加载能读这 118 个 ID 和 117 条剪辑。固定上游对照、刚性重定向和真实矩阵缓存的断言计数见 [动作构建验证说明](动作构建验证说明-2026-10-24.md)。游戏观感还没有验。加载器不把这 118 条标成 ready，也不回写清单的 `pending-runtime`。

### 注册和播放

`ActionRegistry.registerPlayable` 接受新动作。`ActionPlayer` 只按定义采样，没有术式 ID 分支。原创示例是 `xueximod:example/acknowledge`，一个 0.36 秒的点头，不进入正式术式列表。

发行版目标骨架是 `xueximod:target/humanoid`。绑定是按米手写的 Root、Body、Head、ArmRight、ArmLeft，没有抄授权 localBind。水刃兜底是：

- `xueximod:fallback/water_blade_left`
- `xueximod:fallback/water_blade_right`
- `xueximod:fallback/water_blade_horizontal`

`WaterBladeActionMap.resolve(拍号)` 在对应的 `sword_auto1`、`sword_auto2`、`sword_auto3` 可采样时返回那条开发姿态，否则返回上面的原创兜底，并写明兜底不是上游动作。播放器不认识拍号。

播放器支持 play、replace、stop、pause、resume(long)、finish(long)。速度要是有限正数且不超过 20，时长要是有限正数，循环在时长不足时拒绝，混合在 0 到 2 秒。时间事件只进视觉通知；一步跨过整段循环时每个事件最多派发一次。取消和自然结束各自最多一次。

结束判断用未取模的累计秒，不用循环取模后的采样时间。事件游标只向前走；更早的采样或更早的 tick 不把游标拉回去，也不会重放已经派发过的事件。暂停记下这份累计时间和当时的混合进度；恢复只从暂停态回到同一条播放器，把暂停占用的 tick 从播放和混合时钟里扣掉，不重播、不重发开始。暂停期间采样仍保留混合后的姿势。`finish(long nowGameTick)` 由调用方给出关卡 gameTime。循环和暂停停在该时刻的姿势上；非循环的自然结束停在定义时长的末帧。重复结束只通知一次。无参 `finish()` 在还没结束时会拒绝。stop、finish 和其它终态不能恢复。

### 服务端会话

`ActionRuntime.play`、`stop`、`pause`、`resume` 和 `notifyAttackGroup` 都在服务端检查玩家。会话带主人 UUID、实体 ID、维度、纪元、递增序号、开始时的维度 gameTime，以及可选的攻击组 ID。成功的攻击组只播放一次；再提交同一组不会重播。后一次姿态替换不会取消旧的攻击几何，本批也不碰命中实体。

`notifyAttackGroup(ServerPlayer, UUID, ResourceLocation)` 仍保留，但直接拒绝，不再播放。命令 `/xuexi action play` 不走许可。真正播放用：

`ActionRuntime.notifyAttackGroup(ServerPlayer player, CommitPermit permit, ActionCommit commit)`

`CommitPermit` 在 `com.bslx.XueXiMod.animation.runtime`。构造是 `new CommitPermit(UUID ownerId, UUID groupId)`。它只保存主人和攻击组编号，并用 `consume()` 记一次消费。构造不证明发生过攻击。`HostGroupReceipt.commitPermit(ownerId)` 只在 `COMMITTED` 时懒创建并缓存同一份许可。水刃成功的 `notifyCommit` 回调用这份许可调用上面的入口。动画失败只降视觉，不回退拍号，也不再收一次费。接上这一入口时没有启动游戏。后来的构建状态见 [动作构建验证说明](动作构建验证说明-2026-10-24.md)。

调用先核对玩家 UUID、许可主人和 `ActionCommit.groupId()`。对不上就不消费。对上之后只消费一次。开发动作不可播放时，同一次调用里改播原创兜底，不再消费第二次。消费之后成功或失败都不能重试，也不退回拍号。缓存里没有这个组时，运行时不会自己造许可。

防重记录在 `GroupReplayLedger`。每个主人最多 `256` 条，保留 `1200` 个服务端 tick。正常 finish 和 stop 把记录标成终态，不立刻删。超过条数或超过 1200 tick 之后，旧许可仍然是已消费，不会再播。死亡、离线、换维和停服清掉该主人或全部记录。正在播放的会话单独放着，不跟这些记录绑成一份永久全集。

回执 `groupId()` 是攻击组 UUID，`startGameTick()` 是开始时的关卡 gameTime。素材缺失只换姿势，不回滚伤害或费用。

### 冻结挥斩帧

给 A/B：`directionX/Y/Z` 是世界空间里冻结的弧中心前向 F，对应最终 `ArcBandSnapshot.forwardAxis`。`planeX/Y/Z` 是带符号的单位法线 N，对应 `normalAxis`，不是 right，也不是 up。右手系里 R = N × F。弧上原来的关系是 N = F × crossAxis。B 复制已经验收的快照，不要在释放时按玩家朝向重算。

`ActionCommit.framed` 会把 F 归一化，去掉 N 沿 F 的分量后再归一化，然后保存这对规范向量。零向量、平行、NaN 和无穷大直接拒绝，不挑备用轴。`ActionCommit.group` 没有帧，`hasSlashFrame` 为假，六个分量保持 0。拍号只选素材，不旋转这个帧；世界平面由最终帧决定。帧只是视觉元数据，校验失败不重算伤害或费用。

网络仍是原来的六个 float。接收端用 `ActionFrame.resolve`：没有帧就清成 0；有帧但不成立时降成没有帧，不把 NaN 放进采样上下文。

结束和取消沿用开始时的序号。同一序号里的暂停、恢复和快照用递增 revision 分先后；旧 revision 丢掉。终态之后，同一序号的迟到开始或恢复都不能把姿态复活。恢复不是新的 START。客户端用关卡 gameTime、开始 tick 和暂停偏移取样，不按收包时刻从 0 播放，也不读 `serverTickCount`。晚到且已经超过权威时长的单次动作直接结束。旧序号和旧纪元拒绝。中途追踪发的是带同一时钟的完整快照。

权威时长是服务端动作定义的时长。源剪辑自己的关键帧时间可以不同。客户端没有开发剪辑时，用包里的原创兜底，按同一段归一化进度把兜底剪辑拉开到这个权威时长，而不是把速度改成 1。开发开关关闭时仍是原创兜底。

死亡、离线、换维和实体离开会清会话并推进纪元。不写 NBT。同步包是 `ActionSyncS2CPacket`，通道序号 9，只有服务端发往客户端。通用代码不引用 `net.minecraft.client`。

客户端在入队前记下这条连接，执行时如果已经不是同一条连接就丢掉，避免断线前排队的旧包在清空之后把姿态复活。`ClientLevel` 实例换了，或者断线，会清空视图；不靠维度名字，也不只靠旧维度的取消包。同一维度重新连上后，新的纪元 1、序号 1 可以播放。同一条连接上，旧序号、终态和更低的 revision 仍然不能把姿态复活。视图保存实体网络 ID、维度和连接身份。采样时当前实体的 UUID 和网络 ID 都要一致，否则 `active` 为假。
