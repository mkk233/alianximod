## 接通点

第三人称在 `EntityRenderDispatcher.render` 里重定向唯一的 `EntityRenderer.render` 调用。只有 `PlayerRenderer` 会保存模型、推入当前 partial tick、调用一次原来的公开渲染，再在 finally 里恢复。其它实体原样调用。`require = 1`。

姿态写在 `PlayerModel.setupAnim` 调用 `HumanoidModel.setupAnim` 之后、袖子裤子外套 `copyFrom` 之前。因此外套复制的是动作姿态。护甲层随后 `copyPropertiesTo`，手持层 `translateToHand`，都发生在这次渲染返回、模型恢复之前。头饰在父类里已经复制过，所以改头之后再抄一次旋转。

第一人称重定向 `ItemInHandRenderer.renderHandsWithItems` 里的两个 `renderArmWithItem` 调用，`require = 2`。映射字节码里这两处都在 `ForgeHooksClient.renderSpecificFirstPersonHand` 返回真并跳过调用之后，取消的手不会被重画。真正接管的剑手只把这一次调用的 `swingProgress` 改成 0，装备进度和玩家字段不动。挥砍进度为 0 时，原版那次平移和两段攻击旋转净效果是单位旋转。动作矩阵注入在 `applyItemArmAttackTransform` 之后、方法末尾 `popPose` 之前，仍在原来的 push/pop 里面，枢轴是原版手部平移之后的原点。

共享模型用每层自己的快照，不用单个静态槽，也不调用 `resetPose`。`PoseStack.poseStack` 用 accessor 读深度；finally 只把多出来的层退回到入口深度，深度已经不足时不补推。异常继续抛出。

## 采样

渲染只调用 `ActionClientPlayback.inspect`。时间是实体所在关卡的 `gameTime` 加上这次渲染的 partial tick。不另建播放器，不在渲染里推进。`active == false`（含结束和取消）时不改原版。空姿态不当作正在播放。

## 重定向

源模型和原创骨架分开选 profile，不按术式 id 或 `water_blade` / Epic Fight id 分支。

源 profile 只用于 loader 已经转换过的模型空间，`Q = diag(-1,-1,1)`。相对旋转是 `Q * (Rcurrent * inverse(Rbind)) * inverse(Q)`。骨骼矩阵来自 `Armature.getPoseAsTransformMatrix(pose, false)`，不乘 inverse-bind，也不再乘 loader 的 C。

腿只取 `Thigh_R` / `Thigh_L` 的模型旋转。膝弯和落脚位置不还原。躯干读 `Chest`，它的父链已经含 `Torso`。头和手臂是原版同级 `ModelPart`，写入含父链的模型结果，不再乘一次身体。肩和髋随身体整体绕枢轴变换。

手臂优先用 `Hand` 到 `Tool` 的方向，加上手的扭转轴。绑定帧用同一套参考架，相对旋转去掉绑定偏角。武器方向不直接当成原版下垂轴。没有手或武器骨时退回手臂骨。`Elbow` 仍是侧支，不串进手的父链。

原创骨架按自己的约定：右臂在 `+X`，上方向是 `+Y`，单独使用 `diag(-1,-1,1)`。这组符号是按原创轴向写的，不复制授权 bind 数值。原创骨架没有大腿，腿保持原版。

静止且关节仍在采样里时，相对旋转是单位阵，写到原版的欧拉角是 0。不在采样里的部位保持原版行走、抬头和蹲伏。采样里的手臂会盖掉原版攻击挥砍，不写 `attackAnim` 或其他游戏字段。

## 挥斩架

`direction` 是世界前向 F，`plane` 是带符号单位法线 N。`R = N × F`。对齐是目标架乘这条素材参考架的逆。拍号不额外滚转，也不把玩家搬到命中原点。

`ActionVisualCatalog` 按 `visualActionId` 分开登记类别和配方。`audited-whitelist.json` 的 118 条是 116 条 blade 加 2 条 roll。剑、刀、巨剑、打刀、太刀、长剑和双持都是 blade；`roll_forward` 与 `roll_backward` 是 roll，不是 blade。类别可以没有参考配方。未知 id 不猜测，也不是 blade。适用手按 epicfight `9d25f19c` 的攻击相位和武器注册：相位同时点名左右工具，或该动作只属于双手各持一把的双持生活、格挡、空斩和刃突，登记双手；相位只点名左手工具的登记左手；其余登记右手，包括双手握持同一把武器，以及只打右手的双持连段。只有六条水刃带配方。水刃三条开发剪辑用各自 `Tool_R` 关键帧：`sword_auto1` 是 0、0.1、0.6 秒，`sword_auto2` 是 0.0833、0.2167、0.6 秒，`sword_auto3` 是 0、0.2、0.6 秒。三条原创兜底用作者关键帧 0、0.45、1；左斜和右斜读下垂轴，水平挥砍的下垂轴不动，改读侧向轴。参考 F/N 只对带配方的动作，在剪辑和骨架对象换掉之前只算一次，存在客户端缓存。没有配方就不校准，也不做世界对齐。退化就标未校准，不用通用参考架冒充。授权剪辑算出的向量不写进源码、默认资源或发行包。重载后对象身份变了就重算。算法通过不等于游戏里已经看过。

第三人称在玩家渲染入口记下 PoseStack，`setupAnim` 时读同一条矩阵。这样身体偏航、`scale(-1,-1,1)`、游泳和鞘翅都在世界到模型的变换里，不另写泳姿公式。没有这份矩阵时才退回只含偏航和翻轴的算法，供脱离渲染栈的数学探针使用。死亡由动作生命周期取消，不单做一种对齐。局部结果乘回这份矩阵后，仍落在冻结的世界 F/N 上。

第一人称不用第三人称那份 q。模型旋转按视角轴 `diag(-1,-1,1)` 共轭到相机，参考 F/N 用同一个共轭，再对当前相机的 look/up/left。无挥斩架时不做这一步世界校正。

## 谁接管

类别只来自目录，不按 id 字符串猜测。

已登记的剑或刀，在目录写明的那只手仍是 `SwordItem`，且没有吃喝、格挡、弓、弩、长矛、望远镜、刷子或喇叭时，第一人称接管这只手的普通姿态。没有挥斩架，没有配方，或参考架未校准，就省略世界校正。翻滚和未登记动作不改第一人称相机。

第三人称没有挥斩架时按采样骨播放，不要求持剑。翻滚只改姿态，不位移、不开无敌、不改碰撞箱。有挥斩架且参考架已校准的剑或刀，仍要求目录里的手持剑；没有配方的动作照常播放，不声称已经贴上挥斩平面。

## 第一人称物品轴

比较轴在原版物品显示旋转之后。铁剑 `firstperson_righthand` 的旋转是 `[0, -90, 25]`。左手条目是 `[0, 90, -25]`，`ItemTransform.apply` 对左手再把偏航和滚转取反，所以两边的剑身轴相同。这条物品模型的剑身基轴是 `+Y`。均匀缩放不改变方向，平移不进入轴，这条模型没有额外的 `rightRotation`。179 条断言核对的是这条基轴经过原版 `ItemTransform` 后的方向。这不等于每一种自绘剑纹理或姿态观感都合格。

挥砍进度为 0 时，原版攻击变换是绕 Y 的 `+45` 再 `-45`，净旋转是单位阵，不把 45 度算进动作误差。中性动作的最终轴等于这套原版显示轴。非零动作再乘手部旋转。左右手都按这条链比较。动作四元数仍在 `renderItem` 之前乘上，显示旋转继续由原版乘。

## 接线

目录和参考缓存由 `ActionRenderQueries` 调用。世界到模型的矩阵由现有 `EntityRenderDispatcher` 重定向推入，`PlayerModel.setupAnim` 读取，不新增 mixin 配置。`require` 仍是第三人称 1、第一人称 2。finally、模型快照、Forge 取消后的调用点和外套复制顺序不变。

## 限制

- 生产 refmap 和 reobf 产物的映射核对见 [动作构建验证说明](动作构建验证说明-2026-10-24.md)，那些数字属于前一批刚性版本。最新蒙皮批次还待主控完整编译和用户实机验证。描述符来自 Forge 1.20.1-47.3.33 的 parchment 映射缓存。
- 目录覆盖自动核对已通过。渲染器的独立审阅已经通过。动作类别清单的独立只读复审也已通过。自动通过没有把已发现的问题都说成根治。
- `@Redirect` 独占上述调用点。别的模组如果重定向同一个 `EntityRenderer.render` 或 `renderArmWithItem`，会冲突。这里不为此加依赖，也不保证与所有模组兼容。
- 现行绘制是蒙皮。刚性 fallback 仍在：肘、膝、脊柱公转和完整武器握姿在这条 fallback 上是降阶。肩和髋随身体整体绕枢轴变换。实机是否分离尚未验证。
- 翻滚只改姿态，不位移、不开无敌、不改碰撞箱。
- 外围 finally 不能找回已经被错误 pop 掉的矩阵，只能退回多推的层。
- 瘦手臂的半像素侧移仍由 `translateToHand` 临时处理，本实现不改那个量。
