## 1. 现在到底做了什么

共享底座、三套水体、箭适配和原版近战入口已经接到生产代码。跨批收尾也已接上：后面的合格水体仍可成交，写水幕标记前跳过被完整承接取代的那一面墙，放出后用体积判断是否真的离开宿主。

## 2. 确认规则

1. 水势门槛是 20。必须有当前有效水体实际接住来袭。没有水术式不能变全身护盾。偏转费不在释放术式时预扣。可用水势 `M` 是余额减去尚未提交的预留，也就是 `WaterMomentum.available`。
2. 近战成功承接扣 20，免掉这一次直接伤害、击退和有害命中效果，不新加持续无敌。
3. 弹射物费用 `D` 是捕获时的剩余直接伤害，按无甲、无抗、无盾的目标计，含力量和这一次暴击，不含之后的燃烧和毒。暴击只抽一次，转手不重抽。`M >= 20` 且 `M >= D` 时完整偏转，扣 `D`。`20 <= M < D` 时耗尽 `M`，1 点水势永久削 1 点伤害，剩下的再走旧基础减伤，不卷入、不弹出。`M < 20` 不卸力，只走旧流程。20 是资格，不是最低费用。`D` 小于 20 且水势够付时，只扣 `D`。
4. 每一支箭完整偏转最多 3 次。换飞行段、换主人都不重置。部分卸力不计这 3 次。到 3 次之后不再扣水势、不再卸力，普通防御和旧收益照常。同一次接触只有一个宿主能占住；三分不能各扣一笔。弹出之后可以再被另一次合法接触偏转，总数仍不超过 3。
5. 水幕按入射和墙面法线反射，保留速度和重力，不追踪射手。水环按当前环面绕 6 tick，到随机环上出口朝外甩，不能射回本人。缺月只在真实活动挥斩切片上承接，沿剩余水弧走到末端，再按末端切线打出。拖尾不拦，不延长活动窗。公式在第 8 节，三套宿主已按这些公式登记。
6. 卷入时原箭不能继续飞、不能继续伤害。服务端说了算。仍是同一支弹，尽量留下火焰、药水、穿透。宿主死亡、消失、主人离场或卸载时要安全放出或安全结束，不能复制、丢箭或永久悬空。异常不能伤到友方。卸载清掉该维度的宿主登记。被抓住的箭沿保存的出口或入射方向放出，不新扣一次，也不另计完整次数。
7. 归属改到承接术式的施术者。反击造成的实际伤害正常积势。自己和盟友的来弹放行，不扣款。偏转后的弹不伤新主人和盟友，原来的有害附带效果也不能绕过。盟友沿现有 `Relations`，不另造盟友系统。`Relations.ally` 现在恒为假，`permits` 只认主人自己的 UUID。
8. 用了水势卸力之后，这一次卸掉的量以及其后的基础减伤都不回势。实际受伤和反击正常回势。没用到水势，或已经满 3 次的普通防御，保留旧收益，不能把收益全局关掉。例子：`D = 30`、`M = 25`、水幕 50%。扣 25，直接伤害剩 5，水幕再收到 2.5。被抵掉的 27.5 不回势，最后实际的 2.5 按旧的实际伤害回势。
9. 水环 20%、水幕 50%，以及没有友方阻挡这些已有行为，都留作没偏转时的退路。当前没有“余额放大攻击或范围”的动态入口，本文不虚构删除。潮印每条 +2 伤、+5 湿、施术者 +2 势保留。缺月原来的重水 20 和重压湿 26 从生产登记关掉，水势改给偏转。深海重压这个领域和它自己的减速、潮湿、耗氧不删。缺月潮湿 6 和三向斩面不删。
10. 缺月三面、近身径向体积、冷却、`ReleaseBatch.Tally`、动作宿主拍号、剑追踪、旧编号别名和存档兼容都不改。新能力走公共宿主，不按术式 id 分叉。
11. 首批完整支持原版箭：普通箭、药箭、光灵箭，包括骷髅和弓、弩射出的。药箭的类仍是 `Arrow`。三叉戟、火球、药水瓶、自家法术弹以及其他未知 `AbstractArrow` 子类保持原行为，不扣偏转水势。不能写成支持全部弹射物。

## 3. 报价

`DeflectionEconomy.quote(available, direct, fullCount, isMelee)` 是纯函数。`available` 由调用方传入，生产路径传 `WaterMomentum.available`。

常量：`QUALIFYING_FUNDS = 20`，`FULL_DEFLECTION_LIMIT = 3`。字段名不用 `MAX`，命名门禁把拆开的 `max` 当成含糊缩写。

结果是 `NONE`、`FULL` 或 `PARTIAL`，外加 `cost` 和 `remaining`。`spendsFullAttempt()` 只有 `FULL` 为真。

顺序：

1. `available` 不是有限数，或小于 0：`NONE`，费用 0，剩余 0。
2. 近战：不看 `direct`，也不看 `fullCount`。`available < 20` 则 `NONE`，剩余就是这份可用额。否则 `FULL`，费用 20，剩余 `available - 20`。近战不是“每一支箭三次”的那一枚。
3. 弹射物 `fullCount < 0` 或 `fullCount >= 3`：`NONE`，费用 0，剩余为可用额。调用方传入的是已经完成的完整次数。
4. `direct` 不是有限数，或 `direct <= 0`：`NONE`。0 和 NaN 都拒绝。
5. `available < 20`：`NONE`。
6. `available >= direct`：`FULL`，费用就是 `direct`，剩余 `available - direct`。
7. 否则 `PARTIAL`，费用是全部 `available`，剩余 0。

报价不把 `direct` 再取整。调用方传进来的数已经是冻结后的剩余直接伤害。

服务不保存完整次数。次数放在箭的 `DeflectionMarks.FULL_COUNT`，跨飞行、换主和重进世界。只有完整偏转并且 `commit()` 成功之后，调用方才加一。部分卸力不加。报价本身不会把 `PARTIAL` 记成一次完整，服务也不会私自把次数从 0 改成 1。

## 4. D 怎么冻结

箭适配按这一节冻结 `D`。`tryAcquire` 只接收已经算好的 `direct`，自己不读速度，也不调用 `Random`。

只对首批支持的箭，并且这次接触已经是水势交易候选时才冻结。普通飞过、友方放行、未支持弹种、门槛不够、已经满 3 次，都不提前改随机、不改 `baseDamage`。

候选上的 `D`：

1. 取这一刻 `getDeltaMovement().length() * baseDamage`。
2. 按原版 `Mth.clamp` 到 `[0, Integer.MAX_VALUE]`，再 `Mth.ceil`。
3. 暴击旗标为真时，按原版 `nextInt(i / 2 + 2)` 抽一次，加回后再夹到 int 上限。旗标在发射时已经确定，抽到的整数原版不写 NBT。
4. 若当时存在根箭领域伤害贡献，把那一段加上。`ArrowAuraMixin` 改的是暴击之后、`LivingHurtEvent` 之前的浮点。领域加值不在原版 328–351 的整数里，所以必须显式加上，不能指望它已经在 ceil 结果中。
5. 不含着火、药水、光灵这些后续。

得到的数写入 `DeflectionMarks.REMAINING_DIRECT`。之后任何命中或再次捕获都读这个数，当作 `direct`。不用新速度，不用新主人重算，不重抽暴击，不把领域再加一次。

部分卸力提交成功后，`REMAINING_DIRECT` 减去这次 `cost`。这是唯一写回剩余直接伤害的卸力。

水幕 50% 和水环 20% 只乘在随后那一次实际 `hurt` 上，不写回 `REMAINING_DIRECT`。下一击仍从剩余直接伤害再乘比例。例子里的 5 点会在当次被水幕收到 2.5，存档里的剩余直接伤害仍是 5，不是 2.5。

完整偏转不把剩余直接伤害减成 0。它花掉的是水势里的 `D`，这一次不命中。下次再捕获时，`direct` 仍是这份剩余值，除非中间有过部分卸力。

## 5. 时序

生产上的收购必须在主服务器线程。

完整承接发生在 `AbstractArrow.tick` 里、原版 `findHitEntity` 使用这一段位移之前，并且必须早于方块和合法实体。只有完整承接才取消这一拍剩余的 tick，从而停住穿透循环、着火、`hurt` 和药水。不能 `discard()`，不能用 `ProjectileImpactEvent` 的 `STOP_AT_CURRENT_NO_DAMAGE`（那会删箭）。只取消 `onHitEntity` 会让穿透循环再次选中同一目标。只把 `LivingHurtEvent` 改成 0 挡不住击退、药水和删箭。暴击在进入交易前按第 4 节抽一次；已经冻结之后，`onHitEntity` 不再重抽。

调用顺序：

1. 先判断是不是支持的箭。不是就原样返回，不报价。
2. 友方来弹放行，不报价、不扣款。放行看 `IncomingPassage.letsPass`，不看 `passedOver()`。
3. `DeflectionHosts.contactsOrdered` 取这一段上的全部合格接触，按 `segmentT` 再按 `HostKey`。没有真实水体才离开这次接触。最近一项不合格时继续看后面的，不在这里停住。
4. 用箭的 UUID 和当前接触序号组成 `AttackKey`。序号不是玩家加 tick。同一段里的候选共用这一次抽好的 `D`。
5. `tryAcquire`。只有 `acquired()` 为真才允许改这支箭。失败的预留先 `close()`，才能看下一个宿主。
6. 宿主仍然有效才 `commit()`。`close()` 放在 finally 里。没提交就退预留。
7. `FULL` 且提交成功：停飞、按路线带走，不执行着火、`hurt`、药水。次数加一。放出时用 `armSameTickGate` 记下真实出口，并用 `covers` 保持退出闩，直到箭体离开该宿主。
8. `PARTIAL` 且提交成功：先把剩余直接伤害减去费用，再让原版 `hurt` 继续。`hurt` 期间用 `MitigationCreditScope.open(victim, damageSource, true)` 包住。旧比例照算，减伤不回势，实际掉血仍回势。次数不加。这一次成交后不再改问下一个宿主。
9. 未收购且 `passedOver()` 为假：门槛不足、满三次、伤害非法或预留失败。这一宿主不偏转。门槛不足可以继续看后面的宿主。满 3 次则整支箭不再卸力，旧防御和旧收益保留。
10. `passedOver()` 为真：这支箭已被占用、这个序号已经结算，或同 tick 离体闸门挡住。不要再扣，也不要换成另一个宿主扣第二次。它不是友方放行。已经存在的基础减伤仍然保留，不要因为这个标志删掉水幕标记。

报价本身仍然只有三种。调用方必须先看 `acquired()`，不能只看报价去改箭。预留失败时报价可以是 `FULL` 或 `PARTIAL`，但 `acquired()` 为假，账不变。

缺月三面是三个宿主、三把 `HostKey`。公共查询按 `segmentT` 取序，不按面另扣，也不另给次数。占用期间同一支箭不能再开第二笔。

近战在 `Player.attack` 和 `Mob.doHurtTarget` 里、火焰附魔预置之前收购，提交发生在真正的 `hurt`。身份用 `AttackKey.melee(攻击者, 受害者, 调用方给出的接触号)`，不要在底座里拼玩家加 tick。成功则扣 20 并取消这次 `hurt`，击退和附效不继续，不延长无敌。预置的火要能退回：玩家仍走原版只撤销这一次点着的火；怪物没有失败回滚，所以写回预置前的着火 tick。

## 6. 接触、路线和闸门

`HostKey` 是宿主 UUID 加生成号。生成号用于换代。不用队列视觉序号，也不用三分的复制号。

`HostContact.segmentT` 就是线段参数 t，0 是起点，1 是终点。字段不能叫 `t`，命名门禁不允许短于 3 个字符。`DeflectionHost.intersect` 的终点参数叫 `toward`，同样是因为 `to` 只有两个字符。调用按这个真实签名写，不要改回短名字。

注册表只查已经 `register` 的宿主，按 `ServerLevel` 引用过滤，不扫描世界上的径向体积或护体。停用、`segmentT` 越界、非有限坐标、接触上的宿主实例和登记实例不一致，都丢掉。平局容差 `1.0E-9`，然后比 `HostKey`。

`CaptureRoute` 只描述位置和完成标志，以及紧急放出的位置和单位方向。速度幅值留在弹体适配器，宿主不复制箭的运动状态。本包没有默认路线，没有“调用就返回成功”的空实现。

同 tick 离体闸门 `SAME_TICK_RELEASE_CLEARANCE = 0.75`。完整偏转提交时，用这次接触点先记一笔；弹体若知道更准确的出口，再调用 `armSameTickGate`。同一 `gameTick`、同一支箭、新接触点与任一放出点的距离平方不超过 `0.75²` 时，`passedOver()` 为真，不预留。下一 tick 这些闸门失效。闸门不占用那 3 次，次数仍看调用方传入的 `fullCount`。0.75 大于水幕厚度 0.25，也大于水环带宽 0.12。环的出口在 6 tick 之后，不会被这一闸门误伤。这个距离没有进游戏调过。

部分卸力提交后，同一个 `AttackKey` 记入已结算。连续重叠再来一次不报价、不预留。离开全部有效水体后，弹体把 `CONTACT_SERIAL` 加一，新序号才是新的接触。服务不判断箭有没有离开水，它只认序号。

收购占住期间，同一支箭的任何序号、任何第二宿主都不能再预留。不同箭的 UUID 即使在同一 tick 也各自独立。事务在 `close()` 时放开占用。`commit()` 成功后占用仍留到 `close()`，避免提交和关闭之间被自己接回去。

宿主在预留前、预留后和提交前都会再看 `active()`，需要登记的路径还会再看注册表是不是仍是同一个实例。失效或已注销则不提交，`close()` 退回预留。

## 7. 账和减伤

`PlayerMomentumPurse` 是唯一生产账本：

- `available` 调用 `WaterMomentum.available`。
- `reserve` 调用 `WaterMomentum.reserve`。未接受，或费用不大于 0，则 `release` 并当成失败。
- `commit` 调用 `WaterMomentum.commit`。水势账自己会拒绝第二笔。
- `release` 只取消仍是 `RESERVED` 的预留。

这不是整套经济重构。出手时 `momentumSpend()` 仍是 0，原来的 0 点预留空操作还在。

`MitigationCreditScope` 是同步 try/finally 栈。配对用受害者和 `DamageSource` 的对象引用，不用 UUID，也不用 tick。只有 `partial == true` 的帧会让 `suppressesMitigated` 为真。嵌套时内层来源不同，外层仍只压自己的那一对。

`allowsMitigatedCredit` 在减伤额大于 0.001、且溺水抑制和偏转抑制都为假时才入账。`ReleaseBaseEvents.onHurt` 的场地减伤直接问它。`GuardMitigation.offer` 在入队时把 `suppressesMitigated` 抄进 `Note.deflectionSuppress`。tick 末尾的 `flush` 只读这个布尔，不再读线程栈。原来的 `suppressCredit` 仍是溺水策略抄下来的结果，语义没改。

`onDamage` 不调用这个栈。实际掉血和反击继续 `WaterMomentum.credit`。溺水仍只由 `MomentumCreditPolicy` 同时挡住减伤和实际伤害；偏转不借那条策略，也不借 `TideMarkDamageScope`。

因此 partial 要在 `hurt` 之前打开，并包住会触发 `LivingHurtEvent` 的那段。箭的命中和近战的主伤害都这样包。打开晚了，当场的减伤已经入账；只靠 tick 末尾的线程栈也来不及，所以才抄布尔。

## 8. 三条路线

水幕立即反射。宿主法线要朝向来弹那一侧。若 `incoming · normal > 0`，先把法线取反。反射 `v' = v - 2 (v · n) n`。弹体保留 `v` 的长度，重力仍走原版。不追踪射手。一个样本就可以 `finished`。

水环用接触当帧的环心、当前法线和半径 0.9，沿当前圆环走 6 tick。出口在环上，方向是离开环心的水平向外。主人若仍在环心，向外不会指向本人。主人已经离开环心时，若 `dot(向外, 主人位置 - 出口) > 0`，就另抽角度；有限次仍失败则取最不朝向主人的那个向外方向。不能随机指回本人。

缺月只用 `ProgressArcBand.advance` 给出的剩余进度，从当前进度到 1。不加大 `activeTicks`。拖尾不在窗口里，不能拦箭。现有 `direction` 是径向，不是切线。末端切线由位置对进度求导，不放进 `ProgressArcBand`，由缺月宿主在出口计算：

- `angle(p) = start + sweep * p`
- `radial(p) = forward * cos(angle) + cross * sin(angle)`
- `point(p) = origin + radial(p) * radius`
- `d(radial)/dp = sweep * (-forward * sin(angle) + cross * cos(angle))`
- 出口方向取 `p = 1` 的这个导数再单位化。`sweep` 为 0 时没有切线，宿主不应给出接触。

宿主消失、主人离场、换维、维护失败、`discard`、`broadcastRemove` 或区块卸载时，先让箭上持有的路线 `emergencyRelease`，再注销宿主。路线在宿主注销之后仍能给出当时的出口。正常走完也用 `emergencyRelease` 取设计出口，`active()` 在正常完成后仍为真，这不是宿主失效。维度卸载清掉该维度的宿主登记，被抓住的箭按第 6 条安全放出。注册表清空只是防止宿主对象跨世界留下来。

## 9. 换主、友方和保存

完整偏转提交成功后把主人改成承接者。`Projectile.setOwner` 在新主人非空时才改 UUID。传空不会清掉旧主人。`AbstractArrow.setOwner` 在新主人是玩家时会改拾取模式。必须先把原拾取序数写入 `DeflectionMarks.SAVED_PICKUP`，`setOwner` 之后再设回去。`leftOwner` 原版不会被清掉，也不要为了保护新主人去重置它。

新主人和当时的盟友写入 `EXCLUDE_OWNERS`：每个 UUID 两个 long，先高位再低位，追加而不是覆盖。着火、`hurt`、药水、光灵、穿透判定之前都要跳过这份名单。不额外回满穿透名额，不清 `piercingIgnoreEntityIds`，不清已经命中的名单。火焰、药水、光灵时长、穿透等级和 `ForgeData` 留在同一实体上。

友方来弹：`Relations.permits` 或 `Relations.ally` 为真则放行，不调用 `tryAcquire`。不要新做盟友存档。

反击的实际伤害仍由 `onDamage` 给新的攻击者加势。部分卸力这一次的减伤不加势；箭打中别人之后的实际伤害照加。

键都在 `DeflectionMarks`，由箭适配读写。没有另写位置包。被捕获期间用同步布尔取消客户端的自行积分，服务端继续按路线写位置。墙、环、弧自己的同步不负责驱动这支箭。

占用表、闸门和注册表都只在内存里。停服清空。维度卸载只移掉 `level()` 引用等于该 `ServerLevel` 的宿主，并放开这些宿主的占用。不调用 `WaterMomentum.releaseAll`，以免退掉别的预留。
