# 底座缺口实现指导

依据：`docs/底座缺口建议确认.md`。裁决：gpt-6-astra，2026-10-21。用户审核压过此前的默认建议。能量层已经在代码里，本指导不重做。

真实落点，按这些类写，不要另找同名类：

- 释放执行：`com.bslx.XueXiMod.network.SkillSegmentRunner.runSegment`。`SkillUsePacket` 只负责按键和调度。
- 命中结算：`com.bslx.XueXiMod.shu.technique.release.entity.TechniqueHitSettle.tryHit`。
- 魔力：`com.bslx.XueXiMod.player.PlayerShuData`。
- 模组注册：`com.bslx.XueXiMod.XueXiMod`。现在没有自定义药水效果注册。
- 形态链：`TechniqueHitSpec.spawn` → `TechniqueHitEntity` → `TechniqueHitRenderer`。
- 能量：`ReleaseDefinition.energyScale()` 默认 1，`CastFrame.volumeScale()` 已是能量乘附魔半径。

`ChainRole` 仍是 8 个。不按术式 id 结算。单文件不超过 500 行。玩家不能写弹道函数。

同字段覆盖、没有攻击时能量怎么处理、成品名展开、多运动并用、展开/旋转/包覆的别名、回流是当场还是下一次，这次保持现有释放链，不写配方编译器。

## 1. 语义合同

| 合同 | 这次 |
| --- | --- |
| 场地锚点钉在释放时的世界坐标，不跟镜头 | 做 |
| 贴身跟随的护体 | 不做 |
| 上空锚定单独底座 | 不做。高度继续走现有索敌或弹道 |
| 幻影底座 | 只留接口。不写分身 AI、伤害和战斗归属 |
| 潮湿 0～100，四档，每档 50 秒，药水效果，只能由术式挂上 | 做。底座是属性状态药水，潮湿是第一个 |
| 水势上限 100，溢出丢掉，和魔力分开 | 做 |
| 按实际打出的伤害和实际卸掉的伤害来加；受到伤害时积累，打出后消耗 | 做。同一次打出的顺序见第 2 节 |
| 旧攻击仍按伤害算魔力；防御和治疗另写花费 | 做费用入口 |
| 蓄力可以被打断，打断只清理，不放收尾高伤害 | 做。只给声明了蓄力的术式 |
| 水势只加这次拦截真正削掉的数值 | 做最小拦截口 |
| 随机形状服务端算，客户端只画 | 做 |
| 凝结是会消失的实体障碍 | 做。不改方块，不改流体 |
| 净化可以灭火 | 做 |
| 缠绕 | 不做 |
| 治疗、控制、卸力对其他玩家 | 还没定。不写阵营过滤，也不写成对玩家无效 |

场地是高级附魔，能单独释放。生成和维持都耗魔力。一分为三生成三个场地实体。索敌和弹道不改场地的生成位置，只附着在场地上。三块场地也只套用一次附着的索敌和弹道。伤害按施法者当下站在几块场地里乘倍数，站在三块里是 3 倍，站在两块里是 2 倍。除伤害外的效果不叠加，人只要站在任意一块里就按单份生效。不做位移争夺。

## 2. 水势账本

水势按实际伤害点记账，可保留小数，范围 0～100。魔力和水势分开。

同一次打出固定为：先扣这次预留的水势，再按这次实际造成的伤害加水势。效果不能花自己这一击刚刚打出来的水势。

1. 攻击提交前读取余额并预留。预留不能超过余额。
2. 发射前取消或蓄力中断：退回预留，不扣，也不算伤害收益。
3. 已经打出的攻击，即使没命中或伤害为 0，也扣掉预留；伤害收益为 0。
4. 消费量由效果自己声明。不是每次造成伤害都把水势清空。

| 事件 | 方向 | 数值 | 上限 |
| --- | --- | --- | --- |
| 持有者受到伤害 | 加 | 这次真正扣掉的生命和吸收之和。取消、无敌、完全挡住则为 0 | 最多 100 |
| 本模组卸力成功 | 加 | 拦截前伤害减拦截后伤害，最小为 0。只认这次拦截削掉的部分 | 最多 100 |
| 持有者造成伤害 | 加 | 目标这次实际损失的生命和吸收。先扣消费，再入账 | 最多 100 |
| 声明了水势消费的攻击实际打出 | 减 | 该次预留值，一张票据只提交一次 | 最低 0 |
| 治疗、灭火、挂潮湿、生成或维持场地 | 不动 | 没有实际伤害或卸力就不加水势。花掉的魔力不换成水势 |  |

伤害事务结束才记「实际受到」和「实际打出」。`LivingHurtEvent` 只负责卸力和记录削减差，不能把事件里的数字当成最终伤害。事务被取消时，待入账的卸力作废。一分为三若汇总成一次实际伤害，只记最终那一次。

## 3. 潮湿

自定义药水效果，放大器 0～3 对应四档。服务端另存精确值，和药水实例一起改。

| 潮湿值 | 档 |
| --- | --- |
| 0 | 无 |
| 大于 0 且不超过 25 | 一 |
| 大于 25 且不超过 50 | 二 |
| 大于 50 且不超过 75 | 三 |
| 大于 75 且不超过 100 | 四 |

每次术式成功加上正数潮湿：先累加并截断到 100，再把效果刷新为 1000 tick（50 秒）。同档、跨档、已经满值，都刷新。到期或主动移除时精确值归零。四档是强度，不是四段连着的时间。

这次只做累积、档位、50 秒、刷新、到期，以及别的术式读取档位的接口。减速继续用原版缓慢，点燃和灭火继续用现有着火接口。潮湿本身不自动灭火，也不绑定导电或冻结。不做成药水物品，不由站在水里自动挂上。

## 4. 场地

登记为现有的 `ChainRole.ACTION`，再带「高级附魔场地」能力。不新增第九个角色。执行器读能力，不读术式 id。

能力至少包括：区域、加成、附着的索敌和弹道、生成魔力、维持魔力和周期、寿命。

生成位置在套用附着的索敌和弹道之前，从这次释放的基础原点钉死。外观仍走形态链。`TechniqueHitEntity` 只挂场地行为，规则放在独立类。

一分为三发出三份生成请求，三个实体各自扣维持费。允许重叠在同一坐标。没有攻击的场地不进伤害汇总。三份的生成费先检查再一次扣除，魔力不够就一个都不生成。单独释放和链上有没有攻击无关，都走这个入口。伤害倍数不在生成时乘进场地，而在施法者释放时按他身体所在的场地份数计算。

维持：每个周期先扣成功，才延续下一周期。扣失败的那一份立刻失效并移除。施法者死亡、离线、换维度或场地卸载时结束。场地不跟着人走。

施法时看施法者身体被几块有效场地包住，份数记为 `fieldCount`。伤害乘这个份数：三块都包住是 3 倍，两块是 2 倍，一块是 1 倍。索敌和弹道从这些场地里只取一份附着，不按份数重复执行。除伤害以外的场地效果，只要 `fieldCount` 至少为 1 就按单份生效，不叠第二次。不做多块场地互相拉人的位移争夺。打出去之后场地再变，不改已经飞出的那发。从外面飞进来的弹丸不算站在场地里。

无攻击时的收尾：场地这种能独立执行的能力先创建并消费掉；还要等普通攻击的附魔继续印主手。已经变成场地的那一项不再印进主手。查场地时不递归再创建一个场地。

## 5. 蓄力、灭火、凝结、幻影

蓄力：只有声明了蓄力的术式才开会话，可有前摇。死亡、离线、换维度、施法资格失效，以及术式自己的打断，都进同一个中断入口。中断停计时、清预览和临时实体、退回未提交的水势预留。不新增魔力退款。完成和中断只能成功一个。已中断的会话不能再放收尾高伤害。不要写成任何受伤都打断，也不要给瞬发术式强加前摇。

灭火：净化作用到目标时走现有 `clearFire`。清当前着火，不提供持续防火，不拆其他药水，不改火方块。

凝结：服务端定几何，再经 `TechniqueHitSpec.spawn` 生成障碍实体。客户端只按同步形状画。障碍默认碰到不掉血。要接到移动碰撞上，不能只摆模型。寿命结束、解除或区块卸载时拆掉碰撞。不放方块，不改流体。

幻影：这次只留描述、创建入口和句柄。描述含变换、外观、寿命、清理用的来源令牌。创建入口以后必须调用现有 `spawn`，不能成为第二条生成管线。句柄能查询、改变换、结束。不写分身 AI、仇恨、伤害代理。

## 6. 书写顺序

每一步验收都包含：能量为 1、没有新能力的旧术式，生成位置、尺寸、爆燃半径、伤害、魔力和命中汇总与现在一致。

1. **属性状态和潮湿。** 新建状态定义、存储、服务、药水效果和潮湿档位。在 `XueXiMod` 注册效果。术式施加入口调用它。不改能量计算。
2. **水势和实际伤害。** `PlayerShuData` 增加独立水势。在 `TechniqueHitSettle` 和 `ReleaseBatch.Tally` 的最终伤害处记释放和消费票据。卸力走伤害事件，实际伤害在伤害调用结束时入账。
3. **独立魔力和蓄力。** `ReleaseDefinition` 增加可选的显式费用和蓄力描述。旧攻击费用公式不动。`SkillSegmentRunner` 接入会话。
4. **场地。** `ACTION` 加场地能力。三份生成、钉死原点、维持扣蓝、无攻击时先执行场地再印主手。施法时按身体所在份数乘伤害，索敌和弹道只套一次，其他效果不叠加。
5. **灭火和凝结障碍。** 净化调用 `clearFire`。障碍走形态链，并接到移动碰撞。
6. **幻影契约。** 只有描述、工厂接口和句柄。工厂必须委托 `spawn`。不登记可释放的分身。
