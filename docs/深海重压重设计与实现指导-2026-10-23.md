## 1. 已确认目标与不增加的效果

用户要求固定7×7×3高级领域、所有方向自由进入离开，原生效果仅减速、窒息、潮湿三种。用户要求领域原生效果和重压窒息伤害均不产生水势，其他攻击照常。

删掉旧原生压强2.5伤害和到期14爆发，不能新旧同时执行；不新增拉扯、重力、击退、伤害墙或困敌。高阶共同友方攻击贡献、外接E接触是底座层，不冒充第4/第5种原生效果。

不使用雾雨的视距限制、雨幕或水坑副效果；不做全屏蓝滤，不改全局天气，不生成真实水方块。

| boundaryPolicy | NONE | 六面自由进入离开，服务端和客户端均NONE |

## 4. 三层效果与水势边界

| 层 | 内容 | 不做什么 |
| --- | --- | --- |
| native敌向 | 减速、真实air资格及倍率、潮湿 | 不压强伤、不到期爆、不主动供扣水势 |
| 高阶共同友方贡献 | owner/盟友实际命中时完整在域内，普通攻击/箭/攻击术式获得公共额伤 | 不另送外接E效果，不改永久属性，不写主手NBT |
| 外接E敌向contact | E+域同段合CD，持续接触约2tick正常hurt尝试；成功后效果 | 不首次消耗、不延寿、不绕帧，不给友方复制E |

友方贡献沿基础水E中性magicDamage公共解析，当前预计2，仅额伤。多域取单最大，tie稳定实例ID；根hurt前原伤加一次贡献，再一次hurt。三份Tally实际归账合并后只加一次；箭命中时查询真实owner当前资格，不冻结发射位置。

原生溺水、领域接触、DOT及状态派生伤不得再拿领域aura递归放大。伤害归真实攻击者；溺水无caster归属，不伪造playerAttack替caster挣势。

原生slow/wet无伤害且不主动供扣水势；普通攻击和外接E伤害沿[ReleaseBaseEvents](../src/main/java/com/bslx/XueXiMod/shu/technique/release/momentum/ReleaseBaseEvents.java)通用产势；重压窒息伤害的全部产势按第6.3节来源策略抑制，不改变其他伤害及卸力收益。

## 5. 原生减速与潮湿仲裁

每10tick汇集全部活跃且资格合法的领域候选，再对目标逐类仲裁，不能先逐域grant后试图回滚。

潮湿同类跨domain目标10tick只取最大贡献：雾雨2与重压4同轮只+4，不是+6，也不能先到雾雨2占槽导致重压4丢失。新建、刷新、离开重入不得重置目标级限流。

减速按同effect最大强度与必要续期：重压只提供amp0。已有更强效果不覆盖；同强且剩余≥20tick不缩短或刷新。外部同强长效果不能被重压替换成20tick。退出领域不removeEffect清别人，只停止供给，重压自己最后一份最多自然残留20tick。

潮湿复用[WetnessState](../src/main/java/com/bslx/XueXiMod/status/WetnessState.java)，每次成功grant刷新1000tick；离域不清湿，按原状态到期/移除归零，没有新加逐点自然衰减。

呼吸倍率按活跃资格取最大2，不随重叠域增加到4、8。不靠周期pulse反复setAirSupply，呼吸在原版事件链里独立解析。

## 6. 真实呼吸事件接入：已核事实

已直接核验本机Forge 1.20.1-47.3.33映射源码，不靠旧原版水分支猜测：

- LivingEntity.baseTick约368–370行调用ForgeHooks.onLivingBreathe，旧水呼吸分支为if(false)。
- 陆地同样计算 `air - decreaseAirSupply(air)`；通常为0或1，已经抽过Respiration随机免减。
- LivingBreatheEvent不可cancel，但可设置canBreathe、canRefillAir、consumeAirAmount、refillAirAmount。
- ForgeHooks约1575–1578行的canBreathe混合“空气/气泡柱环境可呼吸”和“生理免疫”，不能拿陆地canBreathe=true直接免疫重压。
- 减气免疫应查 `entity.canDrownInFluidType(ForgeMod.WATER_TYPE.get())`；IForgeLivingEntity针对WATER返回 `!canBreatheUnderwater()`。禁止查询当前AIR fluid，否则陆地玩家全被判免疫。
- 另检查水下呼吸效果、玩家abilities.invulnerable及旁观；其他模组免疫通过事件顺序兼容验证，不能宣称无条件兼容。水下呼吸效果及水生/亡灵等生理呼吸免疫仅免窒息，不因此免减速或潮湿，后两者仍按原生敌我资格判断。
- 原版回气每tick4；原版decreaseAirSupply已处理Respiration，领域不得再次随机一次或硬写每tick减2。
- LivingDrownEvent在air≤0可触发，默认到≤-20才造成溺水；normal hurt(drown,2)，air置0，默认8个BUBBLE。不要手动另发事件或新增周期hurt。

推荐落点是在领域原生呼吸适配器订阅LivingBreatheEvent，复用DomainService的实时活跃几何/关系查询。适配器类名拟新增，事件和上述方法已存在。

### 6.1 呼吸伪代码（设计，不是现成新API）

```text
onLivingBreathe(event):
  target = event.entity
  查活跃重压候选，完整身体包含且满足敌向native权限
  无合格域：完全不修改event，返回
  若旁观/玩家invulnerable/水下呼吸/!canDrownInFluidType(WATER_TYPE)：返回
  multiplier = 合格候选最大呼吸倍率，上限2
  event.canBreathe = false
  event.canRefillAir = false
  delta = event.consumeAirAmount    // 原版已处理Respiration，陆地也已计算
  若delta > 0：event.consumeAirAmount = delta * multiplier
  若delta == 0：保持0，不重抽、不强扣
  保留其他合法事件状态，处理顺序兼容须测试
```

水下+领域只在这一次呼吸流程取倍率，不先按水扣一次再手工扣一次。出了域不改呼吸事件，恢复环境原版行为：陆地回气，真实水下仍按水下规则；不一离域就把air设满。

默认air300且每tick正delta为1时，×2约150tick到0，约160tick首伤；这只是无Respiration/免疫的估算，不能承诺所有装备精确同tick首伤。原生不走TechniqueHits绕帧、不重置air、不另造伤害时钟。

### 6.2 呼吸HUD与状态

原版HUD在眼睛处于水中或air<max时可显示氧气条，现air同步可复用。无需假造眼睛在水里，不把玩家设成游泳/水中，也不另画第二条氧气。真实水下、水下呼吸、创造/旁观和Respiration须逐项验证。

第一/第三人称都看同一个世界水压视觉；第一人称不盖住原版呼吸条、准星、手持物。氧气消耗翻倍与保留Respiration随机免减已获确认，沿原版air及氧气HUD实施。

### 6.3 重压窒息来源与全部水势入口

以下伤害归属边界和hook是Astra裁决的实施建议，不冒充用户逐字指定的技术方案。以原版LivingDrownEvent确定本次要实际伤害的时刻查询：目标仍位于有效重压内、满足敌向完整包含及呼吸资格，则该次drown标为重压窒息。真实水与重压重叠也如此。离域后的普通drown恢复通常产势规则，即使低air此前由重压消耗；这是按伤害发生时的确定性归属，不追溯每点混合空气因果。

在原版实际溺水hurt调用处为这一笔附来源标记，拟采用MomentumCreditPolicy.SUPPRESS或通用来源能力，不按术式ID分支。保持drown原伤害类型、标签、无攻击者及正常无敌帧，不伪造playerAttack/caster。LivingDrownEvent没有替换DamageSource字段，不能声称订阅事件即可换source：须核验ForgeHooks实际hurt处最小定向hook，是否需要额外依赖/注入须实施前确认。

可替代方案是严格包住这一hurt调用的可重入scope并finally清理。禁止在事件回调开始放ThreadLocal等“下一次伤害”，禁止玩家+tick猜测下一笔，禁止跨tick追溯空气因果。取消或不实际hurt时不得留下票据；没有通用来源标记支持前不能以全局过滤drown代替。

当前drown绕护甲但不绕无敌能力，水环仍可按现20%卸力。SUPPRESS只禁止此笔所有水势，不改伤害、水环免伤或全局关闭水环：必须统一覆盖ReleaseBaseEvents.onHurt场地较强分支的creditMitigated、GuardMitigation延迟卸力credit，以及onDamage受伤/造成伤害credit。队列Note保存来源策略/身份并在最终提交再次尊重SUPPRESS，不能入队后丢标记复活奖励。普通同tick攻击、箭、术式、外接E及aura攻击和它们的卸力收益仍正常。

具体落点：[ReleaseBaseEvents](../src/main/java/com/bslx/XueXiMod/shu/technique/release/momentum/ReleaseBaseEvents.java)、[GuardMitigation](../src/main/java/com/bslx/XueXiMod/shu/technique/release/guard/GuardMitigation.java)、WaterMomentum实际credit调用前的统一来源策略；拟新增来源能力/最小hook适配器。native drown仍从aura递归入口排除，不给玩家写持久“暂停产势”状态。

## 7. 视觉主方案：低顶收压纹与内收短弧

目标是“低矮、向内压”，同时让人看出7×7×3可自由穿过。无shader方案仅两张sprite合批即可完成主表达。

### 7.1 空间布置

1. 上部多层稀疏横片显示向内收压，不封满顶板；层间留大量空隙，仍能辨认地形和目标。
2. 四周内部短弧向中心移，不连成整面边壁；对称但略错相，避免像四道伤害墙。
3. 地面角落断续细纹提示范围，不能画连续实体框或发光封界线。
4. 不复用六面蓝盒，不做雾雨式视距限制/全屏滤镜，不加雨或水坑。
5. 相机接近片面时淡出，避免进入领域瞬间满屏贴图；不修改真实通行几何来迁就视觉。

### 7.2 像素素材建议（尚未生成）

拟资源：

- `textures/domain/deep_pressure_bands.png`
- `textures/domain/deep_pressure_arcs.png`

每图32×32一帧、4帧纵排总32×128；renderer手动UV每4tick一帧，16tick循环。不能假设当前renderer已支持mcmeta动画或直接贴整张图。

颜色试调：深青阴影#123C50、青蓝主体#287F9B、少量浅青高光#9EDBE1；避免纯白大片。线宽1–2px，推荐每帧透明占比≥70%，纹理中心留大空白。RGBA透明边缘要干净，避免黑边。

绘制清单：

- 最浅高光只占少数像素，不把中心画满水滴；低透明度仍保留动作可读性。
- 资源制作和逐帧检查属于后续实施，本次没有生成PNG。

## 9. 同步与自由通行

扩现DomainSyncPacket/DomainSightStore/DomainClientState的数据而非重造：保留owner、id、revision、geometry、observerpass及permissionrev，补visualKind=DEEP_PRESSURE、boundaryPolicy=NONE、birth/endtick及animseed。

中途观察者收到完整快照，按服务端年龄选帧；旧revision丢弃，到期TTL/移除/重连无残影。服务器关闭实例时统一停止native、呼吸资格、aura、contact与render；无封界也要清掉旧预测样本，不能残留雾雨约束。

客户端只画面和普通预测，不判native减速/湿度/air/水势，也不自行判断盟友权限。NONE使两端都不裁六面位移，不能只服务端放行而客户端仍拦。

## 10. 成本、复制与生命周期
