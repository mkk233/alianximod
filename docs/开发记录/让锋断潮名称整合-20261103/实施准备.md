# 让锋与断潮名称整合：实施准备

现行决定（2026-11-03）：用户选择只改名。`water_yielding_ribbon` 的显示名是断潮，`tide_sever` 的显示名是薄水切。两项可用性、效果、稳定 ID、配置键和存档保持原样，水幻形仍支持 `tide_sever`。下文关于 `DEVELOPMENT_ONLY`、退出玩家目录，以及拒绝水幻形旧链的方案已经撤销，不是当前批准。

本文件只记录已经核对过的接入点。本次没有改 Java、资源、语言文件、工作簿或其它文档，没有编译、打包、启动游戏或提交。行号对应当下源码哈希；实现前若哈希变了，先停，不要按过期行号改。

【已撤销】原准备提案：`water_yielding_ribbon` 继续是重斩和真实分水，玩家看见的名字改为断潮。`tide_sever` 继续是薄水切，退出玩家可用列表，注册、效果、配置键和存档编号都留着。名字「让锋」不再指任何术式。不交换两边的效果，不把旧薄切存档升级成高伤重斩。

## 1. 身份、文案和功能

玩家看见的术式名来自 `Technique.name`，也就是 `ModTechniques` 构造时写入的中文字面量。`Technique.getName()` 直接返回它。剑技装配、法杖装配、术式管理、刻印、术式石名称、收纳箱和已绑定技的组成行都读这个字段。`src/main/java` 里没有 `technique.xueximod` 的翻译键读取，所以语言文件不是这两项的显示来源，也没有英文回退。客户端语言设成英文时，这两项仍显示构造器里的中文。

| 稳定 ID | 当前显示名 | 当前功能 | 整合后显示名 | 可用性 |
| --- | --- | --- | --- | --- |
| `water_yielding_ribbon` | 让锋 | 重斩加水路分开。`WaterYieldingEffect`，基础伤害 40、冷却 600、复杂度 0、魔力按 `ceil(基础伤害 × 2)` 为 80。释放定义寿命 32、厚度 0.55，`ChainRole.ATTACK`。配置键 `lifetimeTicks` `boxDepth` `boxWidth` `boxHeight` | 断潮 | 保持 `PLAYER` |
| `tide_sever` | 断潮 | 薄水切。`TideSeverEffect`，基础伤害 6、冷却 20、复杂度 0、魔力 12。释放定义寿命 6、厚度 0.4。水幻形唯一适配器 `TideSeverActorAdapter`，版本 1。配置键 `lifetimeTicks` `thickness` `beamLength` `boxHeight` | 薄水切 | 改为 `DEVELOPMENT_ONLY` |

`ModTechniques` 里的现行字面量：

- `tide_sever` 在第 145–148 行，十参数构造，名字「断潮」，说明「一道薄而长的水切」。十参数构造默认 `TechniqueAvailability.PLAYER`。
- `water_phantom` 在第 149–154 行，说明要求法杖槽 0 先装水幻形再装断潮，并写默认魔力 10+12、冷却 20+20。
- `water_yielding_ribbon` 在第 228–231 行，名字「让锋」，说明「先铺开水面，再从中间劈开。水分开没有伤害，只有中间那一刀」。

语言文件只给水幻形备了一份未被代码读取的副本：

- `src/main/resources/assets/xueximod/lang/zh_cn.json` 第 127–128 行：`technique.xueximod.water_phantom` 为「水幻形」，说明同样要求再装断潮。
- `src/main/resources/assets/xueximod/lang/en_us.json` 第 70–71 行：英文名为 Water Phantom，说明里的 Tide Sever 指旧薄切。
- 两份语言文件都没有 `tide_sever` 或 `water_yielding_ribbon` 键。缺键时游戏不会改走这两份文案。

功能归属保持现状：

- 重斩和分水只在 `water_yielding_ribbon`：`WaterYieldingEffect`、`WaterPartingService`、`WaterPartingRenderer`。`ReleaseDefinitions` 第 29 行登记该 ID。`BalanceCatalog` 第 43 行把它列入伤害宿主。
- 薄切只在 `tide_sever`：`TideSeverEffect` 用 `horizontal_slash.png`。`ReleaseDefinitions` 第 38 行登记该 ID。`ActorPayloadRegistry.registerBuiltins()` 只登记 `TideSeverActorAdapter`，`TECHNIQUE_ID` 为 `tide_sever`。`BalanceCatalog` 第 38 行把它列入伤害宿主。
- `TechniqueIds.canonicalId` 只把 `water_open_ring` 收成 `water_blade`。这两个 ID 互不改写。

术式石按 `spell_id` 再查注册表。编号还在时，名称用现行 `getName()`，伤害说明用现行基础伤害重算，不会沿用刻印快照把薄切显示成 40 伤。编号被删掉时才会退回存档里的 `spell_id` 和刻印快照。所以注册必须留下。

## 2. 可复用的退出入口

现成入口只有 `TechniqueAvailability`。枚举只有 `PLAYER` 和 `DEVELOPMENT_ONLY`。注释写明注册后只读，不从技能 NBT 改写。没有另一套 legacy、隐藏或废弃枚举。开发分身和开发脉冲已经用 `DEVELOPMENT_ONLY`，薄切沿用同一档。

`TechniqueAccess.allowsPlayerUse` 在可用性不是 `DEVELOPMENT_ONLY` 时放行。`playerCatalog()` 只收这一档。拒绝文案是字面量「该术式只属于开发入口」。

各入口在改成 `DEVELOPMENT_ONLY` 之后的行为：

- 普通玩家目录：术式管理 `ShuManagementMenu` 第 84 行、刻印台 `ImprintDeskMenu` 第 79–90 行、登录自动学习 `PlayerConnectionHandler` 第 20–24 行，都只遍历 `playerCatalog()`。复杂度 0 的现役断潮仍会在登录时学会。薄切不再出现，也不会被新玩家自动学会。
- 学习记录：`PlayerShuData.learnTechnique` 第 99–106 行遇到 `DEVELOPMENT_ONLY` 直接返回，不新增。读取 `Learned` 时原样保留已有 ID，登录流程不删除它。`hasLearned("tide_sever")` 对旧档仍可为真，但目录界面不再列出它。
- 命令：`/shu` 要求权限 2。`list`、`learn`、`learn all`、`stone`、`book write` 和 `reset` 的建议与授予都走 `playerCatalog()` 或 `allowsPlayerUse`。直接写 `tide_sever` 会失败并显示上述拒绝文案。没有绕过该门、按 `getAll()` 发放术式的命令。
- 创造：`ModCreativeModTabs` 只放空白术式石、原胚、法杖和收纳箱，不按术式 ID 铺石头。创造栏不会多出一个断潮。
- 新装配：刻印 `ImprintActions` 第 33–35 行、法杖和剑技装配 `SpellAssemblyMenu` 第 355–356 行与第 420–421 行、`SkillAssemblyPacket` 第 127–129 行、第 322–324 行和第 380–381 行，都先拒绝 `DEVELOPMENT_ONLY`。拒绝发生在消耗收纳箱条目之前。
- 已装配旧链：剑技在 `SkillUsePacket.offerNow` 第 195–198 行、`executeSkill` 第 329–331 行，整段技能只要含有该可用性就拒绝，位置在报价和扣费之前。法杖在 `StaffSkills.castRefusal` 第 137–138 行对每一格做同样检查，水幻形加薄切的旧链会在这里停下。水幻形捕获门 `ActorCaptureCarrierGate` 第 76–77 行和第 107–108 行也会拒绝该载荷。玩家看到的是开发入口拒绝，不会先扣魔力再空放。
- 已有术式石和收纳箱：NBT 的 `spell_id` 不动。界面用现行 `getName()`。名字改成薄水切后，旧石头显示薄水切和原来的 6 伤，不能再刻印或装进新链。

`Skill.toNbt` 把装配当时的技名写进 `Name`，术式本身只存 `Id`。`Skill.fromNbt` 用 ID 找回注册对象，技名快照不跟着注册表改。因此旧让锋链的标题可能仍是「让锋」，组成行会变成「断潮」，释放仍走重斩。旧断潮链的标题可能仍是「断潮」，组成行会变成「薄水切」，释放在扣费前被拒绝。不回写这个 `Name`，避免顺手迁移存档。玩家重新装配现役断潮后，新标题才会是断潮。

## 3. 兼容方案

实现只做下面这些事。

1. `water_yielding_ribbon` 的构造名字从「让锋」改为「断潮」。伤害、冷却、等级上限、复杂度、属性、弹速、说明、效果、释放定义、分水、贴图视觉号和配置键都不动。
2. `tide_sever` 改为十一参数构造，最后一参为 `TechniqueAvailability.DEVELOPMENT_ONLY`，附魔参数保持 `false`。显示名改为「薄水切」。数值和说明「一道薄而长的水切」保持原样。效果注册、适配器、释放定义和配置键保留，这样旧 `spell_id` 仍能解析，而且不会变成重斩。
3. `water_phantom` 的玩家说明改成：「法杖槽0的水幻形不再接受玩家入口里的下一攻击。薄水切已退出可用列表；现役断潮尚未适配。未适配的下一攻击在收费前拒绝。」魔力 10、冷却 20 等代码默认值不改。
4. `ActorCaptureTexts.STRUCTURE` 改为：「水幻形后仅支持一段已适配水系攻击；薄水切已退出玩家入口，现役断潮尚未适配。」玩家若把现役断潮装到水幻形后面，会在收费前看到这句。适配器仍只认 `tide_sever`，不把 `water_yielding_ribbon` 登记进去。

这样目录、学习、命令、创造和刻印里只有一个现役断潮。薄水切留在注册表里供旧编号解析，不进入上述入口。两个 ID 的配置覆盖继续各读各的键，不合并，不改名，不把薄切覆盖套到重斩上。

水幻形是这条门的直接后果，不是另一套停用系统：它唯一的玩家载荷是 `tide_sever`。载荷一旦变为 `DEVELOPMENT_ONLY`，旧的「水幻形 → 薄切」链在收费前被拒绝，新链也装不进去。现役断潮没有适配器，装上去同样在收费前被 `STRUCTURE` 拒绝。这次不给水幻形换载荷，也不恢复薄切的玩家可用性。要让水幻形重新可玩，属于之后的新设计。

### 不可逆取舍

没有必须删注册、删 NBT、清空 `Learned`、改写 `Skill.Name` 或把旧石头换成重斩的事项。上述显示名是可逆字面量。若主会话要把旧薄切显示成别的、且不是「断潮」或「让锋」的名字，只替换「薄水切」这一个玩家可见字，并同步水幻形说明和 `STRUCTURE` 里的同一称呼。
