# 实现第1轮（主会话亲自复核，1/3）

输入：所有本批Cursor作者已返回exit0并释放后的源码，散列见外部task目录review1-manifest.json。本轮未编译、未运行游戏/测试程序。结论：需要下列定向返修，未标通过。设计仍1/2。

## 必修

1. **Java lambda捕获非effectively-final变量**。CastExecutionSession.java:385定义claimSuffix，390会重赋值，405和410的新lambda捕获它。须先确定最终claim再用不可变局部值捕获，否则编译不能通过。

2. **零伤害宿主被错误排除复制/兼容修饰**。MulticastParser.java:224–256使用baseDamage>0作为全部payload条件。`双重、一分为三、水幕`读取了copy+水幕，却把copy当无用而仅生成一份；旧CompiledReleaseStep/BarrierService明确支持复制数，用户只禁止直接复制整个多重，未禁止内部复制零伤宿主。按原有宿主能力保留支持范围，复制、索敌/弹道、增幅分别按适用性归属，不把所有零伤术式一概排除，也不把不兼容修饰硬套所有宿主。费用/CD随实际归属一致。同步指南中“只有正伤”的过窄描述。

3. **先用旧split做附魔拒绝，误判新作用域**。SkillUsePacket.java:357在371编译新成员之前调用ContactCast.refusal(skill,segments)。例`双重、双重、潮印、聚能、冲刺`：内层两格应使潮印成为独立成员、聚能无宿主忽略，外层余一格执行冲刺；旧TechniqueChain.split却把潮印挂到冲刺，拒绝“不能承载附魔”。多重应验证编译后的成员及前导动作真实附魔，普通链继续原验证，不能删除接触附魔安全检查。

4. **多重绕过结构缓存，缓存内容也仍有旧分段残留**。SkillChainPlan带planContext的copies/lock/drop/frozenInput/releasedSegments先重新解析，后才读缓存；CastExecutionSession已有memberView仍在每个复制里再次调用全链扫描的lock/drop。CompiledCastPlan.java:123用旧三参数copiesBefore，139–144用segments.indexOf(新成员)可能存-1，170新增展开只计固定8单位。正确缓存不可变展开/成员归属，缓存命中和已绑定成员不重复解析；修正缓存成员映射与复制数据，计入新增结构预算，epoch失效保留。不能仅用运行时重解析隐藏缓存不一致。

5. **通用N扩展后的报价加法可能溢出**。MemberCastView.copyProduct溢出截到MAX，CompiledReleaseStep.scaleByCopies截到MAX，但memberShare/groupBill/ruleShare和AutomaticRound.priceQuote仍直接int加法。MAX+规则费会负数，GroupBudget.reserve用Math.max(0,cost)当免费，后续按copyCount分配数组/生成。金额/复制数超表示范围要在付款/分配前明确拒绝，不能负数转免费、不能截断仍继续超大复制；正常合法数量和价钱不悄悄缩减。只修新多重相关路径，不扩大重构整个旧术式计价。

6. **领域第一成员未发布，后续成功时退掉全部规则费**。AutomaticRound.OpenRound.retainLoose/retainHost只在memberIndex==0留ruleShare。首个剑技因空手跳过、后续法术成功时，多重确实运行但规则费全退。该轮首个真实成功成员保留规则费一次；全部未发布仍全退，其余部分退款/独立轮语义保持。
