# 用户追加的实现第 4/4 轮

授权来源：用户明确表示“考虑到双会话并行可以允许额外一次复核”。原三轮不重置，本轮是唯一追加轮。统一 Java 第二次编译已最终返回，源码、Gradle 和相关文档作者全部释放后，由主会话亲自只读检查。

## 检查范围与结果

- 第三轮留存的 37 个本任务文件中，仅 SkillChainPlan.java 在编译返修后改变。与第 2 轮留存版本的差异也仅为四处 expansionAtRule 实参换序。四个调用均保持段下标传入，函数内部仍通过 actionIndex 映射回原始槽；没有把内层多重变成另一条独立队列。
- 手动多重仍按成员 ordinal 和 gapTicks 排程，复制份沿用同一成员时点；成员自己的修饰视图、附魔、复制数和冻结输入送入运行器。领域自动轮仍从同一展开生成自己的成员切片，并保留领域上下文、生命周期与实际发布回执。
- 对照并行任务改动的四个直接适配点：TrajectorySampler、TrackingSupport、SwordTrackingStep、MeleeCorridorMath。其接口仍在当前调用中计算并立即返回坐标、方向、步长或判定；没有改变链成员顺序、3tick时序、目标选择时点、费用或CD结算。
- 现有调用在纯计算返回后立即复制所需数值到 Vec3／结果对象或基本值，没有把线程局部 ComputeOutput 或 native 复用数组留给后续成员／tick。标量 native 调用使用 count=1，不为凑批延迟成员；不可用或不被接受时回到 Java。没有把玩家、世界、付款或成员视图交给数值数组接口。
- 手动与领域成员的几何、复制下标、冻结输入仍由原运行层生成；计算适配消费数值，不写入结构计划缓存或改动作用域。

本轮未发现需要返修的新问题。没有写生产源码，没有重新跑编译或测试，也没有扩展为 C 数值公式／完整 ABI 的第二套审查；后者由纯计算会话按其用户授权承担。
