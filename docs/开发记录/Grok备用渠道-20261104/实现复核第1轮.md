## 高

1. 审批拒绝可以被账户证据或同任务周额度路径换渠道。`Test-ApprovalBlocked`（`Invoke-CursorTask.ps1` 1551–1562 行）只拼接 `blocker` 和 `stderr.log`。Cursor 失败若把 `Auto-review rejected the tool call` 只放在 result 正文、stderr 为空，则 `blocker` 会落成普通 CLI 失败句，1731 行的判断为假，随后仍会启动 Grok。同任务周额度分支（1752–1810 行）完全不调用这个判断：stderr 里同时有周额度句子和 `Auto-review` 时，会被标成 `eligible` 并切换。现有 `auto_review` 夹具两边都写了 stderr，所以测试仍是绿的。建议：同一函数同时读 `result.txt`，并且两条切换路径都先拒绝审批。

2. 已收束的 `failed` 取消会随账户证据切到 Grok。1724–1729 行只放行 `lifecycle=failed`，取消字样没有单独判断。进程被外部杀掉时会记成 `interrupted` 并拒绝；Cursor 自己以非 0 退出、stdout 仍可解析、stderr 为 `canceled by user` 时，进程戳齐全，结算为 `settled`，审批正则不中，就会新建 Grok 会话。这和流程第 11 节“取消不能借证据绕过”不一致。建议：取消、中止和用户中断保持原失败，不进入 Grok。

3. Grok 的审批拒绝退出码仍是 0，终局匹配时会被记成 `reported`。headless 文档写明拒绝时 stderr 为 `permission required: ... cannot ask for approval`，退出码保持 0。分类在 2020–2067 行：退出码 0、`stopReason=end_turn`、会话和目录一致就进入 `reported`，这条 stderr 不改变 `failureKind` 或回执 `blocker`。模型若仍给出 `reported_done`，Status 看不到这次拒绝。建议：stderr 出现该句时，回执保留拒绝原文，并且不要把它当成干净的 `reported_done`。
