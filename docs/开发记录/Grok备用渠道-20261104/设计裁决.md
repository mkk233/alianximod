## 2. 什么情况可以切换

只有本 task 最新 Cursor attempt 的**真实 CLI 错误通道**证明账户用量耗尽，才能标记 `fallbackEligibility=eligible`。首版识别已验证的 `ActionRequiredError: Weekly usage limit reached.` 错误形式；尾部重置时间/购买提示可以变化，不能依赖整句完全相同。其他配额错误码/文案必须先有真实 CLI 证据和对应夹具才加入识别集合，不凭空猜枚举。

证据必须来自本次被启动 Cursor 进程的错误事件或标准错误中的已知错误格式，并关联该 attempt。不能扫描任意 stdout、prompt、工具结果、源码或模型最终文字，只要出现“usage limit”就触发。模型自称额度不足不是 provider 配额证据。

这些情况均不自动切换：一般 429/速率限制、网络/超时、认证失败、模型不存在、CLI 缺失、用户中断、审批/auto-review 拒绝、工具命令失败、编译失败、缺终局/错误 JSON/会话错配、模型自报 blocked 或 needs_input。不能通过换 provider 绕过已有拒绝。真实配额事件伴随初始化或结果协议异常时，先对账解决异常，不能越过协议不确定性执行接替任务。

原 Cursor attempt 保持原 lifecycle/exitCode/raw/result/reportStatus，绝不改成 reported 或补造成功终局。独立增加派生字段：`failureKind=cursor_quota_exhausted`、`quotaEvidence`（来源位置、规则版本、脱敏短摘录）、`fallbackEligibility`。这些字段不是模型自报，也不是实施复审通过。

已有失败历史可作为 bootstrap 授权依据：`cooperative-slash-20261103/compile-final/attempts/a2026110318480502362ed` 已记录真实周额度失败。不得为建立依据再跑旧编译，不修改其旧回执，不把旧 task 换成新实现 task。常规运行期切换则要求该 task 自己的最新 Cursor 配额 attempt，不能用一次历史额度错误永久绕过所有新任务的主渠道。

## 3. 启动器调用与一次切换规则

原 Start/Resume/Status/Result 参数默认行为保持，Cursor 固定模型和 auto-review 参数不变。新增一个明确参数 `-UseQuotaFallback`，只允许与 Resume 一起使用；不提供任意 provider 任意模型选择开关。

流程：

1. Start 或普通 Resume 运行当前 provider；新 task 默认 Cursor。
2. Cursor 正常失败并被识别为配额耗尽后，只返回最小可切换状态，不在原调用里启动 Grok。
3. 主会话取得最终回执，确认原进程及已启动的写入子进程结束、相关文件作者释放、未提交改动保留、当前输入与授权/依赖/阶段计数未变。
4. 主会话调用同 task 的 `Resume -UseQuotaFallback -ResumeReason <具体对账结果>`，带本次 PromptFile，原来需写入的任务仍必须显式 `-WriteMode`。不因 fallback 自动打开写权限。
5. 启动器复核 eligible、原 attempt ID、任务身份/输入版本、模式、排他锁和此前未切换，再创建新 attempt，运行 Grok。失败保留现场；不回 Cursor、不换其它模型、不再链式切换。

切换次数按稳定 task 计 **最多一次 Cursor→Grok**，不随 attempt/进程重启或重新 Resume 清零。切换后普通 Resume 继续同一 Grok 会话，不每次先试 Cursor，不自动恢复主渠道。若未来确需迁回 Cursor，属于主会话另行明确安排的工作流迁移，本版不自动实现。新 task 仍默认 Cursor。

ResumeReason 只是对账摘要，不替代检查。启动器能核对的 PID/启动时间/锁必须自己核对；不能证明已结束的运行标 interrupted/unknown 并停止接替。配额失败通常没有 writesSettled=true 模型报告，不能因此补写它：另存由主会话负责的 `handoff` 记录，写明进程收束证据、文件所有权及部分改动状态。已知后台编译/写入子进程尚存时不允许接替。

## 4. task/state/attempt 向后兼容

TaskFile 最小必填字段不变：batchId/taskId/workspace/stage/operation/authorization/inputVersion/recordPath/writePaths/dependencies。继续沿同 batch 和 task，保留同授权、输入版本、文件所有权与阶段计数；切换不会重新领取表、复审或获取额外写路径。

state 增加有版本的 provider 信息，至少包含 `activeProvider`、`sessions.cursor`、`sessions.grok`、`fallbackUsed`、`fallbackFromAttemptId` 和切换意图状态。已有无 provider 的 state/attempt 在读取时视为 Cursor，旧 `cursorSessionId` 仍能读取并保持原义。不要把 Grok UUID 填进名为 cursorSessionId 的字段。旧字段保留供兼容消费者读取，provider-neutral 新字段是 `providerSessionId`。

每个新 attempt 自带 provider、providerSessionId、固定模型别名/期望 wire model、reasoningEffort、权限模式、readOnly/writeMode、父 attempt 与切换原因；旧 attempt 原文件不重写。输出可对旧数据计算缺省值，但不能就地“迁移”历史证据。相同 task 下所有 attempt 使用原目录规范；Status/Result 支持按旧 AttemptId 查询。

排他锁同时覆盖 task 和 `(provider,sessionId)`。UUID 恰好相同也不表示同 provider 会话。切换意图、fallbackUsed、预生成 Grok UUID 和新 attempt 的创建需原子持久化，并采用文件替换/锁防止双击 Resume 启动两个 Grok。先持久化意图再启动进程；进程启动不确定或状态写入中断时不能生成第二个 UUID 重试。先对账，已存在的 Grok 会话只能明确 resume，确认未创建的预留 UUID 才能重新执行首次启动。不得自动删除旧锁或把 PID 重用当作原进程。

输入交接不假装跨 CLI 共享聊天：保留原 TaskFile 与 PromptFile 快照、原 inputHash，再生成本 attempt 的 handoff prompt，含未完成目标、授权边界、失败证据摘要、已保留改动和未运行项。单独记录 handoff/effectivePromptHash。原模型完整思考、密钥、整个 raw 日志和无关旧聊天不搬运。新 Grok 作者先读当前任务和交接，不重做已完成的有副作用步骤。

## 5. Grok 精确启动合同

固定 executable 来自已验证的本机 Grok 路径（本机为 `C:/Users/baishang/.grok/bin/grok.exe`）。测试替身可通过专门 `-GrokAgentPath` 注入，作用仅选可执行文件，不能传任意附加 CLI 旗标、改模型或权限。

所有 Grok 调用显式带：

```text
--model grok-4.7
--reasoning-effort high
--permission-mode auto
--cwd <TaskFile.workspace>
--prompt-file <该 attempt 的有效提示文件>
--output-format json
--no-subagents
--disable-web-search
--no-auto-update
--deny MCPTool
```

每个 Grok 子进程同时固定环境 `GROK_WORKFLOWS=0`、`GROK_MEMORY=0`、`GROK_DISABLE_AUTOUPDATER=1`，和主会话真实续跑测试一致。仅写子进程环境，不持久化用户/系统环境或配置；防止额外工作流、记忆写入、自动更新脱离本 task 生命周期。若实现用临时当前进程环境传递，必须在 finally 恢复，不能污染随后 Cursor/Grok 任务。

首次为该 task 创建 Grok 会话：由启动器生成并持久化全新 UUID，传 `--session-id <uuid>`。同 provider 后续仅传 `--resume <已存 uuid>`，二者互斥。不传会话标题，不用 --continue、--fork-session、--restore-code、--always-approve、--yolo、bypassPermissions，也不把 Cursor UUID 当作 Grok 会话。对 Create/Resume 的字段与返回 sessionId 都做核验。

固定别名必须解析为用户已有“老猪的中转站”配置的 `grok-4.7-build-fast`，responses 后端，high。不创建同名仓库配置覆盖用户条目，不复制 API key/base URL 到 prompt 或回执，不为消除内置目录刷新认证警告改用户全局配置。连通测试已经证明本机别名可用；运行期 modelUsage 若出现未批准模型，作为 provider/model 协议异常停止，不自动用另一个模型完成。缺少 modelUsage 不伪造调用模型证明；保留请求参数和实际可得信息，交回明确的不确定性。

### 权限选择

读写两种模式均显式 `--permission-mode auto`。本机全局 permission_mode=always-approve，而 ui.yolo=false；不能依赖后者推断安全模式。CLI auto 覆盖已由主会话连通试验验证，每次新建和 resume 都重传。不得因 headless 需要顺利跑完而改为 acceptEdits、dontAsk+宽泛 allow 或 always-approve。

默认只读额外使用：

```text
--tools read_file,grep,list_dir
--deny Edit
--deny Write
--deny Bash
```

同时保留 no-subagents、disable-web-search、deny MCPTool。文档说明 --tools 不自动移除 MCP 元工具，所以 MCP deny 不能省略。明确不保留 shell、工作流 execute、编辑、删除、任务派生或计划文件写入工具；不能只用 plan 模式冒充严格只读，因为 plan 允许计划文件写入且不天然禁 shell。启动器正常落自己的回执不属于被委派模型的写权限。

只有显式 -WriteMode 才提供写工具，首版使用已文档化的最小内置集：`read_file,grep,list_dir,write,search_replace,run_terminal_cmd,get_task_output,wait_tasks`。保留相同 auto/MCP/子代理/Web 限制；后台命令必须在任务结束前收束，不能以启动后台进程就 reported_done。工具名称不识别的警告应视为能力合同失败并停止，尤其不能接受“未知 allowlist 项后仍保留其它默认工具”的宽松行为。

writePaths 仍是任务授权/单作者合同，不声称 auto+allowlist 是对 Shell 的 OS 路径沙箱。不要宣称 `--allow Edit(path)` 是封闭白名单；本机文档明确未命中 allow 的请求仍可进入 auto 分类。作者只能改授权路径，不能修改全局配置、启动器运行证据、其它作者文件。原有 managed deny/ask 规则继续生效。

auto 审查无法自动允许时，headless 会向模型返回 blocked。允许模型在相同权限内改写为可批准的等价操作；不允许换 provider、开 bypass 或添加大范围 allow 来逃避同一个拒绝。无法推进则报告真实阻塞与具体动作，不反复让用户批准已经授权的正常任务，也不隐藏工具拒绝事实。

## 6. 输出归一化与真实性

首版选 json 终局模式，减少流式协议面。stdout 必须有唯一有效结果对象，stderr 单独保存；不要从混乱 stdout 任取最后一个看起来成功的 JSON。Grok 的 text/stopReason/sessionId/requestId/cwd 原样保留在 providerResult，再映射公共 lifecycle。

- 退出非 0 或 error 对象：failed。
- 退出 0 缺可识别终局：missing_result。
- 多个冲突终局、sessionId 不匹配、cwd 规范化后不同：protocol_error。
- stopReason=end_turn 且身份/路径正确：可标 reported，再独立解析模型工作报告。其它 stopReason（如 max_tokens）保留原原因，标 failed，不伪装正常完整交付。
- 进程仍活跃或结束不确定：沿原 running/interrupted/unknown 处理，不凭一段 text 判断已停写。

为最小兼容，Grok 仍输出既有 `<<<CURSOR_TASK_REPORT>>>` 标记块，字段/workStatus/reportStatus/writesSettled 语义不变。标记名字是兼容协议，不表示 provider=cursor。只从终局 text 解析，不从工具输出寻找自报。reported 与 valid/reported_done、正式复审/编译/待验收仍分开；stopReason=end_turn 不证明工作完成。

Status 只增 provider、最小 lifecycle、自报概要和 fallbackEligibility/是否已切换，不输出 raw、完整 meta 或密钥。Result 返回完整归一化回执并可指定历史 attempt。日志仅记录非秘密请求参数；禁止记录环境变量全集、用户配置全文、Authorization 头或凭据。真实错误含敏感内容时脱敏后保存可交付日志，不能为了定位 provider 把秘密写入仓库。

## 7. 一次性 bootstrap：先造适配器再收回入口

当前 wrapper 还不能启动 Grok，不能要求先通过不存在的 Grok adapter 才允许实现 adapter。用户已明确授权备用渠道，且 Cursor 周额度失败和 Grok 连通均有证据，因此批准一次范围明确的 **native-bootstrap** 实现会话，不需要再问用户开工。

主会话先准备本批同一稳定 bootstrap task 的 TaskFile/PromptFile，明确脚本、离线测试、流程第 11 节及必要规则文档的唯一作者路径，禁止业务 src/制作表/旧批源码和改历史回执。启动前登记文件所有权及依赖完成情况。为新原生实现会话生成独立 UUID；不要复用连通测试会话或 Cursor 会话。

主会话只调度原生 grok.exe，使用第 5 节写入模式的同一固定模型、high、显式 auto 和工具限制。Grok 作者负责 adapter/测试/必要文档实现，主会话不代写脚本实现或业务 Java。启动器运行记录机制尚未支持该 provider 时，主会话在本批专门 bootstrap 记录目录保存输入快照、UUID、命令非秘密参数、时间、PID、exitCode、stdout JSON、stderr 和作者最终自报；不手工伪造普通 wrapper attempt。

“一次性”指一个 bootstrap 工作项和一个原生 Grok 会话，不要求模型在一轮文字中必然完成。若需范围内补齐 adapter，显式 --resume 这一 UUID，并记录同 task 的执行次数与原因；不新建会话重置额度、不借 bootstrap 继续 unrelated 业务。只有真正的审批/环境阻塞才交回说明，不为循环依赖反复确认授权。

作者返回、相关写入收束并完成离线测试后，主会话通过新增 wrapper 做最小真实新建/续跑验证（测试任务，不是旧编译）。验证不需要再制造真实付费额度失败：使用现有可执行文件替身机制，在明确标注的隔离测试工作区/task 中让 Cursor 替身返回配额夹具，再由同一 wrapper 的正常切换路径调用真实 Grok。回执标明配额来源为模拟、Grok 调用为真实，不能把模拟失败冒充生产额度证据。生产不新增“强制跳过额度检查”的参数。

bootstrap UUID/回执在完成后由 wrapper 兼容导入流程登记为该任务的 Grok session，或将 bootstrap task 结项，后续另建正常 task；选前者时必须验证 task/工作目录/UUID/输入关联并保留原始记录，不能伪造其曾由 wrapper 创建。常规任务从此回到 Invoke-CursorTask。不能等 adapter 已可用后继续用原生入口做业务任务。

## 8. 必要兼容性测试与交付范围

固定 Grok 作者扩展现有离线启动器测试，不触发 mod Gradle。至少覆盖：

1. 原 Cursor Start/Resume/Status/Result 与旧 state/attempt 无 provider 读取保持；原参数和模型不变，历史文件哈希不被迁移改写。
2. 真实格式 weekly limit 能识别；普通 429、网络/认证/审批/编译错误、模型自报额度、工具输出引用相同文案、畸形终局均不能触发。
3. eligible 但进程/子进程未收束、锁占用、输入改变或所有权未交接不能切换；同 task 双调用只有一个获得切换权。
4. 第一次 Grok 用 session-id，之后只 resume 同 UUID；Cursor/Grok ID 不串用；只切一次、不自动回切；创建意图中断不启动第二会话。
5. 缺 -WriteMode 的 fallback 不授写；每次显式 auto；不带任何 bypass/continue/restore；工具过滤遇未知名称失败；MCP、shell、编辑、子代理不出现在只读执行能力中。
6. Grok json 正常/错误/缺失/截断/冲突、错误 session/cwd、max_tokens、缺报告/多报告、reported_done+writesSettled=false 等状态分别保真；退出 0 不替代有效报告。
7. TaskFile/inputVersion/batch/stage/writePaths 与原收据保持，handoff 有独立 hash；旧失败证据不改；Status 不泄露 raw，Result 可选旧 attempt。
8. 固定别名/high/期望 wire model 与凭据零复制；日志不包含模拟敏感头/密钥值；禁止自动换模型的测试必须存在。

真实烟测限少量无业务副作用操作：本次已完成的连接测试；wrapper 经授权测试路径启动 Grok 只读任务并返回结构化报告；同 UUID resume 一个只读核验任务；写模式只在指定临时测试目录写/读一个无害文件并由作者收束。审批拒绝可用离线夹具验证，不故意发危险真实操作。生产 quota 触发用已核实错误夹具，不能为了测试重复跑旧任务或耗尽账户。

Grok auto 不是保证所有任务都不会受阻；原生 CLI 连通成功也不代表 adapter 已实现。最终交付应分别列脚本改动、离线测试、实际 CLI/续跑结果、未做项及 bootstrap 是否已关闭。正式实现判断只按本批额度记，不借该工作流重审旧协同批。本文定稿停止写入；脚本、测试和其它规则文档由主会话指定的唯一 Grok 作者接手。
