# 状态入口作者交付

本阶段只做不依赖资源作者和效果作者的 `SELF_STATUS`。没有注册花谱效果，没有新增花谱术式，没有把 600 tick 写成全局时长。没有改 `FurnaceService`、`FurnaceMath`、`FurnaceMobEffect`、炉心事件、网络注册、资源查询、公共伤害包装、其他作者目录或制作表。`ReleaseDefinition.selfStatus()` 原来就是默认返回空的 `SelfStatusCast`，签名没改。

## 1. 提交契约

`SelfStatusCast.prepare(ServerPlayer)` 返回 `StatusPreparation`。`ready()` 为真时 `change()` 才是 `PreparedStatusChange`；否则 `rejectionText()` 是玩家可见失败句，提交器不扣款。

`PreparedStatusChange`：

- `recheck(ServerPlayer)`：扣款前再确认。返回空表示仍可安装，返回句子表示拒绝且不收费。
- `commit(ServerPlayer)`：真正安装。返回真才算装上。抛错视为安装失败。
- `afterCommit(ServerPlayer)`：只在安装成功后调用。这里抛错不得退款，也不得把结果改成失败。
- `failureText()`：`commit` 返回假时给玩家的句子。

`SelfStatusCommit.attempt` 的顺序：

1. 玩家、定义为空，或种类不是 `SELF_STATUS`：`REJECTED`，句子是 `§c自身状态没有就绪`。不调用 `prepare`。
2. `selfStatus()` 为空：同样 `REJECTED` 和上一句。不调用炉心预览、进入、升级或冷却。
3. `prepare`。没准备好则 `REJECTED`，使用准备结果里的句子，不扣款。
4. `recheck`。返回句子则 `REJECTED`，不扣款。
5. 魔力仍按 `explicitManaCost()`，负数当 0，再经 `SpecialBalance.mana(id, BalanceKeys.MANA_COST, rawCost)` 读一次。付不起或扣款没拿到收据：`INSUFFICIENT`，句子是 `§c魔力不足`，不写冷却。
6. `commit`。抛错先退回这一笔再把异常抛出去。返回假则退款并 `REJECTED`。
7. 花费大于 0 时 `MagicPool.showBalance`。然后 `afterCommit`。视觉异常只记日志。结果仍是 `COMMITTED`，不退款。

`Result` 仍是 `COMMITTED`、`REJECTED`、`INSUFFICIENT` 三个枚举常量，空玩家和非自身状态仍然 `== REJECTED`。失败句子不在枚举上，而在同一线程的 `SelfStatusCommit.playerText()`。调用方要在 `attempt` 返回后立刻读取；`COMMITTED` 会清掉这句。

冷却没改。`SkillUsePacket` 只有 `COMMITTED` 才用 `configuredBaseCooldown` 写槽位冷却。拒绝和魔力不足都在这之前返回。

`SelfStatusOrder.decide(previewReady, paid, furnaceReady)` 的三参数顺序没改：预检失败、未付款、安装失败退款、否则提交。新增四参数版本在预检和付款之间插入 `recheckReady`，失败步是 `RECHECK_REJECT`。安装前那次调用把最后一个参数固定为 false，返回的 `REFUND` 只表示还没安装，提交器不会在这一步退款。

`SelfStatusCast.action()` 仍保留，默认返回空。提交器不读它。炉心三式的定义继续返回原来的 `ENTER_NORMAL`、`ENTER_OVERDRIVE`、`COOL`，给既有注册检查用。有限效果不覆盖它。

## 2. 炉心适配

`FurnaceSelfStatusCast` 只适配原来的预览和三个服务动作。

| 定义 | id | 魔力 | 动作 |
| --- | --- | --- | --- |
| 升温 | `fire_heat_up` | 20 | `ENTER_NORMAL` |
| 燃烧 | `fire_burn` | 20 | `ENTER_OVERDRIVE` |
| 冷却 | `fire_cool` | 0 | `COOL` |

三式仍然是 `SELF_STATUS`、`ChainRole.ACTION`、拒绝混链、松开再按、装配消耗 1。`END` 和空动作在预览前拒绝，不调用进入或冷却。

预检和二次校验都调用 `FurnaceService.preview`。预览会走炉心既有对账；二次校验因此会再对账一次，不改热量公式。安装仍是 `enterNormal`、`enterOverdrive`、`cool`。升级是否留热、主动冷却是否放蒸汽、被动结束是否不放蒸汽，都还在炉心服务里。

玩家句子仍是 `§c炉心状态没有改变`。视觉仍在安装成功之后：`ENTERED_NORMAL` 用升温循环，`ENTERED_OVERDRIVE` 和 `UPGRADED` 用过载循环，`COOLED` 用冷却一次。升级不重播升温。

## 3. 有限效果

`FiniteMobEffectCast(MobEffect effect, int durationTicks, int amplifier, PresencePolicy policy)`。

- 效果必须已在 `ForgeRegistries.MOB_EFFECTS` 中。没注册的直接拒绝，不会去构造实例。
- 时长必须是正数。`MobEffectInstance.INFINITE_DURATION` 不是正数，会被拒绝。类里没有 600 这个常量。
- 等级是 0 到 255。客户端效果包把等级收成一个字节，超出会被截断，所以这里当非法拒绝。
- `REJECT_IF_PRESENT`：身上已有同一种效果就拒绝，不调用 `addEffect`。
- `REFRESH_SAME_LEVEL`：没有效果就安装。已有且等级相同、剩余时长更短，才交给 `addEffect` 延长。等级不同、无限时长、剩余时长相同或更长，都当没有变化拒绝。不读取、不写入原版隐藏等级链。
- `commit` 调用 `addEffect`。返回假，或装上之后的实例不是所请求的效果、等级和有限时长，都算失败。若这次是新挂上的且对不上，会 `removeEffect` 再返回失败，避免把被效果自己改写过的实例留在身上。原先已经在身上的效果不会因为刷新失败被摘掉。
- 这个类没有 `afterCommit` 视觉，也不注册术式。

有限效果的失败句是 `§c自身状态没有改变`，和炉心那句分开。

## 4. 包内接线

`SkillUsePacket.executeSkill` 仍先走 `CooperativeCastRouter.route`。协同链不会落到后面的自身状态分支。报价仍由 `SkillChainPlan.pressCommitCost` 计算，本文件没改这段，也没改领域绑定。

自身状态分支只在 `COMMITTED` 时沿用原来的冷却返回。魔力不足和其它失败都 `tell` 提交器给出的句子：炉心成功路径之外的失败不再写死炉心原文；炉心适配器自己仍提供原文。
