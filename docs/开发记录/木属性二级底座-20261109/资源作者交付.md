缺主人、缺花谱分项，读取结果是 0。身份、坐标、区间、到期缺键或坏掉的地面条作废，不发奖。负数的整名主人条目作废，不保留其余正数。六项都非负但超过 180000 时，从彼岸向桃花截断。根号或片段编号重复、区间重叠、普通批次潜力超过 60000、根数超过 256，按下面的上限整批或整根丢掉，不发奖。

## 单位与上限

`WoodLimits.UNITS_PER_DEGREE = 60000`，`FULL_UNITS = 180000`，`BATCH_POTENTIAL = 60000`。这是账本分辨率，不是花瓣产量。

六项顺序固定，不能重排：桃花、青竹、紫藤、寒梅、幽兰、彼岸。`SuihuaSnapshot.total()` 是六项之和。`degrees()` 是 `total / 60000`。

内存保护，超限整批拒绝，不挤掉旧资源：每批 256 根，每名主人 256 个活跃批次、4096 个活跃片段，全服 65536 个活跃片段。同一主人同时未发布票据最多 256。水平坐标超出 ±30000000 方块则整批拒绝。

区间潜力：`WoodInterval.potential(P, E, low, high) = floor(P*high/E) - floor(P*low/E)`，乘积用 long。原始区间是 `[0, E)`。部分消费从低端取。分割只切开现有区间，根、来源、到期继承。没有复制或合并入口。

`ULTIMATE` 写入的根潜力强制为 0。调用方传来的正数被丢掉；负数整批拒绝。片段上没有单独的可充能开关。

## 公开签名

失败一般不抛异常。`SuihuaSnapshot` 的规范构造器在负数或超过三度时抛 `IllegalArgumentException`；显示和修复走 `clamped` / `repairOrNull`。`ready` 抛 `RuntimeException` 时本次不改账，返回空。

### 票据与地面

```text
ProductionTicket beginProduction(ServerPlayer owner, ResourceOrigin origin)
CreateResult publish(ProductionTicket ticket, List<GroundLotSpec> lots)
GroundQueryResult query(ServerLevel level, UUID ownerId, AABB bounds, int limit)
Optional<GroundConsumeReceipt> consumePrepared(ServerPlayer actor, List<FragmentTake> takes, Predicate<GroundConsumePreview> ready)
SplitResult split(ServerPlayer actor, FragmentHandle fragment, int leftUnits)
RemoveResult discard(ServerPlayer actor, FragmentHandle fragment, RemovalReason reason)
```

`beginProduction`：主人必须是服务端主线程上的存活玩家。成功返回票据并推进持久编号；失败返回 null（错线程、未存活、账本封存、未发布票据已满、编号耗尽）。票据只在签发的那个服务器 tick 内有效。没有公开构造器。同一次催花的多个目标要共用调用方自己保存的这一张票据；服务不会把多次 `beginProduction` 猜成同一动作。

`publish`：整批成功或整批拒绝。识别到的票据无论成败都作废，不能拿同一张再发布。错线程不作废。空列表会消耗票据和编号，但不留下活跃批次。`GroundLotSpec.lifeTicks` 是该维度游戏时间的正 tick，没有默认寿命。`expireGameTime = 发布时该维度 gameTime + lifeTicks`。目标维度必须已加载，目标区块必须已经 `hasChunkAt`，不会去加载区块。未加载、坐标非法、`effectiveUnits <= 0`、`potentialUnits < 0`、寿命溢出，都是 `VALIDATION` 并作废票据。普通批次潜力合计超过 60000，或根/片段/批次数量超限，是 `CAPACITY`。成功时 `fragments` 与入参顺序一致，修订号都是 1。`ULTIMATE` 的存储潜力为 0。

`query`：只读，不改账，不发奖。错线程返回 `THREAD`。`bounds` 要有限；包含规则与原版 AABB 相同，最小边含、最大边不含。`limit < 1` 返回 `LIMIT`。结果按批次号、根号、区间低端、片段 UUID 排序。超出 `limit` 时 `truncated` 为 true。封存返回 `SEALED`。

`consumePrepared`：演员 UUID 必须等于片段主人。校验片段编号、修订号、数量、重复项，整组全成或全不成。`ready` 只能看 `GroundConsumePreview`。返回 false、抛运行时异常，或回调里再调用任何改账方法，都不扣。扣的是区间低端 `units` 个有效数量。`potentialUnits` 是被取走区间的潜力，不会入账。成功后才返回收据。空 Optional 表示拒绝，不另带原因码。

`split`：`leftUnits` 是留下的低端那段的长度，必须大于 0 且小于当前长度。原片段编号保留，修订号加一；新片段修订号为 1。两边同一根、同一来源、同一到期。超限则 `CAPACITY`，原片段不变。错线程是 `THREAD`，未存活是 `ACTOR`。

`discard`：只有 `EXTERNAL` 会删除，并且不发岁华。成功工厂是 `RemoveResult.success()`，得到 `accepted == true`、`reject == NONE`。拒绝走 `RemoveResult.rejected(WoodReject)`。实例上判断是否成功用记录访问器 `accepted()`。

### 岁华

```text
SuihuaSnapshot readSuihua(MinecraftServer server, UUID ownerId)
boolean ledgerWritable(MinecraftServer server)
Optional<SuihuaSnapshot> consumeFullPrepared(ServerPlayer player, Predicate<SuihuaSnapshot> ready)
void installBalanceSink(SuihuaBalanceSink sink)
List<UUID> drainDirtyOwners(MinecraftServer server)
```

`readSuihua` 在错线程、没有主人或账本封存时返回全零，并且不写档。封存时要先看 `ledgerWritable`。

`consumeFullPrepared` 只在总额正好 180000 时继续。未满不调用 `ready`、不扣账。`ready` 和返回值都是清零前的六项快照。拒绝、抛错、重入都不扣。成功后六项一次变 0。

`SuihuaBalanceSink.onChanged(UUID ownerId, SuihuaSnapshot snapshot)` 收到的是**变更之后的绝对六项**，不是增量，也不是三度消费返回的那份清零前快照。没有安装 sink 时，变过的主人留在 `drainDirtyOwners`，避免每 tick 全量广播。安装了 sink 且通知成功的主人会从脏集合去掉。通知抛错，或回调里又改了账，则留到下一次服务端 tick 再通知。不要在 `ready` 里改账或 drain。回调里不要把绝对快照当成增量相加。

`SuihuaSnapshot` 字段单位都是账本点：`peach bamboo wisteria plum orchid higan`。`amount(FlowerKind)`、`total()`、`degrees()`。`repairOrNull` 供坏档，有负数则返回 null。`clamped` 只给客户端显示：负数当 0，再从彼岸向桃花截到三度。

## 生命周期调用点

都在服务端主线程。错线程的生命周期方法直接返回，死亡/登出/换维会打一条警告。

| 时机 | 方法 | 效果 |
| --- | --- | --- |
| `ServerStartedEvent`，主世界已就绪 | `onServerStart` | 加载账本，丢弃旧地面，恢复岁华 |
| `TickEvent.ServerTickEvent` 的 END | `onServerTick` | 扫掉过 tick 票据；主人在线、存活、与片段同维度且区块仍加载时，才自然到期入账 |
| 玩家死亡 | `onOwnerDeath` | 清本人地面和岁华，不把地面潜力加进岁华 |
| `PlayerLoggedOutEvent` | `onOwnerLogout` | 清本人全部地面，岁华保留 |
| `PlayerChangedDimensionEvent` | `onOwnerChangeDimension` | 清本人全部地面，岁华保留 |
| `ChunkEvent.Unload` | `onChunkUnload` | 清该区块地面，不加载区块 |
| 维度卸载 | `onLevelUnload` | 清该维度地面；岁华仍在主世界这份账上 |
| `ServerStoppingEvent` | `onServerStop` | 丢掉未发布票据，不发奖，不在停服时抹地面 |

死亡按玩家 UUID 清账，不要在 `PlayerEvent.Clone` 里把岁华抄回新身体。死亡事件和死亡克隆都调用 `onOwnerDeath` 时，第二次是空操作。

同一 tick 里，如果到期扫描发生在登出/换维之前，而且当时主人仍在线、区块仍加载，已经到期的部分会入账；还没到期的地面随后被清掉且不入账。登出、换维、卸载、死亡都必须接上，否则人回来后，tick 会把仍留在账上的到期片段入账。离线不追补。

主人不在、死亡、不同维度或区块未加载时，tick 跳过该片段，不删除、不发奖。删除交给上面的生命周期方法。

自然入账按批次号、再按批次内根号（提交顺序，从 1 起），再按区间低端。满额只收剩余容量，多余丢掉，片段仍然结束，不保留补领票据。同一 tick 重复调用 `onServerTick` 不会第二次发奖。
