# 迎击整合交付

本阶段只把已经收束的通用迎击接到现有 `hurt` 包装和独立事件订阅上。没有改 `combat/counter`、`MagicPool`、木系资源目录，也没有新增术式、花谱或渲染。

## 1. hurt 包装

`FireHurtMixinPlugin.preApply` 仍只调用 `FireHurtBoundary.wrapMappedHurt`。没有第二套 ASM。

`wrapBooleanInstance` 保留原来的 `tokenLocal`、`returnLocal`、`thrownLocal`，并在后面加一个引用槽 `counterLocal`。`maxStack` 仍只保证至少为 4。元素帧的 `enterHurt` / `exitHurt` 和覆盖方法体的 `finally` 都还在。

一次调用的顺序：

1. `ElementDamageScope.enterHurt`，令牌存进 `tokenLocal`。
2. `CounterService.enterHurt`，帧存进 `counterLocal`。关联只用这条调用栈，不用受害者、来源和 tick 拼键。
3. `CounterRuntimeEvents.markHurtEntered`，为这一层包装压一个空的伤害事件槽。
4. 原方法体。原来的 `IRETURN` 仍改成保存布尔值并跳到正常出口。
5. 正常出口：`sealDamage`，再 `CounterService.finishHurt(frame, 最终布尔)`，然后原来的 `exitHurt`，最后 `IRETURN`。
6. 异常出口：`discardDamage`，再 `CounterService.abortHurt`，然后原来的 `exitHurt`，最后把原异常 `ATHROW`。

`sealDamage` 和 `discardDamage` 自己吞掉记录过程中的异常，避免跳过后面的 `exitHurt`。`finishHurt` / `abortHurt` 仍由效果作者的实现吞异常。

## 2. 最终取消

`LivingEntity.hurt` 的布尔返回值不能单独代表伤害事件的最终取消。盾牌把剩余伤害减到 0 时返回 false；受伤事件或伤害事件被取消、以及吸收把生命伤害扣成 0 时，原方法仍可能返回 true。

消费仍由效果作者的账本决定：要有预留、`finishHurt` 收到的布尔为真、受伤事件没取消、伤害事件已经到达且最终没取消。吸收把生命伤害扣成 0 时，只要伤害事件到达且没取消，账本仍算这次有效。没有到达伤害事件，或 `hurt` 返回 false，或异常出口走 `abortHurt`，都不消费，窗口继续。

伤害事件监听放在 `LOWEST`，监听当时就调用一次 `CounterService.onLivingDamage`。同一次包装调用正常返回前，`sealDamage` 再用同一个事件对象读 `isCanceled()`。这时事件派发已经返回，后来的同优先级监听器做的取消也能看见。正确性不依赖“同优先级后面不会再取消”。

归属不再用笔记条数和进入深度比较。`DamageEventSlots` 每次 `push` 一个槽，`writeCurrent` 只写最内层那个槽，`popSeal` 和 `popDiscard` 各自只弹出当前槽。外层还没有自己的伤害事件时，内层先结束并被改成取消，内层 `popSeal` 交回的是内层那个事件；外层随后弹出的是空槽，不会把内层事件记到外层帧上。内层在伤害事件之前走 `popDiscard`，外层已经写下的事件还留在自己的槽里。包装外的事件没有槽可写，不会挂到下一次调用上。正常出口只在槽里真有事件时再调用 `CounterService.onLivingDamage`，读到的是派发返回后的 `isCanceled()`。异常出口不调用服务。

## 3. 事件

`CounterRuntimeEvents` 用 `@Mod.EventBusSubscriber(modid = xueximod)` 注册一次。没有再把同一批方法注册到 `ReleaseBaseEvents` 或 `MinecraftForge.EVENT_BUS`。

| 事件 | 优先级 | 调用 |
| --- | --- | --- |
| `LivingHurtEvent` | `LOW` | `CounterService.onLivingHurt` |
| `LivingDamageEvent` | `LOWEST` | 先记住事件，再 `CounterService.onLivingDamage` |
| `TickEvent.ServerTickEvent` | 默认 | 只在 `Phase.END` 调用 `CounterService.onServerTick` |
| `LivingDeathEvent` | `LOWEST` | 事件未取消且是玩家时 `onOwnerDeath` |
| `PlayerLoggedOutEvent` | 默认 | `onOwnerLogout` |
| `PlayerChangedDimensionEvent` | 默认 | `onOwnerDimension` |
| `ServerStoppingEvent` | 默认 | `CounterService.onServerStopping(event.getServer())`，然后丢掉当前线程的伤害事件槽 |

`LOW` 在 `ReleaseBaseEvents.onHurt` 的 `HIGH` 持续卸伤之后。减伤、不取消事件、不写无敌帧，都在 `CounterService.onLivingHurt` 里，这次没有改那段实现。反击仍由 `onServerTick` 在拍末打出，不在受伤事件里当场打。反击来源、递归标记和无敌帧仍由效果作者的 `perform` 负责。

死亡订阅在 `CounterRuntimeEvents.onOwnerDeath`（77–84 行）。已取消的死亡直接返回，不调用 `CounterService.onOwnerDeath`。

停服在 `CounterRuntimeEvents.onServerStopping`（105–110 行）。它不读玩家列表，没有在线玩家时也调用 `CounterService.onServerStopping(event.getServer())`。空服务器或非服务端线程时，服务自己返回且不清表。调用之后，无论服务是否清表，当前线程的 `DAMAGE_SLOTS` 都会 `remove`，同一次 JVM 再开服不会留着上一局的伤害事件槽。死亡、登出、换维仍各自清本人。

## 4. 字节码检查

`FireHurtBytecodeCheck` 已改成核对现在的包装：元素 `enterHurt` / `exitHurt` 按 owner 和描述符计数，迎击 `enterHurt` / `finishHurt` / `abortHurt` 另计。正常出口是 `sealDamage`、`finishHurt`、`exitHurt`、原布尔 `ireturn`。异常出口是 `discardDamage`、`abortHurt`、`exitHurt`、原异常 `athrow`。覆盖全方法的 finally、字段写入和第二次 `wrapMappedHurt` 拒绝仍在。这是可执行检查，运行命令写在 `整合交付.md`。这次没有跑。
