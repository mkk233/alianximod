## 必须修复

### 1. 中，归属 C：嵌套时伤害事件和包装层对不齐

`CounterRuntimeEvents.markHurtEntered`（36–38 行）只加深度，不压槽。`rememberDamage`（130–146 行）在 `notes.size() < entered` 时直接 `addFirst`。`sealDamage`（49–50 行）和 `discardDamage`（70–71 行）只有 `notes.size() == entered` 才弹出。

触发：外层 `hurt` 已经进入包装，自己的 `LivingDamageEvent` 还没记下，内层 `hurt` 先走完并产生了伤害事件。内层 `sealDamage` 对不上，事件留在队列里。

后果有两条：

- 内层同优先级、更晚的取消，`sealDamage` 看不到。监听当时的 `onLivingDamage` 已经按未取消记下。
- 外层随后没有自己的伤害事件，但 `hurt` 仍返回 true（例如 `LOW` 预留之后，更晚的受伤监听把伤害改成 0 或取消）。`sealDamage` 会把残留的内层事件记到外层帧上。外层 `damageReached` 变成 true，窗口会被消费。

当前仓库的受伤/伤害监听不再次调用 `hurt`。原版荆棘在外层伤害事件已经入栈之后才嵌套，这时 `size == depth`，内层 `seal` 能对上。非嵌套的同优先级晚取消也能被正常出口再读到。

最小边界只改 C：每次 `markHurtEntered` 压一个槽；伤害事件只写入当前槽；`sealDamage` 和 `discardDamage` 各自弹出恰好一槽。有事件才按最终 `isCanceled()` 再调 `CounterService.onLivingDamage`。异常槽只丢弃，不记成命中。不要改 B 的消费条件。

元素帧的 `finally` 仍然在。`FireHurtBoundary` 正常出口是 `sealDamage`、`finishHurt`、`exitHurt`、`IRETURN`（87–96 行）；异常出口是 `discardDamage`、`abortHurt`、`exitHurt`、`ATHROW`（97–105 行）。`sealDamage`、`discardDamage`、`finishHurt`、`abortHurt` 都吞掉自己的异常。入口处的 `enterHurt` 和 `markHurtEntered` 在 `try` 之前，这两次调用本身不会抛。

### 2. 低，归属 C：停服只清当时在线玩家

`CounterRuntimeEvents.onServerStopping`（118–128 行）只对 `getPlayers()` 调用 `onOwnerLogout`。窗口和待反击在 `CounterLedger` 的静态表里，没有全表清空。

正常登出会先清掉本人。专用服务器进程退出后，静态表一起消失。会留下来的，是已经不在玩家列表里、又没经过登出、死亡、换维的窗口。这只影响同一个 JVM 再次开服，例如集成服务器。

必要修复：在 `ServerStoppingEvent` 里无条件清空全部窗口和待反击。不必新增按 UUID 的公共 API，也不必扫维度或写存档。

### 3. 低，归属 C：已取消的死亡仍清窗口

`onOwnerDeath`（97–101 行）是默认优先级，不看 `isCanceled()`。事件一旦发出，窗口和还没打出的反击都会被清掉。按 1.20.1 的常见结构，图腾在 `die()` 之前生效，不会发出这次死亡事件；这次没有打开 Forge 的 `LivingEntity`。图腾救下后，`finishHurt` 仍按主人存活结算。

最小修复：订阅改到 `LOWEST`，只在事件未取消时调用 `CounterService.onOwnerDeath`。
