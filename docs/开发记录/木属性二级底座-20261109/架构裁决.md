# 木属性二级底座接入裁决

- 裁决者：本批唯一 gpt-6-astra，2026-11-09，设计第 1/2 轮。
- 依据：本目录三份 Cursor 只读事实报告及最终玩法文档。
- 用户已回答：死亡清空岁华和本人花瓣，清除不产岁华。
- 范围：两资源可运行底座、通用效果API、SELF_STATUS最小通用化。不制作花谱术式、插枝、催花、花海侵蚀、大招、生命恢复、净化或美术。

## 1 单一权威账本

新增 `status/wood/resource/`，主世界 DataStorage 中一份 `WoodResourceSavedData` 保存全服批次/地面片段/玩家岁华贡献/单调批次编号/版本。不得每维度另存玩家岁华；玩家NBT、实体、客户端不另存可发奖余额。自然凋谢的资源删除与岁华增加在同一账本提交并标脏，避免跨文件双写。

固定 `UNITS_PER_DEGREE = 60000`、满额180000。六项非负整数贡献之和为岁华总值，不另存可失配总余额。乘除中间值用long。该精度是底座分辨率，不决定花瓣产量、混种折扣或技能数值。六花谱只是稳定来源键/枚举，不是新增术式ID。

## 2 批次与片段守恒

- Batch：batchId、ownerId、origin、dimension、createdGameTime。
- RootLot：rootId、batchId、flowerKind、原始有效数量E（正int）、原始岁华潜力P（非负int）、expireGameTime。
- Fragment：fragmentId、rootId、dimension、position、区间[lo,hi)、revision。
- origin只有NORMAL_BLOOM与ULTIMATE；创建后不可修改。ULTIMATE所有根P强制为0，不允许片段独立提交可充能开关。
- 普通批次P合计至多60000，允许不足一度；一次提交完整根列表，整批验证后落账，不提供后续追加预算入口。
- 区间潜力：`floor(P*b/E) - floor(P*a/E)`。原始[0,E)。部分消费从前端取，拆分只能切现有不重叠区间，来源/根/到期继承。反复拆分消费不重新分配预算。
- 不做跨来源实体合并；将来视觉合并仍组合原片段，不抹除来源。复制等于切分已有份额，不能克隆相同区间发两份奖励。

公共接口职责（名称可按项目习惯）：

```
beginProduction(ServerPlayer owner, ResourceOrigin origin) -> ProductionTicket
publish(ProductionTicket ticket, List<GroundLotSpec> lots) -> CreateResult
query(ServerLevel level, UUID owner, AABB bounds, int limit) -> GroundQueryResult
consumePrepared(ServerPlayer actor, List<FragmentTake> takes,
                Predicate<GroundConsumePreview> ready) -> Optional<GroundConsumeReceipt>
split(ServerPlayer actor, FragmentHandle fragment, int leftUnits) -> SplitResult
discard(ServerPlayer actor, FragmentHandle fragment, RemovalReason reason) -> RemoveResult
readSuihua(MinecraftServer server, UUID owner) -> SuihuaSnapshot
consumeFullPrepared(ServerPlayer player, Predicate<SuihuaSnapshot> ready)
    -> Optional<SuihuaSnapshot>
```

所有修改限服务端主线程。ready是同步只读能力检查，不允许修改资源或产生伤害；异常失败不改账。消费校验片段ID/修订号/所有者/数量/重复项，整组全成或全不成。消费成功返回不可变收据，技能之后才产生效果。最终消费重新校验，不能只信查询快照。

ProductionTicket由服务生成，构造器不对外，仅成功publish一次，失败/过期票据废弃，不能重建闭合批次。使用持久单调编号，禁止提供任意ID重新注册旧批次；未publish票据限制当前调用期或当前tick，不积累永久空批次。未来同一次催花的多个目标/复制必须共用根动作创建的同一ticket；服务不能猜多个随机ID实际属于同一动作，本轮不假称解决未定的动作分组。

查询显式owner/空间范围，返回不可变视图和截断标记，读操作无副作用。普通消费actor UUID须等于owner，系统凋谢走内部路径。未来共享玩法可扩授权接口，本轮不开放任意人消费任意UUID；这不决定枝印多人归属。

技术容量：每批256根，每owner256活跃批次/4096活跃片段，全服65536活跃片段；超限整批拒绝，不挤掉旧资源或奖励。拆分受相同上限。寿命调用方传正tick，不写6秒默认。这些为内存保护边界，不是玩法产量配置。

## 3 自然结算与生命周期

只有服务tick检测的自然到期可发岁华，不向调用者开放NATURAL移除原因。消费/外力清除/死亡/登出/换维/区块维度卸载/重启清场不奖励。自然到期先计算仍存在区间的潜力，删除和入账同一次账本更新。满额只收剩余容量，多余丢弃，资源仍结束，不保留以后补领票据。同时到期按批次号、根号稳定排序，满额截断不能由HashMap顺序决定谱比例。

- 死亡：用户已选清本人地面资源和岁华，不奖励。
- 登出/换维：清本人地面资源，不奖励；岁华保留。
- 区块/维度卸载：清其中地面记录，不奖励，不强行加载区块。
- 重启：清前次会话地面记录，不奖励，恢复岁华。保存地面记录为确保同一账本快照一致，不代表重启后恢复场地。
- tick先核对主人在线/存活/同维度和区块仍加载，再判自然到期。无离线追补。
- 缺键为零。已知版本坏数据校验限额、引用、区间、组成，坏片段不发奖；未知新版本拒绝账本写入并保留原数据、给出日志，不能覆盖损坏为零。

生产接线必须覆盖tick、死亡、登出、换维、区块/维度卸载、启动恢复、停止清理。只同步本人岁华六项整数，登录/重生/换维/余额变更单发，断线清客户端缓存，客户端不计算发奖。地面显示和UI不是本轮必需，服务端空间记录可运行，岁华客户端数据缓存必须有。

保持ResourceView签名。登记 `xueximod:suihua`，value和tier均为floor(total/60000)，durationTicks=-1；现有resourceAtLeast(suihua,3)表示满三度。精确份额读SuihuaSnapshot。花瓣只走空间查询，不硬塞活体ResourceStatus，不造没有空间含义的玩家花瓣余额。

三度消费先取不可变六项快照，ready通过后六项一次清零再返回。原子性只承诺单账本单线程资源，不承诺未来伤害/魔力/世界/视觉跨系统崩溃事务。

## 4 SELF_STATUS 最小通用化

不注册六种花谱效果或占位花谱；并存选择仍未定。只提供提交任意已注册有限MobEffect的入口，将来使用600tick。

SelfStatusCast从FurnaceMath.Action改成小型提交行为：prepare(player)->PreparedStatusChange/rejection；PreparedStatusChange.recheck/commit/afterCommit。提交器统一沿用耗魔配置、ManaPaymentReceipt、成功才COMMITTED。预检/二次校验失败不收费，安装失败退款，成功后仅视觉失败不能退款已生效状态。不是DSL。

FurnaceSelfStatusCast适配原preview和三个服务动作；三式ID/魔力/冷却/拒混链/新按键/升级保热/主动冷却蒸汽/被动无蒸汽/升级不重播升温均保持。FurnaceService/Math/MobEffect专属规则不改。

FiniteMobEffectCast接受已注册effect、有限正时长、等级与小型覆盖政策，至少REJECT_IF_PRESENT和REFRESH_SAME_LEVEL；不管理隐藏等级堆栈。非法/无限时长与无变化拒绝，addEffect实际失败算提交失败。

SkillUsePacket失败消息由提交结果带出，炉心适配器保留原文。协同仍前置路由；SELF_STATUS但selfStatus为空不误送炉心。保持原协同结构/报价/绑定。

## 5 通用回蓝与一次迎击

MagicPool新增 `int restorePool(ServerPlayer player, int requested)` 返回实际增加量；原void restore委托它，保持兼容。安全long或差值计算，不能int相加溢出。非正请求/非服务端线程/无效玩家返回0；只增加玩家池，不填法杖，实际变化才存盘同步。退款仍由ManaPaymentReceipt，不改扣款顺序、自然回蓝与幻剑固定回蓝。不绑木系或自动消费花瓣。

通用迎击独立服务，不塞水环GuardStates。API arm(owner,CounterWindowSpec)、cancel(owner)、active(owner)。spec包括窗口tick、有限0<=减伤比例<1、有限非负反击实际伤害、直接攻击准入枚举。一个玩家一个窗口，已有拒绝，不叠/刷/盖。调用方传结算好的参数，本轮无花谱ID/属性倍率/自动配置。多次迎击由每次资源消费后重装。

准入枚举显式区分近战与有存活活体所有者的弹体。近战要求direct==source且为存活LivingEntity，只接受普通player_attack/mob_attack/sting等明确近战，不把荆棘法术算近战。弹体要求真实Projectile及存活攻击者。环境/持续/无主/反击/绕过无敌来源拒绝。排自己、isAlliedTo、自己的驯服物，遵守PVP许可，其余沿hostileCapture。不能只靠目前恒false的Relations.ally声称过滤队友。

减伤在既有持续卸伤之后对当前伤害乘1-ratio，不取消、不写无敌帧；已取消/非正/不合格不占窗口。成功语义：
- 本次LivingEntity.hurt调用内暂时预留；只有最终hurt接受且Hurt/Damage事件链未取消才永久消费并排队反击。
- 取消或hurt失败解除预留，窗口继续；有效伤害被吸收生命接住也算成功，完全未进入有效伤害流程的盾牌格挡不算。
- 同调用只一次，第一成功后同tick后续不能再用；超时/死亡/登出/换维清窗口与待反击，主人已死不补死后反击，不免死。
- 不能在LivingHurtEvent当场反击，也不能只把Hurt事件引用留到tick末，因为LivingDamageEvent还可取消。

执行者在动此时序前必须精确读现有LivingEntity.hurt包装实现：事实仅有enterHurt/exitHurt。优先利用已有包装得到最终boolean返回并保证finally，在极小通用调用帧中记事件和结果，finally清帧。不能用受害者+来源+tick作为嵌套关联键。若包装不够安全，交回精确事实暂停迎击提交接线，其余可推进；不要先猜代码。

成功先关闭窗口，再服务器tick末反击。新增中性 `xueximod:counterattack` DamageType，归属窗口主人，无绕过无敌标签，直接尊重原版无敌帧。不用TechniqueHits默认清帧路径，不用FireDamage。提供CounterDamage.isCounter(source)及调用范围标记；迎击拒绝该来源，未来插枝/催花入口也应拒绝。本轮不重写水环/水势/火伤。
