# 通用效果作者交付

本单只交通用回蓝和一次迎击。没有制作术式，没有接木系资源，没有做回血或净化，也没有改公共事件、网络或 hurt 包装。永久消费要等整合作者把下面的钩子插进现有包装之后才生效。

## hurt 包装事实

`FireHurtMixinPlugin.preApply`（38–44 行）只在 mixin 类名以 `FireResourceHurtMixin` 结尾时，对目标类每个方法调用 `FireHurtBoundary.wrapMappedHurt`。后者只包装非静态、名为 `hurt`、描述符为 `(Lnet/minecraft/world/damagesource/DamageSource;F)Z` 的方法。

`wrapBooleanInstance`（42–101 行）的实际顺序：

- 46–48 行分配 `tokenLocal`、`returnLocal`、`thrownLocal`。`returnLocal` 是 boolean，占一个局部槽。
- 56–61 行在方法入口、`tryStart` 之前调用 `ElementDamageScope.enterHurt(Object, Object)`，返回值存进 `tokenLocal`。`enterHurt` 在 `ElementDamageScope` 62–76 行，按调用栈压入 `HurtCall`。
- 66–75 行把原来的每个 `IRETURN` 改成 `ISTORE returnLocal`，再 `GOTO tryEnd`。最终 boolean 只留在这个局部槽里，没有传给任何 Java 方法。
- 77–82 行是正常出口：`tryEnd` 之后先 `exitHurt(HurtCall)`，再 `ILOAD returnLocal` 并 `IRETURN`。
- 83–88 行是异常出口：先保存异常，再 `exitHurt(HurtCall)`，然后 `ATHROW`。这条路径没有 boolean。
- 103–105 行的 `exitInsn` 描述符是 `(L...ElementDamageScope$HurtCall;)V`。`exitHurt` 在 `ElementDamageScope` 78–99 行，只按帧对象退栈。

正常和异常出口都会清掉元素帧。现有包装已经能在同一次调用里留下最终 boolean，但 Java 侧拿不到它。效果作者没有改这个公共包装。不能改成受伤事件当场反击，也不能把 `LivingHurtEvent` 留到 tick 末再看，因为 `LivingDamageEvent` 还可以取消。

## 整合作者要插入的钩子

在 `FireHurtBoundary.wrapBooleanInstance` 里增加一个引用局部槽，不要改已有的 `tokenLocal` / `returnLocal` / `thrownLocal`：

```text
int counterLocal = thrownLocal + 1;
method.maxLocals = counterLocal + 1;
```

现有 `maxStack` 至少为 4，下面三次调用都不超过它。三个方法都不把异常抛出去；正常出口和异常出口在调用它们之后仍然要执行原来的 `exitHurt`。

所有者：`com/bslx/XueXiMod/combat/counter/CounterService`

帧类型：`com/bslx/XueXiMod/combat/counter/CounterHurtFrame`

1. 入口，插在 60 行 `ASTORE tokenLocal` 之后、61 行 `tryStart` 之前。`enterHurt` 不接收目标或来源，关联只靠这条调用栈，不能用受害者、来源和 tick 拼键。

```text
INVOKESTATIC com/bslx/XueXiMod/combat/counter/CounterService.enterHurt ()Lcom/bslx/XueXiMod/combat/counter/CounterHurtFrame;
ASTORE counterLocal
```

2. 正常出口，插在 77 行 `tryEnd` 之后、78 行 `ALOAD tokenLocal` 之前。先按最终 boolean 结算，再 `exitHurt`。

```text
ALOAD counterLocal
ILOAD returnLocal
INVOKESTATIC com/bslx/XueXiMod/combat/counter/CounterService.finishHurt (Lcom/bslx/XueXiMod/combat/counter/CounterHurtFrame;Z)V
```

3. 异常出口，插在 84 行 `ASTORE thrownLocal` 之后、85 行 `ALOAD tokenLocal` 之前。先解除预留并清掉这一帧，再 `exitHurt`，最后抛出原来的异常。

```text
ALOAD counterLocal
INVOKESTATIC com/bslx/XueXiMod/combat/counter/CounterService.abortHurt (Lcom/bslx/XueXiMod/combat/counter/CounterHurtFrame;)V
```

`finishHurt` 和 `abortHurt` 会吃掉 `Throwable` 并记日志，避免把后面的 `exitHurt` 跳过。hurt 方法体抛出的异常仍由上面的异常出口解除迎击预留。嵌套 `hurt` 各有一帧，内层先结束。

只插帧、不订伤害事件时，窗口不会永久消费。只订事件、不插帧时，事件看不到当前帧，也不会预留。两处要一起接。

## 事件优先级

不要在本包上加 `@SubscribeEvent`。整合作者自己的订阅者调用下列静态方法即可，不必为了这三处去改 `ReleaseBaseEvents`。

- `CounterService.onLivingHurt`：`LivingHurtEvent`，优先级 `LOW`。`ReleaseBaseEvents.onHurt` 在 44 行，优先级 `HIGH`，持续卸伤先改数量。`LOW` 看到的是卸伤之后的当前伤害，再乘 `1 - 比例`。不取消事件，不写 `invulnerableTime`。已经取消、非正或不合格的不占窗口。比 `LOW` 更晚的取消会使 `actuallyHurt` 在伤害事件之前返回；这种调用没有 `noteDamage`，预留会放开，窗口继续。
- `CounterService.onLivingDamage`：`LivingDamageEvent`，优先级 `LOWEST`。这里只记录这次调用有没有走到、事件有没有被取消。吸收生命把生命伤害扣成 0 时，原版仍会发出这个事件且不一定取消；只要走到了且没取消，就记为有效。请把这个监听放在 `LOWEST`，并且不要在它之后再取消同一事件。同一优先级里更晚的取消，这次回调看不到。
- `CounterService.onServerTick`：只在 `TickEvent.ServerTickEvent` 的 `Phase.END` 调用。成功的反击排到这一拍末尾，不在 `LivingHurtEvent` 里当场打。同一次 `END` 里如果有人在这次调用之后才发生 `hurt`，那次反击要等下一次 `END`。
- `onOwnerDeath`、`onOwnerLogout`、`onOwnerDimension`：分别接死亡、登出、换维。三者都清窗口，并取消已经排队、还没打出的反击。
- `CounterService.onServerStopping`：接 `ServerStoppingEvent`，参数用 `event.getServer()`。必须在该 `MinecraftServer` 的服务端线程上调用。服务器为空或当前线程不是它的服务端线程时直接返回，不清表。这一次不读 `getPlayers()`，所以已经不在玩家列表、又没经过登出、死亡或换维的窗口也会被清掉。它清空全部内存窗口和待反击，并把当前线程上的 hurt 帧、账本反击深度和 `CounterDamage` 标记深度归零。不写玩家数据、魔力或伤害类型。连续调用没有副作用，也不会把已经清掉的反击补回来。同一个 JVM 再次开服前必须调用，否则静态表还在；清完之后可以重新 `arm`。死亡、登出、换维仍然各自清本人，停服这一次是全表清理。

## 公开 API

回蓝，`MagicPool`：

```text
public static int restorePool(ServerPlayer player, int requested)
public static void restore(ServerPlayer player, int amount)
```

`restore` 改为委托 `restorePool`。`restorePool` 用 long 差值计算实际增加量，只加玩家池，不填法杖。请求不大于 0、玩家无效、已移除、客户端，或不是该玩家所在服务端线程时返回 0。池没有变化时不存盘、不同步。自然回蓝、退款收据、法杖扣款和幻剑固定回蓝没有改。

补蓝纯计算还暴露为 `ManaRestoreMath.accepted(int current, int upperBound, int requested)`，供定向检查调用。

迎击窗口：

```text
public static CounterWindowSpec tryOf(int windowTicks, float reductionRatio, float counterDamage, CounterAdmission admission)
public static CounterArmResult arm(ServerPlayer owner, CounterWindowSpec spec)
public static boolean cancel(ServerPlayer owner)
public static boolean active(ServerPlayer owner)
```

`tryOf` 在窗口 tick 不是正数、比例不是有限的 `[0, 1)`、反击伤害不是有限非负数、或准入为空时返回 null。一个玩家同时只有一扇窗口。已经有窗口时 `arm` 返回 `REJECTED_OCCUPIED`，不覆盖。参数或玩家无效返回 `REJECTED_INVALID`。装上返回 `ARMED`。

`CounterAdmission`：`MELEE`、`OWNED_PROJECTILE`、`DIRECT`。`DIRECT` 表示近战或有主弹体任一即可。

`CounterArmResult`：`ARMED`、`REJECTED_INVALID`、`REJECTED_OCCUPIED`。

帧和结算：

```text
public static CounterHurtFrame enterHurt()
public static void finishHurt(CounterHurtFrame frame, boolean accepted)
public static void abortHurt(CounterHurtFrame frame)
public static void onLivingHurt(LivingHurtEvent event)
public static void onLivingDamage(LivingDamageEvent event)
public static void onServerTick(MinecraftServer server)
public static void onOwnerDeath(ServerPlayer owner)
public static void onOwnerLogout(ServerPlayer owner)
public static void onOwnerDimension(ServerPlayer owner)
public static void onServerStopping(MinecraftServer server)
```

来源：

```text
public static final ResourceKey<DamageType> CounterDamage.TYPE
public static boolean CounterDamage.isCounter(DamageSource source)
public static boolean CounterDamage.markActive()
public static CounterDamage.Mark CounterDamage.open()
public static void CounterDamage.close(CounterDamage.Mark mark)
```

标记打开时，`isCounter` 对当前线程上的任意 `DamageSource` 都返回 true，用来挡住同一次反击调用里的嵌套 hurt。标记关闭后，只有 `xueximod:counterattack` 返回 true。迎击准入两种情况都拒绝。以后的插枝、催花入口也应拒绝 `isCounter`。

近战要求直接实体和来源实体是同一个存活、非旁观的 `LivingEntity`，并且类型是 `player_attack`、`mob_attack`、`mob_attack_no_aggro` 或 `sting`。荆棘、魔法、环境和持续伤害不进。弹体要求直接实体是 `Projectile`，`getOwner()` 与 `DamageSource.getEntity()` 是同一个存活生物。无主弹体不进。带 `bypasses_invulnerability` 的来源不进。

敌对先排除自己、`isAlliedTo` 双向队友和自己的驯服生物，再走 `RelationPolicy.hostileCapture()`。玩家是否能打仍由那里的 `canHarmPlayer` 决定。不使用恒为 false 的 `Relations.ally` 当作唯一队友过滤。

成功时先关窗口，再把反击放进队列。tick 末打出前会再看主人存活、未移除、非旁观、目标存活、同一维度、仍然敌对。反击调用 `target.hurt(counterattack, damage)`，来源归属窗口主人，不走 `TechniqueHits`，不伪装 `player_attack`，不用火伤，也不清无敌帧。原版护甲、抗性和无敌帧仍然生效。反击伤害为 0 时窗口可以因那次挨打而消费，但不会去调用 `hurt`。主人在这次 hurt 里已经死亡或不适合继续时，窗口关掉，不补死后反击，也不改这次伤害去免死。查不到主人时不消费，避免一次查找失败把窗口丢掉。

每个服务端 `END` 给仍开着的窗口减一拍，减到 0 就摘掉。这一拍若对应的 hurt 帧还在调用栈上，先不减，避免把正在结算的预留当成超时。死亡、登出、换维和 `cancel` 会清窗口，并丢掉该主人还没打出的反击。新窗口超时不会取消上一扇已经成功排进队列的反击。
