# 火种共享燃料改造执行契约

日期：2026-10-29。用户明确授权按最新版本由Cursor落实。

## 用户确认与范围

用户原话：这样改好一点所有燃烧效果都遵循火种值唯一的设计，燃烧启用后依然可以叠加其他燃烧上去，他们同时造成伤害也同时消耗火种值，这样不会损失伤害同时在多层是加剧了消耗量避免可以持续燃烧的同时触发高额引爆。

随后用户确认主会话的以下具体化，并要求：就按照这版让cursor落实。

1. 目标只有一份0至100整数火种余额。所有资源燃烧逐段从中取燃料，立即引爆消费当时剩余量，不建立第二套私有燃料池。
2. 新挂载燃烧不再预先扣完整余额。每层保留自己的伤害参数、结算间隔与持续限制。每段伤害和真实扣款绑定，无燃料不造成该段资源伤害。
3. 多层燃烧可以共存，各层燃料充分时保留自身完整单段伤害，层数增加会加快共同余额消耗。补种继续进入同一个余额，现有燃烧可自动消耗它，无需重放引燃。
4. 同一目标同一tick到期的燃烧按需求量比例分配不足的燃料，按实际投入比例缩放伤害。总扣除不得超过真实余额，也不能先后顺序造成只有第一层拿满、其它层无资源。
5. 余额耗尽则结束正在运行的新式资源燃烧，不能成为永久等待补种的免费状态。引爆先清余额则燃烧失去燃料；燃烧先扣部分则引爆只消费余量。
6. 焚天遵守同一消费机制，启动时锁定指数伤害档数与炉心参数，最多40有效tick结束，不因补种提高指数或延长上限。
7. 不新增燃烧期间禁止引爆、禁止产种等全局互斥。之前关于全局互斥的提案已撤回。

本轮实施公共底座及现有消费者接入，并同步相关规格与制作表。不要制作尚处于设计稿的引燃/引爆独立术式、幽冥、陨岩或其它基础组合；也不改正在由其他会话编写的领域计费方案。

## 具体落地口径

### 扣款和伤害

使用前述示例的标准燃料单位：一个完整燃烧段请求10点火种。公共计划明确携带单段需求，今后其它档案可配置自己的需求，不按术式ID分支。当前燎原和焚天按10点完整段接入。

燎原保留20tick间隔，启动时观察n=floor(当前余额/10)和F，完整段伤害保持2×(1+0.1n+F)。既有(3+n)×20tick作为最长有效期保留；燃料不足会提前结束，后续补种不刷新这个上限。

焚天保留4tick间隔，启动时观察n和F，完整段保持2×(1.2^n+F)。最多10个结算机会、40有效tick结束。补种仅提供后续燃料，不能刷新期限或指数。小于10点的实际分配按10点完整段比例缩放；不得再叠乘旧的启动余数尾段比例导致双重折减。

燎里保持6点物理与0.36S×(1+F)即时火伤，继续消费当时全部余额。新基础设计稿里的0.2S是未来引爆附魔，不得错误套到燎里。

启动时只观察初始档数和F，不把观察快照当成已经付款的消费凭证。实际每段付款才是本段的伤害凭证。燃料充足保持单段伤害，不保证无补种时仍享有旧版预付计划的全部段数；燃烧时长同时受燃料和自身有效期约束。

### 同tick分配和原子性

统一收集一个目标本tick到期的合法新式燃烧需求，再分配和扣一次总量。整数分配守恒，采用按比例向下取整后分配余数的确定性方法，不能超扣、负余额或复制点数。并列余数的顺序必须稳定，并避免固定首项长期独占可分配资源。

先完整验证能结算的计划，再原子更新共享余额与各层进度，最后按已提交的各层分配执行伤害。重复回调不得重扣重打。提交后的免疫/取消伤害按既定规则不退款、不补打。

无余额时终止新式燃烧；扣到0时本次已经付款的段仍执行，但其它未付费未来段结束。伤害回调中新添的火种不能使已终止的旧层复活，也不能被旧账本回写覆盖。引爆与燃烧按服务端事件顺序争用同一真实余额，不回滚他人后续生产。

### 层数与去重

合法的独立释放可以叠加燃烧层；不再用同效果键/同施法者或焚天同键目标排他阻止用户要求的多层。仍保留每目标最多8条计划的容量上限，满额拒绝必须发生在扣火种之前。

同次真实施法中的复制体、重复接触或迟到回调不能重复挂同一燃烧层；启动去重至少绑定原施法身份、目标和效果。周期扣款采用燃烧记录身份和结算序号，不能通过每段伪造new FireCastContext来绕过保护。即时引爆仍保持同次施法对同一目标最多一次。

每层原来的归属、伤害参数与实际结算时间独立；共享燃料不混淆归属，不把全部层合并成一条伤害。跨效果、跨施法者均竞争同一目标池。

### 生命周期和旧存档

死亡清除。卸载/退服暂停有效tick，不补离线伤害、燃料消耗或焚天期限；恢复时不能重复结算已提交段。只由服务端主线程写入，不改全局无敌帧，不绕过护甲/抗火等防御。
