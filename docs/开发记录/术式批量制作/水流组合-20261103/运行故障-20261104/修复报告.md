# 区块加载自等待修复

本单只改深海静水租约的区块加载回调。设计 2/2、实现 3/3 未重置，这次自查不是追加正式复审。未编译，未进游戏，未改制作表。

## 两个读取点

线程现场停在 `StillWaterLease.sweepOrphans` 的 `Level.getBlockState`。同一回调里 `reconcile` 也有一处 `Level.getBlockState`。`Level.getBlockState` 走 `ServerChunkCache.getChunk`，缓存未命中时 `managedBlock` 等待当前还没完成的区块 future。`getChunkNow` 才看 `currentlyLoading`，这条路径用不到。

两处都改为本次 `ChunkEvent.Load` 传入的 `ChunkAccess.getBlockState`。补放前的方块实体检查改为 `ChunkAccess.getBlockEntity`。回调里不再调用 `Level.getBlockState`、`Level.setBlock`、`ChunkAccess.setBlockState` 或 `Level.getChunk`。

需要改世界的格子记入 `LoadedEdit`。回调结束前用 `MinecraftServer.tell(new TickTask(当前 tick, ...))` 入队。`BlockableEventLoop.tell` 只放入 `pendingRunnables` 并 unpark，已在服务端线程时也不会当场执行。同线程的 `execute` 会当场 `run`，所以没有用它推迟。出队后先用 `Level.isLoaded`（内部是 `hasChunk`）确认区块已在，再走原来的 `clearIfOurs` 和 `placeIfAir`。

## 清理仍在

- 主人已不在或 `pendingClear`：摘掉租约；格子仍是临时静水则排队收回。
- 主人仍在且已是临时静水：标成已放置。
- 空气、尚未放置、没有方块实体：排队补放。`placeIfAir` 仍只在空气且没有方块实体时放置。
- 其他方块：摘掉租约，不覆盖。天然水不是临时静水方块，不归这份租约。玩家后来改过的格子同样不回填。
- 本区块里没有活租约的临时静水：排队收回并删掉对应租约记录。
- 重叠主人、`setDirty` 保存、卸载时未加载则 `pendingClear`，这些边界保持原路径。`fill` 和 `releaseOwner` 不在加载回调栈上，仍直接用世界接口。
