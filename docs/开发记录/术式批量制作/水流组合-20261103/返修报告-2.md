# 返修报告-2：运动撤销

日期：2026-11-03。这是按 `实现裁决-3-运动撤销.md` 落地的执行记录，不是新的正式复审。设计 2/2 与实现 3/3 已用完，本结果未追加复审。

## 做法

持续牵引、环绕和气泡不再写入 `deltaMovement`。每拍只发布一份位移意图，在原生 `Entity.move` 参数上合成一次。抛出仍是先退役持续意图，再写一次冲量。关闭、离开、死亡和换维只退役意图并推进该实例的运动纪元，不按相等比较回滚整段速度，也不按比例猜测重力或击退。

同一根上多个来源各自留记录。水平贡献优先已入册的来源，否则取较小的实例编号。上升取更高的下限。关掉 A 只删 A 的记录；旧纪元的回执不能把 A 重新算作有效。

## 裁决第 7 节路径

1. 持续流场不写持久速度，抛出仍是一次冲量，关闭不整段恢复。  
   `VolumeMotionRuntime.orbit`、`pull`、`liftBubble` 改为 `FlowMotionIntents.offer`。`ejectGroup` 先 `retireRoot` 再 `setDeltaMovement`。`onClose`、`steerGroup` 离开和 `releaseMissing` 只 `retireRoot` / `retireInstance`。`ReleaseMotionLedger` 已去掉 `writtenMotion`。

2. 两份来源、未入册的外围、独立气泡，以及关闭后旧回执不能复活。  
   记录在 `FlowMotionIntents` 的 `BY_ROOT` / `BY_INSTANCE`，按实例编号分开。外围 `pull` 在名册为空时不发布。气泡是自己的实例，`liftBubble` 用 `FlowRole.BUBBLE`。`retireInstance` 把该实例纪元加一。`FlowPlayerBridge.receiptHolds` 要求回执纪元等于当前纪元，且步号不大于已发布步号。

3. 普通生物、静止物品、玩家、玩家驾驶的船或坐骑、在轨矿车各有一次入口。玩家模拟和包末位置不会覆盖或再加一次流场。  
   普通生物和静止物品：`FlowStepMixin` 在 `ServerLevel.tickNonPassenger` 开始清消费、结束时若本步没有 `move` 就补一次 `Entity.move`。  
   玩家：`FlowPlayerMoveMixin` 把 `doTick` 包在 `simulating` 里，这段不注入流场；位置仍由原版 `absMoveTo` 落地。客户端 `FlowClientMotion.combine` 在本地 `move` 前加一次，`FlowLocalMoveMixin` 把原版移动包换成 `FlowMoveC2SPacket`。服务端 `acceptPlayer` 置 `alreadyIncluded`，`handleMovePlayer` 不再加第二份。  
   玩家驾驶的非矿车载具走 `acceptVehicle` 和 `handleMoveVehicle`，同样置 `alreadyIncluded`。  
   在轨矿车：`FlowMinecartMixin` 在本拍有流场时把 `moveAlongTrack` 转到 `comeOffTrack`，不额外再 `move`。矿车即使有乘客也不改成客户端桥。

4. 持续上升时原版重力不积出虚假向下速度；墙和顶仍走原生碰撞；落地只走原生路径；真实跳跃、外部击退、原版飞行和抛出冲量在关闭时保留。  
   `FlowGravityMixin` 在有效上升时让 `isNoGravity` 返回真，不写 `DATA_NO_GRAVITY`。查询走 `FlowMotionIntents.hasEffectiveRise`，客户端读 `FlowClientBridge.riseFloor`。`FlowPlayerMoveMixin` 在接受回执后清 `clientIsFloating`，并在连接 `tick` 开头清悬浮计数。上升结束后不再清，原版公式恢复。`WetnessFlight.correctDragonDescent` 在有效上升时不再 `setPos`。抛出冲量写在退役之后，后续清理不改这段速度。

5. 晚包、重复步、换根或换维、来源结束后的纠正，以及来源结束后恢复悬浮检查，都有分支。协议拒绝会记警告，不会静默卡死。  
   `FlowPlayerBridge.receiptHolds` 拒绝未来步和纪元不符。旧步且纪元仍匹配时接受绝对位置，不再注入第二段。`correct` 每拍记一次警告并发送 `FlowCorrectionS2CPacket`，不用原版绝对传送。`FlowMotionEvents` 在离维、死亡、换维和登出时 `retireEntity`。`FlowClientMotion.acceptCorrection` 复位位置和预测锚点，保留速度与飞行，再发确认和新位置。悬浮计数只在 `hasEffectiveRise` 为真时清零。

事实补充里「0 不满足 `d7 >= -0.03125`」不采用。悬浮保护按裁决保留，不因那句而省略。
