# 实现第 3 轮裁决：持续流场运动的撤销

2026-11-03，batchId `water-vortex-20261103`，实现累计 3/3。本轮只裁剩余运动撤销错误，不重审第 2 轮已对上的六项。输入为《实现复核-2.md》《返修报告-1.md》及已收束的《运动接口事实补充.md》《运动接口事实补充-2.md》《运动接口事实补充-3.md》，必要语义沿设计 1/2。没有读取当前 Java、修改源码或编译。v3 与 v3.1 已采用，本轮不审美术。

**当前实现该项仍不通过。必须停止把持续牵引、环绕、气泡写进持久 `deltaMovement`；改为带来源的单次位移意图，进入原生碰撞移动。一次抛出保留为独立冲量。** 以下为唯一作者的修复契约，不是修复后已经通过的结论。

## 1. 决定与范围

不再比较当前速度与旧写值，不按阻尼比率推算，不缓存整份旧速度在结束时恢复，也不拦截全游戏每一次速度赋值来猜来源。原生重力、阻尼、击退、游泳和飞行继续管理原有 `deltaMovement`；本次持续流场不进入该字段，因此无需事后减回。

“同拍撤销”指：关闭/退出处理一发生，此后的物理入口和移动包入口立即看不到该来源；不再产生下一次持续位移，也没有它遗留的持续速度。已经合法完成的碰撞位移不回滚，网络中已发送但尚未到达的客户端预测通过版本校验纠正；不能声称跨网络零延迟。不能为撤销倒退实体位置或清掉它的外部速度。

不改入卷费、返还、分体结算、占位、顶部出口、实体类别和视觉尺寸，不恢复旧深海下压。只替换持续运动的传递、施加与失效方式，以及为正确执行所必需的原生入口适配。

## 2. 来源记录与清理

新增/收拢一个小型 `FlowMotionIntent` 运行记录，键至少为 `(维度, 实例UUID, 根实体UUID, 来源代次)`，值含水平位移贡献、可选上升下限、生成步号及有效条件。代次用于失效旧指令，不能拿恒为 1 的 `DomainInstance.revision` 冒充。结算名册继续按原释放组共享，运动来源必须按真实实例区分。

同时维护实例→全部受影响根的反向索引，包括外围未入卷目标、已入卷根、独立气泡。禁止仅遍历 `roots(instanceId)`；禁止名册为 null 时仍写运动。删除旧 `writtenMotion`、`BUBBLE_ACTOR/BUBBLE_RISE` 的速度回退职责，不保留两套同时生效的路径。

同一根一拍选一个水平驱动，优先已有控制者，外围竞争按稳定顺序选定；竖直取有效上升中的最大值，不叠成多倍。一个来源结束只删自己的项，仍有效的其他来源可继续。每次物理入口重新检查实例活跃、寿命、主人/维度、水势、几何/通视、水支撑和骑乘根；不能仅依赖 END 曾经生成的快照。

退出范围、通视失效而本拍不施力、成员缺失、来源关闭、气泡离开、父宿主溃败、死亡/换维/卸载都统一使对应意图失效。父关闭同拍失效其挂载；未参与挂载的独立领域不清。源代次失效要同时撤掉未消费的客户端指令。超时未续发的意图自动失效，不留世界级 UUID 黑名单。

## 3. 在一次原生 move 中施加，不额外跑第二遍物理

`VolumeMotionRuntime` 的 pull/orbit/liftBubble 改为发布意图，不调用 `setDeltaMovement`。`ejectGroup` 仍走原一次抛出路径，但先撤持续意图并记已抛出；后续清理不得触碰这笔冲量。

在现有 `EntityMoveMixin` / `DomainMotion.clip` 前端组合位移，再执行原有封闭领域裁切和原版 `Entity.move` 的方块碰撞。OPEN 只表示不封界，不能导致跳过流场。原来的近零向量早退必须在组合之后判断，否则静止实体永远不受力。

- 水平：`本次位移 = 原生本次位移 + 本来源水平贡献`，仅约束流场自己的幅度。不要把 pull 以前复制进去的原生 Y 当成贡献再加一次；不要为了保持总速度上限把外部击退截掉。
- 竖直：有有效上升时，本次 Y 取原生位移 Y 与上升下限的较大者；无上升时原生 Y 原样。这只改变本次 move 参数，不回写为持续速度。更强的向上击退/飞行不压低。
- 同一根每个物理步只消费一次流场贡献。龙等原生一拍可能调用多次 move，后续原生调用不重复加流场。乘客不独立施力；控制、碰撞与已批准的并集容纳仍按根处理。
- 正常碰撞仍可依法改变原生速度、着地和摔落状态；“保留外部速度”不是让击退穿墙。不得在 move 返回后恢复整份速度来抹掉正常碰撞结果。

增加受来源约束的 `isNoGravity()` 返回适配：仅当根当前有有效上升时，返回“原值或有效上升”；不写 `DATA_NO_GRAVITY`，不调用 `setNoGravity` 保存再恢复。这避免被托举时原生负 Y 每拍累积，结束后突然带着人为积累的巨大下坠速度。只牵引/平面环绕不豁免重力，已有无重力/飞行状态不改。来源失效后查询立即恢复原值。`WetnessFlight` 的有效上升优先仍沿同一有效性查询。

严禁在 ServerTick.END 无条件追加一次 move，也不手写 `checkFallDamage`/`causeFallDamage`。原生移动已经负责碰撞、着地和摔落，流场只进入其这一次位移；不额外施加重力、不造第二份落地伤害。

## 4. 服务端自行模拟的实体与特殊原生路径

在 `ServerLevel.tickNonPassenger` 的实体物理步建立/结束本根的消费记录。生物、物品、空船、飞行生物等原有 SELF move 消费一次；不把这套回退用于下面的客户端控制玩家/载具。没有实际物理的旁观/noPhysics 等排除沿原设计，不增加生物类别白名单。

静止物品每四拍才可能 move，不能因此漏掉其余三拍：该实体步结束时若确实没有发生原生物理 move，且仍有非零有效意图，补一次原生 SELF move，输入当时的原生位移/速度并由同一组合入口消费意图。只能是“本拍没有 move”的补足，不能给已经移动过的实体再追加第二段。若本拍已由其他原生移动事件推进，不额外补一遍摔落处理。移除/死亡/已换维者不补。

矿车在轨会在 move 后再次投影位置并把 Y 清零，单改 move 参数不够。对本拍有有效流场的服务器矿车，将那一次 `moveAlongTrack` 分支改走已有 `comeOffTrack` 物理路径，避免随后轨道投影覆盖上升/侧移；没有意图时完全恢复原分支。只改此次原生分支选择，不额外再调用 move、不拆车乘客、不重写轨道物理。现有 off-track 速度/碰撞流程保留。

实际接受流场位移后，通过正常实体位置追踪促使位置更新（可用现有 `hasImpulse` 触发追踪），不要把流场伪装成 `ClientboundSetEntityMotionPacket` 的持续速度。非本地控制客户端只显示服务器位置，不再给远端实体叠一遍预测流场。

## 5. 玩家与本地驾驶载具：必须配对接入

只改服务端 `Entity.move` 不成立：玩家 `doTick` 后会被 `absMoveTo(firstGood)` 写回；移动包又会用最终客户端坐标覆盖 move 结果。玩家控船/坐骑的实际 travel 在客户端。不得将“服务器自己的 isControlledByLocalInstance 为 true”误当成玩家位置的最终权威入口。

采用有限的流场运动桥，不重造输入或碰撞引擎：

1. 服务端只向受影响玩家/驾驶者发送其物理根的临时流场指令：根身份、实例/代次、单调步号、水平贡献、上升下限及有效期。外围未入卷也发。费用、占位和来源选择仍由服务端决定；客户端不能创建来源或结算资源。根/驾驶者变化立即退役旧指令。
2. 本地客户端在其玩家或驾驶根的原生 move 前使用第 3 节相同组合；其原生碰撞/旅行只运行一次。必要的无 move 补足放在该本地物理步结束、发送移动之前，且必须确认本步未移动。客户端也只临时改 isNoGravity 返回，不改持久速度。对尚在睡眠等原生拒绝移动状态的玩家，先通过正常原版状态退出/唤醒入口使其可接受物理移动，不靠 absMoveTo 强行搬睡眠玩家，也不取消其飞行能力。
3. 给发出的玩家位置包/载具包附带“本次已经消费的流场指令回执”。使用一个 C2S 包封装原移动包的完整字段与回执，在服务端主线程校验后调用现有 `handleMovePlayer` / `handleMoveVehicle`；不要用两个互相猜先后关系的并行包。保留原位置/旋转/onGround 及原生非法值、超速、碰撞校验。多个客户端步的回执不得积压后一次补出一串流场；旧步丢弃，不突发补运动。
4. 校验连接对应的玩家/真实根、来源当前仍有效、代次、服务端已签发步号、未重复消费及有限幅度。服务端由回执确定这次包的位移**已经包含流场**，在该 native handler 上下文中禁止再注入一次。这样最后 absMoveTo 使用的就是经过客户端原生碰撞、又经服务端校验的完整目标，不会把服务端另加的一段覆盖掉。不能客户端加一次后服务端再加一次。
5. 玩家 `connection.tick → doTick → absMoveTo(firstGood)` 的模拟中不注入持续流场位移，也不对它做“无 move 补足”。它仍可按有效上升暂时豁免重力，避免其真实 delta 每拍累积下降；普通飞行/阻尼保留。客户端驱动的船/坐骑服务端清零分支同样不补流场；其最终位置由带回执的载具包进入。服务器自行模拟的矿车仍走第 4 节，不因为有乘客就误换成客户端控制。
6. 当源关闭后迟到的包含旧流场回执时，整次位置提案拒绝，不能把它当普通移动接受，也不能从最终位置/速度猜减旧流场。发一次专用位置纠正并等待该纠正的确认；确认前继续拒绝该根积压的旧位置提案，避免下一份无流场标记的旧坐标又把残余位置带回来。纠正使用当前合法的服务端位置和校正序号，客户端重设位置、原生着地/预测基准并清掉待发回执，**保留当前原生 delta、飞行状态及已收到的抛出/击退冲量**，确认后立即发送新的位置。不要为这次流场失效直接使用会把非相对轴速度清零的原版绝对玩家 teleport 包。载具纠正根后走正常乘客定位，不分别给乘客加位移。

该桥只在本地玩家/驾驶根有流场指令、待发回执或待确认纠正时接管封包；普通移动保持原路。原版因真正非法移动/碰撞产生的纠正仍按原路，不能把原有安全校验全关掉。发/收包绑定正确方向，主线程处理，断线/换维清空桥状态。

有来源时不能静默长期接受遗漏回执的控制客户端来绕过流场：指令有明确确认/超时，控制桥生效后的位置包必须遵守该协议；客户端尚未收到/正在重同步时允许正常协议握手，不能把未消费的指令记成已施力。正常网络延迟不等于服务端可以直接改位置补一段未经碰撞的流场。

## 6. 玩家原生派生行为的两处必要保护

`handleMovePlayer` 会把“上一拍着地、包离地且 Y 增大”解释为跳跃并调用 `jumpFromGround`。纯气泡上升若走此分支，会凭空制造持久的原版跳跃速度。流场回执必须同时保留本步流场组合前的竖直移动意图/真正跳跃信息；只有上升完全由流场造成、没有原生起跳时，抑制这一处派生跳跃。真正跳跃、击退或飞行照常，不能一律禁止 jump。

有效气泡悬空还需来源受限的防误踢适配：玩家的 `clientIsFloating` 条件不读 isNoGravity，必须在原生接受该移动包后，对确有有效上升回执的根把这次悬浮判定视为合法；连接 tick 的悬浮累计也尊重当前有效上升，来源结束后立即恢复原判断。载具相应处理 `clientVehicleIsFloating`。不得修改 mayfly、全局 allow-flight 或给所有领域玩家永久豁免。补充 3 解释里的“0 不满足 >= -0.03125”为笔误，原条件式里 0 满足，不能据该句省略本项。

玩家一次原生 `Entity.move` 的 checkFallDamage 是空覆盖，原移动包接受/拒绝后的 `doCheckFallDamage` 才是落地处理；保留它的原调用次数。载具则由其 native move 处理，没有另一份 doCheckFallDamage。运动桥不另加摔落结算；客户端纠正也不新增服务端伤害或清空服务端 fallDistance 来造免摔。

## 7. 关闭顺序与作者交付

关闭顺序固定：先将实例/挂载标无效并退役其运动代次，再清全部受影响根的意图与未消费指令，最后做原名册/同步清理。零水势、寿命、父关闭、离开在任何入口观察到都走同一个幂等失效入口。移动包可能在 ServerTick.END 后执行，因此必须在包入口实时核验，不能以“本拍 END 已检查过”为由继续接受旧来源。

最小写入职责：`VolumeMotionRuntime` 发布意图；运动账本/来源索引；现有 `EntityMoveMixin/DomainMotion` 的组合入口；重力查询及矿车分支小适配；服务端实体步和本地玩家/驾驶根的消费边界；有限 S2C 指令/纠正与 C2S 移动封装；网络 handler 的上下文、纯气泡派生跳跃和悬浮保护。保持现有 Prison 的包落点/纠正重定向，不新增与其抢同一个调用的第二套 Redirect。新代码应调用/组合已有入口，不靠 mixin 默认顺序碰运气。

作者必须交回以下定向证据：

- 持续 pull/orbit/bubble 路径已无持久速度写入，原一次 eject 仍在；关闭没有整向量恢复/相等比较/比例猜测。
- 两分体同根、外围未入卷、独立气泡的源索引和关闭路径均可追到；关 A 不删 B，旧回执不能复活 A。
- 普通生物、静止物品、玩家、玩家控船/坐骑、在轨矿车各自的实际入口与每步消费次数；玩家 doTick 回写和包末尾 absMoveTo 不会覆盖/双加流场。
- 持续上升时原生重力不积累假下降速度；墙/顶棚仍走 native 碰撞；落地只走对应 native 路径；真实跳跃/外部击退/原版飞行/抛出不被关闭清零。
- 迟到包、重复步号、换根/换维、来源结束后纠正握手，以及来源结束后的悬浮检查恢复均有明确分支。协议拒绝不得变成无日志的永久不动。

这些是本次修复作者的必要自查与交付，不是新增正式复审。实现与已确认美术写入收束后，由主会话授权约定的统一离线 compileJava；仍不打包、不启动游戏。真实联机时序、碰撞/载具与落地效果未经游戏验证，需在交付中如实列出。若作者无法完成其中某入口，报告具体未完成路径，不以“已有编译通过”替代，也不能退回已判失败的持久速度方案。

本轮结论：已给出可执行的来源隔离和原生移动接入契约；当前旧撤销实现不通过。设计 2/2、实现 3/3 已用尽，随后修复与美术接入结果不再自动追加正式复审。是否满足交付条件以实际完成情况、编译及表写回为准，不把本文写成修复已通过。
