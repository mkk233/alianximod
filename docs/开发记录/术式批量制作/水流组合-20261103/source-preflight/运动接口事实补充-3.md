# 运动接口事实补充 3

2026-11-03。只补两处玩家方法。源码包是 `forge-1.20.1-47.3.33_mapped_parchment_2023.06.26-1.20.1-sources.jar`。

## 1. clientIsFloating 与悬浮踢出

接受分支在 `ServerGamePacketListenerImpl.handleMovePlayer`。写入标志之前，`d7` 先是包内 Y 减去 `lastGoodY`（920 行），`move` 之后改成包内 Y 减去玩家当前 Y（930 行）。绝对值小于 0.5 时被写成 0（931–932 行）。`flag1` 是 `move` 前的 `verticalCollisionBelow`（927 行）。

接受后的赋值（945 行）：

```text
this.clientIsFloating = d7 >= -0.03125D && !flag1
    && this.player.gameMode.getGameModeForPlayer() != GameType.SPECTATOR
    && !this.server.isFlightAllowed()
    && !this.player.getAbilities().mayfly
    && !this.player.hasEffect(MobEffects.LEVITATION)
    && !this.player.isFallFlying()
    && !this.player.isAutoSpinAttack()
    && this.noBlocksAround(this.player);
```

`noBlocksAround`（475–476 行）返回碰撞盒膨胀 0.0625、再向下扩展 0.55 后的方块状态是否全部 `isAir`。

因为 931–932 行已经把落在 (-0.5, 0.5) 的 `d7` 写成 0，而 0 不满足 `d7 >= -0.03125D`，所以这个比较只在夹断之后仍然不小于 -0.03125 时为真。拒绝分支 957 行不写这个字段。

踢出不在 `handleMovePlayer`。`ServerGamePacketListenerImpl.tick` 271–279 行：

```text
if (this.clientIsFloating && !this.player.isSleeping() && !this.player.isPassenger() && !this.player.isDeadOrDying()) {
   if (++this.aboveGroundTickCount > 80) {
      LOGGER.warn("{} was kicked for floating too long!", (Object)this.player.getName().getString());
      this.disconnect(Component.translatable("multiplayer.disconnect.flying"));
      return;
   }
} else {
   this.clientIsFloating = false;
   this.aboveGroundTickCount = 0;
}
```

踢出条件是标志为真，且不在睡觉、不是乘客、未死亡或濒死，并且 `aboveGroundTickCount` 自增后大于 80。这里不再读取允许飞行、创造飞行、飘浮、鞘翅或脚下空气。任一外层条件不成立时，标志和计数都被清掉。

## 2. isEffectiveAi 与 isControlledByLocalInstance

`ServerPlayer.java` 和 `Player.java` 都没有这两个方法。二者用 `Entity` 的实现。

`Entity.isControlledByLocalInstance`（3282–3288 行）：

```text
public boolean isControlledByLocalInstance() {
   LivingEntity livingentity = this.getControllingPassenger();
   if (livingentity instanceof Player player) {
      return player.isLocalPlayer();
   } else {
      return this.isEffectiveAi();
   }
}
```

`Entity.isEffectiveAi`（3294–3296 行）：

```text
public boolean isEffectiveAi() {
   return !this.level().isClientSide;
}
```

`Entity.getControllingPassenger`（3206–3207 行）返回 null。`Player` 和 `ServerPlayer` 都没有覆盖它，所以对这两个类自身的调用不进入 `isLocalPlayer` 分支。`Player.isLocalPlayer`（1355–1356 行）返回 false；`ServerPlayer` 也没有覆盖它。

因此这两个类自身的 `isControlledByLocalInstance` 等于 `isEffectiveAi`，也就是 `!level().isClientSide()`。`Level` 构造把参数 `pIsClientSide` 写入 `isClientSide`（124、134 行）。`ServerLevel` 调用 `super` 时该参数是 `false`（199 行）。服务端 `ServerPlayer` 所在的 `ServerLevel` 上，`isEffectiveAi()` 为 true，`isControlledByLocalInstance()` 也为 true。
