# 返修报告 1

日期：2026-11-03。对应实现复核第 1 轮的 7 项。这不是编译结果，也不是游戏验收。

## 1. 干地选座和没座位就溃败

入口：`VolumeMotionRuntime.findSeat`、`acquire`、`orbit`。

干地和组合共用选座。组合先试漏斗半径，失败再从外向内排同心圆柱半径。每个半径用八个黄金角，并避开已经分给其他根的角度。判定看移动后的真实 AABB、方块碰撞和其他受控体，不看原版掉落物碰撞。没有合法座位，或体积超过 `occupiedVolumeLimit`，`acquire` 返回失败，当前旋流关闭。不再因为当前位置没撞上方块就继续叠在一起。

## 2. 没通视就不动、不入卷、不因擦边关闭

入口：`VolumeMotionRuntime.steerGroup` 里的 `clearLine`。

通视失败时本拍直接返回：不牵引、不环绕、不调用 `acquire`。隔墙接触也不再因为 `touching && !fits` 关闭。已经入卷的成员如果人在柱内并且身体卡进方块，仍按原来的关闭。通视失败时不写新速度。

## 3. 骑乘组用并集到顶并一次抛出

入口：`steerGroup` 的 `atCeiling` 和 `ejectGroup`。

到顶和水平容纳都看整组并集。并集顶进入顶部 0.2 格，且整组向上 0.6 格没有方块时，只给根写一次抛出速度，同组实体一起记入已抛出名册。头部已经高出柱顶、人还在水平圆柱里时，仍走这条抛出，不再掉回吸引。乘客速度不另写。

## 4. 结束时撤掉本实例写下的速度

入口：`writeOwned` / `revertMotion`，以及气泡的 `BUBBLE_RISE`。

旋流每次牵引或环绕记下自己写下的分量。离开、消失、关闭时，只有当前速度仍等于这份记录，才把对应分量清掉。抛出先写成抛出速度，再丢掉旧记录，不把抛出冲量减掉。气泡只记录自己写下的竖直速度；离开柱体或气泡关闭时，竖直速度仍等于这份记录才清零。击退、飞行和其他来源改过的分量保留。

## 5. 气泡半径和挂载

入口：`cylinderRadius`、`columnTouch`、`canMount`、`waterShared`。

`radius` 用于独立上升、上升意图和挂载。方盒四角、圆外的目标不会被抬起。挂载要同一主人、基部高度相交、两根圆柱相交，并且相交范围内有真实水。岸边干地方盒角不再把水中气泡挂死。父关闭仍会退役并关闭气泡，不改挂。

## 6. 水势耗尽

入口：`processHost` 读取 `PlayerShuData.getWaterMomentum`。

存档水势已经不大于 0 时，下一次处理就关闭该旋流，不再要求柱内已有成员。判断不用 `available()`，未提交预留不会被当成永久耗尽。扣返和毛费用仍走 `WaterMomentum.settle`。

## 7. 根编号整份同步

入口：`DomainSyncPacket.encode` / `decode`，客户端 `DomainMotionPreview.capture`。

编码和解析都按实际数量读写，不再截到 64。每一包都是当时的完整名单，客户端整份替换。实例移除时清掉名单。没有另加实体数量上限。客户端仍不根据附近实体猜测归属。
