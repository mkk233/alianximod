# 水流组合设计裁决：第 1 轮

日期：2026-11-03。batchId：`water-vortex-20261103`。本文件是开工前设计第 1 轮的完整结论，不是实现复审、编译结果或游戏验收；不另改批次额度记录。

输入：本批《需求快照.md》（含“只有形成水龙卷才启用湿度收支”的最新补充）、《现状报告.md》、《source-preflight/弹射与下压补充.md》、《表现状报告.md》及流程第 1、4–6 节。事实来自已收束的固定 Cursor 作者回执；本轮没有自行读取 Java、实现、编译或写制作表。视觉 v1 只是未确认草稿；用户新反馈“水流更饱满、水域中也要见水流特效”纳入后续视觉版本。

结论：按下述最小扩展可以实施。没有必须再让用户选择的机制冲突。本文给出的新增数值是可调整的首轮默认，不冒充用户逐项确认。美术接入仍等同版本真实预览确认，不因本设计结论绕过。

## 1. 保留与新增的边界

- 保留 `water_deep_pressure` 的稳定 ID、现有配置覆盖、默认 7×7×3、200 tick、开域魔力 40、冷却 80、开放边界、敌向减速/潮湿/窒息及原生溺水不产势规则。当前代码不收维护费，表内 8/20 是过时字段，本批不恢复收费。不得接回 `FieldZones` 的旧压强或到期爆发，也不恢复空实现 `WetPressure`。
- 新 ID 为 `water_vortex`、`water_bubble_column`。两者使用现有 `ChainRole.ATTACK`，基础伤害 0、水属性、领域载体；表中类型“领域附魔”、释放种类“命中体”、释放标签“触发”、弹道“直线”、链上角色“攻击”。零伤不开放伤害倍率。持续存在不等于持续施法标签。
- 不新增 ChainRole，不复用 `trajectory_storm`，不增加第二套领域实例管理器。旋流、气泡没有自动继承深海的慢/湿/窒息或高阶友方加伤；这些策略显式为空。已有通用接触附魔能力可继续按原合同使用，不给旋流偷偷增加原生伤害。
- “全部实体”不收窄成敌对生物。运动关系与深海原生敌向关系分开：旋流/气泡作用于主人、其他玩家、盟友和敌人；现有 `Relations.ally == false` 不需要为本批发明队伍系统。旁观、已移除、无实际物理/无碰撞的展示与标记实体不施加运动。普通创造玩家不因无敌而被过滤，但仍保留其原版飞行、免摔等规则。

## 2. 现有领域底座上的最小接口

以下名称是拟新增接口职责，作者可顺应现有命名调整，不要求机械照抄类名。

1. 在 `DomainDefinition` 加可选的体积运动规格与临时水规格。运动只需 `NONE`、旋转牵引宿主、上升流提供者三种策略；临时水只有明确声明的领域才启用。策略声明可以在术式注册处绑定，运行中不比较三个术式 ID。
2. `DomainService` 仍唯一管理实例创建、到期、主人失效、关闭和同步。每实例的运动状态、占位、挂载和水租约从此生命周期创建/回收；原有雾雨、幽冥及普通领域默认无新增策略，行为不变。
3. 增加一个小型体积运动运行器，管理候选筛选、占位、速度意图和上升查询；使用现有领域盒作宽阶段查询，旋流的水平圆形与身体完整包含作精确判定。无需把所有领域重构成新几何引擎。
4. 为上升流增加通用父宿主句柄：提供者可独立存在，或成为某个接受上升的体积宿主的附加效果。父实例、来源实例、有效水支撑和到期均可查询，不能只存一个永不失效的布尔值。
5. 新增逻辑释放组名册，按释放组与逻辑声明位置创建，在规则扩份前分配，同一声明的所有分体共享。不要把不同施法或同一链里两次独立声明仅因 ID 相同合并，也不要往伤害 `ReleaseBatch.Tally` 塞非伤害业务。

## 3. 放置与规则扩份

从现有释放流程抽出/复用一个通用空间结果，至少包含最终原点、方向、尺寸倍率、逻辑释放组、分体索引。领域入口也消费该结果，覆盖 `SkillUsePacket` 与 `CastExecutionSession` 两条已发现的开域路径。

必须复用索敌→弹道→规则后的同一空间结果；不得为领域另算一份准星落点，也不得在旋流类里特判落点、一分为三或交错。无空间修饰时保留现有脚底默认，有明确接触点时保留接触点优先级。固定竖轴体积只改位置/排列，不因“垂落”把整个水柱横躺。目标锁定不擅自移动生成位置。

同一释放的每个真实领域成员有自己的几何、寿命、容量和关闭句柄；成员共享结算/抛出去重。一个成员超载只关闭该成员及其子挂载，不级联删除其他分体或独立深海领域。共同水势被用尽后，其他成员可因同一个实际余额不足而各自关闭，这不等于按组强删所有领域。

## 4. 真正的临时水与安全租约

新增专用临时水流体及其方块，实际具有 WATER 流体类型和水标签，能被水浸、游泳、呼吸、熄火和本次气泡水支撑查询识别。它是静止、不向外传播、不产生额外水源的流体；不能简单放原版 WATER 后寄希望于关闭一次更新，也不能用渲染盒、潮湿状态或术式 ID 冒充水。

只在深海领域开启时，对领域内完整落在几何中的空气格创建临时水。不覆盖实心、非空气方块、已有天然水、其他流体或方块实体，不主动水淹/替换植物，不扩展水浸实心块。这是保守的造水范围，不是把整个视觉盒强行填满。格点边缘取内含格，不把水放到领域边界外，也不改变原有领域几何来凑整格。

租约由领域实例 ID 持有，记录维度、格子、临时水身份及所有者集合。遇到本管理器已经创建的临时水可增加一份租约；天然水不接管。最后一个有效租约结束时，只移除仍为该管理器拥有的临时水。玩家替换、挖掉或改成其他状态后，该位置的旧所有权失效；不回填，不在结束时恢复旧内容覆盖玩家改动。只填空气，因此正常撤销目标就是空气，无需通用方块 NBT 回滚框架。

租约必须有世界持久化与异常恢复：领域关闭正常释放；服务器重启后不能确认仍有活跃宿主的遗留临时水清理；区块未加载时不强加载，等加载再核对。临时水自身应能识别无有效租约的孤儿并安全撤除，避免只保存水块却丢失内存名册后留下永久水。不得给玩家可无限复制这种临时水的物品/桶；普通水桶放置的天然水保留。

真实水的游泳、正常浮力和自然呼吸作用适用于所有进入者，和深海原生效果排除主人是两层语义。这是最新“真实水域”要求带来的物理结果，不能为了沿用旧假领域观感而取消真实水判定。深海原生耗氧仍只按现有一次倍率，不再额外造一条周期伤害。

## 5. 气泡独立使用、组合与失效

气泡水支撑通过实际流体查询，接受天然水及上述临时水，不按 `water_deep_pressure` 的 ID 判水。独立气泡在其配置的柱体范围内，对实际连通的水体提供上升；干地无水时不产生有效上升。不得因亡灵不会游泳或不能溺水而排除其上升资格。

上升提供者与同一施法者的兼容旋流在底部支撑区域重合时，可挂到该宿主上；无需来自同一链，也不看术式 ID。支持先旋流后气泡及先独立气泡后旋流。一个提供者成员同一时刻只归一个宿主，多个候选按几何距离及稳定实例 ID 决定；一分为三各成员照此匹配，不把一份来源无限复制。跨玩家自动夺取彼此挂载本批不做。

一旦挂载，其原独立运动输出停止，效果由父宿主负责。宿主关闭时该挂载结束，不回退成独立柱，不重新寻找下一个宿主继续托住刚释放的实体。未参与挂载的独立气泡与独立深海水域不受影响。

组合成立的实时条件是“旋转牵引宿主活跃 + 有效上升挂载 + 基部实际水支撑”。挂载把上升作用施加到宿主完整螺旋体积，允许从浅水上升到水面以上；不能要求实体全程仍浸在仅 3 格高的深海水里，否则无法完成已批准的高处抛出。独立柱仍按实际水体工作。

水被玩家移除、来源到期或挂载失效时，停止该上升贡献，旋流回到平面牵引；已经在高处的对象受正常重力，不补扣或补返入卷水势。仅组合消失不自动制造新的溃败条件；剩余占位确实不合法且无可用空间时才按超载关闭。其他独立浮力/气泡及原版水物理不被删除。

## 6. 吸引、占位与运动

- 外围水平吸引半径默认严格 8 格，精确用水平圆距而非 16×16 方盒。竖直只查询当前本体高度。用 `COLLIDER / Fluid.NONE` 检查通向本体的方块通视；被阻挡者本拍没有吸引、环绕或入卷。液体自身不算墙。
- 用速度引导，接近中心时目标吸引速度增大，并有上限；服务端同步速度。不能复制万剑归宗的逐 tick `setPos` 来搬生物，也不能以占位目标为理由瞬移或穿墙。
- 干地只控制水平运动，不主动托举、上升或顶部抛出。占位在实体当前可达平面分配不同角度及必要的同心半径。气泡挂载后，分配错相角度/高度并螺旋上升。黄金角可作候选序列，但不能代替碰撞盒检查。
- 按真实碰撞盒加少量间隙检查柱体容纳、方块碰撞及其他已占位置。占位预算按扩大后 AABB 体积累计，不能按固定“每实体一个相同槽”让掉落物和巨型生物等价。小实体按各边至少 0.25 格计算，间隙默认 0.1 格，避免零体积/极小体积刷无限数量；这些是几何数值稳定规则，不开放成玩法开关。
- 第一次进入中心本体的对象先检查能否容纳。巨型对象不可能完整放入，或现有体积/预算已无空位时，直接触发该实例超载，不让它永远停在外圈成为隐形排队。仅外围经过者不算入卷，也不预扣费。
- 入卷水势只在完整身体进入本体并通过占位后结算。已经结算者离开释放占位，回来重新占位但不重新扣/返；没有位置仍触发超载。因地形变化导致既有占位失效时尝试可达重排，确实容不下就关闭，不挤进墙里。
- 顶部抛出前确认实际到达顶部且出口可通行，再给一次向外及少量向上的速度，并把该实体记入同次释放已抛出集合。被顶棚挡住时不假装已经抛出；继续容纳或最终因实际拥堵/寿命结束而落下。已抛出者所有分体都不再吸回。
- 溃败和正常结束不添加顶部抛出冲量，停止本实例的牵引、环绕和上升，原地释放并恢复正常重力/运动。不要清除别人的击退、飞行或状态；不另造摔落伤害，不改无敌帧，不强行取消水、免摔或载具的原版规则。

## 7. 实体分类与载具

生物和玩家按下一节结算；物品实体免费但占用几何和负载；弹射物只作一次偏转，不进长期占位。其他具有实际运动的非生物实体（如空船、矿车）以基础入卷费处理、无湿度返还，仍按真实体积占位；不能静默遗漏或免费当作物品。

骑乘组只对根载具施加一次运动，以根及乘客的并集盒做容纳/占位。费用按进入组中尚未结算的有效成员计算：生物乘客各自读取湿度，非生物载具按基础费，物品仍免费；整组支付/返还一次原子提交，付不起就关闭，不半收钱后再拒收剩余乘客。记名按每个实体 UUID，防止上下车刷结算；不强制拆乘客、不同时给根与乘客各写一遍速度。

同一实体重叠多个分体时，只允许一个成员持有控制权，以稳定实例顺序获取；其他成员不能叠加环绕速度或重复收费。脱离后可交接，已抛出标记优先于重新获取。普通实体删除、换维、死亡和域关闭均要释放占位/控制权。

## 8. 水势事务与同次名册

独立旋流不看湿度，生物基础入卷费默认 10。只有结算瞬间满足第 5 节组合条件才用湿度：0 档扣 10；1 档扣 8；2 档扣 5；3 档扣 10、返 13；4 档扣 10、返 16。这里是试调默认，用户没有逐项固定这些数。

高湿仍须支付得起本次毛费用，再原子提交最终余额；不能凭净收益为正让零水势无门槛启动。给现有 `WaterMomentum` 加一笔扣款/返还的原子结算入口，尊重其他未提交预留，扣款与返还结束后只公布一次最终余额。上限仍为 100，超出丢弃；例如余额 10、三档结算后为 13，不能在中间的 0 触发关闭。

不要因现有 reserve 的 0.001 容差让“余额 0、正小额费用”成功变成免费。所有金额保留浮点；不足则不改变余额、不记结算成功，并关闭本实例。一次完整结算的最终余额为 0 时关闭；其他途径真正把余额耗尽也在下一次服务端领域处理时关闭。未提交预留暂时占满可用额不等于余额被永久清空，但实际入卷/偏转支付失败仍按不足关闭。无额外 20/15/10 的隐藏资格门槛。

名册至少有已入卷结算、已偏转结算、已抛出集合及当前成员控制权。入卷成功后才登记，后续升湿、组合形成/解除、离开再入均不重新算账。掉落物不发生金额结算但仍有控制/抛出去重。分体共享这些集合，所有组成员与子挂载结束后整体回收，不能长期积累世界级 UUID 黑名单。

## 9. 全类弹射物的报价与偏转

现有标准报价只覆盖运行类恰好为 Arrow/SpectralArrow（含药箭）、冻结直伤大于 0 的箭。这一事实不能写成“全部弹射物已有标准成本”。

在现有偏转成本包抽出可独立调用的“标准处理成本”读取，不走会触发 20/15/10 门槛和 PARTIAL 扣光余额的完整拦截交易。受支持箭复用现有冻结直伤与射箭者湿度箭比：标准成本 = direct × arrowCostRatio。本次偏转价始终 = 标准成本 × 0.2，保留浮点，不降低成 0。

对没有旧报价的弹射物，以及旧箭报价无正直伤的情形，新增明确的通用固定标准成本兜底：默认 5 水势，实际旋流偏转支付 1。这是本批新增的标准兜底，不能伪称旧底座已有；不根据未知弹种的伤害或速度臆造公式。把 `fallbackProjectileStandardCost` 声明在本次实际消费者 `water_vortex` 的统一平衡配置下，取严格正有限数，建议范围大于 0 至 100。以后别的宿主要复用时可以复用同一报价接口，本批不改变旧水幕、水环、水牢的收费政策。

兜底允许三叉戟、火球、雪球、药水、珍珠、经验瓶、焰火、唾液、潜影弹、鱼钩及其他有实际飞行速度的 Projectile 进入同一正价路径。它们没有额外的药水/爆炸价值估算。预算理由：默认每次 1 点，占现有 100 点池的 1%，可调且没有免费漏洞。

只在本体接触处、通视合法且能让非零飞行速度发生实际方向改变时尝试付款；付款成功才施加一次有限偏转并记名。不能先改轨再发现付不起，不能只被扫到就收费。偏转保留弹体、射手、伤害和后续原生行为；不吞弹、不强换所有者、不入环绕槽、不重置寿命。带持续推进方向的弹体同步调整其飞行方向分量且保持原幅度，避免立刻被旧推进量抵消；寻敌/忠诚等之后重新改变方向属原生后续行为，不因此重复收费。没有实际速度或无法完成有效偏转的对象本拍不收费。

不要调用一次有随机暴击抽样的旧报价，再为收费另抽一次；每次真实偏转尝试冻结一份报价。同次释放跨分体同弹体只付一次。尚未成功支付的不记成功；支付不足立即关闭本实例。

## 10. 气泡与真实潮湿下压的优先级

需要处理的是 `WetnessFlight`，不是已为空的 `WetPressure`，也不是给深海新加一个下压效果。

体积运动运行器提供实时 `hasEffectiveUpdraft(entity)` / 上升意图查询，校验活跃宿主、来源、当前几何和水支撑。`WetnessFlight` 在所有实际施加下降的分支（普通 travel、恼鬼追加位移、龙的特殊下降）首先尊重有效上升，不追加潮湿下降。没有有效上升时原逻辑原样执行；无需改其免疫名单，也不清除潮湿效果。

上升由运动运行器在可参与该拍移动的位置应用，玩家/生物/物品共用来源生命周期；为生物与特殊 travel 保持同一有效性查询。不能仅把某个 tick listener 注册得更晚来碰运气，也不能只修普通 LivingEntity 而漏掉已有特殊分支。来源结束同拍查询失效，不留下长期“免下压”标记。真实水中本来就有的 `actualFluid` 豁免保留；上方离水的螺旋段仍由上升优先保证能升。

## 11. 首轮可调默认与配置消费

沿现有 BalanceRegistry / BalanceService 声明、读取及客户端快照，不在静态初始化读取有效配置。新 key 只在实际消费的位置声明一次，全局魔力/冷却倍率各一次，旋流和气泡不开放伤害倍率。

- 旋流：`manaCost=20`、`cooldownTicks=80`、`lifetimeTicks=200`；`attractionRadius=8`；`bodyRadius=2.5`；`boxHeight=3`（干地本体）；`liftedHeight=8`（有效挂载后）；`pullSpeed=0.35` 格/tick；`orbitAngularSpeed=0.10` 弧度/tick；`motionSpeed=0.45` 格/tick，约束自身水平运动；`occupiedVolumeLimit=12` 格³。
- 入卷：`entryCost=10`、`wetTier1EntryCost=8`、`wetTier2EntryCost=5`、`wetTier3Refund=13`、`wetTier4Refund=16`。高湿毛费用复用 `entryCost`，不再声明一份值相同的假参数。建议费用与返还范围 0–100；“独立不折扣、组合才读湿度”的结构不可配置。本文默认保证三级/四级净增，交付说明必须写明修改这些值会改变净收支。
- 弹射：`fallbackProjectileStandardCost=5`，必须正数。乘 0.2 为用户指定规则，不另开放能把它改成 0 或 0.8 的开关。旧箭标准报价仍按已有档位规则，不另造重复键。
- 气泡：`manaCost=12`、`cooldownTicks=60`、`lifetimeTicks=200`、`radius=1.25`、`boxHeight=8`、`riseSpeed=0.12` 格/tick。独立水柱的实际有效高度还受连通水体限制；挂载后用宿主 `liftedHeight` 作为顶部，而不是两份高度相乘。
- 旋流抛出：`ejectHorizontalSpeed=0.45`、`ejectVerticalSpeed=0.20` 格/tick，仅真实到顶抛出时消费。
- 深海：不改现有默认费用/尺寸/寿命与配置键，不新增维护费或独立造水半径。临时水直接消费同一份已生效领域几何与寿命，避免出现两套对不齐的数字。

首轮本体直径 5、高 3 可容纳普通玩家/多数生物且有明显外围吸引区；组合高 8 让上升与下落可观察；200 tick 可观察多次进入与抛出；容量 12 格³再受真实摆放约束，避免物品无负载或过密重叠。这些是可实测调整的起点。

尺寸、速度、寿命沿指南既有合法边界；角速度使用明确单位的正有限范围，建议 0–0.5 弧度/tick；占用体积用明确单位并给合理上限（建议大于 0 至 1000000）。不开放命中去重、父子生命周期、是否看墙、分体共享记录或结算顺序。客户端视觉直接使用实例同步的有效几何、模式与速度，不能另写一套视觉默认；吸引 8 格是本轮用户指定的默认，不许拿本体半径替换它。
