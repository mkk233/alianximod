## 配置

本作者没有新增或改名 BalanceCatalog 键。数量和成员间隔不是平衡项。

- 固定格数或 remaining 来自核心作者登记的 `MulticastSpec`。本适配只读 `kind()` / `fixedCount()`，在编译器已经接管且链上出现非 2 的 fixed 或 remaining 时生效。
- 复制份数来自 `ReplicationSpec.factor()`。协同无视图时在修饰赋值点生效；有展开视图时在 `MemberCastView` 复制积生效。批量展开外在原连乘处生效，展开内用复制积替换份数。因子至少为 2，单位是份。
- 成员间隔沿用 `MulticastExpansion.MEMBER_GAP_TICKS`（3 刻）。`gapTicks(memberOrdinal)` 在编译时写入协同 `AttackSketch.delayTicks` 和批量 `BranchDraft.memberDelay`，随后仍由原 freeze / expand 使用。第 0 个成员不延迟。
- 协同冻结时的魔力和冷却仍是原调用：`BalanceService.manaCost(BalanceSide.SERVER, techniqueId, BalanceKeys.MANA_COST, technique.manaCost())`（`readMana`，第 696–697 行）和 `BalanceService.cooldownTicks(BalanceSide.SERVER, techniqueId, technique.getBaseCooldown())`（`readCooldown`，第 700–701 行）。默认耗魔、冷却不因这次数量适配而改。

## 功能描述候选

游戏内描述由核心作者写入 `ModTechniques`。下面是本批 N 栏原文对应的候选，O 栏八项相同。

O：规则自身不新增独立特效或美术，沿用现有通用规则图标；宿主视觉继续由原宿主和共享多重/复制底座生成。

- rule_triple_release：沿用双重释放的共享多重释放机制，从自身之后的原始装配格开始，按原始格顺序向后读取最多 3 格；修饰、附魔、复制声明与内层多重仍按既有解析机制处理，3 不是成功攻击次数。遇链尾停止，不回绕、不补足；实际成员释放间隔沿用既有 3 tick。
- rule_quadruple_release：同上，最多 4 格。
- rule_octuple_release：同上，最多 8 格。
- rule_sixteen_release：同上，最多 16 格。
- rule_exhaustive_release：沿用同一多重释放底座，使用 remaining，从自身下一个原始装配格读到当前链尾。不回绕、不无限循环，也不表示持续释放直到魔力耗尽。成员间隔沿用既有 3 tick。
- rule_double_cast：沿用一分为三的共享复制机制，`ReplicationSpec.of(2)` 把后续第一个接受复制的宿主展开为 2 份。资格仍是现有底座已经接受的宿主。
- rule_quintuple_cast：同上，`ReplicationSpec.of(5)`。
- rule_octuple_cast：同上，`ReplicationSpec.of(8)`。
