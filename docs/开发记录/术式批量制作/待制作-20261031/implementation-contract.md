## 二、少量公共接口及所有权

优先扩展现有ReleaseDefinition、CompiledReleaseStep、CastExecutionSession.Group、CastFrame、ReleaseBatch、TechniqueHitSpec和Typed附魔快照，不另造并行施法引擎。下列名称是职责合同，可用现有相近类型实现，不要求每个名字新开类。

1. 编译结果增加每实际实例的branchId/copyIndex/出生偏移/父事件绑定，附魔下标局限所属分支。根组有唯一castId、费用收据、取消令牌；后续实例共享根而有各自HitClock。普通不涉及本批能力的链走原编译/报价语义。
2. 接续编译吞掉明确子段，形成父实例的一份延迟子模板。禁止缺父缺子、循环/嵌套、同分支多种完整运动、超64实例。地表净空和目标冻结在收费前完成。父子只传主人/维度/castId/事件点/方向，不能复制父修饰附魔。
3. 命中结果使用最少四类：INVALID/CANCELLED、ESTABLISHED_NO_DAMAGE、DAMAGE_ACCEPTED、PENDING。逻辑上前两种分别表示未成立（包括取消）和合法但免疫/零最终伤；PENDING只用于账本等待，不能提前当成功。目标已失效、关系过滤、攻击事件被取消均不接续；有效目标免疫或减伤到0可以接续，但不产种。hurt布尔值本身不足以区分，须在现有伤害调用范围内捕获取消状态与最终接受情况，保持线程局部/嵌套作用域清理。
4. Tally增加一次性结算完成回调/结果收据，每条记录保存其所属实际父实例，flush无论成功、失效、取消或异常收束都完成该记录一次；不按flushTick猜结束，不另建轮询任务。合并多个副本伤害时，完成结果回送各参与实例，但每实例接续闩锁独立，最多触发一次。直接结算与Tally走同一结果合同。旧hurtRoot绕无敌帧行为不在本批全局改变；新效果不得再增加额外绕过。
5. 实体与地形候选在同一扫掠路径比较最早接触。合法事件暂存；取消则不消费首次事件机会，按剩余有效路径候选推进，不能卡死在同一个取消目标无限重试。免疫成立则消费机会。超时/强制清理不是撞地。父范围结果全部完成后触发子，固定父事件点；原几何候选与遮挡快照已保存，不因等6tick后挖坑而纳入原先墙后目标。
6. HitClock绑定实际载体副本；本体、留焰片段共用目标集合/间隔。父子分别有命中集合；ImpactPartition可传中心排除名单用于环带。根火资源去重独立于伤害份数，不能因分支切账或Tally退休清掉。

## 三、费用和取消的最小兼容方案

现有普通复制是整段（含附魔）×份数，不能把首版说法当现行事实。本批采用明确版本化报价策略：当计划含本批任一新术式/规则/附魔时，整组使用新策略；仅旧内容的组仍保留现有策略。策略由定义能力声明触发，不按编号逐个if判断。32槽本身不触发新费用策略。旧领域/条件等特殊费用形态沿用原计算，不自动拉平；若不支持新接续，则编译期拒绝该组合，不免费执行。

新策略：宿主费用按其原有报价能力×实际份数；附魔每原装配下标收费一次，第一次所属攻击实例提交时保留；纯修饰使用各自显式费用，不重复收已归属项。相同附魔占两个不同格就是两份价格，但效果按去重规则不必叠加。不要用消除重复收费同时删掉用户装配内容。

GroupBudget.reserve/ManaPaymentReceipt继续作为唯一魔力账。报价包括全部最坏子实例，整数溢出/不足整组拒绝。每实例出生成功才commit自己的宿主份，子同理；本组不可能再产生子时才settle余款。不能父出生后立刻关闭预算，使子无钱可扣；也不能等火径/燃烧全部消失才退款：所有出生计划与接续机会收束即可退预约，根去重上下文仍可由存活效果持有。

正常松键结束下一次按住循环，不取消现组。取消令牌失效后未出生份、尚未触发子均不生成并退款；已发生的父伤害不回滚，已存在陨岩残骸不删除。退款返回原收据记录的玩家池/原法杖，不能按当前主手找另一个法杖退款。独立附魔普通武器挂载须走可确认的现有提交路径并只收一次；不能依赖事实报告已证明普通链不会进入的segments为空分支。

## 四、附魔和火种接口

本批实际上只有6个新附魔：留焰、种火、引燃、引爆、幽冥、崩地；不存在额外两项要创建。统一作者负责这6种载荷与既有五元素附魔兼容适配，不能把“8种”解释为新增需求。

附魔快照分开“魔力价格、直接附加伤害、产种贡献、燃烧计划、即时消费、轨迹扩展、领域修饰、地形修饰”。新附魔费用2须显式配置，直接伤害默认0；不能为沿用magicDamage=2收费入口而给所有新附魔加2伤害或原版燃烧。旧magic_ignite等伤害与附魔折叠保持。

一次确认命中收集本体及本分支全部合法贡献，再提交一次根产种事务。新倍率基数先求和乘seedMultiplier向下取整，旧固定贡献按原语义加进最终请求，最后上限100；禁止两个produce/deposit调用各建castId。满额0增量仍用掉一次机会。先前该目标已生产，后来副本/子段不补差额。新引燃挂层去重与新引爆消费去重使用各自effectKey，不能沿用hasConsumed导致禁止后续补种的跨效果总锁；保留旧API行为，新增显式策略参数或新方法，仅本批调用启用。

F=fireBonus不是seedMultiplier。引燃冻结启动F，引爆读取消费F；新资源伤害表达严格B×(1+F)，资源增量A=0，并在现有火伤帧标记炉心已结算，避免ElementAdjustment重复加F。账本公平分配复用BurnLedger，不另建私有燃料池；若现有整数余数不是轮换，局部扩展新策略，旧公式不改。

幽冥走不要求contactDamage的领域周期入口，每窗口目标只发一次；遍历当时全部覆盖领域选最高请求，稳定id打破同值，不按每领域单独给钱。周期scope是(castId,domain,window,target)再经目标窗口仲裁，不伪造新真实施法。只改可支持火色调的表现通道，不影响判定与资源归属。
