我先读这份复审任务，确认授权范围后再核对返修代码并交完整报告。终稿说只改了版本顺序和结束标记。我对照这四个文件里的实际分支核对。未发现实质问题。同维度同宿主的版本单调、结束标记和 `surfaceEnd` 接线与返修 2 一致。

- 已显示版本只在来包维度与当前画面维度相同时传入。`SurfaceSnapshotAssembly.accept` 在版本小于等于已显示版本时直接返回，不碰待组装；同维度且低于待组装版本同样返回，待组装保留。
- 同版本分片数或帧元数据不一致时拒绝该包，不清待组装。已收过的分片下标直接丢掉，不改开始时刻、已收片数和 80 tick 截止；新下标只补片。
- 与待组装不同维度的包直接丢掉，即使版本号更高也不清当前组装。同维度更高版本先换掉未完成组装，未收齐时客户端不改画面；收齐后只更新切片和版本，出生与到期不动。
- `SurfaceFireHosts.close` 是 `surfaceEnd(visualId, dimensionId, birthGameTime, expireGameTime)` 的唯一调用，写入已有维度、出生、到期字段。`GROUND_END` 仍是空维度和 0 时刻，切片尾只加在 `SURFACE` 上。结束包清画面和待组装，结束标记留到原到期时刻的下一 tick，期间迟到分片不能复活；到期后再来的首包会被寿命检查丢掉。
- 空世界、登出、客户端维度卸载都走 `forget`，待组装、结束标记和地表画面一起清。同版本 40 tick 补发不升版本，客户端当已显示版本忽略。空几何仍是一片 0 切片。包头与切片边界校验仍在。
