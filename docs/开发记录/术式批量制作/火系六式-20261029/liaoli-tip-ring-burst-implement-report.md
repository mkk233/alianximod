## 三道环

触发条件没变。有效命中、扣种前成功快照 `amount() > 50` 才 `pulseRearRing` 并发包。50 不触发，51 触发。空挥、权限失败、扣款失败不播。同一世界时刻重复触发仍是同一出生时刻，客户端按施法者加出生时刻去重。更晚一拍的另一次合格命中是新的一轮，旧的一轮继续播完。

每道的中心在进度 0 等于 `thrustTip()`：横向 `+0.3375`、高低 `-1.06875`、前后 `+2.053125`。父变换是施法者这一帧的插值眼睛，朝向是视线偏航，和手持刺击剑同一套。沿剑尖指向剑柄的深度往负方向退，不从眼睛中心或旧的背后常量出发。

进度不取小数、不取模。一道自己的年龄是 `age - ringIndex×6`。还没出发时不画。走完 20 tick 就停在末端，不会跳回剑尖。

一道内部：

- 进度 0 到 0.78：环线半径 `0.20` 收到 `3.80`，环心前后收到 `-3.40`，透明度保持 1
- 进度 0.78 到 1：环线再收到 `4.10`，环心再收到 `-4.10`，透明度收到 0

半径和后移都只增不减。透明度收到 0 后不再画，不再在 0.65 硬切。贴图仍是 `rear_ring.png`。`RING_FRAMES` 仍是 24，画面条仍按帧循环，这只换贴图行，不把环心拉回起点。`RING_QUAD_SCALE` 仍是 `48/32`，可见环线落在 `ringRadius` 上，不是方片外沿。

三道错开 6 tick，每道都走完上面的全程：

- 第 0 道：出生后 0 到 20 tick
- 第 1 道：6 到 26 tick
- 第 2 道：12 到 32 tick

整段尾迹 32 tick。不再用旧的 24 tick 共用截止把后两道剪掉。渲染器不再调用 `rearRingVisualAge` 来停画；这个方法还在，不改变命中体寿命。

末端对照的是布局公式里的剑阵包络，不是游戏里量出来的。轴是穿过剑尖、沿刺击前后的线。站立、含剑身和火舌半宽，离这根轴最远约 2.89 格，火舌最深约 `-1.78`。横身俯冲最远约 2.76，最深约 `-2.21`。蹲下再俯冲最远约 2.97。环线先到 3.80，比 2.97 大出 0.83 格，环心先到 `-3.40`，比最深的 `-2.21` 更靠后约 1.19 格，然后才淡出。身体偏航和视线偏航不一致时，八剑跟身体、环跟视线，这组包络按两者同向计算。

命中体仍是 40 tick，松开、换剑、死亡仍提前收招。环不延长这个窗口，也不再打一次、不再扣一次火种。客户端尾迹在命中体消失后继续画满 32 tick。触发时另发消息 13，避免收招和命中同一拍时客户端还没看见实体数据。正在渲染命中体的客户端也会记下同步来的出生时刻，给晚开始跟踪的人补上。尾迹最多留 12 条，同一出生时刻不重复。施法者暂时不在客户端世界里，10 tick 内不画、之后丢掉。死亡、实体离开、登出、客户端世界卸载立刻清掉。尾迹不保存世界坐标，所以不会留在原地。

高速跟随仍只认施法者 UUID，不用距离猜人。v7 八剑、六张贴图、手持剑、火流和火种常驻火苗没有改几何或像素。

## 迎面速度和伤害

`v = clamp(max(0, (施法者速度 − 目标速度) · 刺击单位向量), 0, 40)`，单位格/秒。

速度在服务端命中回调里取，不读 `getSpeed()`，不读冲刺布尔，不用客户端自报。每个实体先看本拍位移 `位置 − xo/yo/zo` 和 `getDeltaMovement()`，都是格/tick。位移长度大于 8 格、并且比速度长度还大出 4 格以上，这个实体记 0，用来避开瞬移那种不连续跳跃。否则取两者里更长的一条，再乘 20。位移还是 0、速度已经有值时用速度，避免玩家还没在本拍移动就被读成 0，冲刺加成还在。贴墙时如果位移被挡住、速度还留着，用的是速度。

刺击方向是命中体这一拍的 `forward()`。跟随施法者时，这个向量就是当时的视线，含俯仰；锁定时是指向锁定点的方向。没有可用向量时才退回 `getLookAngle()`。俯冲和迎面把正投影加上，横移投影为 0，背离变负之后夹成 0。40 是投影之后的统一上限，不是先把每条速度夹到 40。

物理伤害是登记基础 `6` 加 `1.5×v`，仍进 `TechniqueHits.hurtRoot`。领域光环仍只在这条通道里、并且施法者当时站在会给根术式光环的领域中才加上。没有把武器攻击属性、锋利或暴击接回来。`suppressRootSettle` 仍开着，链上已经算好的 `CastFrame.damage` 仍不进入这一下。无火种也走这道物理。

火种仍在权限通过后一次性消费当时全部共享余额。`thrust` 现为 `BurnComponent.of(S, 0)`，A 仍是 0。`FireLayer.combine` 没改，结果是 `S×(1+F)`。`strikeOnce` 仍标记炉心已结算，不会再乘一次。物理和火伤仍是各一次 `hurt`，没有为了提高伤害再加一刀。冷却 300、魔力 40、每目标一次、单体、不炸地形，都没改。

不计领域、护甲、保护和抗火时：

- S100、v0：火伤 100，物理 6，合计 106
- S100、v20：火伤 100，物理 36，合计 136
- S100、v40：火伤 100，物理 66，合计 166
- S0、v0：6
- S0、v40：66

F=0.30、S100 时火伤是 130，物理另算。抗火仍可取消火伤这一下，护甲仍作用在没有绕甲标签的结算上。这些没有在本单里改。

`thrust` 的生产调用只有燎里。`SixFireLogicCheck`、`SixFireFunctionalCheck` 和 `docs/开发记录/火种双路线消费核查-20261029/fixture/DualRouteConsumeProbe.java` 仍按旧的 `0.36×S` 写着。本单不允许改测试，也没有跑。`LiaoliV6LayoutCheck.checkRings` 仍调用已删除的 `ringProgress` 相位。这些检查现在和源码不一致，不能当成本次结果。

## 用户实测四行

1. 火种严格大于 50 的命中：三道环是否都从手持剑尖出现，依次变大退到身后，环线明显大过站立和俯冲的整套背剑与火舌后才淡没；40 tick 末尾或松开收招时，已经出现的环是否仍能播完，并且不会再打一刀或再扣火种。
2. 火种正好 50、空挥、打在不能造成伤害的目标上：不应出现环。火种 51 应出现。常驻火苗数量仍按当前余额，每 10 点一朵。
3. 站着打、向前冲刺或俯冲迎面、横移、目标逃离：物理应分别接近基础、升高、不因横移升高、不因逃离变成负数；速度很高时加成为 60 封顶，也就是物理 66。不要用属性面板里的移动速度代替实际速度。
4. 100 火种且双方几乎静止：减免前合计应接近 106，其中火伤 100、物理 6。同一目标这一次出手只结算一次。炉心只放大火伤。护甲和抗火仍可减少或取消对应的那一下。八剑姿态和六张贴图应保持原样。
