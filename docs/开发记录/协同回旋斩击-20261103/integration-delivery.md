# 协同回旋斩击整合说明

本次把斜斩、回旋、协同和普通分身接到玩家释放链。旧链没有这些前缀时仍走原来的编译和结算。斜斩效果和回旋效果的 `execute` 会抛异常，玩家路径不会调用它们。

## 玩家怎么打出来

- 手动释放：`SkillUsePacket.executeSkill` 在旧批量编译之前进入 `CooperativeCastRouter`。链里有斜斩、回旋、协同或普通分身时整段改走执行族。
- 单独斜斩：立即门，出刀时发布薄斩击体积。
- 回旋，或回旋后再接斜斩/横劈：定时门。没有分身时马上播放回旋。有预约时先等分身到达端口已经选好的站位，再给玩家和分身发同一条冻结时间线。回旋没收势之前不再播放单独斩击姿态。
- 协同加已适配斩击：分身端口自己选边并归位，执行族不再把分身拉向瞄准右侧。每次出刀用当前主人帧调用 `validate`，失败才退回单人，并退还未提交的协同份额。
- 冲刺加已适配斩击：每一次合法接触单独开一次子执行，使用自己的账本、发布槽和攻击份额。接触点是该次斩击锚点，方向进入刀面，目标由命中实体按同一套窄判定结算。同一目标只处理一次，同一接触里多名演员只提交一次攻击份额。动作费和协同费不按接触重复收。没有新能力的旧冲刺不进这条路径。冲刺伤害仍由原来的冲刺效果负责。
- 跳跃加斩击：跳跃仍先做原来的位移，再出斩。跳跃没有被改成新的动作门。
- 领域自动轮：绑定编译时若冻结链含有本批能力，会在第一名宿主上留下草图，其余宿主标记为已吸收。自动轮的原报价计入一次协同费。预付启动接的是这张收据，不再另扣按键。没有双人发布时，协同份额退回这张收据的原池。
- 没有新前缀的横劈仍走原来的横劈效果。横劈只有跟在回旋、协同或冲刺后面时才使用新适配器。

## 普通分身

法杖槽 0 只装 `clone_body` 时释放会部署普通分身。潜行释放撤回自己的普通分身，不扣部署费。和其他术式放在一起会在扣费前拒绝。幻影分身和基础脉冲仍是开发入口。开发命令权限没有改，仍走原来的生成，不走玩家部署端口。

部署报价用 `CloneBalance.readSpawn` 读一次。扣款、退款和生成冷却在分身端口内部完成，这里不再扣第二笔。载体比对使用主手栈引用、选中槽和已有世代，不调用 `CarrierWatch.observe`，因此不会为了这次部署清掉水刃节拍。

## 付款、冷却和取消

手动释放在结构、适配器和预算都通过之后才扣一张新收据。领域轮的付款方是自动轮原来的 `GroupBudget` 收据：报价已经包含协同费，执行族只把动作、攻击和协同份额挂到这张收据上，再用 `detach` 把这些金额移出本轮待退余额，避免轮末再退一遍。动作份额在回旋或接触真正进入运行时提交，攻击份额在该成员体积发出时提交，协同份额在第一次真正双人发布时提交。没发出的份额按原收据退回。

单独的立即斩击在这次释放里就安装冷却。协同立即斩击要等分身站位，冷却改到这一族结束时安装，只汇总已经提交的份额。定时门和接触门同样等到结束再安装。领域份额的冷却额是 0，不把按键冷却再装一次。没有公开的在世分身查询，所以协同份额会先挂上；预约返回没有演员时，在体积发出前退回该份额并改单人。

主人死亡、下线、换维、复制、父族取消、世界卸载和服务器停止会丢掉还没结算的账本并停掉动作。载体失效只取消尚未提交的份额，已经发出且主人仍合法的体积继续等到刷新。软失败只退未提交的协同并回到单人。

## 体积和结算

落点和交错先用原来的 `CastFrame.forAttack` 解出锚点，再由适配器加上演员眼点相对玩家眼点的差。接触点优先作为这次锚点。近垂直瞄准会在准备前收成水平朝向，准备和发出用同一条方向。斜斩体积带厚度，命中走新的有向盒；旧的无厚度斜面判断还留给原来的姿态斩击。横劈仍用原来的贴图、纵深和宽度。

每一名攻击成员一本账。两名演员写同一个结算序号，第二名不会把伤害再乘一次。显式生成不读取环境释放帧，也不再乘一遍全局实体倍率；倍率只在做计划时展开一次。超过本族 128 份会在扣费前拒绝，不会把 4096 裁小。双人发不下，或双人中途没能进世界时，先丢掉这一次的双人暂存，再在同一次调用里发完整单人。

记录和刷新都复查会话、世界、主人，以及 `DamagePermission`、任意分身、主人驯服动物和同队。刷新按每个目标再查一次。没有守卫的旧账本仍走原来的路径。协同账本刷新时用深度 1 的分身来源作用域包住这一次结算，方法返回前关闭。

## 配置

已消费的标准项是斜斩、回旋、协同各自的魔力和冷却，以及斜斩的伤害倍率。斜斩和回旋的专项仍由原作者声明各一次。协同规则另外声明并读取 `selectionRadius`、`moveLimit`、`sideOffset`。`moveLimit` 就是归位距离。回旋和协同规则不声明伤害倍率。

2026-11-04 之前，代码默认是选择半径 8、归位上限 4，允许范围是 [0,16] 和 [0,8]。那一组数字现在只作为历史记录。当前声明是选择半径默认 24、范围 [0,48]，归位上限默认 32、范围 [0,64]，侧距仍是 1.25、范围 [0.75,2]。`CooperativeChainCompiler` 在准备执行族时读一次并冻结。执行族仍只调用 `tryReserve`，不直接调用远距搬移。实际位移不超过 8 格走原来的短距，大于 8 格且不超过冻结上限才由分身端口做远距瞬时归位。

`D:/alianximod/run/saves/新的世界/serverconfig/xueximod-balance.json` 原来没有 `rule_cooperative`。这次只补上 `selectionRadius` 24 和 `moveLimit` 32。其他世界和全局模板没有改。重开该世界或重启服务器后，这场测试用的是这两个显式值，而不是“缺键才落到新默认”。这场世界里的旧 8/4 并不存在，所以没有把一份显式旧值覆盖掉。
