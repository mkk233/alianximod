# 协同回旋斩击第 2 轮返修

这七项都落在整合代码里。没有改分身核心、斩击适配或客户端文件，也没有改公共几何记录的字段。

## 1. 站位和出刀复验

`FamilyExecutionService` 不再调用 `offerReposition`。分身仍由 `CloneServerPorts.tryReserve` 和 `advance` 走到已经选定的左右站位。每次成员出刀前用当前主人帧调用 `CooperationActors.validate`。失效才退回单人。需要走动的分身不再依赖预约当下的眼点，偏差由 `validate` 按当前脚点重查。

## 2. 接触几何

接触门把 `TriggerGeometry.point()` 当作这次斩击的锚点，方向仍进入刀面。落点和交错继续从该锚点用原来的 `CastFrame` 解。目标写入已有的 `TechniqueHitSpec.localTargetId`。显式几何记录没有目标组件，这次不加字段。没有新能力的旧冲刺不会进入这条路径。

## 3. 领域协同费

`TechniqueChain.waitsForHost` 把 `RULE_COOPERATIVE` 当成等待宿主的规则。`SkillChainPlan.pressCommitCost` 不再因为它的释放种类是自身状态就跳过，所以自动轮原报价包含这一次协同费。预付启动不再 `charge`。动作、攻击和协同份额挂在自动轮那张收据上，金额是报价里的对应部分，不是 0。`GroupBudget.detach` 把这些金额移出轮末待退余额。没有成功双人发布时，协同份额通过 `refundShare` 退回这张收据的原池。动作在进入运行时提交，攻击在体积发出时提交，协同在第一次双人发布时提交。领域冷却额保持 0。

## 4. 结算权限

`CooperativeSettlementGuard.active` 每次重查服务器会话、维度、主人是否仍在该世界，以及父族有没有硬取消。`allows` 使用 `CloneEntity.rejectsPulseTarget`，其中包含 `DamagePermission`、任意分身、主人本人、主人驯服动物和同队。账本记录时已经调用 `allows`。刷新时除了总开关，还对每个目标再调用一次。没有守卫的旧账本不走这条判断。无敌帧规则没有改。

## 5. 载体失效

换手或载体失效只取消尚未提交的份额，并停止后续出刀。已经提交的攻击份额和待刷新账本保留。主人死亡、下线、换维、复制、父族取消、世界卸载和停服仍会关掉守卫并丢掉待结算。这两种失效不再共用一个全族硬开关。

## 6. 双人发布失败

某一具体积没能进世界时，先丢掉这一次已经放进世界的双人暂存，并撤回这次未完成的发布槽。然后在同一次调用里按单人计划再发一次。下一刻不会继续尝试双人，也不会把已经丢掉的玩家体积再留一份。费用只在最后这次成功发布时提交。

## 7. 共同回旋

有预约且分身还没 `READY` 时，族停在准备，不提交回旋费，也不播放回旋。分身到达或确定退回单人之后，玩家和分身使用同一个 `serverStartTick`、前摇和收势。分身 `mirrored` 为真，并用预约句柄上的演员身份、实体编号和世代，武器只用只读快照。没有分身的回旋不等这两刻。出刀仍由服务端时间线触发一次。回旋没收势之前不播单独斩击姿态。失败或取消沿用原来的 `stop(family, actorId, sequence)`，不另发新序号。
