# 水幻形实机画面返修

本阶段额度已用完，返修结果未追加复审。

## 原因

确认版水线贴图、模型内嵌贴图和游戏资源 `steve_water_lines.png` 是同一份 128×128 RGBA。头部北面的逻辑 UV 是 64 格空间里的 8..16，对应位图像素 16:32。中心像素 (24,24) 是 (0,0,0,0)。这块 16×16 里 256 个像素有 115 个不透明，颜色只有水线的 (22,81,115)、(58,188,226)、(232,247,255)、(14,92,132)。`lines.bin` 里头部北面四个角的 UV 是 (0.125,0.125) 到 (0.25,0.25)，是盖住这块镂空区域的矩形，顶点顺序也不是蝴蝶结。面 UV 的换算没有把采样推到一块实心颜色上。旧的 `lines.bin` SHA256 不能单独证明绘制正确，但这次对文件的拆包和对像素的取样能证明源矩形是空心的。

用户截图里头部内部是一整片 RGB(37,135,163)，也就是 `#2587a3`。轮廓边是 `#23809b`，即 (35,128,155)，三个通道大约都暗 5%。这个颜色不是贴图里的任何一个纹素，最近的不透明纹素是 (14,92,132)，距离 97。两条主水线色各取一半是 (40,134,170)。透明纹素的 RGB 是 0，所以把透明当成黑色不会得到这块青色。头部后面的天空大约是 `#82aeff`，也没有从头部中间透出来。六个 Steve 方体当时按整面四边形提交，UV 盖住整块含水线也含透明中心的矩形。

本地 1.20.1 的 `entityTranslucentEmissive` 不启用光照图。当时的自定义批次用了自发光实体着色器，另外又打开了光照图。该片元着色器只丢弃 alpha 低于 0.1 的样本，顶点着色器仍做方向光，并且不读光照图。整面采样没有停在透明中心上，帧缓冲里就是一块被水线颜色混出来的实心面。截图本身分不出最后一步是整面 mip、四个顶点变成同一个 UV，还是多出来的光照图状态。返修不靠把 alpha 门槛调高：那样只会把已经平均过的面整块丢掉。

## 改动

透明中心不再生成三角形。资源载入时读取确认版水线贴图，六个方体的每个不透明纹素单独成为一个四边形，四个顶点的 UV 都钉在该纹素中心。片和滴仍用原来的整面。批次改成与水环相同的位置-颜色-贴图着色器，最近点采样、不开 mip、不剔除背面、不写深度。不再走自发光实体着色器，也不再绑光照图和叠加层。

- `src/main/java/com/bslx/XueXiMod/client/SteveWaterLineVisual.java` 第 68–76 行：绘制不再把光照写进顶点。第 79–95 行：批次改为 `POSITION_COLOR_TEX`。
- `src/main/java/com/bslx/XueXiMod/client/SteveWaterLineMesh.java` 第 30–31、76、114–123、129–146、149 行起以及第 265 行起：载入贴图，按不透明纹素展开，顶点只写位置、颜色和 UV。
- `docs/开发记录/水幻形术式-20261102/runtime-visual-mapping.json` 增加 `draw` 记录。

确认版 bbmodel、两张原图、正式归档和运行时 PNG、`lines.bin` 都没有改。运行时水线贴图仍是 SHA256 `9E7E5B01A7E09C393D3FFA1800468BD61AE919F68CF628152B00D9C347793DA5`（2687 字节），水花贴图仍是 `CEFDEE9E3E3FB7F701E19FC9CB3438C586C4841D3A50E3F8C9399A635BD4D70C`（608 字节），网格仍是 `26EF5093F3FC9CAD03272F7BDFAD06DF771953E161B69310B2FF7E37B89F9025`（60666 字节）。没有新的换算，也没有新的网格哈希。
