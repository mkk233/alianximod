## 根因

垂落、喷涌、风暴是链上的路径覆盖，陨岩是带默认抛物线、且允许改弹道的攻击宿主。`BatchReleaseCompiler` 把宿主登记的 `PARABOLA` 再计进 `motions`，和前面已经计数的覆盖加在一起超过 1，按键释放直接拒绝。

即便放行，`TechniqueHitEntity.applySpec` 仍按登记弹道无条件换成 `ParabolaMotion`。链上喷涌还被「原生弹道不是 `PARABOLA` / `VORTEX`」挡掉，覆盖到不了 `UpwellMotion`。

`birth.dropPath` 和效果最初抄来的 `dropThisCast` 对风暴也为真，因为风暴角色是 `TRAJECTORY_DROP`。精确路径在生成时已经写成 `spec.path`：垂落是 `DROP`，风暴是 `VORTEX`。喷涌没有对应的 `Path`，用 `upwellThisCast`。

### 编译计数

修饰段的 `fullMotion` 计数不动。宿主只有在「没有链上路径覆盖」或「宿主不允许改弹道」时，才把自带 `PARABOLA` / `UPWELL` / `VORTEX` 再加一段。已有 `dropPath` 或 `upwellPath`，且 `trajectoryMutable` 时，这段默认弹道不再计数。不按术式编号判断。父宿主和命中接续的子宿主走同一处。

因此单独陨岩仍是 1 段。垂落、喷涌或风暴再加陨岩不再因为默认抛物线被拒绝。垂落加喷涌、垂落加风暴、任一路径覆盖加追踪，仍在修饰计数处拒绝。

### 执行运动

`applySpec` 在宿主 `trajectoryMutable` 时按本发最终路径选运动，不再被登记抛物线盖回：

- `spec.path == DROP` 且登记不是垂落：`DropMotion`
- `spec.path == VORTEX` 且登记不是螺旋：`VortexMotion`
- `upwellThisCast`：`UpwellMotion`。不再排除原生 `PARABOLA` / `VORTEX`
- 没有上述覆盖且登记是 `PARABOLA`：仍是 `ParabolaMotion`

`dropThisCast` 不能把已经写成 `VORTEX` 的路径改成直落。直线宿主仍可按原有 `dropThisCast` 进入垂落。喷涌参数若不是喷涌种类，`UpwellMotion` 仍退回批准的喷涌常数。

### 最早扫掠

陨岩登记了 `prefersEarliestContact`，这是宿主自己的最早接触，覆盖成垂落或风暴后仍保留。碰撞伤害、撞地销毁、费用、附魔和复制没有改。

扫掠若只因为默认抛物线或喷涌才打开，最终运动是垂落或风暴时关掉。最终运动是喷涌或未覆盖的抛物线时，仍打开最早扫掠。编译期的 `prefersSweep` 未改，执行层在运动定案后覆盖这一位。

## 最终路径优先级

1. 宿主允许改弹道，且本发路径已是垂落或风暴：用该路径的运动。
2. 宿主允许改弹道，且本发标记了喷涌：用喷涌运动。
3. 否则用宿主登记弹道。陨岩没有覆盖时仍是抛物线。

## 未改变的边界

- 同一分支两段真正的完整弹道仍然拒绝，包括两条路径修饰，以及路径覆盖加追踪。
- 追踪在命中直线、垂落、螺旋时仍可换成 `TrackingMotion`。这次没有放宽追踪互斥。
- 不可改弹道的斩击仍不吃路径覆盖。普通直线宿主的原有垂落入口保留。
- 修饰作用在它后面的宿主。覆盖写在宿主后面时，不回溯已经出生的弹。
- 多重、领域和按键仍进同一次批次编译，再进同一套 `applySpec`。没有改多重读取、冷却或魔力。
