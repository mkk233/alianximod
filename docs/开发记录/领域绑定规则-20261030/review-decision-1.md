## 结论

需要限定返修，当前不能按功能完成进入最终交付编译。核心是自动释放的真实提交回执没有接齐，造成空放扣费、复制部分失败仍全扣、已发布后异常或关闭却退款。另有自动提示刷屏及垂丝复制布局兼容问题。以下为本轮完整必须返修清单，所有相关作者收束后再集中核验，不逐文件追加复审。

## 必须返修

### R1 / P2：以真实发布或实际状态提交代替 execute 正常返回

报告明确：SkillSegmentRunner 在 effect.execute 正常返回后无条件设置 automaticSpawned，AutomaticRound 据此提交费用。空剑列表、幻剑资格早退、beginVortex 因令牌失效返回，都可能没有实际释放却被计为成功。

删除这种无条件成功依据。松散释放需要与本轮/成员/复制序号绑定的真实提交记录：新实体只有发布被接受才算；操纵既存剑只有实际进入该次有效控制状态才算，空列表或拒绝进入不算。不能仅数调用次数、执行返回、构造了实体，不能按术式 ID 罗列例外。宿主组继续使用其既有 HostGroup/COMMITTED 回执，不把暂存实体发布当作整组成功。

幻剑同时检查冻结武器和当前资格是现有冻结输入与资格约束，不要求为使它成功而删除其中任一检查；两者不满足而早退时，必须可靠地表现为失败和退款。

### R2 / P2：复制部分失败只能保留实际成功的计划份额

当前任一复制份成功就提交整成员费用，之后因令牌/资格失败的份数不退，违背未生成份额应退款的契约。

一次整轮预留保持不变；在内部把现有报价分解到成员及其计划复制份额，成功的复制份提交自己的价格，未提交份额退款。固定规则份额按既有报价归属结算一次，不为每份再次收费，不引入新的费率。若存在不可整除的整数余额，分配必须确定且总和等于原报价，不能逐份四舍五入改变总价。

计价单位是计划复制份，不是任意实体数量：同一计划复制份内部合法生成多个实体不能被重复收费；不同复制份也不能因其中一份成功而一起提交。宿主组保持原原子组语义，确实整组提交则收既有组价，未提交则沿其原回执结算，不擅自拆散原子宿主。

### R3 / P2：已发布与取消/异常之间不得先退款后提交

报告证据是 addFreshEntity 已发生、但 spawnMember 尚未返回到 budget.commit 时，异常或重入 close 会先 settle 未提交预算，使已出现的攻击免费。

真实回执必须尽靠近实际发布/状态提交点记录，并与预算结算协调。进入一次发布尝试前标明该复制份正在提交；同线程重入 cancel 立即禁止后续生成和延迟成员，但不能提前退掉这个尚未返回的发布尝试。退出该调用栈时先依据实际回执确定保留费用，再结清剩余未提交份额。已确认成功的发布不能被后续异常倒退成失败；尚未成功的不能因异常一律收费。异常继续传播，不通过吞异常、补造成功或删除已正常生成实体掩盖账务错误。

这是修当前报告已经确认的调用窗口，不要求新增全局实体事务或 Mixin 去证明所有未知引擎异常。对 addFreshEntity 返回 false、正常返回 true 后再异常、复制循环中途异常、控制状态实际提交后异常，必须给出明确结果。没有证据的“引擎内部写一半再抛出”不在本轮另立缺陷。

还要封住句柄交接窗口：C 调用 executeAutomatic 返回后，若实例已在执行栈中被关闭/到期，不能再把未完成句柄挂回关闭实例；应立即取消并由上述提交保护结清，而不是等未来延迟回调才发现 token 失效。正常已关闭实例不继续持有新句柄。

### R4 / P2：自动无剑失败不每 20 tick 提示

SwordReturnAllEffect 空剑列表每轮发送“没有可操纵的剑”。自动来源静默失败并交回未提交结果；手动提示保持原样。不要把无可操纵剑当成“无攻击目标”：无目标仍可生成其他普通攻击，不等于允许凭空创造剑。

### R5 / P2：保留垂丝一分为三的现有复制横排

自动 overrideGeometry 跳过 WeepingCurtainEffect 原有每份 0.72 横向布局，导致三份同源；报告已给出明确代码路径，属于自动输入适配漏掉原攻击复制几何。

在自动来源使用本轮显式源点和朝向，保留原复制序号的横向偏移，不读取准星或眼位。每份偏移后的生成源点再钳入真实领域；边界钳制造成的重合允许，不能为了强制分开而越界。已有落点/交错等显式规则的位置优先级仍按原规则，不无条件二次偏移盖掉它们。垂丝函数轨迹、世界竖直下落、唇口抬升和既有寿命不改。没有复制时仍用本轮源点，不搬回玩家眼前。

## A/B/C 唯一作者分工与修复接口

### A：预算、真实回执契约及执行栈

独占 AutomaticRound、GroupBudget、SkillSegmentRunner，以及 bind 包必要的提交观察/回执类型与 ReleaseExecutionContext 接线；必要时只改其已拥有的 ReleaseBatch 接点。负责 R1/R2/R3 的预算和调用方逻辑，不改 B 的实体/效果文件。

给 B 一份共同使用的发布观察接口，满足以下最小职责即可，具体命名由 A 贴合现有类型，不复制第二套收费系统：

- 创建属于 roundId/memberIndex/copyIndex 的尝试句柄，进入/退出可嵌套作用域，try/finally 恢复外层。
- B 在真实发布被接受或实际剑控制状态提交后报告成功；一计划份多次报告幂等，不跨份串账。
- 当前尝试可查询是否还允许继续发布；取消禁止新尝试和后续发布。
- 完成本次尝试时把真实成功/未成功结果送回预算；异常也必须先完成该记录再退款剩余金额。
- HostGroup 原子回执单独接入，不能把其暂存发布通知当成松散成功。

预算结清要区分“已请求取消”和“所有在途发布已结清”。done 只在预算实际终结后为真；取消和 finish 幂等，不能靠同一个先置位的 AtomicBoolean 让随后成功回执失效。不存在在途发布时 cancel 仍立即退款，不延迟普通关闭行为。

A 先交精确接口给 B；B 不自造另一份提交观察器。A/B 可在接口固定后并行各自文件，不互写。

### B：实际发布报告、自动提示及垂丝复制几何

独占其既有 TechniqueHitSpec、PhantomSwordEffect、SwordEntity/SwordVortex 中必要发布或控制状态接点。新增明确写权限：SwordReturnAllEffect、WeepingCurtainEffect，分别处理 R4 和 R5。每次真正发布前仍核验 token；发布成功后立即向 A 的当次尝试报告。空返回、addFreshEntity 拒绝、beginVortex 未改变状态不得报告成功。

针对操纵剑的发布回执，可让实际控制方法返回/报告是否提交；避免只在调用它之前推测成功。手动模式保持原提示、生成、复制几何与控制行为。不改旧伤害计费 Mixin 或查询缓存。

### C：关闭与返回句柄的最后交接

只在 DomainBindingRuntime/DomainInstance 的 executeAutomatic 返回和 trackRound 接点补有效性复查，失效则取消并不入集；保留已有 close 的清空、逐句柄取消和异常收尾。C 不修改预算或发布回执，不再 charge。其余周期、选敌、真实范围、注册无需返工。

外部任务已释放的状态不代表所有文件都要修改；上述即本轮允许的必要修复面。作者发现必须额外修改文件时先报告准确调用点，再由主会话分配唯一作者。

## 本轮没有另列必修的问题

- 当前无目标使用球面方向、目标完整包含与局部复核、规则先变换再钳源点、有目标不覆盖垂落等规则方向，报告与已批准语义相符，没有证据要求重定设计。
- 首发 20 tick、A/B 两成员 5 tick、投影消费、前后附魔归属与原索引映射，已有静态证据；不因未游戏验证自动判失败。
- 自动 A 失败后是否继续 B，现契约按成员独立退款且用户要求保留两段顺序，并未明确要求复刻手动会话“首段失败中止全组”；本轮不据此新增停止规则。
- chargeReady 非栈的实现问题先记限制：当前无正蓄力攻击声明，没有已证据化的现行功能失败，不扩大本轮修复为新蓄力设计。
- 剑读档后仅留方向、主人死亡的旧剑控制检查、极端时刻溢出、其他未实测分支均不能仅凭未知反推本轮新增漏洞；按报告如实保留验证限制。
