# 领域绑定规则：设计第 1/2 轮裁决

依据：本目录记录、read-chain-final.md、read-domain-final.md，以及同轮补齐的 read-entry-facts-final.md、read-capability-facts-final.md；遵守 max-dispatch 技能。未读源码、未实现、未编译。本次只裁决新增领域绑定能力，上一任务已交付的维护停用及接触计费不重审，其额度不重置。本次设计使用 1/2，实现仍 0/3。

## 结论

可实现，不需要再向用户询问实质玩法项。采用“切步前捕获子计划 + 共享释放执行入口 + 显式发射源上下文 + 每实例定时调度”。不能仅调用 buildSegmentRunnerAt，也不能伪造按键或直接裸 spawn。

不能为了缩减改动，暗中禁用跟随、持剑、幻剑、操纵剑或持续攻击。其现有输入依赖必须通过统一上下文替代；持剑等装备资格保留。以下技术默认仅服务已授权功能，不扩大修改旧领域计费或非绑定按键行为。

## 1. 捕获与消费的唯一规则

新增通用、无属性、零规则魔力和零规则装配消耗的“领域绑定”，暂定内部标识 rule_domain_bind，独立结构角色 RULE_DOMAIN_BIND，使用现有 other_none 图标。它是 ReleaseKind.RULE，不是假攻击或聚能边界。登记效果可为空，但执行器不能把它当普通可运行宿主。

在 ChainSteps.list 切步、TechniqueChain.split 分配附魔、以及任何开域预扣之前，先对完整原始装配链做结构捕获，生成不可变 BindingLayout：普通链投影视图、原始下标映射、每个领域宿主对应的 BoundReleasePlan。所有开域入口使用同一结果，禁止各写一套吞段逻辑。

- 合法排列为“领域宿主 → 领域绑定 → 子链”。绑定标记紧接领域术式；中间夹附魔或其他项时报结构错误，清楚提示正确排列，不能猜测附魔归属。
- 从标记后开始，只接受现有有效链修饰和基础附魔，直到第一个正基础伤害、非附魔、攻击角色的宿主。以通用定义和角色判断，不按术式 ID 白名单。领域、护体、屏障、动作、自身状态、条件释放、另一个绑定标记均不能越过寻找更远攻击。
- 上述结构错误、没有攻击、已移除规则或不完整双重，应在开域前报告并拒绝该次结构，不能悄悄跳过或把残段回落成普通攻击。
- 捕获范围含标记、沿途修饰及附魔、被绑定攻击。默认到第一个攻击结束；若捕获段存在双重，继续捕获构成现有双重组所需的第二个攻击及中间修饰/附魔，保持 A 再 B，间隔沿用实际执行的 5 tick，不能复制 A 冒充 B。
- 双重组只拥有两个攻击宿主；重复双重标记按现有计划语义解析，不通过新增无限递归扫描扩张到第三个攻击。若现有编译器明确拒绝一种重复组合，绑定保持同样拒绝，不自行发明新嵌套双重能力。
- 消费后紧随的未捕获内容继续留在普通链，正常形成后续按键步。双重之前作用于开域宿主的规则只控制开域，不把捕获子攻击当成其第二个普通成员。
- 一个链可以有多个独立“领域 → 绑定 → 子链”结构。每个标记只归属自己的直接前驱领域；子计划内不能再开领域，因此自动绑定不递归产生新的领域。

附魔归属必须在原始索引上确定：领域之前、按现行等宿主规则等待领域的附魔属于领域接触；绑定标记之后、等待 A 的附魔属于 A；A 后到 B 前的附魔属于 B。领域前修饰不泄漏到子计划，子计划修饰不回流到领域。聚能从子计划自身开始，沿用现有元素/类型适用性，不把领域的几何倍率再自动乘给子攻击。

必须修正现有报告的入口概括：普通“领域 → 修饰 → 攻击”原本分成两次按键；双重“领域、攻击”在同一次会话中相隔 5 tick 执行。新捕获在两种入口切步/成员编译之前统一消费，所以两种都不能在开域时额外释放被绑定攻击。

## 2. 冻结内容与每轮执行

开域冻结子计划结构、各攻击自己的附魔快照、规则、成员次序、能量输入及来源索引；不保存可变技能列表或按键会话引用。每份实际成功发布的领域实例携带自己的运行状态，复制域各自触发和支付。

首发为 startedAt + 20 tick，此后固定间隔 20 tick。开域当拍不发子攻击。一次双重的第二成员仍按 5 tick 延迟，不把两成员分别解释成 20 tick 周期。长期蓄力若以后存在，可跨越下一轮，但每轮拥有独立会话和收据，不因上一轮仍在等待而擅自跳过新轮；当前没有正伤攻击声明正蓄力时间。

同 tick 多域按主人 UUID、实例 UUID 稳定顺序逐份执行，实时检查余额。先收本拍实例快照再调度，不能在 ACTIVE 的直接 for-each 内执行可能改变集合的工作。超过期限先失效；如时刻异常跳跃只触发当前一次并推进到下一个未来节拍，不补发累计欠轮。

换装不改冻结的术式链，但不会冻住无限装备资格：每轮形成执行快照时读取当前主手，用其副本与现有属性计算作为该轮攻击输入；费用使用当轮当前资金来源。要求持剑的成员在实际生成时仍检查现有资格，失败只取消该未提交成员并退款。不能用开域时曾持剑来永久绕过持剑门。成功生成后的自动子实体不再因玩家松键或换手被追溯结束，而按自身寿命；这是自动释放上下文与手动输入的区别。

无目标也必须尝试正常生成；缺魔、主人失效或确实不满足装备资格是不同失败原因，不能被写成“没有目标所以跳过”。失败不关闭仍有效的领域，不刷每拍缺魔提示。

## 3. 显式发射源与几何

提炼共享 ReleaseExecutionContext，至少有 MANUAL 与 DOMAIN_AUTOMATIC 两种输入模式。普通路径的玩家输入解析仍按原逻辑；领域模式必须显式提供世界、主人、领域/轮次标识、发射点、方向、局部目标、几何范围、武器快照、自动持续策略、有效性令牌和确定种子。缺字段属于执行错误，不能回退读眼睛或准星。

每轮从实例最终 geometry 的真实范围均匀取一个基础发射点，轴对齐盒采用各轴独立均匀采样并避开浮点边缘；不用外扩 queryBox。选取完整位于域内、存活、非旁观、非主人且通过现有关系过滤的最近目标，距离从该随机点算，等距按 UUID。无目标用均匀球面单位向量作为基础方向。不能使用玩家锁定标记来选目标，也不创建、刷新或清除玩家的锁定/发光状态。

本轮两成员共用这一轮基础发射源及初始选敌结果，成员自己的规则仍各自生效。延迟成员重新确认目标有效性，失效时用该轮冻结备用方向，不重新读准星；不因目标消失取消无目标释放。

领域的真实范围约束的是发射源/生成锚点，不要求攻击体积、剑身、水帘或后续飞行始终塞在盒子内。执行规则后，最终初始发射点仍应限制在真实范围：交错位置偏移后回投范围；垂落抬高后的源点限制至领域顶面内，方向仍向下。规则变换先做，范围约束后做，不能约束后又被 spawn 的二次采样移出去。垂丝唇口等术式自有形状偏移不是发射源越界，不改其函数路径。

具体规则适配：

- 落点指定以领域本轮显式锚点替代准星锚点；不把默认有目标解释成瞬移到目标身上。
- 实体锁定使用本轮局部目标；可接受目标覆盖的攻击朝该目标，缺目标仍沿备用方向。后续追踪只读子实体自己的目标句柄，不读 owner 的全局标记。
- 跟随/追踪在领域输入模式下使用该次发射源与局部目标。目标仍有效时按原轨迹的追踪性质更新方向，失效后保留最后合法方向或初始备用方向；不自动切到玩家准星或跨域重新搜索目标。现有“追踪在落点附近选敌”的选择入口也应接收局部选择器，不能另选域外目标绕过本轮限制。
- 交错、垂落、路径覆盖按现有适用性和优先级作用；有目标不强制覆盖规则最终方向。一分为三仍通过原 copies/Tally 机制生成和结算，不私写循环伤害。
- 不可改弹道仍不可改：垂丝只更改源点/帘面朝向，仍世界竖直下落；斩击只改允许的生成位置与刀面，不能强改成飞弹或垂落。

## 4. 输入依赖能力必须统一承接

公共执行器应先完成计划和修饰解析，再构造显式 CastFrame，强制领域模式写 overrideGeometry、origin、look、anchor；不能只在最终 spawn 时盖一个位置，让前面仍调用 LockTargetService.resolve、crosshairCenter 或 resolveAnchor。

新增可传递到已生成实体的发射源/瞄准快照或等价运行对象，不能把 ThreadLocal CastFrame 当成跨 tick 存储。它持有局部目标与来源方向；实体生成后即独立于领域调度存活，关域不使既生成攻击强行消失。

- 普通命中体、热光束、静止斩和函数轨迹：使用显式源点/方向，不留空值回退。
- 燎里及跟随行为：保留其跟随轨迹性质，但跟随领域发射源；生成器在领域模式不能清空 start/anchor 后回到玩家。自动持续标志必须真正绕过按键 releaseSlot 判定，不能仅塞 -1（当前 -1 会被视为松手）。保留固有 lifetime，不能新做无限持续。手动释放的松手/换手结束逻辑不变。
- 幻剑：生成时保存显式初始瞄准/局部目标，悬停更新只使用该输入，起飞冻结方向仍按原行为。幻剑效果内部的武器资格保留，不能因没有定义字段就跳过；可把同类资格规范到共享能力检查，禁止按 ID 特判。
- 万剑归宗等操纵现有剑的攻击：保持操纵已有剑而非凭空复制剑；选择中心/瞄准使用显式发射源。现有剑自身当前位置是物理资源，不为“随机生成点”强行传送既存剑；新生成攻击/控制锚点来自随机点。没有可操纵剑时沿用失败/空放结果和公共提交语义，不伪造成功生成。
- 空间切割等效果即使后续覆盖锚点，也必须在领域上下文直接取显式锚点，不能先读一遍准星再覆盖。
- 蓄力与双重延迟使用领域运行令牌；不能沿用玩家 ChargeGate 代际使普通按键打断自动域，也不能把自动域会话登记为占用玩家按键冷却的会话。当前没有正蓄力攻击，无需新增蓄力玩法，但公共延迟入口必须接收取消条件。

以上以上下文/能力分支实现，不在 DomainService 枚举术式 ID。作者不得声称“其余全部支持”却留下报告列明的实时准星读取。

## 5. 共享计划、支付及取消契约

从 SkillSegmentRunner 和 CastExecutionSession 提炼可供按键与自动来源共用的执行核心；复用 CompiledReleaseStep、ModifierPlan/RoleScan、ReleaseInput、既有报价、GroupBudget/UncommittedShare 与 ReleaseOutcome，不在领域包抄一套扫描和计价。

建议契约（名称可贴合项目，但职责不能合并丢失）：

1. BindingLayout.compile(rawSkill) → projectedSkill、sourceIndexMap、domainSite→BoundReleasePlan、结构错误；纯结构解析，无世界操作、无扣费。
2. BoundReleasePlan → 冻结的子成员与修饰、每成员附魔、既有计划引用/值快照；不含玩家槽位、活动线程状态或可变按键游标。
3. 自动公共入口 executeAutomatic(plan, context, lifetimeToken) → 可取消的 RoundHandle；复用共享报价与成员执行核心，内部持有独立收据和未提交份额。
4. lifetimeToken.valid(now) 必须同时检查领域 active、now < expiresAt、主人存活在线且同宿主维度。RoundHandle.cancel() 幂等退未提交份额；已提交成员不退、不删除生成实体。
5. DomainService 成功创建每份实例时显式安装 bound plan；普通无绑定调用保留旧重载。所有普通/已预留/双重/接触开域入口都传同一捕获元数据。

开域只收普通投影视图应收的生成与起手附魔费用，绝不预扣捕获子链未来费用。每轮到时用冻结子计划走既有规则报价，独立一次预留整轮费用（双重含两个成员），不足则整轮跳过。延迟 A/B、复制份数、聚能和成员附魔费用沿用现有计算，不用接触附魔每种 1 点的单价收费。绑定规则本身免费。

成功生成/提交的成员保留对应份额；生成失败、不满足资格或尚未生成就被取消的成员退款。已经生成而后打空不退，也不再为其自然存续收费。复制和 Tally 沿用原计划份数与提交语义，不能逐份再 charge 一遍。异常必须关闭当前轮的未提交预算；成功提交记录不能被随后失败误退，不能吞异常伪装成功。这里不重做上一任务伤害结算。

close 时同步 cancel 本实例所有未完成 RoundHandle，退款不必等待调度器下一次 tick。排入 ChainScheduler 的旧回调可以逻辑取消后留到执行时空返回，但不得再扣费或生成。每次真正生成之前独立核验 expiresAt：调度器与领域 tick 同为 END 且无顺序保证，不能只看 active。死亡/下线/跨维同样清理；取消闭包保存原主人及收据，不依赖重新找到在线玩家才退款。

不改 MagicPool、ManaPaymentReceipt 的既有资金来源与法杖身份规则。法杖已离开可找到背包时既有退款局限须如实保留，不声称本功能解决该旧问题。每轮保存自己拿到的收据对象，不能以后再查询 LAST_RECEIPT 当成本轮账单。

同 tick 开域去重不能让绑定归属丢失：带绑定的开域声明用稳定的本次施法/原始领域位置标识作为 claimSuffix，避免不同绑定计划误合并；同一声明重入仍幂等，合法 copies 仍生成多份。无绑定的旧路径去重不改。
