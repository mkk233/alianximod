## 根因

`D:/alianximod/run/logs/latest.log` 的修改时间是 2026-11-17 00:13:27.288，大小 30019 bytes。第一异常在第 25 行，第 45–48 行展开：

`Registry Object not present: xueximod:daozhang`

堆栈指向 `RegistryObject.get(RegistryObject.java:204)`，再指向 `ModItems.lambda$static$17(ModItems.java:55)`。本次日志没有上一轮 Redirect 0/1。

原第 55 行在物品注册工厂里调用 `DaozhangTypes.DAOZHANG.get()`。`XueXiMod.java:121` 先注册物品，`XueXiMod.java:138` 才注册实体，因此创建刷怪蛋时实体注册对象还不存在。物品 ID、颜色 `0x6E6250`、`0xE8D7AE` 和道长实体 ID `daozhang` 都不是错误点。

## 本地 API 证据

检查的构件是：

`C:/Users/baishang/.gradle/caches/forge_gradle/minecraft_user_repo/net/minecraftforge/forge/1.20.1-47.3.33_mapped_parchment_2023.06.26-1.20.1/forge-1.20.1-47.3.33_mapped_parchment_2023.06.26-1.20.1-recomp.jar`

`javap` 确认：

- 原版只有 `SpawnEggItem(EntityType, int, int, Item.Properties)`，构造时必须已有实体类型。
- Forge 提供 `ForgeSpawnEggItem(Supplier, int, int, Item.Properties)`。
- 构造字节码把实体参数以 null 传给原版构造，只保存 `typeSupplier`，不调用 `Supplier.get()`。
- `RegistryObject` 实现 `Supplier`，可直接传入。
- `getType` 先走原版 NBT 类型，没有覆盖时才调用 `typeSupplier.get()`。
- `CommonHandler.onCommonSetup` 在 common setup 才调用 supplier，把实体类型放进 `TYPE_MAP` 并注册发射器行为。
- `ColorRegisterHandler` 仍按两个颜色注册物品染色。

因此构造刷怪蛋不再提前解析 `xueximod:daozhang`，使用和颜色行为仍由 Forge 的既有延迟路径处理。
