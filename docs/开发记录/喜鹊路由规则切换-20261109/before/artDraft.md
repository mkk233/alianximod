# Aseprite 与 Blockbench 美术预览

用于 XueXi Mod 已经明确要做或要改的游戏内美术。只讨论玩法、机制或方案时，由当前 Codex 主会话直接回答，不打开制作工具，不归档，不接入。

## 何时做 Blockbench

有空间形状、朝向、厚度、遮挡、环绕、挂载、尺寸，或运动、姿态关系的特效和模型，都要做空间示意。运行时最终只是二维透明贴图或粒子的，同样要做。

跳过 Blockbench 只限于纯背包图标、界面等确实只在二维里显示、并且没有空间表现的素材。跳过时写下这项为什么不涉及空间。

## 顺序

1. 读现行需求：制作表里的 `N`、`O`、`DV`，以及最新已批准版本。「待制作原始数据」只供历史对比。
2. 用 Aseprite 制作，并查看二维像素预览。
3. 适用时在真实 Blockbench 中对照该二维版本搭空间示意，并从实际视口展示。
4. 等用户确认这一实际版本。
5. 归档到 `docs/资源库/`。
6. 需要进游戏时，把确认版交给固定的 Cursor CLI `--model grok-4.7-high-fast` 接入并编译。
7. 游戏效果由用户实测。默认不打包、不 `runClient`、不启动游戏。

可以集中交出一批二维和三维结果。二维通过不等于三维通过。同一版本已经明确确认的，不重复追问。草稿和脚本可以先放进 `docs/资源库/过程归档/`，不需要用户批准。未经确认不得列为正式采用版本或正式确认版，也不得送去运行接入。等待确认时，与这次确认无关的任务可以继续。确认之后若改形状、位置、方向、比例或动画观感，只重新确认受影响的部分。已经明确授权接入的确认版，不再反复要求确认。

用户选稿、看预览和游戏实测，不是 Codex 的正式正确性复审。真正做正式裁决时，仍计入既有阶段：设计最多 2 轮，实现最多 3 轮。不另开视觉审核阶段。额度用完不能写成用户已经视觉确认。

## Aseprite

优先用当前会话里已经暴露的 Aseprite MCP。调用前先看当前工具元数据。已出现过的操作包括 `status`、`app_state`、`open_sprite`、`run_lua`、`render_preview`、`save_sprite`、`export`。元数据里没有的名字不要编造。

先确认目标文档。保存 `.aseprite` 可编辑源，以及原尺寸透明 PNG 或帧图。记下尺寸、帧顺序、时长和循环方式。像素预览用最近邻。

用户明确指定 Photoshop 时，二维部分按指定工具做。这不取消 Blockbench。

不要用 ImageGen 代替用户要求的绘画或建模。

## Blockbench

必须真实打开 Blockbench，载入与已查看的二维版本对应的素材，搭可编辑模型或示意场景，保存 `.bbmodel`，并从实际视口取出足够判断的截图或动画。

先按当前工具元数据查找 Blockbench 专用 MCP。没有就不要编造调用名。此时只有会话里已经可用、并且已获授权的 Blockbench 桌面或浏览器控制入口可以操作；会话里有对应的 computer-use 技能就按该技能执行。两条都没有时，把 Blockbench 环节标成阻塞，独立的二维工作可以继续。

不得静默跳过，不得伪造截图，不得用生成图、离线拼贴、手写 JSON，或只保存 `.bbmodel` 来声称已经展示。模型文件生成之后，仍要导入真实 Blockbench 再看结果。

示意里放上必要的玩家、实体、武器或地面参照。把计划采用的贴图贴到对应的面或模型上，并设好比例、轴向、厚度、层次和透明关系。视角按风险选，通常要有整体透视，以及能看清前后距离的侧面或背面。单张正面图不够。动态效果要看到关键姿态、阶段和相位变化。假人、占位物和辅助网格单独命名为示意辅助，不放进运行资源。

`D:/alianximod/docs/资源库/特效/火焰/燎里_剑阵姿态_v7/README.md` 只说明坐标、挂点和占位模型可以怎样写。那里的 32 单位、1.8 格、坐标、时间和数量不是通用规则。

## 交接与归档

要接入时，把观感写成可执行的记录。按这项实际需要选取参数。纯二维例外保留 Blockbench 不适用记录，其他用不上的项删掉。记录前阅读 [references/visual-handoff.md](references/visual-handoff.md)。

模型单位和游戏单位的换算按这项的实测关系写，不要一律写成 1 模型单位等于 1 方块。预览速度只用于演示，写清楚，不要当成施法时长。Blockbench 模拟不了的运行效果单独列出，不要写成 Forge 已经证实。

适用 Blockbench 时，最终确认绑定同一版本的素材、`.bbmodel`、实际视口预览和交接参数。符合上面写明的纯二维例外时，`.bbmodel` 和三维预览写「不适用」并附原因，确认绑定同一版本的二维源、导出、二维预览和交接参数。用版本号、路径和必要哈希对上。源文件、导出、示意、预览和接入映射使用同一版本。

同一 MCP 实例和同一份活跃文档串行使用。每个目标文件只有一个作者。保留用户未保存的内容，不关闭、不覆盖无关文档。归档遵循 `docs/资源库/README.md`。正式资源按用途、对象、版本存放，保留可编辑源、原尺寸导出和交接记录；适用 Blockbench 时保留实际视口预览，纯二维例外在交接里写「不适用」及原因。草稿和脚本放 `docs/资源库/过程归档/`，不需要另等批准。索引由该文件的唯一作者更新。

Blockbench 场景和占位模型不一定能被游戏加载。运行时格式、转换、代码渲染、复制到 `src/main/resources/assets/xueximod/`、引用核对和 `compileJava`，由该项的 Cursor 实现者按批准的交接参数做。整个 `.bbmodel` 和假人留在示意归档里。接入结果和交接不一致时，明确交回。
