# 本批命中裁决接口

返修 2 作者 A 交给 B 的命中合同。返回类型都是 `com.bslx.XueXiMod.shu.technique.release.batch.HitVerdict`，与 `TechniqueHits.classifyRespecting` 相同。

`continues()`：`ESTABLISHED_NO_DAMAGE` 或 `DAMAGE_ACCEPTED`。成立和接续读这个。

`grantsSeeds()`：只有 `DAMAGE_ACCEPTED`。产种、正伤载荷和正伤收据读这个。

不要把 `continues()` 写成 `DAMAGE_ACCEPTED`。旧 `hurt`、`hurtRoot`、`hurtConfirmed`、`confirmTracked` 的布尔值只等于 `grantsSeeds()`。合法的恰好 0 返回 false。

## 金额边界

合并领域供给之后再判断。`classifyRoot` 自己合并一次；调用方已经合并过的，用 `classifyHit` 或 `classifyConfirmed`，不要再走 `classifyRoot`。

- 有限且恰好为 0，并且 `DamagePermission.allows` 通过：`ESTABLISHED_NO_DAMAGE`。不调用原版 `hurt`，不改无敌帧。
- 负数、`NaN`、正无穷、负无穷：`INVALID_OR_CANCELLED`。不调用原版 `hurt`。
- 权限不通过，包括空目标、死亡、旁观、自身、无敌、`canHarmPlayer` 拒绝：`INVALID_OR_CANCELLED`。
- 正数：沿用该方法原来的无敌帧和确认结果。原版打出正伤才是 `DAMAGE_ACCEPTED`。

`classifyRespecting` 使用同一条 0 与非法边界。正数仍区分取消、免疫和正伤。

## 签名

```java
public static HitVerdict classifyHit(LivingEntity target, ServerPlayer player, float amount)
public static HitVerdict classifyHit(LivingEntity target, ServerPlayer player, float amount, Landing landing)
public static HitVerdict classifyHit(LivingEntity target, ServerPlayer player, float amount, Landing landing, TideMarkSuccess tide)

public static HitVerdict classifyRoot(LivingEntity target, ServerPlayer player, float amount)
public static HitVerdict classifyRoot(LivingEntity target, ServerPlayer player, float amount, TideMarkSuccess tide)

public static HitVerdict classifyConfirmed(LivingEntity target, ServerPlayer player, float amount, Landing landing, TideMarkSuccess tide)
public static HitVerdict classifyConfirmed(LivingEntity target, ServerPlayer player, float amount, Landing landing, TideMarkSuccess tide, ConfirmedDamage outcome)
```

`Landing` 与 `ConfirmedDamage` 都在 `TechniqueHits` 里。最后一条与 `confirmTracked` 使用同一套跟踪：没有 `outcome` 时与五参数 `classifyConfirmed` 相同；有 `outcome` 时，正伤确认才安装监视。`outcome.accepted()` 仍只表示正伤被接受。0 与非法会 `record(false, false, false)` 并返回上面的裁决。

`classifyConfirmed` 只在 `Landing.RESPECT_INVULNERABILITY` 时对正数调用原版伤害。其它着陆方式在正数上返回无效，不绕过无敌帧。恰好 0 不看着陆方式。

`classifyHit` 的正数路径：`RESPECT_INVULNERABILITY` 保留无敌帧，其它着陆方式仍先把无敌时间清掉再打，打完按原逻辑恢复。原版 `hurt` 返回 true 才是 `DAMAGE_ACCEPTED`，false 是 `ESTABLISHED_NO_DAMAGE`。

`classifyRoot` 先按根攻击并上当时的领域供给，再以绕过无敌帧调用 `classifyHit`。
