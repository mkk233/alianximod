# 配置平衡指南（草稿）

**状态：接入实现中，尚未完成最终编译，也尚未做游戏验证。** 本文按已批准架构说明整合包作者和以后的术式开发者会怎么用这套平衡配置。它不是已可运行的功能说明，不能据此认为游戏里已经有这份文件、这些字段已经生效，或客户端已经能看到配置后的数字。

精确的术式参数键、可粘贴的 JSON 示例、schema 版本号和 Java 方法签名，等共享接口收束后再补进本文。下文只用已经批准的文件位置、全局字段和参数种类。

## 这份指南给谁

- 整合包作者：改全局倍率和单个术式的平衡，而不改结构。
- 以后新增术式的人：让新术式使用同一套配置，而不是再写一套常量。

中文名和制作表编号不能用来定位配置。只认术式的完整稳定 ID。当前已登记 62 个术式都会进入参数目录，但每个术式只出现自己真正会用到的字段。

## 两个文件，以及谁覆盖谁

平衡使用独立 JSON，不写入现有的 Forge toml。

| 用途 | 位置 |
| --- | --- |
| 整合包模板 | `defaultconfigs/xueximod-balance.json` |
| 某个世界真正生效的文件 | 该世界的 `serverconfig/xueximod-balance.json` |

读取顺序：

1. 世界文件已经存在：只读这份。模板后来改了什么，都不会覆盖这个世界里作者已经写下的值。
2. 世界文件还不存在：把模板复制成世界文件。新世界走这条。
3. 模板也不存在：按当时已经登记的参数生成一份完整默认文件。

已有世界里的旧文件保持原样。某一项是后来新增的、旧文件里没有，这一次在内存里用代码默认值，不改写作者的旧值，也不自动删掉认不出的键。认不出的术式 ID 和认不出的字段会警告，并留在原文件里，它们不会悄悄生效。

已知 ID 会归并到正式 ID。目前的别名是 `water_open_ring`，正式 ID 是 `water_blade`。两处同时写了数值时，正式 ID 优先，并记录警告。不要用中文名或表编号再写一份。

整份 JSON 语法损坏，或 schema 版本无法识别：保留原文件，给出明确错误，这一次改用代码里的默认快照。不会静默把损坏文件重写成新文件。本草稿不写 schema 版本号。

单个字段非法：警告，并只让该字段回到自己的默认值。其余字段仍用世界文件里的值。费用和伤害不能是负数。寿命和周期这类正时间至少为 1。现有代码里本来就支持的特殊哨兵值，只在原来那个位置仍然允许。费用乘以份数时，原来的溢出检查还在。减伤比例沿用现有上限。`NaN`、无穷大和溢出都拒绝。

## 何时生效

改文件之后，下一次服务器启动，或重新打开单机世界，才会生效。世界开着的时候改磁盘，当前这一局不变。

本版不做热重载。进行中的魔力收据、燃烧账、剑和命中实体不能混用两套数值。

服务端在内置术式和外部术式都登记完之后，封存参数目录，并在这个世界开始提供玩法之前做成一份不可变快照。客户端登录时接收同一份快照，用来更新本地显示和有效参数缓存；断线后只清空客户端这份。单机集成服务器不能因为客户端断线，把服务端快照一起清掉。配置只由服务端发给客户端，不接受客户端把改动送回来。

因此：界面上的伤害、费用和冷却应当和服务端这一局正在使用的快照一致。本草稿不宣称这个同步已经接通。

## 三个全局倍率

全局只开放三项，默认都是 `1`，也就是保持现在的手感：

| 已批准字段 | 作用 |
| --- | --- |
| `damageMultiplier` | 全局伤害倍率 |
| `manaMultiplier` | 全局魔力倍率 |
| `cooldownMultiplier` | 全局冷却倍率 |

每一项只应用一次。术式自己的伤害倍率再乘这一次全局伤害，不能在命中出口、账本份数或另一处监听上再乘。魔力倍率在「这一笔费用的单价」形成时乘一次；之后的复制份数、成功目标数和维护次数仍按原来的账单累加。冷却倍率在读取该术式基础冷却时乘一次；其后的附魔反应、段间合成和法杖减免保持原来的顺序，不能在法杖减免里再乘一次全局冷却。现有「冷却至少 1 tick」的边界保持，不能靠把倍率写成 0 来改掉冷却语义。

不开放全局的实体数量、复制份数、几何能量或结构规则。

## 现有 toml 保持原样

下面两份配置继续用原来的含义，平衡 JSON 不接管它们，也不要把伤害或魔力写进去：

- `xueximod-common.toml`
- `xueximod-batch-terrain.toml`

潮湿飞行豁免名单仍按原规则，包括名单被改成空时保持空名单。地形破坏开关仍只服务原来的地形机制。这些 toml 的加载和重载行为不因平衡文件而改变。

## 术式配置怎么读

`techniques` 里用完整稳定 ID 找到术式。该术式对象内部是扁平参数，不按中文分组。

原默认伤害和原默认费用彼此独立。基础魔力仍按原来的优先级，用**尚未做平衡缩放的基础伤害**推导。只改伤害倍率，默认耗魔不变。想一起改，就分别写伤害和费用。

`Technique` 上的原始基础伤害继续参与宿主识别、附魔边界、默认耗魔和装配等结构判断。不要把「配置之后的伤害」写回这个原始值。伤害倍率写成 `0` 时，这一下可以没有伤害，但攻击不会因此变成规则术式，领域绑定也不会因此失效。

原本费用就是 0 的术式，仍可以显式写成别的费用。这样做不得改变原来收几次费。

## 首版开放的参数种类

只生成有真实作用的字段。底伤不参与实际伤害的术式，不会因此得到一个无效伤害键。尺寸、速度和寿命是替换原来的默认值，发生在现有能量缩放和附魔倍率之前，不是在那些倍率之外再叠一层。

尚未经实现确认的具体键名不在这里列出。下表是首版承诺的种类。

**每个术式**

- 基础冷却。
- 适用的基础魔力，或适用的单位魔力。

**普通攻击、会碰撞的动作、批次载体**

稳定 ID 包括 `sword_thrust`、`sword_horizontal_slash`、`sword_vertical_slash`、`movement_dash`、`magic_arcane_missile`、`test_sustained`、`space_cut`、`tide_sever`、`stone_hammer`、`metal_needle`、`fire_orb`、`fire_burst`、`water_yielding_ribbon`、`water_blade`、`fire_meteorite`、`fire_shock_ring`、`fire_spark`。

- 伤害倍率。
- 实际生效的寿命、运动速度和主要命中尺寸。
- 同一项寿命若原来写死在两处，只能有一个来源。

**热光束 `heat_beam`**

- 长度、寿命，以及真实的命中间隔。

**寄生种子 `parasite_seed`**

- 寿命，以及主要散布和作用范围。
- 颗数保持固定三颗，不开放。

**幻剑 `phantom_sword`**

- 真实剑伤倍率、飞行速度、寿命。
- 改的是生成时写进剑物品的那份伤害。只改术式面板上的基础伤害，剑伤不会变。

**剑来 `sword_come`、万剑归宗 `sword_return_all`**

- 适用的费用和冷却。
- 实际使用的搜索范围和移动参数。
- 本版不加通用伤害倍率。已经生成的剑保持生成时的伤害。这两式面板上的旧底伤不是实际剑伤。

**水幕 `water_curtain`**

- 生成费、维护费、维护周期、寿命、主要尺寸、弹速衰减。

**水环 `water_ring`**

- 生成费、维护费、维护周期、寿命、半径、卸伤比例。

**雾雨 `water_mist`、深压 `water_deep_pressure`、幽冥 `fire_nether_gloom`**

- 实际开域费用或附魔费用、寿命、盒子尺寸。
- 适用时，还有光环附加伤害，或产种参数。
- 不生成已经废弃的领域维护费。幽冥的附魔费不是领域开域费，不能再配成第二笔开域费。

**水牢 `water_prison`**

- 每个成功目标的费用、扫描范围、监牢时长、压强伤害倍率、实际脉冲间隔。
- 四层门槛和环境伤害的归属不变。压强仍是没有攻击者的环境伤害，不绕过无敌帧，也不因此新增水势收益。

**燎原 `fire_liaoyuan`、灼地 `fire_scorch_field`、燎里 `fire_liaoli`、焚天 `fire_fentian`、主动冷却 `fire_cool`**

- 各自真实伤害路径上的倍率，以及已经存在的实际范围或寿命。
- 燎里的物理刺击和火种伤害都归 `fire_liaoli`，两笔分开缩放，各一次。
- 主动冷却另有真实蒸汽伤害。升温 `fire_heat_up` 和超频 `fire_burn` 本版只有费用和冷却。

**旧五附魔**

`vine_mark`、`tide_mark`、`sinking_edge`、`keen_mark`、`magic_ignite`。

- 适用的附加伤害倍率、费用、冷却，以及实际控制持续时间。
- 潮印的伤害金额和条数分开。改伤害不会改变潮湿条数或水势条数。
- 点火的着火秒数只改着火时长，不表示原版燃烧伤害也进了本模组的伤害倍率。

**资源附魔**

- 引燃 `fire_kindle`、引爆 `fire_detonate` 的真实伤害倍率。
- 种火 `fire_seed_sow` 的数量。
- 引燃实际使用的段伤、周期和持续参数。
- 幽冥实际使用的产种量和周期。
- 数量仍受现有资源上限和合法账本约束。引燃每段燃料需求、焚天段数上限和档位上限不开放。

**只改规则、索敌或路径的术式**

包括 `movement_leap`、`magic_create_water`、`universal_lock_target`、`rule_dual_release`、`trajectory_drop`、`rule_cast_anchor`、`rule_triple_cast`、`rule_domain_bind`、`rule_gather_energy`、`trajectory_3d_interleave`、`trajectory_tracking`、`trajectory_storm`、`rule_surface_anchor`、`fire_upwell`、`rule_stagger`、`rule_hit_continue`、`fire_flame_trail`、`earth_break_ground`，以及上面已经单独说明费用边界的炉心升温、超频。

- 费用和冷却。
- 搜索距离、散布之类，只有已经确认有实际读取者才开放。
- 没有被飞行使用的弹速，不能当成飞行速度来配。

垂丝 `water_weeping_arc` 只开放实际被效果读到的那些专项。本草稿不把尚未对上消费者的常量写成可调项。

## 首版不开放

下列内容不进平衡文件。文档和界面都不能写成「所有数值可配置」：

- 结构角色、结算顺序、命中去重和账本规则。
- 复制份数、双重释放份数、一分为三份数，以及其他多重数量。
- 原生元素反应表。
- 装配消耗、解锁等级。
- 炉心内部属性改写和热量公式。炉心三式只保留上面写明的费用、冷却，以及主动冷却的蒸汽伤害。
- 几何能量规则。
- 只用于画面的常量。
- 地形机制开关。
- 寄生种子的颗数。
- 已废弃的领域维护费。

## 伤害只缩放一次

每一笔伤害先按原来的公式得到**原始金额**，再按它的来源术式做成**已配置金额**。这一步同时乘上该术式伤害倍率和全局伤害倍率，各一次。之后的合并、份数和命中只使用已配置金额，不再做平衡缩放。

不要在总的命中出口上对整刀再乘。那样会把复制账本、领域光环再乘一遍，也会把原版普通攻击卷进去。

使用时可以按下面的结果理解：

- 普通宿主自己的基础伤害和原有武器加成，作为宿主这一笔缩放一次。附魔附加伤害按自己的来源另算，再相加。同属性、法杖和场地原来怎么作用，仍怎么作用。
- 释放链、命中规格和账本里保存的伤害，都已经是配置后的值。账本最后仍是「这一份伤害乘命中份数」，这份数不是另一次平衡倍率。
- 领域光环先按领域来源变成已配置贡献，再在原来允许合并的位置加上一次。哪些命中可以吃到领域加伤，范围不变。
- 火伤按每条真实贡献各自转换。炉心那一笔要先按原公式算进原始金额，再转换；不能先转换、过后又补上一截没缩放的炉心，也不能把已经结算的炉心再乘一次。
- 水牢压强在产生那笔环境伤害时，按 `water_prison` 转换一次。

### 原版普通攻击和原版燃烧

有潮印的武器印记，只在原版主目标那一刀上**加上**已经配置好的潮印金额和共享附加金额。不乘原版那一刀的伤害，也不给横扫加上这笔钱，也不因此打出第二刀。

没有潮印时，原来的额外一刀仍在。其中来自印记的武器份额只吃全局伤害倍率，不套任何一个术式倍率；共享附加额用的是保存时已经配置好的金额。这一额外刀不是原版普通攻击本身。原版最初那一刀不套本模组的全局伤害倍率。

玩家被点燃之后，原版自己产生的燃烧伤害不归本模组的全局伤害倍率管。平衡文件不能把这项写成可调。

### 剑上已经保存的伤害

幻剑生成时，把物品上的剑伤按 `phantom_sword` 转换一次并保存。之后的飞行、召回和读档都不再应用配置倍率。

旧存档里剑的伤害按已经写下的最终数值使用，读档时不追乘。剑来和万剑归宗召回时也是如此：不会因为召回，把剑伤再放大一次。

### 火、木、土、金的共享附加额

这四系在普通攻击链上共用**一笔**附加伤害，不是每条附魔各给一笔再相加。

这笔钱归**第一次把它建立出来的那个术式**。后面的同属性附魔仍按原来的规则修饰这一笔，包括原来的同属性修正和层数，但它们的伤害倍率不再乘它。宿主的伤害倍率也不包裹这笔附加额。来源看的是「谁先建立这笔原始金额」，不看配置之后它是不是 0。因此第一个来源的伤害倍率即使是 0，归属也不会挪给后面的附魔。没有这笔贡献时，金额是 0。

接触附魔是另一条规则：仍按原来每一格的加数分别计算，每一格用该格术式的倍率缩放一次。不要把接触附魔改成「只算第一个来源」，也不要把普通链改成「每一格各加一笔」。

不能写成「每条附魔在所有场景都独立加伤」。

### 潮印

条数和伤害金额是两件事。

- 条数继续负责潮湿、水势和潮印原有的状态。改潮印伤害，条数不变。
- 伤害金额单独配置。并入原版主目标那一刀时，只加上这笔已经配置的金额。
- 旧印记没有新的伤害字段时，按旧的最终金额使用，读出来不再乘配置。保存时乘过的，读取时不能再乘。

### 没有潮印的武器印记

额外那一刀里的武器份额没有对应的宿主术式，不能算成某一条附魔的基础伤害。它只受全局伤害倍率影响。共享附加额仍是已配置金额。原版普通攻击那一刀不受影响。

## 费用和冷却的实际结果

魔力池只是钱包，本身没有全局倍率。某一笔已经扣下或写进收据的金额，退款时退原来那一笔，不能按后来改过的配置重算。

维护费若在放置时抄进了实体，抄的是哪一种单价必须只有一个答案：要么保存原始单价、扣款时再乘一次，要么保存最终单价、扣款时不再乘。不能两端都乘。

水牢的成功单价只在每个成功目标上形成一次，不能再进按键预扣。幽冥开域费保持它原来的零，真正的附魔费留在附魔那一笔。

## 给以后写术式的人

新术式必须走这套配置。重要平衡值要声明键、默认值、单位和范围，并且有真实消费者。只登记、效果里仍用硬编码，不算接入。缺配置时用声明里的默认值。默认值必须等于接入前的行为。

服务端玩法和客户端显示使用同一份已生效快照。

### 谁可以登记

- 标准项只有一处登记：基础冷却、适用的魔力费用、以及这个术式确实会进入伤害公式时的伤害倍率。这些从术式和释放定义里已有的原始默认值导出，不要另抄一份数字表。
- 专项参数由真正消费它的那一侧登记一次。另一侧只读取或接收已经算好的时长、金额和载荷，不能再登记同名项，也不能在下游再缩放。
- 重复声明是错误。后写的声明不能覆盖先写的，用来掩盖两边都注册了。

已经定下的专项归属：

- 燎原半径由火场侧声明一次。调用方先读取，再乘现有的体积缩放，然后传入火场。寿命由释放定义侧声明，使用同一个默认来源。
- 灼地的寿命和半边范围由接触火场侧声明并消费。不要把释放定义上的寿命再登记成另一个键。
- 幽冥的产种量和周期由火种侧声明。种火量只在发放处消费。周期不额外乘全局冷却倍率。领域盒子、寿命和原来的开域费仍由领域侧负责。
- 焚天半径由焚天效果侧声明和消费。火伤侧不登记这个半径。
- 种火数量，引燃的段伤、间隔和持续，主动冷却的作用范围，缠枝的控制时长，点火的着火秒数，都由附魔与火伤侧声明并消费。
- 燎原、焚天、燎里、灼地、引燃、引爆、主动冷却，以及旧五附魔里真正进入金额公式的术式（含潮印），即使面板基础伤害是 0，也仍有标准伤害倍率。这项由公共侧登记，火伤和附魔侧只消费。

基础伤害为 0 不能用来删掉一条真实存在的伤害倍率，也不能反过来给没有伤害的规则术式编一个伤害键。

### 原始金额和已配置金额

调用缩放时传入的必须是还没乘过本配置的原始金额。得到的结果是已配置金额。

- 保存已配置金额的存档、武器、剑和延迟燃烧计划，读出后直接使用。
- 若数据带版本：缺版本按旧格式的最终金额解释，不追乘。新写入的已配置金额必须用能被识别的新版本。本草稿不编造版本号。
- 不能在保存时乘一次、读取时再乘一次。
- 延迟伤害在形成那一笔时就带上来源。不能拖到造成伤害时，再凭伤害类型猜测是哪个术式。

注册和类的静态初始化只建立原始默认值。不能在那个阶段读取本世界的有效配置，再写进永久常量。参数目录可以封存；每一局的有效值只来自这一局的快照。

### 旧的外部登记

已有的外部登记入口保持可用。它会自动得到标准费用、冷却，以及适用时的伤害支持，并警告专项参数还没有声明。不能为了兼容旧入口，伪造范围、速度或其他没有声明过的键。

新入口在共享接口收束后提供。本草稿没有可抄的方法签名。新术式在那之前不要假设 `docs/配置平衡指南.md` 里的某个类或某个 JSON 示例已经存在。

新增或重命名参数时，保留玩家世界文件里已有的值，并让旧的稳定 ID 仍能归并到正式 ID。
