# 统一开发与术式批量制作流程

本文是代码线、美术线和批量模式的唯一流程正文。`AGENTS.md` 与 `.grok/skills/max-dispatch/SKILL.md` 只保留摘要和指向本文的入口，不另定状态。游戏 MCP 限制和术式技术约束仍以 `AGENTS.md` 现行第 4–6 节为准。当前授权是 Cursor Grok 4.7 High Fast、默认不打包、游戏由用户实测。用户以后明确要求可以修改这些规则；代理不得自行换模型或降档。后文各节不再重复这条。

代理只在接到批量指令后执行本文。用户填表不会启动任务。没有自动调度脚本，没有后台监控。空的「待制作」是正常结束，等待用户下次填写后再领取。

## 讨论与执行

先按用户当前意图区分直接讨论设计与执行任务。

直接讨论设计：用户在 Codex 中探讨玩法、机制、需求、方案或设计取舍时，当前 Codex 主会话直接理解、推理、回答并提出建议。不派给 Cursor，也不以先启动子代理或先走完整执行流水线为回答前提。仅因提到某个术式、待制作表或设计较复杂，不自动转成执行。这类交流本身不是批次正式校验。

执行任务：用户明确要求按表制作、落地实现、修复、编译或其他执行工作时，继续走后文的 Cursor Grok 4.7 High Fast 流程。主会话负责调度，并按既有额度做逻辑复核。困难裁决，以及设计最多 2 轮、实现最多 3 轮 Codex 校验的约定不变。没有独立测试阶段。该阶段额度用完后不再自动追加复审，只转达 Cursor 的工作结果；追加须用户明确同意。主会话不因此亲自实现或编译。

同一条消息里两者都有：主会话直接回答设计部分；已经授权且设计明确的执行部分再按原流程交 Cursor。讨论本身不自动领取制作表、改代码、编译或迁移表状态。用户已经明确授权的执行工作不重复要求确认。

若交流实际是在对现有批次做正式正确性或验收复审，仍按原阶段额度计数，不能把额外复审改称设计讨论来避开设计 2 轮或实现 3 轮。后文的主会话调度、新需求交给 `gpt-6-astra` 和模型派发只约束执行任务。额度未用完或已获追加授权时，等待 Cursor 完成并返回最终反馈后再集中复审、不实时跟进工作内容的规则仍然有效。额度用完且未经用户明确同意追加时，不再自动集中复审。

## 1. 角色与工具

- 用户：填写「待制作」；集中回复视觉和实质设计选择；做游戏实测；判定完整术式是否完成。
- 主会话（执行任务）：调度、指定本批唯一记录者、读记录、汇总已跑命令、未跑项和环境阻塞。该阶段 Codex 额度未用完时，可按已记录轮次集中做逻辑复核，每次正式正确性判断算该阶段一轮；额度用完后，当次不再自动追加该阶段复审，主会话只派发、等待最终反馈并转达 Cursor 的工作结果，不重新判断正确性，也不交给 Cursor、其他 Codex 子代理或新会话继续复审。不必用满该阶段上限。用户明确同意前不启动追加复审。主会话可读简单符号和文档，不通读整仓，不直接改 Java，不直接编译。
- 唯一 `gpt-6-astra`（只用于执行任务）：只在该阶段 Codex 额度未用完时裁决难点和新需求，只开一个。直接讨论设计不交给它。根因不明、改动牵涉多处、接口或架构未定、并发或 NBT、需求含糊、改错成本高，额度内先交给它。涉及正式校验判断时先看实际阶段额度，按本节约定的阶段计数。额度用完后，不再请它或其他子代理重审，也不自动把该阶段复审交给 Cursor。待裁决且无法在已批准设计内执行的事项只报告阻塞。用户偏好选择集中问用户，不逐项追问是否开工。
- Cursor CLI：代码实现、修复、编译、代码定向检查一律显式 `--model grok-4.7-high-fast`。禁止 Low、grok-4.5、省略 model、默认继承和自动换模型。用 CLI，不用 computer-use 操作 Cursor。Cursor 不可用时留下现场并报告真实阻塞，主会话不接管实现，也不改模型。
- 美术：实际制作或修改先读取 `~/.codex/skills/xueximod-art-preview/SKILL.md`（`C:/Users/baishang/.codex/skills/xueximod-art-preview/SKILL.md`）。二维用 Aseprite MCP，用户指定时用 Photoshop。有空间关系的都要真实 Blockbench 示意，贴图或粒子也一样。不用 ImageGen 代替绘画或建模。
- 游戏：效果由用户测。默认不 `build`、不打 jar、不 reobf、不发布、不 `runClient`、不启动游戏。离线文档和代码任务不要求游戏桥在线。用户以后明确要求游戏内操作时，再遵守 `AGENTS.md` 的 `ping`、`screenshot_to_file` 和先释放鼠标。

设计最多 2 轮、实现最多 3 轮，分别计数，不必用满。没有独立测试阶段，不为测试单计额度。Codex 主会话和全部 Codex 子代理共享本批对应阶段的计数。不能按文件、术式、ready 子批、新会话、新代理、拆项、改名或重启重置；版本变化和返修仍承接原阶段计数。多次返修后的每次正式 Codex 复审也各占该阶段一轮，无论通过与否都计数。设计例：初审 1/2，返修后复审 2/2，其后不能自动开第三次。实现例：初审 1/3，第一次返修后复审 2/3，再次返修后复审 3/3，其后不能自动开第四次。一次正式的正确性或验收条件审查并给出结论，算一轮；这一轮里的读取和汇总仍是同一轮。领取、读输入、进度采集、协调、阻塞通报和转达 Cursor 结果不算轮次，但不得借这些名义再做正确性审查。计数规则优先于无条件先问脑子。涉及正式校验判断的脑子裁决，调用前先看实际阶段额度，并按该阶段计数：开工前的方案裁决算设计，代码复核算实现，不因脑子身份一律算设计。纯调度和信息采集不算校验。父子代理各自独立重审不能并成一轮。该阶段额度用完后，当次任务不再自动追加该阶段复审，只等待并转达 Cursor 的最终工作结果。不得自动交给 Cursor、另一 Codex 子代理或新会话继续复审，也不能把重复正确性审查说成咨询、定向检查、设计讨论或跨阶段改名。已明确授权的 Cursor 返修、实现、编译和必要定向检查可以照常完成，用户游戏实测不受复审额度限制。Cursor 实现完成、相关写入收束，且适用的编译、资源和需求快照等交付条件已经满足时，可以迁入待验收。没有额外复审、没有独立测试，都不能单独卡住这次迁移。额度耗尽本身不是完成，不能掩盖已知编译失败或实现未完成，也不能写成已经新增复审通过。已知现象和限制写入用户实测记录。游戏实测通过后才迁已完成。未满足这些交付条件不能标通过。上文的直接讨论设计不计本段轮次；若实际是对现有批次的正式正确性或验收复审，或是返修后的正式复审，仍按本段计数，不能改称设计讨论来避开上限。

确有追加必要时，可以向用户简明提出已用次数、未决问题、追加原因、拟复审范围、执行者和拟追加轮数。用户明确同意前不得启动追加复审。沉默、继续返修或报告完成都不等于追加授权。默认直接交付现有结果，不每次机械追问。授权后只在批准的范围和次数内复审，记录授权与累计轮次，不重置原计数。额外复审默认仍可交固定的 Cursor Grok 4.7 High Fast；用户明确选择 Codex 时按该授权执行。交付分开写 Cursor 报告的结果和已做复审的结论。额度已用完且未追加复审时，如实记录「本阶段额度已用完，返修结果未追加复审」，保留原未决问题和缺少的验证。不能把旧版本的通过记录套到新返修版本，也不为此新增表状态。

仅当该阶段 Codex 额度未用完，或用户已明确同意追加复审时，正式复审默认等本阶段已派发、且还能推进的 Cursor 任务全部完成或交接并返回最终反馈，相关写入收束后再集中进行。额度耗尽且未获追加授权时，任务收束也不自动触发本段复审。只等当前阶段，不等还没开始的实现。阻塞项记下原因和下一步，单列；能推进的项组成 ready 子批集中审。拆子批不重置轮次。需要止损的阻塞或风险可以立即通报，这不算按项另开复审。

派发 Cursor 后，等待它完成并返回最终反馈。该阶段额度未用完或已获追加授权时，再按上一段集中复审校验；否则只转达工作结果。执行期间不实时跟进工作内容：不持续读取思考过程、流式输出、工具调用详情、中间代码，不重复扫描 diff，不边执行边审查，以节省 token。工具若必须轮询，只做低频最小状态检查（运行中、已完成、失败、需要输入），不拉取工作内容；优先使用完成通知或等待工具。只有实际失败、阻塞、需要用户输入，或用户明确要求查看进度时，才按需读取必要信息，不默认持续跟踪。本文的「跟踪」「等待最终反馈」和「进度采集」只指上述最小状态检查与最终反馈，不是实时内容监控；进度采集不借此读取工作内容，也不另计校验轮次。仍只等当前阶段可推进任务的完成反馈和相关写入收束，不等尚未开始的后续阶段；阻塞和交接按上一段单列。本段不改变设计最多 2 轮、实现最多 3 轮；没有独立测试阶段。额度用完后不自动追加复审。

## 2. 制作表事实

待制作和制作中：`N` 是用户的完整需求，也是验收依据；`O` 是用户的文字视觉意图。这两列在进入待验收前保持原文，不改成游戏内简句或资源名。`DV` 中的用户原话必须和 `N`、`O` 一起读取、保留。

待验收：`N` 改为准确描述已实现行为的游戏内一句话，并与游戏内显示文案对齐；`O` 改为真实可定位的资源名或资源标识，必要时写路径和多资源对应。游戏接入项核对真实运行引用，纯素材核对正式归档。没有独立资源就写「不适用」及原因。不伪造资源名，也不把文字特效需求留在待验收的 `O`。已完成沿用待验收的这一展示。后续验收仍按批次记录里的完整需求和最新已批准版本，不用这句简写替代。

进入待验收前，按 `B` 编号在已有批次记录保存当次 `N`、`O`、`DV` 原文、最新已批准需求版本、用户后续明确修改、实际资源映射和转换前后值。

## 3. 领取、编号与状态

唯一键是 `B` 编号。工作表名和行号只记录领取时的位置。技术列非空不表示完成，也不构成新任务。四张状态页内每个 `B` 只出现一次。档案页出现相同 `B` 是合法的，不纳入四页重复判定；档案内部每个 `B` 只有一个首次快照。「资源状态明细」仍按既有规则关联同一编号的后续明细，不把明细重复当成状态页重复。任务数量、领取防重和行数守恒只计这四张状态页。

领取前读完四张状态页：

1. 有效行：第 3 行及以后，`B` 去首尾空白后非空，且四页中该编号只出现一次。
2. 问题行：`B` 空但同行有其他内容、编号在四张状态页内重复、四页之间跨页重复。记入本批「待澄清」，其余有效行继续。不自动重编号，不改历史编号。档案页的相同 `B` 不算这个问题。
3. 新任务只从「待制作」的有效行领取。不从已完成补队列，不把历史已完成当成这次已经游戏通过。
4. 用户说按表批量制作时再领取。默认每项是完整术式，包含确认版归档和授权范围内接入。用户写明仅素材时，该项按纯素材范围做。已有设计和已批准版本直接使用。

状态只按页移动：

- 领取时按 `B` 核对四张状态页，以及已有批次记录和交接记录。新编号首次领取前，先按第 8 节把当时待制作完整原始行和适用的原始资源状态明细留档；捕获失败不能先迁走或丢掉原行。留档完成后、开始该项实现前，按第 8 节把该行从「待制作」实际迁到「制作中」，并重开核对。不能只在进度文档里标已领取。写回受阻则该项不作为新项反复派发，记下原因，其他独立项继续。设计、二维、三维尚未确认也留在制作中，细节写批次记录。
- Cursor 实现完成、相关写入收束，且适用的资源归档、代码、必要实现检查、编译和第 2 节需求快照已经满足后，按第 8 节从「制作中」迁入「待验收」。没有额外复审、没有独立测试，都不能单独卡住这次迁移。编译失败、实现未完成或快照缺失则留在制作中。额度用完只整理 Cursor 结果并注明未追加复审，不能写成已经新增复审通过。进入前按第 2 节保存详细需求快照，再转换表内 `N`/`O`。
- 用户游戏实测通过后，才迁入「已完成」。
- 返修回到「制作中」，只重做并重验受影响部分。表内 `N`/`O` 按第 9 节从最近一次已批准的详细需求快照恢复。缺快照则待澄清，本轮不迁移该行。不动历史已完成。
- 纯素材项没有代码、编译和游戏阶段。最终素材验收通过后进入「已完成」。

批量是连续推进互不阻塞的项。等视觉确认的项停在制作中；其他项继续。静默不是批准。可以集中交出一批预览，仍要等用户回复后才归档为确认版。二维确认不等于三维通过。

## 4. 最小输入与底座

领取时至少抄下：编号、名称、来源页、行号、当时表哈希与文件最近更新时间、`N` 功能描述、`O` 特效意图、`DV` 备注原文、最新已批准需求版本、类型、属性、释放种类、释放标签、弹道、链上角色，以及本项实际依赖的尺寸、持续、能量缩放和其他依赖列。缺哪一列，按这项是否用得到判别。完整术式缺功能描述或链上角色，该项待澄清，不补猜。纯图标可以没有链上角色。不要求 144 列全填。同一编号在「资源状态明细」里还有记录时，按编号一起读取。行在待制作或制作中时，抄下的 `N`、`O`、`DV` 保持用户原文。

带下拉约束的枚举列，中文取值只许用「数据表」名称列。`N`、`O`、`DV` 是自由文本。代码对应执行时的现行源码；不一致则该项停在制作中，交给该阶段额度内的唯一 `gpt-6-astra`。额度用完则报告阻塞，不再请脑子重审，也不自动交给 Cursor 复审。表内参数是任务输入，不是覆盖底座的授权。旧设计文档和旧表同样不能单独授权改底座。

新术式在 `ReleaseDefinitions` 登记 `ChainRole`，走同一套收集和结算。结算顺序是索敌、弹道、规则、攻击。枚举声明顺序不是结算顺序。「弹道可被修改」为否时，斩击只改生成位置。落点、交错、一分为三和附魔不按术式 id 分叉。共享底座（释放注册、链结算、公共注册表、语言文件、资源库索引、制作表）先经审查，再由该文件的唯一作者修改。

缺列按角色补，仍缺就待澄清：

- 攻击且释放种类是命中体：要有功能描述、特效和链上角色。移动中的命中体为「是」时，补存活 tick 或飞行速度。用到弧带、护体、屏障、领域或附魔时，只抄该分组里这项要改的列。
- 一分为三：功能描述写明汇总的是后面哪一段攻击，不另造伤害公式。
- 双重释放：必须有双重释放再拉段数。
- 落点指定、锁定实体、追踪、垂落改写、三维交错：功能描述写明改的是方向、落点还是下一段。索敌不改生成位置。
- 动作为释放种类：要有功能描述，不要求命中体尺寸。
- 纯素材：要有编号、名称、特效或外观意图、尺寸。链上角色和代码写不适用。
