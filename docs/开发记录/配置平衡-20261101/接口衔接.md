# A1最终接口与设计第2轮的衔接
A1已最终返回，公共API合同.md可作为已收束输入。其实现期间第2轮补充裁决已经落盘；若A1合同与第2轮不同，以架构裁决.md最后一节为准。本说明是派发合同对齐，不是新正式复审。
- A2负责补 globalDamageContribution(double rawAmount) 及与现有一致的分侧重载，返回 ConfiguredDamage；只应用全局伤害一次，保护规则与damageContribution一致。C按此签名在新无潮印武器印记形成时使用，不在消费或原版首刀使用。
- C bootstrap固定 public static void EnchantmentDefinitions.declareBalance(BalanceRegistry registry)，可使用A1的静态声明入口；A2自行提供同一目录的受控句柄并调用，不能新建第二套注册表。B bootstrap固定 public static void ModTechniques.declareSpecialBalances()。
- 第2轮要求同键重复声明明确报错（包括相同默认值），A2据此把A1兼容合并政策对齐；不同键仍可正常合并。标准与专项的唯一声明者已在架构裁决中确定。A2不得因补标准覆盖B/C专项键。
- 第2轮已固定的C专项键拼写和唯一声明归属优先于A1“建议键”表，例如controlTicks、burnSeconds、periodTicks、intervalTicks、flatTicks、tierTicks、halfExtent。不要因BalanceKeys包含建议常量就额外登记未批准/未实际消费的键。
- A1读取返回ConfiguredDamage；接既有float消费者时使用.amount()，禁止把已配置金额再次送进damageContribution。C提供rawHostAttack/rawAddedDamage/addedSourceId/rawTideDamage/tideMarks精确接口，A负责所有生产carriedDamage调用方接入。
- A2登记前读取原始默认时，不可因Technique公开getter改成有效值而导致RawDefault计算器回调BalanceService；保留独立原始默认来源。
- 实现并行期间各自只依赖这些已定合同，不读他人中间源码；最终交付再统一复核和编译。
