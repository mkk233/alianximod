## 问题 1：被吃掉的修饰进入原来那一次预扣

`pressCommitCost` 在跳过一段链上修饰时，把这段的 `segmentManaCost` 加一次。单独索敌、连续多段修饰、聚能，以及攻击或双重前面被同一计划吃掉的修饰都算。不乘后面的份数。出手仍只按攻击份额拆已经付过的收据，不会再扣一笔。

默认 0 加进去还是 0。领域、屏障、护环的宿主报价仍是占位 0，开域费和生成费不进这笔预扣。自身状态和已删除规则仍跳过。有基础伤害的攻击段不按修饰再加一次，仍按原份数计价。

## 问题 2：求和和乘份数溢出就拒绝

`SkillSegmentMath.exactAdd` / `exactMultiply` 与批量编译一样使用精确整数运算。结果超出 int，或变成负数，返回空。空值不会进入 `MagicPool.trySpend`，也不会再用 `Math.max` 收成 0。

覆盖了这些合计：按键预扣的每一笔累加、附魔报价、段费用乘份数再乘波次、双重成员乘份数、跟随释放的触发与维持合计、印记链的附魔合计，以及自动轮把预扣收成总价。

## 溢出时在哪里停

| 边界 | 拒绝方式 | 收据 |
| --- | --- | --- |
| `SkillUsePacket` 按键预扣，扣款前 | 提示「这组费用算出来越界了」，释放被拒绝 | 还没扣，没有收据 |
| 条件失败后的尾段退款 | 算不出尾段时，退这张收据上还没划走的金额 | 不按回绕后的数字退 |
| 链上触发段另一次扣款 | 报价为空就不扣、不放 | 这一笔没有发生 |
| 印记链 | 扣款前拒绝 | 没有收据 |
| `SkillFollowCast` | 不构造会扣款的跟随 | 没有收据 |
| `AutomaticRound` | 报价为空则直接结束这一轮 | 在 `GroupBudget.reserve` 之前 |
| 已编译计划的 `groupBill` | `CastExecutionSession` 不预留预算 | 没有新收据 |

成功时仍是原来那一次预扣。失败时退的是当时收据上的金额。跟随触发原来就在命中时另扣的那一笔还在，溢出时连这一笔也不扣。
