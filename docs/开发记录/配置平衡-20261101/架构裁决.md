**一、配置与生命周期**

采用独立 JSON 平衡文件，不把动态术式目录塞进现有 `ForgeConfigSpec`。外部术式在 `RegisterXueXiContentEvent` 才登记，早于它构造完整静态配置规格会漏掉扩展内容。

- 整合包模板：`defaultconfigs/xueximod-balance.json`。
- 世界生效文件：`<世界>/serverconfig/xueximod-balance.json`。
- 世界文件不存在时，复制模板；模板也不存在时，根据已登记参数生成完整默认文件。
- 世界文件已经存在时只读取，不用模板覆盖。新增字段在内存中回退到代码默认，不覆盖作者旧值，不自动清掉未知键。
- 修改在下一次服务器启动或重新打开单机世界时生效。本版不提供热重载，避免进行中的收据、燃烧账、实体和缓存混用两个版本。
- 保留现有 `xueximod-common.toml`、地形配置及全部旧键语义，包括潮湿豁免空名单。
- JSON 顶层固定为 `schemaVersion`、`global`、`techniques`。术式对象按完整稳定 ID 定位，内部为扁平参数名。不按中文名或制作表编号定位。
- 已知 ID 别名按 `TechniqueIds.canonicalId` 处理；新旧键同时存在时正式 ID 优先，记录警告。未知 ID、未知字段警告并保留原文件，不让它们悄悄生效。

全局只开放 `damageMultiplier`、`manaMultiplier`、`cooldownMultiplier`，默认均为 1。不开放全局实体数量、复制份数、几何能量或结构规则。

服务端完成内置和外部登记后封存参数目录；在世界开始提供玩法服务前加载、校验、生成不可变有效快照。客户端登录接收同一快照，更新本地展示和有效参数缓存；断线清空。集成服务器不能因客户端断线清理而把服务端快照一起清掉，必须分侧存储。配置包只允许服务端发往客户端，不接收客户端修改请求。

注册和静态初始化阶段只建立原始默认值，禁止提前读取有效配置并永久封入 `static final`。参数目录可以封存，运行时有效值必须来自本次世界快照。

**二、参数声明和共享接口**

新增 `shu/balance/`，由公共作者统一实现。以下接口含义固定，具体类型细节可以由 Cursor 在此合同内实现：

- `BalanceRegistry`：按术式 ID 注册参数声明；声明含键、类型、原默认值或原默认计算器、边界、单位和说明。
- `TechniqueBalanceSpec`：某术式的标准参数及额外参数声明，不包含 `ChainRole` 等结构属性。
- `BalanceService`：获取当前侧不可变快照；解析有声明的参数；统一做伤害贡献、费用、冷却的配置计算。
- `damageContribution(id, rawAmount)`：将**尚未配置缩放的一笔伤害贡献**转换为配置后的伤害，乘本术式伤害倍率及全局伤害倍率各一次。
- `manaCost(id, key, rawDefault)`：读取该费用键并应用全局魔力倍率一次。
- `cooldownTicks(id, rawDefault)`：读取术式基础冷却并应用全局冷却倍率一次。
- `number/intValue(id, key)`：读取已声明的专项参数。生产代码查询未声明键应明确报错，不能静默制造无效配置。

`Technique` 保留原始基础伤害。它参与宿主识别、附魔边界、默认耗魔、装配等结构判断，不能直接把 `baseDamage()` 改为配置后伤害。尤其 `damageMultiplier=0` 不能把攻击变成规则或让领域绑定失效。

基础魔力默认值沿用原代码优先级，用**原始基础伤害**推导；调整伤害倍率不会顺带改变默认耗魔。玩家想同时改变两者时分别配置。

标准声明尽量由 `Technique` 与对应定义已有默认值导出，不再抄一份 62 项伤害/冷却数字。专项声明就近放在所属定义或效果的参数工厂中。原始默认值、配置声明和实际消费者共享同一来源。

内部登记必须显式完成平衡声明，即使某规则只有费用和冷却；封存目录时检查所有已登记术式。对外新增带 `TechniqueBalanceSpec` 的登记入口。旧扩展 API 保持可用，自动获得标准费用/冷却及适用伤害支持，并警告其专项参数尚未声明；不能为兼容旧扩展而伪造范围、速度等键。

**三、首版承诺范围**

全部 62 个术式必须进入参数目录。每个只生成有真实作用的字段：

- 全部术式：基础冷却、适用的基础或单位魔力费用。原本为零的费用仍允许显式配置，但不得改变原收费次数。
- 普通攻击、动作碰撞、批次载体：伤害倍率；实际生效的寿命、运动速度和主要命中尺寸。重复写死的寿命必须接到同一来源。
- 热光束：长度、寿命及真实命中间隔；寄生种子保留固定三颗，不开放数量，开放寿命和主要散布/作用范围。
- 幻剑：真实剑伤倍率、飞行速度、寿命。不能只修改不参与剑伤的 `Technique.baseDamage`。
- 剑来、万剑归宗：适用费用/冷却、实际搜索范围和移动参数；本版不增加通用伤害倍率，已有剑仍保留生成时的伤害身份，避免召回一次就重复放大。指南明确这两式的旧面板底伤不是实际剑伤。
- 水幕：生成费、维护费、维护周期、寿命、主要尺寸、弹速衰减。
- 水环：生成费、维护费、维护周期、寿命、半径、卸伤比例。
- 雾雨、深压、幽冥：实际开域或附魔费用、寿命、盒子尺寸；适用的光环附加伤害或产种参数。**不生成已废弃的领域维护费键。**
- 水牢：每个成功目标的费用、扫描范围、监牢时长、压强伤害倍率及实际脉冲间隔；不改四层门槛和环境伤害归属。
- 燎原、灼地、燎里、焚天、主动冷却蒸汽：真实伤害路径的倍率，以及已有实际范围/寿命。燎里物理与火种伤都归 `fire_liaoli`，分别缩放各自贡献。
- 旧五附魔：适用的附加伤害倍率、费用/冷却和实际控制持续时间。潮印的伤害值与条数分开，调整伤害不改变潮湿/水势条数。
- 资源附魔：引燃、引爆的真实伤害倍率；种火数量；引燃实际段伤、周期、持续参数；幽冥实际产种量和周期。数量边界保持资源上限和合法账本行为。
- 纯规则/索敌/路径术式：费用和冷却；只有已经追到实际消费者的搜索距离等才开放。不能拿未被使用的 `Technique.projectileSpeed` 冒充飞行速度。

首版不开放：结构角色、复制/多重数量、去重与账本规则、结算顺序、原生元素反应表、装配消耗、解锁等级、炉心内部属性改写和热量公式、几何能量规则、视觉专用常量、地形机制开关。炉心三式保留费用/冷却，主动冷却另接真实蒸汽伤害。文档必须明确这些边界，不能写“所有数值可配置”。

**四、伤害唯一乘算合同**

采用“贡献生成时缩放，后续只合并”的方案，**不在 `TechniqueHits` 或 `LivingHurtEvent` 对整刀统一再乘**。否则会重复乘复制账本、领域光环，或把原版普攻伤害一起修改。

具体要求：

1. 普通宿主自己的基础伤害及其原有武器加成，作为宿主贡献缩放一次。附魔附加伤害分别按来源术式缩放后相加。已有同属性、法杖、场地等行为保留。
2. `CastFrame.damage`、`TechniqueHitSpec.settleDamage`、账本中的伤害均视为已配置的值。账本仍是最后一份伤害乘命中份数，不再配置缩放。
3. 领域光环按领域来源形成已配置贡献，再在原有允许合并的位置加一次。不改变哪些命中路径允许领域加伤。
4. 剑生成时，把物品剑伤按 `phantom_sword` 转换一次并保存；后续飞行、召回和读档不再应用配置倍率。旧存档 `Damage` 按已有最终数值使用，不额外追乘。
5. 火伤不能只改登记底伤。`GroundFireFields`、`SurfaceFireHosts`、`FireConsumerPlans`、`KindlePlan`、`DetonatePlan`、`SteamBurst` 等在各自真实贡献边界转换；`FireDamage` 收到已转换金额后只保持原结算。需要保留 `effectKey` 或源 ID 的延迟计划应携带它，不能到 `hurt` 才猜来源。
6. 炉心火基数是另一笔参与公式的数。伤害缩放后，它与 `furnaceSettled` 的关系必须一致，不能让后来追加的炉心份额漏乘，也不能再乘已结算炉心。实现作者须按最终原公式先得出原始该笔伤害，再执行配置转换。
7. 水牢压强在 `PrisonPressure` 产生环境伤害金额时按 `water_prison` 转换。仍没有攻击者、不绕过无敌帧、不新增水势收益。
8. 武器印记保存已配置的附加金额。潮印增加独立的有效伤害金额，不能继续仅靠 `Tide * 2` 恢复配置伤害；条数仍保留原作用。并入原版普攻时只加这笔已配置金额，绝不乘原版那一刀。旧 NBT 缺新字段时走旧金额回退，不叠乘。
9. 普通点燃后由原版自行产生的燃烧伤害，不宣称受本模组全局伤害倍率控制；不注册宽泛伤害事件去捕获原版火伤。

所有保存“已配置金额”的数据都需明确语义；若新增版本标识，缺失时按旧格式解释。不能在保存时和读取时各乘一次。

**五、费用、冷却与边界**

- 魔力倍率在每个有术式归属的费用单价形成时应用一次。之后复制份数、实际成功目标数量及维护次数沿用原账单逻辑。
- 覆盖普通报价、资源附魔、水牢成功单价、护体/屏障生成及维护、领域开域、领域自动子计划和接触附魔收费。
- `MagicPool` 仍是钱包，不做全局倍率；退款必须退原收据金额，不能重新计算配置。
- 冷却配置在各术式的基础冷却读取处统一完成，原附魔反应、段间合成和法杖减免保持原顺序。`scaleCooldown` 不再补乘全局倍率。现有至少 1 tick 的边界保持，不借配置实现改变冷却语义。

声明时为每项设置语义边界：非负费用/伤害、正寿命/周期、有限数值、合法尺寸、比例范围。正时间至少 1，现有特殊哨兵值只在原本支持的位置允许；费用与份数的乘积继续检查溢出。减伤比例沿用现有上限。拒绝 NaN、Infinity 和数值溢出。

单个非法字段告警并回退该字段默认；整个 JSON 语法损坏或未知 schema 版本保留原文件、输出明确错误，本次使用代码默认快照。不得静默重写损坏文件。

## 设计第2/2轮补充裁决

本轮只依据已收束的 `author-B1-final.md`、`author-C1-final.md` 裁决共享附魔金额归属、跨作者接口和重复声明。设计累计 2/2，实现仍 0/3。不全面重审第一轮方案；下列更具体约定覆盖第一轮相应概括，其余架构不变。没有读取源码、没有实现或编译。

### 1. 共享附加额保持原公式，由首次建立它的术式拥有

火、木、土、金在 `EnchantBonus.resolve` 中原本共享一笔 `addedDamage`。这笔钱不是各附魔分别提供 2 点再求和。必须保留当前循环顺序、首次赋值、后续同属性 bump、层数及其他修饰的全部原计算顺序，不做平均分摊、不按最后出现者重归属、不把后续附魔各算一笔。

新增来源记录 `addedSourceId`：在原算法第一次从“尚无共享附加额”建立这笔金额的那个分支，记录当时术式的 canonical ID。后续操作仍修改同一原始金额，但不改变来源。来源记录依据原公式的建立事件，不能依据配置后金额是否为 0；因此第一来源的伤害倍率为 0 时，不会把归属转交后面的附魔。没有这笔贡献时来源为空，金额为 0。

执行完整旧公式得到 `rawAddedDamage` 后，仅调用一次 `damageContribution(addedSourceId, rawAddedDamage)`。宿主伤害倍率不再包住这笔附加额；后续附魔的伤害倍率也不再乘它。这样默认值完全保留原式，配置为非默认值时归属清楚且全局倍率唯一。

C 保持 `carriedDamage(float weaponBonus)` 为旧的原始合计，不在该兼容方法内部加入配置。C 新增并固定这些只读接口：

- `float rawHostAttack()`：原 `attackDamage`，已经过原同属性处理，尚未应用配置；不含附加、潮印、武器。
- `float rawAddedDamage()`：共享附加额的旧公式最终原始值。
- `String addedSourceId()`：首次建立共享额的 canonical ID；无贡献时为空。
- `float rawTideDamage()`：原潮印附加伤害，当前等于条数乘 2，尚未应用配置。
- `int tideMarks()`：原条数，继续独立承担状态与水势语义。

A 的链段伤害组装合同为：宿主项 `damageContribution(hostId, rawHostAttack()+weaponBonus)`，共享附加项 `damageContribution(addedSourceId, rawAddedDamage())`，潮印项 `damageContribution("tide_mark", rawTideDamage())`，三项求和。没有贡献的项直接为 0。之后沿现有场地、帧、实体和账本路径传递，禁止再对合计调用 `damageContribution`。A 必须覆盖普通链、批次链、自动领域和后续释放等所有现有 `carriedDamage` 生产调用方；保留兼容方法不等于允许生产路径漏接配置。

接触附魔不是上述共享公式。`EnchantmentSnapshot.damageOf` 保持原来按下标累加的公式，在每个原始加数上按该下标术式转换一次，写出已配置的 `contactDamage`。B 的接触和领域计费后伤害消费者原样使用，不再缩放。不得把接触公式改成第一来源独占，也不得把普通链改成接触公式。

### 2. 武器印记和无宿主武器份额

C 在新印记形成时按同样“首次来源拥有共享额”规则保存已配置的 `Added`，保存已配置 `TideDamage`，另存原条数 `Tide`。有潮印时，原版主目标那一刀只增加这两笔金额；不改原版基础伤害、不修改横扫，仍不产生第二刀。缺版本旧印记继续按旧最终金额解释，读档不追乘配置。

无潮印时，旧机制额外打一刀 `Attack + Added`。这里 `Attack` 是印记武器数及原 bump，缺少真实宿主术式，不能冒充第一附魔的基础伤害；但它是模组产生的额外伤害，不能漏掉全局伤害倍率。A 因此提供 `globalDamageContribution(rawAmount)`：只应用全局伤害倍率一次，不应用任何术式倍率，使用与 `damageContribution` 相同的有限值/溢出保护。C 在形成新印记时用它处理 `Attack`，保存已配置金额；消费时只加已配置 `Added`，不再缩放。不得对原版最初那一刀调用此接口。此项修正 C1 中“Attack 完全不缩放”的建议，保持全局倍率承诺，同时不捏造术式归属。缺版本旧印记保持旧金额，不追乘。

用户指南必须明确：普通链的火/木/土/金共享附加伤害只受首次建立该金额的附魔伤害倍率影响，后续附魔仍按原规则修饰这同一金额；接触附魔则按原有各格加数分别调整。不能写“每条附魔在所有场景都独立加伤”。无潮印武器印记的武器份额仅受全局伤害倍率影响，原版普攻不受影响。
