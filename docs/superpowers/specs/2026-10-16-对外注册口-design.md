# 对外注册口（第一刀）

日期：2026-10-16

代码还没改。当前实现仍以 `docs/交接-2026-10-16-当前进度.md` 为准。

## 目标

别的模组能在不改本模组源码的情况下，往现有链里登记新术式和新附魔。剑、法杖、第三方魔力下一刀再做。

登记时机钉在本模组 `ModTechniques.registerAll()` 之后。addon 监听本模组的 MOD 事件总线，不在自己的 `commonSetup` 里直接写三张表。

## 公开面

类：`com.bslx.XueXiMod.api.RegisterXueXiContentEvent`，继承 Forge `Event`。

方法只有两个：

- `registerCast(Technique technique, TechniqueEffect effect, ReleaseDefinition definition)`  
  同一次写入 `TechniqueManager`、`TechniqueEffectRegistry`、`ReleaseRegistry`。三条记录用同一个术式 id。
- `registerEnchantment(Technique technique, EnchantmentDefinition definition)`  
  写入 `TechniqueManager` 和 `EnchantmentRegistry`，不写 release 行。`effectId` 只能是 `fire`、`wood`、`water`、`earth`、`metal`。其它 id 拒绝登记并打日志。

已有 id 拒绝并打日志，不能覆盖本模组已经登记的术式。`ReleaseDefinitions.define` 保持 private。addon 自己实现 `ReleaseDefinition`。

`TechniqueManager.register`、`TechniqueEffectRegistry.register`、`ReleaseRegistry.register`、`EnchantmentRegistry.register` 先保持 public。文档写明 addon 不要直接调。

## 抛出

`XueXiMod` 构造函数里的 `modEventBus` 现在是局部变量。实现时存成字段。

`commonSetup` 里，紧挨 `ModTechniques.registerAll()`（现 `XueXiMod.java` 第 93 行）之后，用这条 MOD 总线 `post`。不要放进 `enqueueWork`。不要抛到 `MinecraftForge.EVENT_BUS`。

addon：

- `@EventBusSubscriber(modid = "xueximod", bus = MOD)`
- `@SubscribeEvent` 接收 `RegisterXueXiContentEvent`
- `mods.toml` 强制依赖 `xueximod`，顺序 `AFTER`
- 监听不要标成仅客户端

`commonSetup` 在客户端和专用服务器各跑一次。两边登记同一批 id。没有术式名单同步包。客户端没登记时，装配写槽会因 `TechniqueManager.getById` 为空而拒绝。

## 这一刀顺手改的硬编码

`ReleaseBatch.open`（`ReleaseBatch.java` 第 34–36 行）现在按术式 id `"rule_cast_anchor"` 把 `wantAnchor` 设为真。改成查 `ReleaseRegistry`：`role() == ChainRole.SEEK_SPACE` 就设上。不新增字段。

不改的话，addon 登记的落点指定只会走到 4 格视线，没有现在 8 格寻实体那条。`SkillUsePacket` 已经按角色认 `SEEK_SPACE`。`space_cut` 单独释放时链上没有 `SEEK_SPACE`，仍走 4 格。

`EnchantBonus` 的五行 `switch` 不改。新元素靠登记口直接拒绝。

## 行为约束

结算顺序仍是索敌 → 弹道 → 规则 → 攻击。不要按术式 id 接落点、交错、一分为三或附魔。

`ChainRole` 保持现有 8 个值：`ATTACK`、`ACTION`、`SEEK_SPACE`、`SEEK_ENTITY`、`TRAJECTORY_DROP`、`TRAJECTORY_SCATTER`、`RULE_TRIPLE`、`RULE_DUAL`。addon 不能加新角色。

攻击段在 `TechniqueEffect.execute` 里填 `TechniqueHitSpec`，再 `TechniqueHitSpec.spawn`。修饰段的 `execute` 可以是空的，行为只看 `ReleaseDefinition.role()`。

`trajectoryMutable == false` 的斩击只改生成位置。`phantom_sword` 的 `manipulatesSwordEntities()` 保持 false。操纵剑实体的标记只在 `sword_come`。

## 不做

- 不加新 `ChainRole`，不改结算顺序。
- 不打开第六种附魔元素，不改 `EnchantBonus`。
- 不改 `SkillCarrier`，不认外部剑、法杖。
- 不接第三方魔力。
- 不做术式名单同步包。
- 不做数据包 JSON。
- 不在事件上放 `registerSwordCarrier`、`registerStaffCarrier`、`registerManaSource`。没接线的方法不要先占着。
